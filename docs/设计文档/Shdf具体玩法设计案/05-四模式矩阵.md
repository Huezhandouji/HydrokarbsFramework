### 5.1 差异与复用的总览(v1 §4.1 扩 lobby 列)

| 维度 | 大厅 (lobby) | 炸弹攻防 (BombDefusal) | 团队死斗 (TeamDeathmatch) | 首领战 (BossRaid) |
|---|---|---|---|---|
| 队伍模型 | 无队(不挂 TeamComponent) | 2 队 + 观战(ATTACKER / DEFENDER) | 2~4 队自由(RED/BLUE/GREEN/YELLOW) | 1 队玩家 vs 1 个 Boss 阵营 |
| 回合制 | 无 | **有**(多回合,先到 N 分胜) | 无(连续) | 无(多阶段代替) |
| 结束判定 | 倒计时到点 → `NEXT` + intent | 回合胜 → 比分;比分到顶 `WIN` | 分数阈值 `WIN` / 时限 `WIN/DRAW` | Boss 死 `WIN` / 团灭 `ABORTED→WIN(boss)` |
| 计分载体 | 无 | 回合分(整数) | 击杀分(可加权) | 不用分数(Boss 血线阶段) |
| 重生 | — | 回合内**禁**重生 | 定时重生(5~15s 可配) | 限定生命数(0~1)或禁重生 |
| 阶段链 | Gathering → Vote → Countdown | Warmup → Prep → Live → RoundEnd → (loop) → MatchEnd | Warmup → Live → (SuddenDeath) → MatchEnd | Warmup → P1 → P2 → P3 → Resolution → MatchEnd |
| 角色策略 | 不挂 RoleComponent | 严格池 + 禁重复 + 部署时应用 | 宽松 + 可重复 | 锁定池 + 少量重选 |
| 入场控制(JoinControlComponent) | ✖ 不挂(默认接纳) | ✅ 对局中 REJECT(回合制,观战转待位) | ✅ 对局中 SPECTATE | ✅ 对局中 SPECTATE |
| 记史 | 否 | 是 | 是 | 是 |
| 所需能力标签 | 无 | `"role"` | `"role"` | `"role"` |
| 独有组件 | —(全复用) | RoundComponent BombObjective PlantInteraction EconomyComponent | SuddenDeathComponent | BossComponent BossPhaseGate AggroComponent |
| 静态地图需求 | lobby 出生点、活动区 | 炸弹点区域 × N、双方出生点、活动区 | 队伍出生点 × N、竞技场边界 | Boss 生成点、竞技场边界、机关交互点 |

### 5.2 阶段表、目标、结束条件(竞技三模式;v1 §4.2 保留;阶段表是 PhaseComponent 的数据,结束判定是 EndGateComponent 的数据)

#### 玩法 A:炸弹攻防(回合制)

```
                    ┌────── PhaseComponent 阶段表 ──────┐
  ┌────────┐  join  ┌────────┐  ready  ┌────────┐  ┌──────────┐
  │ Warmup ├───────▶│  Prep  ├────────▶│  Live  ├─▶│ RoundEnd │
  │ 热身/  │        │ 冻结期 │  5s    │ 进行中 │   │ 结算播报 │
  │ 分队   │        │ 禁移动 │        │ 115s   │   │   5s     │
  └────────┘        └────────┘        └───┬────┘   └────┬─────┘
                                       回合胜负判定        │
                              ┌──────────────┬───────────┘
                              ▼              ▼
                        比分未到顶      比分到顶 / 无回合可打
                              │              │
                              └── 回 Prep ───┴──▶ ┌──────────┐
                                                   │ MatchEnd │──▶(缺省策略)回大厅
                                                   └──────────┘
```

**Objectives**(每张图每个炸弹点一个实例):

```java
public final class BombObjective implements Objective {
    private final RegionId siteRegion;      // 来自 MapDefinition.regions
    private BombStatus status = UNPLANTED;  // UNPLANTED → PLANTED → EXPLODED | DEFUSED
    private long fuseDeadlineTick;
    @Override public Progress progress() {
        return switch (status) {
            case UNPLANTED  -> new Progress(0, 1, "已安放");
            case PLANTED    -> new Progress(1, 1, "已引爆");
            case EXPLODED   -> new Progress(1, 1, "已引爆");
            case DEFUSED    -> new Progress(0, 1, "已拆除");
        };
    }
}
```

**EndConditions**(按 `priority` 降序求值,同 tick 命中取高优先级;★v3.1:判定器产出 `GateVerdict`——下表「结果」列即 `MatchOutcome`,引擎只见去向 `TransitionIntent`):

| 优先级 | 条件 | 结果 |
|---|---|---|
| 100 | 某队本回合比分 ≥ `bestOf` | 整场结束,该队 `WIN`(reason=`ROUND_LIMIT`) |
| 90 | 任一炸弹 `EXPLODED` | 本回合 ATTACKER `WIN`(reason=`BOMB_EXPLODED`) |
| 80 | 全部炸弹 `DEFUSED` **且**本回合无未安放炸弹 | 本回合 DEFENDER `WIN`(reason=`ALL_DEFUSED`) |
| 70 | Live 倒计时归零 **且**无炸弹 PLANTED | 本回合 DEFENDER `WIN`(reason=`TIME_EXPIRED`) |
| 60 | 某队存活 = 0 且无重生配额 | 本回合对方 `WIN`(reason=`TEAM_WIPED`) |

```java
// 规则示例:安放成功 → 起爆倒计时 + 记录 + 广播(全声明式)
new Rule("bomb.planted.confirm",
        ev -> ev.is(BombPlanted.class),
        ctx -> true,
        ctx -> {
            var e = ctx.eventAs(BombPlanted.class);
            ctx.component(ObjectiveComponent.class).get(e.siteId()).markPlanted(ctx.tick() + cfg.fuseTicks());
            ctx.stats().recordObjective(e.planterUuid(), "plant");
            ctx.display().flash("炸弹已在 " + e.siteName() + " 安放!");
        });
```

> 回合内的 `WIN`(优先级 90~60)只是**回合结束**;整场 `WIN` 是优先级 100。回合结束走 `RoundComponent` 的阶段回跳(Prep↔Live),不触发 `switchMode`——只有整场结束才产生面向框架的 `EndResult`。

#### 玩法 B:团队死斗

```
  ┌────────┐  join≥min  ┌────────┐  时间到/分数到  ┌──────────┐
  │ Warmup ├───────────▶│  Live  ├────────────────▶│ MatchEnd │
  └────────┘            └───┬────┘                 └──────────┘
                            │ 剩余时间 < 阈值 且 分差 < 阈值
                            ▼
                      ┌──────────────┐
                      │ SuddenDeath  │  重生关闭 / 分数翻倍 / 缩小边界
                      └──────┬───────┘
                             └──▶ MatchEnd
```

**Objectives**:`ScoreObjective(teamId, current, target)` —— 每队一个,`current` 由 `ScoreComponent` 驱动。

**EndConditions**

| 优先级 | 条件 | 结果 |
|---|---|---|
| 100 | 某队分数 ≥ `scoreLimit` | 该队 `WIN`(reason=`SCORE_LIMIT`) |
| 90 | 时限归零 | 最高队 `WIN`;并列 `DRAW`(reason=`TIME_LIMIT`) |
| 85 | 只剩一队有存活且其他队重生配额为 0 | 该队 `WIN`(reason=`LAST_TEAM_STANDING`) |

```java
new Rule("tdm.kill.score",
        ev -> ev.is(RoleKillEvent.class),
        ctx -> !ctx.eventAs(RoleKillEvent.class).isSelfKill(),      // 自杀不计
        ctx -> {
            var k = ctx.eventAs(RoleKillEvent.class);
            int base = ctx.cfg("tdm").getInt("score-per-kill", 1);
            int streakBonus = ctx.component(ScoreComponent.class).streakOf(k.killerUuid()) >= 5 ? 1 : 0;
            ctx.component(ScoreComponent.class).add(k.killerTeam(), base + streakBonus);
            ctx.stats().recordKill(k.killerUuid(), k.victimUuid(), k.victimRoleId());
        });
```

#### 玩法 C:首领战

```
  ┌────────┐  ≥min  ┌────────┐  HP≤66%  ┌────────┐  HP≤33%  ┌────────┐  Boss死/团灭  ┌──────────┐
  │ Warmup ├───────▶│   P1   ├─────────▶│   P2   ├─────────▶│   P3   ├──────────────▶│Resolution│
  │ 集结   │        │ 100~66%│  转场    │ 66~33% │  转场    │ 33~0%  │   团灭倒计时30s│ 结算     │
  └────────┘        └────────┘          └────────┘          └────────┘                └────┬─────┘
                                                                                           ▼
                                                                                      ┌──────────┐
                                                                                      │ MatchEnd │
                                                                                      └──────────┘
```

**Objectives**:`BossHealthGate(phaseIndex, hpPercent)`(血线门,progress = 阶段内剩余血量反向比例);`WipeCounter`(存活数,归零触发团灭判定,Resolution 阶段给 30s 宽限避免同 tick 竞态)。

**EndConditions**

| 优先级 | 条件 | 结果 |
|---|---|---|
| 100 | Boss 实体死亡 | 玩家队 `WIN`(reason=`BOSS_DEFEATED`) |
| 90 | Resolution 结束且玩家存活 = 0 | Boss `WIN`(reason=`RAID_WIPED`) |
| 80 | 限定复活次数耗尽且全员死 | Boss `WIN`(reason=`OUT_OF_LIVES`) |

**独有 `BossComponent` 骨架**(节选;v3:依赖声明移入 Spec,地图需求用 `checkMap` 前置到装配期):

```java
public final class BossComponent extends MatchModeComponent {
    private UUID bossEntityId;
    private final List<BossPhaseGate> gates;   // 按 HP 阈值升序

    public static final class Spec extends MatchModeComponent.Specification<BossComponent> {
        public Spec(BossConfig cfg) {
            super("Boss");
            requires(ObjectiveComponent.class);      // v2 的 requires() 接口方法 → Spec 声明
            requires(DisplayComponent.class);
            requires(RespawnComponent.class);
            requires(PhaseComponent.class);          // jump 推进阶段,装配期保证它在场
        }
        /** 地图适配前置:缺 boss 出生点在切换 A3 就被拒,不再等到 awake(v1 的或ElseThrow 消失)。 */
        @Override public List<String> checkMap(MapDefinition map, MatchModeConfig cfg) {
            return map.spawns("boss").isEmpty() ? List.of("缺少 boss 出生点") : List.of();
        }
        @Override public BossComponent create(String id, MatchModeInstanceServices svc) { ... }
    }

    @Override public void start() {          // 玩家可见副作用(生成 Boss)从 awake 挪到 start
        var svc = svc();
        var spawn = svc.self().map().spawns("boss").stream().findFirst().orElseThrow();
        var entity = svc.self().map().world().spawn(spawn.location(),
                cfg.bossType(), e -> configure(e, cfg.p1()));
        bossEntityId = entity.getUniqueId();
        svc.self().events().publish(new MatchModeInstanceEvent.Custom("boss.spawned", Map.of("entityId", bossEntityId)));
    }

    @Override public void onEvent(MatchModeInstanceEvent ev) {
        if (ev instanceof EntityDamaged d && d.entityId().equals(bossEntityId)) {
            var hp = d.currentHealth() / d.maxHealth();
            int next = nextGateIndex(hp);
            if (next > currentPhase) getComponent(PhaseComponent.class).jump("P" + (next + 1));   // 阶段推进
        }
    }
}
```

### 5.6 `DisplayComponent` 三模式构建函数(自框架侧 06-共享组件 §6.2 迁入,原文完整)

> **来源**:框架侧 `06-共享组件.md` §6.2——框架侧引语已改中性、函数已替换为中性 `exampleDisplay`;以下为原文(原引语 + 三个模式函数 + 原注释)。

原 §6.2 引语:「旧插件的 Renderer 直接渲染"据点链/炸弹三态/票数",换个模式整套报废。新做法:组件只认一个中立模型。」;`DisplayModel.globalProgress` 原注释:「全局进度(炸弹触点 / 分数 / Boss 血线)」。

```java
// 大厅:在线数 / 上局战报(来自 Handoff)/ 本场倒计时
DisplayModel lobbyDisplay(MatchModeInstanceView ctx) {
    var last = ctx.handoff().get(StatsComponent.LAST_SUMMARY);   // ★v3.1:交接键由 StatsComponent 持有
    return new DisplayModel(
        Component.text("大厅 · " + ctx.session().members().size() + " 人在线"),
        List.of(new DisplayLine(voteLine(ctx), 1, NORMAL)),
        last.map(s -> List.of(new DisplayLine(summaryLine(s), 1, HIGHLIGHT))).orElse(List.of()),
        ctx.component(PhaseComponent.class).countdown(), Optional.empty());
}

// 炸弹模式
DisplayModel bombDisplay(MatchModeInstanceView ctx) {
    return new DisplayModel(
        Component.text("炸弹攻防"),
        List.of(new DisplayLine(Component.text("回合 " + ctx.component(RoundComponent.class).current()
                + " / " + ctx.component(RoundComponent.class).target()), 1, NORMAL)),
        ctx.component(ScoreComponent.class).teams().stream().map(t -> new DisplayLine(
                Component.text(teamName(t) + ": " + ctx.component(ScoreComponent.class).of(t)), 1, NORMAL)).toList(),
        ctx.component(PhaseComponent.class).countdown(),
        ctx.component(ObjectiveComponent.class).globalProgress());
}

// 首领模式
DisplayModel bossDisplay(MatchModeInstanceView ctx) {
    return new DisplayModel(
        Component.text("首领战 · " + ctx.component(BossComponent.class).currentPhaseName()),
        List.of(new DisplayLine(bossHealthBar(ctx), 2, DANGER)),
        List.of(new DisplayLine(Component.text("存活: " + ctx.participants().aliveCount()), 1, NORMAL)),
        Optional.empty(), Optional.of(ctx.component(BossComponent.class).healthProgress()));
}
```

package com.shdf.match.mode.bomb;

/** 对照 v2 的 BombDefusalMode implements GameMode(10 个方法,plan() 100+ 行):
 *  v3 工厂只有 Builder 链——每行一个组件声明,阶段表/规则/结束判定/角色策略全是构造数据。 */
public final class BombDefusalModes implements MatchModeProvider {

    @Override public String id() { return "bomb_defusal"; }

    @Override public MatchMode build(MatchModeConfig cfg) {
        var bombCfg = BombConfig.from(cfg);
        return new MatchMode.Builder("bomb_defusal")
            .displayName(Component.text("炸弹攻防"))
            .icon(Material.TNT)
            .mapTags(Set.of("bomb"))
            // ★v3.1:meta 逐字段自建(引擎预设常量已删);"role" 标签字符串,词汇由桥接注册(§8.8);
            // ★v3.2:joinPolicy 字段已删,入场策略见下方 join 组件行(§3.2.1)
            .meta(new MatchModeMeta(Set.of("role"), true, 4, 24,
                    MatchModeMeta.DefaultTransition.FALLBACK))
            // ── 通用件(L3) ──
            .addComponent("teams", new TeamComponent.Spec(List.of("ATTACKER", "DEFENDER"), List.of("SPECTATOR")))
            .addComponent("join", new JoinControlComponent.Spec(JoinControlComponent.MidJoin.REJECT_WHEN_RUNNING))  // ★v3.2:回合制,对局中拒绝参赛(§3.2.1)
            .addComponent("score", new ScoreComponent.Spec(bombCfg.roundLimit()))
            .addComponent("respawn", new RespawnComponent.Spec(RespawnPolicy.NONE))
            .addComponent("phases", new PhaseComponent.Spec(bombPhases(bombCfg)))
            .addComponent("objectives", new ObjectiveComponent.Spec())
            .addComponent("regions", new RegionComponent.Spec())
            .addComponent("interact", new InteractionComponent.Spec())
            .addComponent("role", new RoleComponent.Spec(BOMB_POLICY, 0,
                    List.of(RoleReward.onCustom("bomb.defused", (ctx, ev) -> ctx.addEnergy(ev.actorUuid(), 20)))))
            .addComponent("display", new DisplayComponent.Spec(BombDisplays::bombDisplay))
            .addComponent("stats", new StatsComponent.Spec())

            .addComponent("rules", new RuleBookComponent.Spec(BombRules.all(bombCfg)))

            .addComponent("endgate", new EndGateComponent.Spec(List.of(
                    new RoundLimitEndCondition(bombCfg),
                    new BombExplodedEndCondition(),
                    new AllDefusedEndCondition(),
                    new TimeExpiredEndCondition(),
                    new TeamWipedEndCondition())))
