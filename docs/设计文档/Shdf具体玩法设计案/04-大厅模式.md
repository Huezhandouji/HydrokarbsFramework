### 4.1 大厅与竞技模式的同构性(逐维对照)

| 维度 | 大厅 (lobby) | 竞技模式 (bomb / tdm / boss) |
|---|---|---|
| 是什么 | 一个 `MatchMode` 聚合根(Builder 拼的组件表) | 一个 `MatchMode` 聚合根(Builder 拼的组件表) |
| 地图 | `maps/lobby_main.yml`(`tags: [lobby]`):出生点、活动区、交互点(靶场/跑酷起点) | `maps/*.yml`(`tags: [bomb]` 等) |
| 组件表 | Display / Vote / RegionGuard / IdleActivities / Phase / EndGate / RuleBook | Team / Score / Respawn / Objective / Role / Phase / EndGate / RuleBook / … |
| 阶段表(PhaseComponent 的数据) | Gathering → Vote → Countdown | Warmup → … → MatchEnd |
| 结束判定(EndGateComponent 的数据) | CountdownElapsed → `NEXT` + intent(票选结果) | 各竞技判定 → `WIN` / `DRAW` |
| 角色接入 | **不挂 RoleComponent**(角色清空由旧实例的 RoleComponent.stop() 保证——角色只有它一个写者,§9.4;引擎不兜底,§3.2-B2 注) | 挂 RoleComponent(策略是它的 Spec 构造数据,BOMB/TDM/BOSS 三策) |
| `meta.recordsHistory` | `false`(大厅不写 match_history) | `true` |
| 入场控制(JoinControlComponent,§6.1-#24) | **不挂**(默认全接纳,★v3.2) | 挂(对局中转观战/拒绝) |
| `meta.defaultTransition` | `STAY`(去向永远由 EndGate 的显式 intent 决定) | `FALLBACK`(切到 `session.fallback-mode` 配置的回退模式) |
| `meta.requiredCapabilities` | 空(角色系统缺失也能开大厅) | `{"role"}`(★v3.1:字符串标签,词汇由桥接注册) |

> 引擎里没有任何一行代码检查"当前是不是大厅"。上表每一行的差异都是**声明**——这正是 v1 "机制 = 声明,不是命令"纪律在大厅上的延续。v3 补齐最后一块:v2 的对照表里还有"RolePolicy() / transition() / recordsHistory()"三个接口方法,现在它们全变成了 `Builder` 的参数或组件 Spec 的构造数据——**大厅与竞技模式连"实现面"都同构了**。★v4:会话级组件与模式无关(按会话装配,不按模式);大厅既不需要也不受影响。

### 4.2 大厅的声明(`MatchMode.Builder`,完整骨架)

```java
package com.shdf.match.mode.lobby;

/**
 * 大厅模式:一个用 Builder 声明的聚合根。本类没有任何生命周期代码——
 * 等人靠 PhaseComponent 的 AwaitPhase 数据,收票靠 VoteComponent,
 * 到点离开靠 EndGateComponent 里的判定器。★ 与 v2 的差别:不再 implements MatchMode,
 * 没有任何 @Override。
 */
public final class LobbyModeFactory implements MatchModeProvider {   // SPI:注册面(§7.2)

    @Override public String id() { return "lobby"; }

    @Override public MatchMode build(MatchModeConfig cfg) {
        return new MatchMode.Builder("lobby")
            .displayName(Component.text("大厅"))
            .description(List.of(Component.text("等人、投票、闲玩。")))
            .icon(Material.NETHER_STAR)
            .mapTags(Set.of("lobby"))
            // ★v3.1:meta 逐字段自建(引擎预设常量已删):无能力标签 / 不记史 / STAY;
            // ★v3.2:入场控制不挂组件 = 默认全接纳(§3.2.1),大厅零配置
            .meta(new MatchModeMeta(Set.of(), false, 2, 200,
                    MatchModeMeta.DefaultTransition.STAY))
            // ── 组件表(声明序 = 派发序;全 L3 现成件,零模式特有组件) ──
            .addComponent("phases", new PhaseComponent.Spec(lobbyPhases(cfg)))
            .addComponent("vote", new VoteComponent.Spec(
                    Duration.ofSeconds(cfg.getInt("vote-seconds", 30)), votePool(cfg)))
            .addComponent("idle", IdleActivitiesComponent.SPEC)   // 靶场/跑酷,由地图声明驱动
            .addComponent("guard", new RegionGuardComponent.Spec())   // checkMap 声明 bounds 需求
            .addComponent("display", new DisplayComponent.Spec(LobbyDisplays::lobbyDisplay))
            .addComponent("rules", new RuleBookComponent.Spec(List.of(
                    // 倒计时期间人数跌破 min → 回 Gathering(显式数据,不是隐式 if)
                    new Rule("lobby.underflow",
                            ev -> ev.is(MatchModeInstanceEvent.MemberLeft.class),
                            ctx -> ctx.component(PhaseComponent.class).currentId().equals("COUNTDOWN")
                                 && ctx.session().members().size() < cfg.getInt("min-players", 2),
                            ctx -> ctx.component(PhaseComponent.class).jump("GATHERING")))))
            .addComponent("endgate", new EndGateComponent.Spec(List.of(
                    new LobbyCountdownEndCondition())))
            .build();                                   // 聚合根成型,进程级复用
    }

    /** 阶段表:纯数据。v2 的 phaseChain(cfg) 逻辑原样,只是不再产出引擎对象。 */
    private static List<PhaseSpec> lobbyPhases(MatchModeConfig cfg) {
        return List.of(
            new PhaseSpec("GATHERING", PhaseSpec.Kind.AWAIT,
                    ctx -> ctx.session().members().size() >= cfg.getInt("min-players", 2), null),
            new PhaseSpec("VOTING", PhaseSpec.Kind.TIMED, null,
                    cfg.getInt("vote-seconds", 30) * 20),      // 起票/收票:VoteComponent 订阅 PhaseChanged 驱动
            new PhaseSpec("COUNTDOWN", PhaseSpec.Kind.TIMED, null,
                    cfg.getInt("countdown-seconds", 10) * 20));
    }
}
```

```java
package com.shdf.match.mode.lobby;

/** 大厅唯一的结束判定器(纯函数,由 EndGateComponent 持有与求值)。
 *  ★v3.1:产出 GateVerdict——玩法结局(NEXT)留内容层,只有去向交给引擎。 */
final class LobbyCountdownEndCondition implements EndCondition {
    @Override public int priority() { return 100; }
    @Override public Optional<GateVerdict> evaluate(MatchModeInstanceView ctx) {
        var phases = ctx.component(PhaseComponent.class);
        if (!phases.currentId().equals("COUNTDOWN") || !phases.currentExpired()) return Optional.empty();
        // 票选结果在实例 attrs 里(VoteComponent 收票时写入);无人投票 → 按 lobby.yml 的 rotation 缺省
        VoteResult vote = ctx.attr(VoteComponent.RESULT)
                .orElseGet(() -> VoteResult.rotationDefault(ctx.cfg()));
        return Optional.of(new GateVerdict(
                new MatchOutcome(MatchOutcome.Kind.NEXT, null, "LOBBY_COUNTDOWN_ELAPSED"),
                Optional.of(new TransitionIntent(vote.selection(),
                        Handoff.of(VoteComponent.HANDOFF_RESULT, vote)))));
    }
}
```

map-version: 1

### 4.4 `modes/lobby.yml`(大厅参数 = 可调运营,不含坐标)

```yaml
mode-version: 1
id: lobby
display-name: "大厅"

min-players: 2              # 低于此数不进入投票/倒计时(防单人偷跑)
vote-seconds: 30
countdown-seconds: 10
vote-pool:                  # 投票候选(mode@map);空 = 全 registry 扫描
  - bomb_defusal@crossfire
  - team_deathmatch@crossfire
  - boss_raid@ruin_yard
rotation: [bomb_defusal, team_deathmatch, boss_raid]   # 无人投票时的缺省轮换序
idle:
  enable-shooting-range: true
  enable-parkour: true
```

### 4.5 `VoteComponent`:通用投票(L3,大厅与局末共用)

```java
package com.shdf.match.component.vote;

/**
 * 通用投票组件:候选集 + 时长 + 计票策略。
 * 两个出厂用法:①大厅 VOTING 阶段投"下一场玩什么"(结果经本组件 HANDOFF_RESULT 交接);
 *             ②竞技模式 MatchEnd 阶段投"下一张图"(结果经 StatsComponent.LAST_SUMMARY 顺路带回大厅)。
 * 投票 UI(聊天点击/箱子 GUI)是组件内部实现,模式无感。
 * v3:基类换成 MatchModeComponent(获得 svc/getComponent/声明序派发),收票结果写实例 attrs 的
 *     命名空间自动 = 组件 id("vote"),不再手写常量(§2.7)。
 */
public final class VoteComponent extends MatchModeComponent {

    /** 收票结果(写到本组件命名空间下);EndCondition 从这里读(见 LobbyCountdownEndCondition)。 */
    public static final AttributeBag.Key<VoteResult> RESULT =
            AttributeBag.Key.of("vote", "result", VoteResult.class);

    /** ★v3.1:交接键(本组件命名空间 "vote")——投票结果由生产者自己持有,
     *  框架不设保留键(HandoffKeys 已删,§3.3)。 */
    public static final Handoff.Key<VoteResult> HANDOFF_RESULT =
            Handoff.Key.of("vote", "result", VoteResult.class);

    public static final class Spec extends MatchModeComponent.Specification<VoteComponent> {
        public Spec(Duration duration, List<VoteCandidate> pool) { ... }
        // 计票策略:多数胜;平局 → TieBreak.RANDOM(配置可改 FIRST_LISTED)。每人一票,可改票。
        // 零票 → 组件不写 RESULT,消费方用 rotationDefault 兜底。
        @Override public VoteComponent create(String id, MatchModeInstanceServices svc) { ... }
    }
}

public record VoteCandidate(String modeId, String mapId) {}
public record VoteResult(VoteCandidate winner, Map<VoteCandidate, Integer> tally,
                         boolean fromDefaultRotation) {
    public MatchModeSelection selection() { return new MatchModeSelection(winner.modeId(),
            Optional.of(winner.mapId()), false); }
}
```
