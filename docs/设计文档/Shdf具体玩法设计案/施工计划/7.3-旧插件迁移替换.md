## 目标

1. 交付**迁移脚本** `LegacyMapMigrator`:输入旧插件数据目录(`config.yml` + `maps.yml`),输出 `maps/map_crossfire.yml`、`maps/lobby_main.yml`、`modes/bomb_defusal.yml` 草稿 + `migration-report.md`(字段映射 + 人工确认清单);
2. 交付**字段映射表**(施工步骤 3,勘察自旧仓真实源码)与 golden test;
3. 给出 `SHDFGamePlugin` 停用清单(disabled/删 jar/世界回收)与**回滚预案**;
4. 完成**新老并行跑一局对比**(同一地图、换算后同一规则,行为一致)并留记录表;
5. 落**数据不迁移声明**:旧插件零持久化,无数据可迁(§0.1,本次已实测复核)。

## 施工步骤

1. **固化勘察结论(输入格式快照,写进迁移报告开头)**——全部已验证:
   - 出生点全部是 `{x, y, z}` 三维 `Vector`,**无 yaw/pitch**:`ConfigManager#parseVector` 只读 x/y/z(`ConfigManager.java:482-488`);全仓 `yaw` 仅 1 处注释命中(`BombInteractionController.java:267`,不涉配置);
   - 区域全部是立方体**角点写法** `start/end`:`parseCubeRegion` → `CubeRegion.createFromCorners`(`ConfigManager.java:474-480`),角点无序由工厂归一;
   - 规则参数与地图数据**混在 maps.yml**(票数/重生/时限),违反新设计"地图 = 纯静态,无规则字段"(§15.2);
   - 旧插件**直接玩主世界** `world`,无副本机制:全仓只有 `Bukkit.getWorld(...)`(约 14 处),零 `WorldCreator`/`unloadWorld`(grep 实证);
   - `plugin.yml`:`depend: [ShadowHunterRolesPlugin]`、命令 `shdfgame`(`/sg`)、权限 `shadowhunter.game.player`。
2. **`tools/legacy-migration/LegacyMapMigrator.java`** — 迁移脚本:自带 `main`,纯 JDK + SnakeYAML,**零 Bukkit 依赖、不进 shadow jar**;`build.gradle.kts` 加 `tools` sourceSet + `JavaExec` 任务 `migrateLegacyMaps`(参数 `<旧数据目录> <输出目录>`)。输出四件:
   1. `maps/map_crossfire.yml`(§15.2 格式);
   2. `maps/lobby_main.yml`(world ← 旧 `waiting.world`;`spawns.lobby` ← 旧 `waiting.lobby_spawnpoint`);
   3. `modes/bomb_defusal.yml` 草稿(规则参数换算,映射表见下);
   4. `migration-report.md`:勘察快照 + 逐字段映射结果(旧值原样/新值/换算式)+ **人工确认清单**——脚本对"设计无对应键"的旧值只摘录不编造(错误映射比缺映射危险;§15.2 容错精神)。
3. **字段映射表(脚本内实现 + 报告生成依据)**——三档:直接映射 / 换算 / 人工确认。

   **输入 A:旧 `config.yml`(全局,单文件含大厅与选角出生点)**

   | `role_selection.attacker_spawnpoint` / `defender_spawnpoint` | `maps/map_crossfire.yml`:`spawns.role_select_attacker` / `spawns.role_select_defender` | 直接(yaw 补 0) |
   | `waiting.min_population_per_side` / `max_population` | `modes/bomb_defusal.yml`:`limits.min-players`(=per_side×2)/ `limits.max-players` | 换算 |
   | `waiting.countdown_time: 600`(tick) | `modes/lobby.yml` 倒计时键(tick/20 = 30s) | 换算 |
   | `waiting.mode`(auto/require_ready) | 无直接对应:开局门由 lobby 投票/倒计时承担(§4;§13.2) | 人工确认 |
   | `role_selection.duration` / `reconnect_time_limit` | 选角时限 = RolePolicy/RoleComponent.Spec 构造数据(§9;§10.2"角色策略=配置默认") | 人工确认 |
   | `playing.allow_duplicate_roles: false` | `modes/bomb_defusal.yml`:`role.policy.allow-duplicates`(§15.2 恰有此键) | 直接 |
   | `playing.reconnect_time_limit: 1200`(tick) | `config.yml`:`session.disconnect-grace-seconds`(1200/20 = 60s,恰为 §15.2 默认) | 换算 |
   | `playing.finish_display_time: 200` | lobby 结算展示参数(§4;无对应键 → 人工确认) | 人工确认 |
   | `maps: ["map_crossfire"]` | 每图一文件:`maps/map_crossfire.yml`(§15.2) | 直接 |

   **输入 B:旧 `maps.yml` 的 `maps.map_crossfire` 节 → 静态进 `maps/*.yml`,规则进 `modes/*.yml`**

   | 旧键 | 新去处 | 档 |
   |---|---|---|
   | `name` / `description` / `icon` | `display-name` / `description` / `metadata.preview-icon`(icon 串 → Material,非法名记报告) | 直接 |

   | `spectator_spawnpoint` | `spawns.spectator` | 直接 |
   | `max_tickets` / `initial_tickets` | 票数是规则 → `modes/bomb_defusal.yml`(ScoreComponent.Spec 数据;§6.1;无现成键 → 人工确认) | 人工确认 |
   | `attacker_respawn_time: 100` / `defender_respawn_time: 80`(tick) | respawn 块(§15.2 示例 `enabled: false` 与旧行为冲突——旧插件有重生队列,`SpawnManager.java:59-74` 按 `ShdfTeam` 取等待时长;草稿按旧行为写启用 + tick/20 秒) | 换算+人工 |
   | `sector_advance_interval: 600`(tick) | 据点间歇期 → bomb 规则(PhaseSpec/配置;人工确认) | 换算+人工 |
   | `roles.attacker/defender`(角色 id 池 `red`/`meiqihezi`) | 角色池 = RolePolicy 数据/配置默认(§10.2);角色 id 存在性需角色系统在线校验 | 人工确认 |
   | `objectives[].id/name`(三据点) | `regions.<id>.*` 命名 + 报告摘录 | 直接 |
   | `objectives[].bombs[].region.start/end` | `regions.<bombId>: {type: cuboid, min:[…], max:[…]}`(各轴取 min/max;§15.2 `regions.site_a` 同构) | 直接 |
   | 同上(操作范围语义) | 另生成 `interact-points.<bombId>: {pos: 盒中心, radius: 对角线一半, tag: bomb-site}`(§15.2 interact-points 同构);点/半径是近似,偏差写报告 | 换算 |

## 关键实现要点

1. **脚本是纯函数工具**:输入文件 → 输出文件 + 报告,不碰 Bukkit、不连服——因此可离线 golden test(§16.2-9"规则可离线测"的精神);放 `tools` sourceSet 是为了**不进插件 jar**(发布产物只含插件本体)。
2. **报告优先于猜测**:无对应键的旧值只摘录;人工确认清单是交付物的一部分,不是脚本失败。
3. **换算可追溯**:报告每行带旧值原样 + 新值 + 换算式(如 `1200 tick ÷ 20 = 60 s`),对比表可直接引用。
4. **顺序不能倒**:停用的不可逆点只有"jar 移走",但它改变玩家可玩行为;P8 的验收方式就是对比(§16.1),对比是停用的前置闸。

## 陷阱与纪律

- **§14.7 跨局残留**:对比与停用巡检重点盯"清场是否干净"——旧插件清场 4 处复制是其著名事故(延迟 1 tick 绕时序);新侧由 `close()` 幂等单入口结构性保证(§1.3 对照表行 3)。对比中旧侧出现残留属旧插件已知缺陷,记录不修旧。
- **§14.19 世界句柄**:新侧副本世界泄漏由 `WorldRefCountTest`(★17)守;迁移本身不引入世界操作(模板复制是人工步骤,§3.7)。
- **§15.2 容错三铁律**(脚本同款):缺键有默认/非法值降级告警/单图失败不拖垮整批(旧 ConfigManager 本就逐图隔离,`ConfigManager.java:299-313`,沿用口径)。
- **术语**:报告与注释用 v4.0 词汇;禁 `../../CONTEXT.md` 历史术语表旧名(裸 Mode 接口/RoleLoadoutComponent/HandoffKeys/enum Capability/引擎侧结局枚举等)。
