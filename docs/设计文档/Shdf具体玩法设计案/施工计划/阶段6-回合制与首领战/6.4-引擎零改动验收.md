### 步骤 6:实测总闭环(§16.1 P6/P7 验收方式)

4. 库不可用降级与落库链路不受本阶段影响(阶段5 基线仍绿)。

## 关键实现要点

1. **零改动有三道机械防线,缺一不可**:PR diff 人工核对(本步)、ArchUnit 包依赖(`LayeringTest`)、源码禁词扫描(`EngineHasNoModeStringsTest`/`EnginePurityTest`)——diff 证明「这次没改」,测试证明「以后也改不了」(§13.2、§16.2-★5/★24)。
2. **★5 在 6.4 首次建立**:记录(命令输出摘要 + 路径清单)写进 PR 描述,作为阶段7 API 冻结的证据——模式层已用行动证明引擎契约完备(施工计划 §4 映射——框架线 `../../../施工计划/README.md` §4、本线 `../README.md` §3)。
3. **CTF 预演是「设计承诺的验尸」**:§13.1 的行数预算是设计对复杂度的承诺;bomb/boss 实际行数统计(步骤 5 顺带输出)若显著超预算,预演结论如实记录偏差与原因,不粉饰。
4. **矩阵回归只引用既有验证载体**:缺口回对应子阶段补,本步不新写玩法断言。

## 陷阱与纪律

- **§14.13 让模式在引擎注册自己**:SPI 是 `META-INF/services` 一行,`MatchModeRegistry` 双发现对新模式零感知(§12.2);diff 出现 `MatchModeRegistry.java` 改动即违规。
- **§14.21 大厅特判反弹**:预演同时检查 `lobby` 未被任何切换路径特判(禁词表含 `lobby`,`LobbyIsJustAModeTest` 绿)。
- **§14.12 引擎/组件内容词汇**:`bomb`/`boss`/阶段名等只允许住在 mode/** 与 resources;源码扫描在本步全量重跑,不是抽查。
- **§14.19 世界句柄泄漏**:循环切换实测覆盖 REUSE_DIRTY 与 TEMPLATE_RESTORE 两种处置路径(`WorldRefCountTest` 口径,§3.7)。
- **§14.16/§14.17 切换风暴与重入**:循环切换日志核对无风暴 WARN、无 `SWITCH_IN_PROGRESS` 重试(§3.5 防护在真实模式下复测)。
