### 步骤 5:阶段表 + `BossPhaseGate` + `WipeCounter`

阶段表(PhaseComponent 数据):`Warmup`(AWAIT,≥3)→ `P1/P2/P3`(Objective 型,无时限,由血线 jump 推进)→ `Resolution`(TIMED 600t = 30s)→ `MatchEnd`(TIMED)。

- `BossPhaseGate`(Objective,注册进 ObjectiveComponent):阈值列表**升序** `[0.66, 0.33]`;每次越阈只触发一次;血量回升不回跳阶段;
- `WipeCounter`(Objective):持 RAIDERS 存活数(经 TeamComponent/Participant 读口,§14.26);归零时(且仅一次)`jump("Resolution")`;
- Resolution 是 30s 宽限阶段:期间三条判定照常求值——Boss 在宽限内死亡 → 判定 100 胜;宽限到点仍无存活 → 判定 90(§5.2-C:「Resolution 阶段给 30s 宽限避免同 tick 竞态」)。

### 步骤 6:三条 EndCondition(整场级,全挂 EndGateComponent.Spec)

boss 无回合,不存在 6.1-Q1 的冲突,三条全部进 EndGate(§5.2-C 表):

| 类名 | priority | 命中条件 → 结果 |
|---|---|---|
| `BossDefeatedEndCondition` | 100 | Boss 实体死亡 → 玩家队 `WIN`,reason=`BOSS_DEFEATED`(含 Resolution 宽限期内) |
| `RaidWipedEndCondition` | 90 | 当前阶段=Resolution 且已过期且存活=0 → Boss `WIN`,reason=`RAID_WIPED` |
| `OutOfLivesEndCondition` | 80 | 重生配额耗尽且全员死(任意阶段)→ Boss `WIN`,reason=`OUT_OF_LIVES` |

判定器纯函数、离线可测(§16.2-9);同 tick 命中按 priority 降序取首(§5.2 求值规则)。

## 关键实现要点

1. **生成在 start 不在 awake**:awake 只解析依赖缓存引用、不得改玩家可见状态(§2.4;§9.4 逐钩子表同源);Boss 实体是典型可见副作用,放 `start()` 且至多一次(§5.2 骨架注释)。
2. **checkMap 前置 = 「缺 boss 出生点」在切换 A3 被拒**(§5.2、§3.2-A3):detail 口径与 6.2 一致。
3. **阶段门是组件 jump,不是引擎回调**:任何「让引擎推 boss 阶段」的冲动撞 §14.24;P1/P2/P3 登记为 AWAIT(entry 谓词与血线门同源,实际推进由 BossComponent 血线命中时的显式 `jump` 完成),Warmup=AWAIT(成员≥min)、Resolution/MatchEnd=TIMED——两型口径与 1.5 交付一致(§6.1-#4 的「Objective 型」由 AWAIT entry 谓词覆盖,`../../../CONTEXT.md` 权威)。
4. **宽限的必要性**:最后一名玩家死亡与 Boss 死亡可能跨 tick 先后到达;直接判负会把「本可赢的团灭瞬间」判成输。Resolution 30s 让三条判定在同一窗口内按 priority 仲裁(100>90>80)。
5. **命数与宽限的边界**:判定 80 可在任意时刻命中;宽限内若复活不可能(配额 0),判定 90 到点必中——两条 reason 语义不同,测试都要钉住。
6. **Boss 实体清场**:stop 移除实体幂等;即使 quarantine 强关,close 逆序 stop + 登记回收保证不残留(§14.7、§16.2-6/7)。

## 陷阱与纪律

- **§14.24 引擎回流**:血线推进/团灭宽限全在组件与 mode 数据里;engine 出现 `Boss`/阶段门词汇即 `EnginePurityTest` 红(§16.2-★24)。
- **§14.12 if-else 反弹**:三阶段机制写成 P1/P2/P3 的 Spec 数据与规则,不写 `if(phase=="P2")`;mode id 字面量只存在于 mode/boss 与 resources。
- **§14.26 裸写状态**:存活数/仇恨值/血线门状态各归其主(TeamComponent/AggroComponent/BossPhaseGate),跨组件只走读口。
- **§14.6 任务爆炸**:Resolution 30s 用 PhaseComponent TIMED 表达,不自起定时轮询;转场播报用 `svc().later` 且随实例回收(`delay=1L` 纪律属引擎)。
- **§14.7 跨局残留**:Boss 实体/仇恨表/血线门随实例生灭;下一局的跨局状态只可能来自 `Handoff` 或寄居会话级组件(★v4:两通道口径,D10;§3.3)。
- **§14.10 MiniMessage 注入**:Boss 名/玩家名播报走 `Placeholder.unparsed`。
