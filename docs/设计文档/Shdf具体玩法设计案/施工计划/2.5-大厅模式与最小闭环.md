## 目标

大厅以**普通模式**身份运行(Builder 声明的聚合根,零特权,§4.1 同构表),加上第二个空转测试模式 minilobby,构成阶段2 出口闸门的两个测试对象——**lobby ↔ minilobby 原子往返 100 次:成员零丢失、世界零泄漏、引擎零改动**(§16.1-P1)。新增的可验证物:

1. 大厅全套:LobbyModeFactory/三阶段表/倒计时判定器/VoteComponent/IdleActivitiesComponent/两份 yml;
2. minilobby:Builder 最小表模式,同时预演 §13.3"换一套大厅"验收动作;
3. 离线 100 次往返循环测试(机械部分)+ 起服 ≥10 次人工往返(时序部分);
4. **遗留必须写明**:大厅 Display 组件(与 RegionGuard)留待阶段4 完成后各回接一行 `addComponent`——本阶段组件表暂缺这两件,回接是纯 L4 声明变更、零引擎改动。

## 施工步骤

路径相对 `src/main/`(java 或 resources)。

**新增文件清单**:`VoteCandidate`/`VoteResult`/`VoteComponent`(component/vote/)、`IdleActivitiesComponent`(component/lifecycle/)、`LobbyModeFactory`/`LobbyCountdownEndCondition`(mode/lobby/)、`MiniLobbyFactory`(mode/minilobby/)、资源四件(modes/lobby.yml、modes/minilobby.yml、maps/lobby_main.yml、maps/lobby_mini.yml)、SPI 追加两行、命令三子命令、测试 5 类。

有序步骤:

1. **VoteCandidate + VoteResult**(§4.5 record 原样):`VoteCandidate(modeId, mapId)`;`VoteResult(winner, tally, fromDefaultRotation)` + `selection()`(转 `MatchModeSelection`,带 mapId、非 force)。补静态 `rotationDefault(MatchModeConfig cfg)`:读 `rotation` 列表第一项造 `VoteResult(fromDefaultRotation=true)`(§4.2 消费点);列表为空 → 返回 `Optional.empty()` 语义(消费方兜底,见步骤 4)。
2. **VoteComponent**(§4.5 最小完整版,extends `MatchModeComponent`):
   - 两个公开键:`RESULT = AttributeBag.Key.of("vote", "result", VoteResult.class)`(实例内读)与 `HANDOFF_RESULT = Handoff.Key.of("vote", "result", VoteResult.class)`(**键随主人**,§3.3/§14.20;框架不设保留键);
   - `Spec(Duration duration, List<VoteCandidate> pool)`:计票=多数胜;平局 `TieBreak.RANDOM`(可配 `FIRST_LISTED`);每人一票、可改票;**零票不写 RESULT**——兜底责任在消费方(§4.5 Spec 注释);
   - 行为:订阅 `PhaseChanged`(component/phase,阶段1 件)——进入 `VOTING` 时向全体成员发聊天候选行(Adventure `ClickEvent` 执行 `/sm vote <n>`;玩家名一律 `Placeholder.unparsed`,§14.10);进入 `COUNTDOWN` 时收票、多数胜定 winner、写 `RESULT` 并广播结果;`onHandoff(out)` 写 `HANDOFF_RESULT`。
   - 零 Bukkit 监听器,输入只有命令路由(步骤 7);投票 UI 是组件内部实现、模式无感(§4.5)。
3. **IdleActivitiesComponent**(component/lifecycle/;P1 交付物,§16.1):
   - 单例 `SPEC`(§4.2 用 `IdleActivitiesComponent.SPEC`);常量 `TAG_IDLE = "idle-activity"`(§4.3 地图侧声明);
   - `awake()`:从 `svc().map()` 收集 regions 与 interact-points 中带该 tag 的条目,缓存为不可变活动表(**声明驱动,零硬编码坐标**);
   - `update()`:低频节流(每 20 tick 一轮),遍历成员位置做 `NamedRegion.contains`/点半径判定:进入区域或活动点 → 一次性提示 + 计次写入**本组件命名空间**的 attrs(§2.7;禁止写他人命名空间,§14.26);
   - 刻意不挂 Bukkit 监听器:阶段4 `InteractionComponent`/`InteractionListener` 落地后把事件源换成路由,组件行为不变——替换点写进 javadoc。
4. **LobbyCountdownEndCondition**(mode/lobby/,包私有 final class;§4.2 骨架逐行):`priority()=100`;`evaluate`:当前阶段非 `COUNTDOWN` 或未过期 → `Optional.empty()`;读 `ctx.attr(VoteComponent.RESULT)`,空则 `rotationDefault(ctx.cfg())`;**两者皆空 → 返回 `Optional.empty()`**(无 intent,`defaultTransition=STAY` 原地,自洽兜底);命中 → `GateVerdict(MatchOutcome(NEXT, null, "LOBBY_COUNTDOWN_ELAPSED"), Optional.of(new TransitionIntent(vote.selection(), Handoff.of(VoteComponent.HANDOFF_RESULT, vote))))`——玩法结局留内容层,只有去向交给引擎(§3.4)。
5. **LobbyModeFactory**(mode/lobby/,implements `MatchModeProvider`;§4.2 完整骨架):
   - `id()="lobby"`;`build(cfg)` 按 §4.2 Builder 链:displayName(大厅)/description/icon(`NETHER_STAR`)/`mapTags(Set.of("lobby"))`/`meta(new MatchModeMeta(Set.of(), false, 2, 200, MatchModeMeta.DefaultTransition.STAY))`——**meta 逐字段自建,引擎无预设常量**(§0.5.3);★v3.2:meta 无 joinPolicy 参,入场不挂组件 = 默认全接纳(§3.2.1);
   - 组件表(声明序=派发序),本阶段挂载 5 件:

   | 组件 id | Spec | 说明 |
   |---|---|---|
   | `phases` | `PhaseComponent.Spec(lobbyPhases(cfg))` | 阶段表见下 |
   | `vote` | `VoteComponent.Spec(vote-seconds, vote-pool)` | 起票/收票订阅 `PhaseChanged` |
   | `idle` | `IdleActivitiesComponent.SPEC` | 地图声明驱动 |
   | `rules` | `RuleBookComponent.Spec(List.of(underflow))` | `lobby.underflow`:**`ParticipantLeft`** 触发(§4.2 原文写 `MatchModeInstanceEvent.MemberLeft`,引擎 Structural 族无此类型,§12.2,已登记待裁决)——COUNTDOWN 期间成员数 < min-players → `jump("GATHERING")` |
   | `endgate` | `EndGateComponent.Spec(List.of(new LobbyCountdownEndCondition()))` | 唯一判定器 |

   - **遗留注记(代码注释与本文件必须保留)**:`display`(阶段4 `DisplayComponent.Spec(LobbyDisplays::lobbyDisplay)`)与 `guard`(阶段4 `RegionGuardComponent.Spec`)两行 `addComponent` 待回接——回接零引擎改动(任务书要求写明);

6. **MiniLobbyFactory**(mode/minilobby/;§13.3 四步表):`id="minilobby"`、`mapTags(Set.of("lobby"))`、`meta(Set.of(), false, 1, 200, STAY)`(★v3.2 无 joinPolicy 参);组件表只有 `phases`(单个 `AWAIT` 的 Gathering,**无条件**=永久等待)——不挂 Vote/Idle/EndGate,「不挂结束条件就没有结束判定」是自然后果(§13.3);零外部参数。它就是本阶段的"第二个空转测试模式",并把 `session.initial-mode` 改成 `minilobby` 即为 §13.3 的换大厅验收动作(引擎零改动)。(**★v1.3-D5 注(框架 21-D5):`session.initial-mode` 键已随框架「启动建会话」特性删除——本验收动作同步改为「宿主把 `SessionService.create(SessionSpec)` 的 `initialModeId` 填 `minilobby` 后起服」;「引擎零改动」命题不变。**)

## 关键实现要点

- **大厅零特权是本子阶段的灵魂**:引擎/会话层没有一行认识 `lobby`(§14.21);倒计时→票选→切换的全部语义都是 §4.2 那张组件表的**数据**。★13 的断言方式:lobby 与 minilobby 的切换走同一入口、同一状态机、同一 B1~B5。
- **两把 vote 键的分工**(§4.5):`RESULT`(attrs)给实例内 EndCondition 读;`HANDOFF_RESULT`(Handoff)给下一个模式读——同一份数据、两条通道,常量的主人都是 VoteComponent(§3.3 键表;框架零保留键)。
- **零票兜底链**(三层,逐层可测):

  | 兜底层 | 条件 | 行为 |
  |---|---|---|
  | 有票 | `RESULT` 在实例 attrs | tally 多数胜 |
  | 零票 | `RESULT` 空 | `rotationDefault(cfg)`(列表首项,fromDefaultRotation=true) |
  | rotation 也空 | 再兜底失败 | `evaluate` 返回 empty → 无 intent → STAY 原地 |

  断言落在 `VoteComponentTest` 与判定器离线单测。
- **遗留回接的具体形态**(写给阶段4):在 `LobbyModeFactory.build()` 组件表中按 §4.2 的声明序插入 `.addComponent("guard", new RegionGuardComponent.Spec())`(idle 之后)与 `.addComponent("display", new DisplayComponent.Spec(LobbyDisplays::lobbyDisplay))`(guard 之后)两行——终序 …idle→guard→display→rules→endgate,与 §4.2 原序及 4.3 步骤10 的插入位置一致;`LobbyDeclarationTest` 的组件表断言同步加两行——除此之外零改动。
- **起服实测与离线测试的分工**:100 次的机械保证由 `LobbyMinilobbyRoundTripTest` + `WorldRefCountTest` 承担(可重复、可断言);起服 ≥10 次人工循环负责离线覆盖不了的时序(真实 tick、真实世界加载/卸载、聊天投票 UI、断线重连)——两者在 DoD 分列,不互相冒充。
- **本阶段不做的**(防范围蔓延):投票箱子 GUI(聊天点击已够,§4.5「UI 是组件内部实现」)、Display 渲染(阶段4 回接)、RegionGuard 保护(阶段4)、boss/tdm/bomb 的 vote-pool 行(阶段5/6)——每项在对应阶段的回接点已注明。
- **min-dwell 与 100 次往返的关系**:往返是外部调用,`force` 可豁免防护①(§3.5);离线测试用测试时钟推 tick 或带 force,起服实测间隔 >5s——两种写法都合法,测试里注明用的哪种。
- **id 重复注册即响亮失败**(2.2):lobby/minilobby 各注册一次;`mapTags` 同为 `[lobby]` 合法(`forMap` 返回列表,§12.2),不构成冲突。

## 陷阱与纪律

- §14.21 大厅特判反弹——本子阶段最容易犯:倒计时逻辑出现在引擎/会话层=打回;它只存在于 `LobbyCountdownEndCondition`(§4.2)。
- §14.20 Handoff 键随主人——禁止在 engine/session 定义任何 vote 相关常量;`VoteComponent.HANDOFF_RESULT` 是唯一主人(§3.3 键表)。
- §14.12 if-else 反弹——阶段推进是 PhaseSpec 数据;`lobby.underflow` 是 RuleBook 数据;组件行为层不得按阶段 id 写分支。
- §14.10 玩家可控字符串喂 MiniMessage——投票 UI 与"已投票"提示中的玩家名用 `Placeholder.unparsed`(§14.10 点名的重灾区条款)。
- §14.6 任务管理——投票倒计时是 PhaseComponent 的 TIMED 计时,不是新起 `runTaskLater`;IdleActivities 的轮询节流在 `update()` 内计数。
- §14.18 两层成员——投票"每人一票"以 uuid 为准;组件不自建会话级玩家账本。
- §14.13 同源纪律——minilobby 的存在不要求 engine 任何一行(§13.3);review 发现"为 minilobby 加引擎分支"即打回。
