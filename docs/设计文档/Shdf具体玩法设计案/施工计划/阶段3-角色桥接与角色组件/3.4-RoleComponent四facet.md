## 目标

本子阶段结束后,L3 出现 `component/role` 包:

- 一个 `RoleComponent` 组件,模式挂上它即获得**完整角色接入**(选角授权/数值介入/敌对判定/事件消费/局末释放),**不需要知道 RoleFacade 存在**(§9 章首);
- 四个内部 facet——`Loadout`(授权与占用)/ `State`(数值与采样)/ `Hostility`(敌对口径)/ `Rewards`(事件→角色操作)——是内部接缝不是子组件(§9.3);
- `RoleKillEvent` / `RoleStateChangedEvent` 两个事件词汇与合成器 `RoleEventSynth` 住本包(§8.4 v3.1 迁移;★23 放行的唯一事件位置);
- **stop 后全员清角、幂等——v3.1 起角色清场唯一闸,引擎无兜底**(§9.4 stop 行;§0.5.3 已删切换 B3);
- §9.7 的五个测试 + `RoleEventSynthTest` 全绿。

## 施工步骤

1. **建桥接进程持有器 `RoleBridge`**。
   - 文件:`src/main/java/com/shdf/match/bridge/role/RoleBridge.java`。
   - `public final class`,私有构造;`static volatile RoleFacade instance` + `static void attach(RoleFacade f)` + `static RoleFacade facade()`(未 attach 时懒构造默认 RoleFacade——RoleFacade 只依赖 Bukkit 静态门,无插件句柄需求)。
   - **为什么需要它**:§9.3 的 RoleComponent 拿桥接只有两条路——svc(成员封闭三成员,禁增设,§14.25)或 Spec 构造参数(模式工厂传不了,★23 禁模式 import 桥接)——进程级持有器是唯一合规注入点;消费方(`component/role`)import 桥接合法(★23 豁免包)。
   - 3.3 的 L0 装配处补一行 `RoleBridge.attach(facade)`(推荐显式 attach 保持单一实例;不 attach 则走懒构造)。
   - 设计未指明该注入路径 → 已列文末「待裁决问题」。

2. **建事件词汇 `RoleKillEvent` / `RoleStateChangedEvent`**。
   - 文件:`src/main/java/com/shdf/match/component/role/RoleKillEvent.java`、`RoleStateChangedEvent.java`。
   - 均 `implements MatchModeInstanceEvent`(开放根,§12.2),住本包(§8.4 v3.1:事件类型住桥接则模式无法 import,住 engine 则引擎认识内容——唯一同时满足两边的位置是 component/role)。
   - `RoleKillEvent` 组件:`(UUID killerUuid, UUID victimUuid, String victimRoleId, int tick)`(§12.2 事件示例行字段集;§8.4 合成构造参数 `new RoleKillEvent(killer, victim, victimRole, tick)`);`occurredAtMillis()` 取构造时刻;提供紧凑工厂 `of(killer, victim, roleId, tick)`。
   - ★ 不带队伍字段——消费者经 `getComponent(TeamComponent.class)` 自查(§8.4 代码注释"队伍上下文不带在事件上")。
   - `RoleStateChangedEvent` 组件:`(UUID who, String roleId, RoleSnapshot now, int tick)`(差分后的当前帧;§9.4 update 行"值真的变了才发")。
   - 两事件是普通 record,**不是 Bukkit Event,不进服务端总线**(§15.1 规范清单"自定义事件"行)。

3. **建奖励映射类型 `RoleReward` 与 `RoleOpContext`**。
   - 文件:`src/main/java/com/shdf/match/component/role/RoleReward.java`、`RoleOpContext.java`。
   - `RoleReward` = 匹配谓词 + 效果:`boolean matches(MatchModeInstanceEvent ev)` + `void apply(RoleOpContext ctx, MatchModeInstanceEvent ev)`;静态工厂 `onCustom(String type, BiConsumer<RoleOpContext, MatchModeInstanceEvent.Custom>)`——按 `MatchModeInstanceEvent.Custom` 的 type 匹配(§9.6 声明样例 `RoleReward.onCustom("bomb.defused", ...)` 是形状权威)。
   - `RoleOpContext`(本包,小接口)给三个类型化动作:`addEnergy(uuid, n)` / `gainSanTe(uuid, n)` / `applyBuff(uuid, type, ticks)`——全部转发 `RoleStateAccess`;奖励映射**永远不直接碰字符串协议**(§9.5 分工表"能量/SanTE/buff 类型化读写"行)。

4. **建合成器 `RoleEventSynth`**。
   - 文件:`src/main/java/com/shdf/match/component/role/RoleEventSynth.java`。
   - 包私有 final class,静态方法,**自身不持有任何实例状态**(§8.4 v3.1 注释:合成器是 RoleComponent 的无状态协作者;防腐层不持有实例状态的纪律沿用)。
   - `static Optional<RoleKillEvent> onDeath(RoleFacade role, PlayerDeathEvent e, int tick)`(§8.4 代码签名),逐条:
     - ① `role.roleIdOf(victim.getUniqueId())` 读死前角色——**必须发生在角色系统 NORMAL 清角之前**(读取时序由 3.5 的 LOWEST 监听器保证,本方法按约定顺序读;§8.4 注释①;§14.5);
     - ② `role.lastDamagerUuid(victim)`——★ **不是 `getKiller()`**(§8.4);
     - ③ killer 为 null(摔死/箭矢不入账等无归属)→ `Optional.empty()`,不计分(§8.4);
     - ④ 合成 `RoleKillEvent.of(...)` 返回。
   - §14.4 双源交叉验证门(非自杀/参与者在场/原生归因一致)**在 3.5 补进调用链**——本步骤落 §8.4 基础版,留 TODO 标注"补齐前 RoleKillEvent 不接计分"。
   - `static List<MatchModeInstanceEvent> diffSample(RoleStateAccess state, Map<UUID, RoleSnapshot> lastSeen, Collection<Participant> who)`(§8.4 代码签名):
     - 对每人采一帧(energy/sanTe,经 `RoleStateAccess`;无角色者跳过——`role.hasRole` 或 roleIdOf 判);
     - 与 `lastSeen` 差分:**值真的变了才产** `RoleStateChangedEvent`,并更新 lastSeen;
     - 快照表由组件持有、这里只经参数读写(§8.4"采一帧 + 差分"的无状态纯函数注释)。
   - 采样成本口径写进 javadoc:20 人 × 3 次操作 / 5 tick ≈ 12 次/tick,每次是 HashMap 查表 + 字符串解析,微秒级;**绝不改成每 tick 采样——那才是真成本**(§8.4 成本核算段)。

   - **`LoadoutFacet`**(①授权与占用):解释 `RolePolicy`(§8.6:机制 = 声明,不是命令)。职责清单:
     - 校验 `facade.isValidRole`(目录里没有的角色直接拒);
     - `globallyBanned` 拒(无论池子怎么写都不允许,§8.6);
     - 按队池:`poolByTeam` 键 = 队伍 id,空集 = 不限用全量目录(§8.6);TeamComponent 缺席(可选依赖)而池非空 → 拒绝并在消息里点名装配声明错误(§9.3 requiresOptional 注释"按队限池的模式在 checkMap/awake 自查");
     - 占用去重:`allowDuplicates=false` 时同一角色全场唯一(含跨队,§8.6);

## 关键实现要点

- **facet 是内部接缝不是子组件**(§9.3 末决断):组件粒度判据 = **状态是否同源**。占用表/换角计数/采样快照/授权时机全围绕"本实例的角色占用"一件事,拆开必然跨组件同步;对照角色系统 `FactionComponent`"一个组件管一个概念的全部读写"(阵营真值/判定/复位都在它里面)的先例。facet 测试可直接打,但类包私有,不是公共接口。
- **一个写者原则**:对角色系统的一切写(setRole/clearRole/能量/buff/阵营)都经 `RoleFacade`——它就是操作面的类型化壳,组件内绝不出现第二条写路径(§9.2 末行"FactionComponent 的写口经组件操作面"的镜像)。组件自己也是"占用表/换角计数/采样快照"的唯一主人,其他组件经读口查询(状态唯一,§2.8-决断三)。
- **事件回环是形状不是 bug**:synth 合成的 `RoleKillEvent` 发上总线后会再次进入自己的 `onEvent`(→ rewards)——奖励挂击杀正是设计要的(§9.4 onEvent ②)。当前映射不产生新 RoleKill,无环;若未来某奖励会致死,需自查此回环。
- **异常降级口径**:坏数据(目录缺失/操作面拒绝)降级为"该玩家无角色",不炸实例(§9.2 异常隔离行引角色系统 quarantine 纪律);`RoleStateAccess` 的 OptionalInt 语义在此兑现——empty 即按无数据处理。
- **组件不认识能力标签**:`"role"` 能力在 `MatchModeMeta.requiredCapabilities` 由模式工厂声明、切换期校验(§9.5 分工表能力行);RoleComponent 对 CapabilityRegistry **零依赖**。
- **接入矩阵自检**(§9.6):大厅**不挂**本组件("不介入 = 不声明",§8.6 末行);挂载者策略各异(BOMB/TDM/BOSS)——差异全在 Spec 数据,组件无分支;采样关/开的差异同样是 `sampleIntervalTicks` 数据。
- **目录快照的 TTL 取舍**:awake 取一次快照够整局用(角色目录运行期几乎不变);消费时 `isExpired` 则可选重取——目录只影响展示与校验,不影响真值(§8.5)。

## 陷阱与纪律

- **§14.5 NORMAL 读死前角色**:本组件的 `onVanillaDeath` 只能被 LOWEST 监听器喂进来(3.5);组件内**不得自行注册 Bukkit 监听器**——注册与优先级纪律归监听器层(§15.1"监听器不做重活"行、"监听器注册时机"行)。
- **§14.4 击杀归属**:本步骤的 synth 基础版尚无四条件门;**3.5 补齐前不得把 RoleKillEvent 消费接进计分**——否则箭矢/陈旧 PDC 会产生假击杀(§14.4 后果行)。
- **§14.26 状态主人唯一**:占用表/快照表/计数表字段包私有;`DisplayComponent` 等消费者只能走读口,不能拿表引用(§9.3 读口注释)。
- **§14.25 svc 封闭**:拿桥接只经 `RoleBridge`(步骤 1);绝不以"便利"为由给 MatchModeInstanceServices 加第四成员。
- **§14.12 if-else 反弹**:策略差异(BOMB vs TDM vs BOSS)是 Spec 数据;组件内出现 `if (policy == BOMB_POLICY)` 即违规(§8.6"声明,不是命令")。
- **§14.7 跨局残留**:stop 的全员清角是结构性保证的最后一环;v3.1 引擎无兜底——`RoleComponentLifecycleTest` 用计数断言锁死(见下)。
- **§14.18 两层身份不混**:占用表的键值语义是"本实例内谁持有什么"(实例概念);会话级成员不含角色(`../../../CONTEXT.md` SessionMember 行)。
