## 目标

本子阶段结束后,工程里出现**唯一**一个 import `com.shadowHunterRolesPlugin` 的类:`bridge/role/RoleFacade`。

- 覆盖 RoleAPI 冻结面 **14 方法,1:1**(§16.3(一)对照表)——角色系统加方法时缺口一目了然;
- 覆盖**阵营操作面五动词**(`faction` / `declared` / `hostile <uuid>` / `set <名>` / `reset`,组件 id `faction`)——★ 非对称语义:hostile 在**发起方**实例上判,发起方无实例 ⇒ true(§8.2、§16.3(二));
- **懒解析**:构造不取 API,首次调用才 load 并缓存(§8.8)——角色插件缺席时构造不炸;
- 附带两个自家值对象:`RoleDescriptor`(不含阵营)与 `RoleFaction`(SHADOW/HUNTER/UNKNOWN/OTHER 四值);
- `roleIcon` 缺失回 `Material.AIR` 而非 null(§8.2)。

设计纪律(§8.2 类头注释):本类方法签名只用 JDK / Bukkit / Adventure 类型,**绝不泄漏 RoleAPI 的类型**(如 `RoleInfo`)——角色系统升级换签名时,全工程只改这一个文件。

## 施工步骤

1. **加 test 依赖**。
   - 文件:`build.gradle.kts`,`dependencies` 块追加 `testImplementation("com.shadowHunterRolesPlugin:ShadowHunterRolesPlugin:1.0.0")`。
   - 理由:`compileOnly` 不进测试类路径,而 `RoleFacadeContractTest` 要用假 RoleAPI 实现打桩;坐标与 A1 一致(mavenLocal,§0.2-A1)。
   - 验证:`.\gradlew.bat build` 确认依赖可解析,再继续。

2. **建包与枚举 `RoleFaction`**。
   - 文件:`src/main/java/com/shdf/match/bridge/role/RoleFaction.java`。
   - 四值:`SHADOW / HUNTER / UNKNOWN / OTHER`(§8.2;OTHER 兜住角色系统未来的新阵营名)。
   - 读方向静态方法 `parse(String)`(§8.2 映射口径):
     - 认不出的**非空**串 → `OTHER`;
     - `null` / 空串 → `UNKNOWN`;
     - `"SHADOW"` / `"HUNTER"`(大小写敏感,角色系统 `core.Faction` 枚举名原样)→ 同名值;
     - 外部 `core.Faction` enum **不参与映射**(§8.2:不泄漏其类型,只认字符串)。
   - 写方向实例方法 `wireName()`:`OTHER` 无对应阵营名 → 返回 `null`(调用方据此**拒绝且不发起操作**,§16.3(二)set 行);其余回自己的 `name()`。

3. **建值对象 `RoleDescriptor`**。
   - 文件:`src/main/java/com/shdf/match/bridge/role/RoleDescriptor.java`。
   - record 四字段:`id` / `displayName(Component)` / `description(List<Component>)` / `icon(Material)`。
   - ★ **不含阵营**——`RoleInfo` 只有这四个成分,角色目录没有阵营来源;要"某角色的声明阵营"只能从正持该角色的玩家实例上读 `declaredFaction`(§8.2 RoleDescriptor 注释)。

4. **建 `RoleFacade` 骨架与懒解析**。
   - 文件:`src/main/java/com/shdf/match/bridge/role/RoleFacade.java`,`public final class`。
   - 字段:`private RoleAPI api;`(`@Nullable`,**懒解析**,§8.8)——v1 的"构造期取 API、缺席抛 IllegalStateException"在 softdepend 下会让大厅陪葬(§14.22,§8.8 懒解析行)。
   - 字段:`private final Supplier<RoleAPI> lookup;`——默认 `() -> Bukkit.getServicesManager().load(RoleAPI.class)`(§0.1 唯一出口);提供包私有构造器允许测试注入假 Supplier(唯一测试缝,生产路径零改变)。
   - 私有 `RoleAPI ensureApi()`:缓存命中即返;未命中则 `lookup.get()` 并缓存。★ **null 也缓存**(插件缺席时不该每次调用都打一遍 ServicesManager);失效只经 `invalidate()`。
   - 包私有 `invalidate()`:清空 api 缓存(3.3 的 CapabilityListener 在服务注销时调,§8.8"动态感知"行)。
   - 公开 `boolean available()`:`ensureApi() != null`(给 3.3 能力探测用,§8.8 register 行)。
   - 类头 javadoc 写死两条纪律(§8.2):①全工程唯一允许 import `com.shadowHunterRolesPlugin` 的类;②签名只用 JDK/Bukkit/Adventure 类型,绝不泄漏 RoleAPI 类型。

## 关键实现要点

- **懒解析 ≠ 异步**(§8.8 尾注):只把"取 API"从构造期挪到首次调用;所有方法仍**只能主线程调用**。开发期可在公开方法入口加 `Bukkit.isPrimaryThread()` 断言(照 §2.7 AttributeBag 的开发期断言思路),生产可关。
- **null 占位缓存**:api == null 是合法缓存态——不缓存 null 则大厅场景每次调用都查一遍 ServicesManager;失效只由 `invalidate()` 驱动(§8.8 动态感知)。这是 3.3 动态刷新能生效的前提。
- **不抛原则**:插件缺席时降级为空读/假写,绝不让"角色插件没装"变成 `IllegalStateException` 把大厅掀了(§14.22 的反面教训正是构造期抛)。
- **1:1 计数口径**(§16.3(一)尾注):冻结面 = **14**;阵营五条经操作面**不算进 14**。`available()/invalidate()/handles()`(3.3 加)是桥接自身生命周期方法,不计入对照表——javadoc 要写明,免得后人当"第 15 个方法"删改。
- **为什么 Supplier 注入**:14 方法全走 `Bukkit.getServicesManager()` 静态门,离线单测无法起服;Supplier 是唯一测试缝,生产默认值就是设计指定的唯一出口(§0.1 体检表)。
- **动词字符串只住本层**:`"faction"` 与五个动词 token 是私有常量,消费方只见类型化方法——与 3.2 的 `RoleStateAccess` 同一口径(§14.14 规避:别让上层拼协议串)。
- **值对象不可变**:`RoleDescriptor` 是 record、`RoleFaction` 是 enum,天然不可变;Facade 不缓存 `RoleDescriptor` 实例的可变副本(catalog() 每次现转,缓存归 3.2 的 RoleCatalog,§8.5)。
- **缺失判定成对出现**(§16.3(一)icon 行):图标缺失判 `AIR`、名称缺失判空 `Component`——两个"没有"的表示法不同,写消费方时成对检查,别只判一种。
- **不缓存玩家的当前角色/能量**(§8.5 表第 1 行):角色系统是"玩家当前是谁/数值多少"的权威,本插件不缓存——每次现问;唯一例外是目录类只读快照(3.2 的 RoleCatalog,带 TTL)。Facade 自己不做任何按 uuid 的表。
- **available() 与懒解析的关系**:`available()` 会触发 ensureApi(第一次探测即定缓存);别在它里面绕过缓存直查 ServicesManager——否则 3.3 的失效联动会出现两条缓存真相。

## 陷阱与纪律

- **§14.22 软依赖时序**:构造期取 API + softdepend = 加载顺序不利时大厅陪葬;本子阶段从根上以懒解析规避,strict 强校验留给 3.3。
- **§14.14 null 三重含义**:null = 未识别/拒绝/内部异常被吞——本层只透传不解释;解释权在 3.2 的 `RoleStateAccess`(Optional 化)。别在本层提前做 OptionalInt,层内职责单一。
- **§14.4 击杀归属**:`lastDamagerUuid` 参数必须是 `Player`;**禁止**在本层加 `LivingEntity` 便利重载——角色系统没有这个签名,加了就是自造协议。
- **§14.1 线程纪律**:14 方法全主线程;本子阶段不引入任何异步路径(懒解析也不异步,§8.8)。
- **§14.25 反向提醒**:桥接的进程级传递(3.4 的 RoleBridge)不经 svc——`MatchModeInstanceServices` 三成员封闭,不为桥接开第四成员。
- **§14.13 边界自省**:桥接属于 L1,不是引擎的一部分;本子阶段不往 `engine/**` 加任何文件,`engine/` 的 PR diff 应为空。
- **§8.1 总览图的落位**:RoleFacade 之上的消费者(3.4 的组件)调它;它之下是 `Bukkit.getServicesManager().load(RoleAPI.class)` 唯一出口——本类任何方法都不得绕开 ServicesManager 直连角色系统内部类(§0.1 体检表"对外出口"行)。

## 测试与验收

测试类:`src/test/java/com/shdf/match/bridge/role/RoleFacadeContractTest.java`(§12.1 测试树既有名字;测试类住同包便于打桩)。复用注入假 RoleAPI(实现 14 方法)打桩,断言:

1. **懒解析**:构造时 Supplier 未被调用;首次调方法才取一次;之后命中缓存不再取(§8.8)。
2. **插件缺席**(Supplier 恒回 null):构造不炸;`knownRoleIds()` 空集;`catalog()` 空表;`roleIcon` 回 `AIR`;`playerFaction/declaredFaction` 回 `UNKNOWN`;`setRole/clearRole/setPlayerFaction/resetPlayerFaction` 回 false;`areHostile(a,b)` 回 true(发起方无实例口径,§16.3(二))。
3. **roleIcon**:假 API 回 null → Facade 回 `Material.AIR` 而非 null(§8.2)。
4. **catalog()**:`RoleInfo` 被转 `RoleDescriptor`;反射断言 record 组件恰好 4 个、无 faction 字段(§8.2)。
5. **阵营读方向**:`"SHADOW"/"HUNTER"` 正确映射;`"XYZ"`(未来新阵营)→ `OTHER`;null → `UNKNOWN`;空串 → `UNKNOWN`(§8.2 映射口径)。
6. **阵营写方向**:`setPlayerFaction(u, OTHER)` 返回 false 且断言假 API 收到的 operate 调用次数为 **0**;`setPlayerFaction(u, HUNTER)` 透传 `"set HUNTER"`、回非空 ⇒ true;组件拒绝小写(回 null)⇒ Facade 回 false——组件侧拒绝行为属角色系统(`FactionComponent.java:233`),本测试只验透传。
7. **areHostile**:`(null, b)`、`(a, null)` ⇒ false;假 API 回 null ⇒ true;回 `"true"` ⇒ true;回 `"false"` ⇒ false(§16.3(二))。
8. **invalidate()**:失效后再次调用会重新取 Supplier(为 3.3 动态刷新铺路)。
9. **1:1 完整性**:反射列公开方法,对照 §16.3(一)14 行清单断言齐全(防漏写第 13 个"备用"方法 `lastDamager`)。
10. **透传真值**:`operate` 对任意 `(uuid, componentId, payload)` 原样透传(含 null payload)——断言 Facade 不加预处理、不吞返回值(语义解释权在 3.2,§14.14)。

对应验收编号:**★3**(只有 bridge/role 引用角色插件——规则在阶段1.4 建立,本子阶段起实际生效;步骤 7 + `LayeringTest#onlyBridgeImportsRolePlugin` 守门);为 ★23(3.4 落地)准备消费面纪律。
