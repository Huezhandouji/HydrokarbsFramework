## 目标

本子阶段结束后:

- Bukkit 事件入口就位:`RoleSignalListener`(LOWEST,只路由不合成)把死亡喂给 RoleComponent;`StatsSignalListener`(MONITOR)记账伤害;`SessionIngestListener` / `InteractionListener` / `ProtectionListener` 注册占位(§12.2 listener/ 清单 + §15.1 优先级表);
- §14.4 双源交叉验证门补齐并专测:击杀归属 = `lastDamagerUuid` + 非自杀 + 参与者在场 + 原生归因一致,**四条件缺一不认**;`player.getKiller()` 全仓禁用;

## 施工步骤

1. **建 `RoleSignalListener`**。
   - 文件:`src/main/java/com/shdf/match/listener/RoleSignalListener.java`。
   - **逐行照抄 §12.2 样例**:`@EventHandler(priority = EventPriority.LOWEST, ignoreCancelled = true)` 的 `onDeath(PlayerDeathEvent)` → `sessions.sessionOf(e.getEntity().getUniqueId()).flatMap(Session::currentInstance).map(i -> i.component(RoleComponent.class)).ifPresent(r -> r.onVanillaDeath(e))`。
   - 三条纪律:
     - **只路由,不合成**——合成逻辑在 RoleComponent/RoleEventSynth(§12.2 类注释;§9.3 onVanillaDeath 注释);
     - **必须 LOWEST**——抢在角色系统 NORMAL 清角之前读死前角色;§12.2 javadoc 的因果链(NORMAL 之后读 `roleIdOf` 恒 null)要原样写进代码注释,防止后人"顺手统一优先级";
     - 监听器不持状态、不做重活(§15.1"监听器不做重活"行)。
   - 注意:`PlayerDeathEvent` **不可取消**(不实现 Cancellable),`ignoreCancelled` 在此是 no-op——保留 §12.2 原样写法,但不得误以为它过滤了什么(§15.1 规范清单"ignoreCancelled 的语义"行)。

2. **补齐 §14.4 双源交叉验证门**(3.4 留的 TODO,本步骤收口):
   - 在 `RoleEventSynth` 增加纯谓词 `static boolean trustedKill(UUID killer, UUID victim, boolean killerInInstance, UUID nativeDamager)`:四条件 `killer != null && !killer.equals(victim) && killerInInstance && killer.equals(nativeDamager)` 全过才 true(§14.4 规避代码逐条:非空 / 非自杀排除陈旧值 / 参与者在场 / ★ PDC 与原生归因一致才认)。
   - `RoleComponent#onVanillaDeath` 负责从 Bukkit 事件**抽取**四个原始值:
     - 参与者在场:`svc().self().participant(killer).isPresent()`(§14.4 的 `ctx.participant(killer)`);
     - 原生归因:`victim.getLastDamageCause() instanceof EntityDamageByEntityEvent ede` 取 `ede.getDamager().getUniqueId()`(§14.4 同源写法;投射物可能是 Arrow/Trident,本设计只用它做交叉验证,不做归属来源,§15.1"投射物归因"行);
     - killer / victim 直接取自 synth.onDeath 的中间结果。
   - 谓词通过 → 发布 `RoleKillEvent`;不通过 → 发布引擎结构事件 `ParticipantKilled(victim, null, cause)`(§14.4 else 分支;事件形状按 §12.2 v3.1 版——只带 victim / killer / cause,**不带角色/队伍字段**)。
   - **禁用面扫描**:`grep -rn "getKiller()" src/main/java` → 零命中(§14.4 事实:唯一正解是 `getLastDamagerUuid`;两个已知边界见"前置")。
   - 实现顺序建议:先谓词与单测(纯函数,十分钟绿),再抽取薄层接进 `onVanillaDeath`,最后 runbook 真机复核——谓词错了改一行,事件流错了要起服排查。

## 关键实现要点

- **LOWEST 的因果链要写进代码注释**:角色系统 NORMAL 清角(`PlayerListener.java:21`)→ NORMAL 之后读 `roleIdOf` 恒 null(§14.5)→ 死前读取权 = LOWEST。这段注释是防止后人"顺手统一成 DEFAULT"的唯一防线。
- **谓词与抽取分离**:`trustedKill` 是纯函数(四原始值入参),离线单测全覆盖;Bukkit 抽取(取 cause、取 damager)留在 `onVanillaDeath` 薄层——这正是"规则可离线测"(§16.2-9)在击杀归属上的落法。
- **两条监听器各自独立**(v3.1 拆分,§12.2):伤害记账与角色无关;优先级不同(LOWEST vs MONITOR)、语义不同(读死前状态 vs 最终伤害记账)——**不要合并回一个监听器**。
- ** MONITOR 的纪律**:MONITOR 层"只记账不改状态"(§15.1 优先级表调试/审计行同款纪律);StatsSignalListener 里不得 setCancelled、不得改实体。
- **占位监听器的占位是临时的**:每个占位首行标注接管阶段与目标组件;`InteractionListener` 的 move 是高频事件,即使占位也要"先廉价判断再做事"(§15.1 优先级表 move 行)。
- **debug 命令是 ★23 的活标本**:命令层消费角色信息的唯一合法路径 = RoleComponent 读口;实现完成后它是 `onlyRoleComponentTouchesBridge` 最好的正面教材,也是 3.6+ 时代"其他系统怎么消费角色"的示范代码。
- **击杀合成只发生在会话实例内**(§12.2 路由代码的隐含契约):`sessionOf` 为空(路人死亡)或当前实例无 RoleComponent(大厅)→ 监听器静默返回——路人的击杀不进任何实例总线,大厅的死亡不合成 RoleKill。
- **伤害记账同样以实例为界**(§12.2 StatsSignalListener 代码):两侧都先 `sessionOf(...).flatMap(currentInstance)` 再取组件;不在会话里的伤害(主城 PvP 关闭等)自然落空。

## 陷阱与纪律

- **§14.4 击杀归属**:双源四条件缺一不可;`getKiller()` 全仓禁用(grep 零命中为 DoD);箭矢 null、死亡不清账两个边界都要有测试或真机复核;**禁用面扫描要含测试代码**(`src/test` 一起 grep)。
- **§14.5 NORMAL 读死前角色**:步骤 1 的优先级是验收项,不是建议;`roleIdOf` 的读取发生在 synth 内、由 LOWEST 时序保护。
- **§14.1 异步红线**:监听器回调全在主线程同步执行,回调内只路由/记账,不引入任何异步路径(§15.1"监听器不做重活"行)。
- **§14.10 文本注入**:debug 输出含玩家名与角色显示名,一律 `unparsed`(§14.10;GUI 名称/击杀播报是重灾区,debug 面同样适用)。
- **§14.6 任务爆炸**:本子阶段不新增任何周期任务;临时观测桩验收后必须移除(DoD 有专条)。
- **§14.18 两层身份不混**:监听器路由拿的是 uuid → 会话 → 实例;不把 SessionMember 当 Participant 用(§14.18)。
- **§14.12 词面纪律**:占位监听器的方法体里不出现具体模式 id、具体组件 id 字面量(路由目标是类型查找 `component(X.class)`,不是按 id 找)——占位期养成的坏习惯会带进阶段4。
- **占位的事件即契约**:占位监听器监听的事件集合与优先级一旦按 §15.1 定下,阶段4/5 接管时只许换方法体、不许换监听面——下游(地图/交互/保护)按事件面接线。
- **监听器构造注入只进数据不进行为**:依赖通过构造参数(Consumer/接口)进来,监听器自身不做服务定位(Bukkit.getServicesManager 之类)——保持它"唯一允许 @EventHandler、其余全薄"的层定位(§12.1 listener/ 注释"唯一允许 @EventHandler 的层")。
