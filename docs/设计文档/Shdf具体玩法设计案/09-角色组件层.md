> 篇内 § 引用口径:§0~§3、§6、§7、§10~§20 指框架侧(../)同名篇;§4/§5/§8/§9 指本目录对应篇。

> 本章是 v3 的显式需求:**参照角色插件(ShadowHunterRoles)自己的设计思路,在角色桥接(§8,防腐层)之上封装"一个角色组件"**。它是一个 L3 组件,一个模式挂上它就获得完整的角色玩法接入——选角授权、数值介入、敌对判定、事件合成消费、局末释放——而**不需要知道 `RoleFacade` 存在**。

### 9.1 为什么需要这一层:桥接是翻译器,不是玩法

§8 的桥接层(RoleFacade/RoleStateAccess,以及 v3.1 起随事件词汇移入本层的合成器)解决的是**协议问题**:字符串操作面 → 类型化 API、原版事件 → 合成事件、懒解析 → 能力声明。它刻意保持**无实例状态、无玩法语义**(防腐层纪律)。但模式真正需要的不是"14 个方法",而是四件**有状态、有生命周期**的事:

| 需求 | 为什么不能散在桥接/模式里 |
|---|---|
| 选角授权(池/去重/换角/部署时机) | 有**实例状态**(占用表);v2 把它做成独立的 `RoleLoadoutComponent`,但只覆盖了这一件事 |
| 数值/状态的实例级介入(addEnergy/applyBuff) | 需要实例节奏(什么事件给什么奖励);散写就是 v1 的 if-else 复辟 |
| 敌对判定的统一口径 | `areHostile` **非对称**(在 a 的实例上判),调用方各自记口径必然出错(§8.2) |
| 采样差分的调度 | 采样是**每实例一份**的节拍行为,不是桥接的无状态翻译(v2 放在桥接里调度,v3 移正) |

答案:把四件事收拢为**一个**组件 `RoleComponent`,内部按角色系统的组件纪律组织。**模式只挂这一个组件**;其他组件(计分/显示)要角色信息,经 `getComponent(RoleComponent.class)` 拿强类型读口——与角色系统里"能量/阵营的真值住组件,别处经 `svc().components().get()` 取"完全同构。

### 9.2 参照物对照:ShadowHunterRoles 的组件纪律 → 本组件的逐条落地

下表左列全部来自角色系统源码(出处标注),右列是 `RoleComponent` 的照抄/移植:

| 角色系统的纪律(源码出处) | `RoleComponent` 的落地 |
|---|---|
| svc **构造期注入四条件**:①注入先于一切钩子 ②final 只注一次 ③未注入即抛 ④创建点唯一(`RoleComponent` 类头注释) | 继承 `MatchModeComponent` 即得(§2.4);`RoleComponent` 不另设服务集成员 |
| **状态唯一**:能量/SanTE 真值、buff 账本都在组件里,容器不持有(`RoleInstance` 字段注释"状态归属") | 占用表(`roleId → 持有者`)、采样快照(`uuid → RoleSnapshot`)、换角计数都住本组件;`MatchModeInstance` 不持有 |
| **聚合根不设模板级读写口**:删 `getFaction()/setFaction()`,理由"语义不符 + 无消费者"(`Role` 类尾注释) | v2 的 `mode.rolePolicy()` 同理被删——策略是 `RoleComponent.Spec` 的构造数据,不是模式接口方法(§0.5.2) |
| **awake 只解析依赖、不改玩家可见状态**;**start 发生副作用**;**stop 与 start 严格对称**,返回后框架回收登记资源(`RoleComponent` 生命周期注释) | awake:解析目录快照 + `getComponent` 缓存 TeamComponent;start:无(不预发角色,授权时机由 policy 决定);stop:**全员 `clearRole` + 释放占用表**(幂等,角色清场的唯一闸门,§9.4) |
| **Specification 冻结快照防共享串改**;同一 Spec 实例被两个角色共享互不影响(`Role.Builder#addComponent` 注释) | `RoleComponent.Spec.freeze()` 照抄;`BOMB_POLICY` 之类的常量 Spec 可安全跨模式共享 |
| `requires`/`requiresOptional` + `Role#verifyDependencies` 装配期检查,缺必需依赖不注册(`Specification#requires` 注释) | `Spec` 构造器里:`requiresOptional(TeamComponent.class)`(按队限池的模式在 `checkMap`/awake 自查队组件在场)、`requiresOptional(DisplayComponent.class)`(选角 GUI 渲染) |
| **基类不认识子类**:基类不为能量/热键栏/生命设通用视图(`RoleComponent` 类体注释"本基类不得含任何子类…的语言") | `MatchModeInstanceServices` 不为"角色"设任何成员(§2.5 三成员纪律);要角色就 `getComponent(RoleComponent.class)` |
| 组件异常 → **本实例隔离一次**,拆卸期异常只记日志(`RoleInstance` quarantine 注释) | 继承框架的实例隔离(§3.1);RoleComponent 的坏数据(目录缺失/操作面拒绝)降级为"该玩家无角色"而非炸实例 |
| `FactionComponent` 的写口经**组件操作面**(`executeComponentOperation` + id `faction`),不经 API(`Role.getDefaultFaction` 注释) | 本组件对角色的**一切写**都经 `RoleFacade`(它就是操作面的类型化壳),绝无第二条写路径 |

### 9.3 形状:一个组件,四个内部 facet(内部接缝,不是子组件)

```java
package com.shdf.match.component.role;

/**
 * 角色组件:模式实例内一切"角色系统接入"的唯一落点。
 * ★ 一个组件,四个 facet——facet 是私有协作者(内部接缝),不是独立 MatchModeComponent:
 *   拆成四个组件的话,占用表/采样快照/授权时机就要跨组件同步,而它们本来就是一件事
 *   ("这局的角色怎么管")的四面。对外只暴露本类的强类型读口。
 */
public final class RoleComponent extends MatchModeComponent {

    public static final class Spec extends MatchModeComponent.Specification<RoleComponent> {
        /** 玩法对角色系统的规则请求(§8.6 的 RolePolicy,纯数据)。 */
        public final RolePolicy policy;
        /** 采样间隔 tick(0 = 关;§8.4-②)。 */
        public final int sampleIntervalTicks;
        /** 事件 → 角色操作的奖励映射(§9.4-④,默认空)。 */
        public final List<RoleReward> rewards;

        public Spec(RolePolicy policy, int sampleIntervalTicks, List<RoleReward> rewards) {
            super("Role");
            this.policy = policy;
            this.sampleIntervalTicks = sampleIntervalTicks;
            this.rewards = List.copyOf(rewards);
            requiresOptional(TeamComponent.class);     // 按队限池的模式需要;TDM 全员池可缺
            requiresOptional(DisplayComponent.class);  // 选角 GUI;缺了走命令选角
        }
        @Override public RoleComponent create(String id, MatchModeInstanceServices svc) { ... }
    }

    // ── 状态唯一:全部住在这里,随实例生灭 ──────────────────────────
    private final Map<String, UUID> occupied = new HashMap<>();      // roleId → 持有者(占用表)
    private final Map<UUID, RoleSnapshot> lastSeen = new HashMap<>();// 采样差分的上一帧
    private final Map<UUID, Integer> reselects = new HashMap<>();    // 换角计数

    // ── 四个 facet(私有,构造于 awake;对外只经本类读口) ───────────
    private LoadoutFacet loadout;      // ① 授权与占用
    private StateFacet state;          // ② 数值与采样
    private HostilityFacet hostility;  // ③ 敌对口径
    private RewardsFacet rewards;      // ④ 事件→角色操作

    // ── 生命周期(逐钩子职责见 §9.4) ─────────────────────────────
    @Override public void awake()   { /* 目录快照(RoleCatalog,只读) + getComponent 缓存 */ }
    @Override public void update()  { /* state.sample():每 N tick 差分 → RoleStateChanged */ }
    @Override public void onEvent(MatchModeInstanceEvent ev) { /* 死亡钩子 + rewards 求值 */ }
    @Override public void onHandoff(Handoff.Builder out) { /* 上局角色战绩摘要(可选) */ }
    @Override public void stop()    { /* 全员 clearRole + 清占用表;幂等 */ }

    // ── 对外强类型读口(其他组件消费面) ───────────────────────────
    /** ★v3.1:LOWEST 监听器(listener/RoleSignalListener)的唯一落点——读死前状态、
     *  经 RoleEventSynth 合成 RoleKillEvent 并发布到实例总线(§8.4)。监听器只路由,不合成。 */
    public void onVanillaDeath(org.bukkit.event.entity.PlayerDeathEvent e);
    public AssignmentResult requestRole(ParticipantRef p, String roleId);  // GUI/命令/自动分配统一入口
    public void applyPending(UUID uuid);                     // 部署/复活时的统一应用点(policy.applyOnDeployOnly)
    public OptionalInt energyOf(UUID uuid);                  // 转发 RoleStateAccess(OptionalInt 语义不变)
    public boolean applyBuff(UUID uuid, String type, int ticks);
    public boolean areHostile(UUID a, UUID b);               // ★ 统一封装非对称口径,调用方不再自己记
    public Optional<String> roleIdOf(UUID uuid);
    public Set<String> occupiedRoleIds();
}
```

> **为什么不拆四个组件**(设计决断):组件的粒度判据是**状态是否同源**。占用表、换角计数、采样快照、授权时机全部围绕"本实例的角色占用"这一个事实,拆开必然出现跨组件同步;而角色系统自己的 `FactionComponent` 也是"一个组件管一个概念的全部读写"(阵营的真值/判定/复位都在它里面),不拆 `FactionReadComponent`/`FactionWriteComponent`。facet 是 `codebase-design` 意义上的**内部接缝**:测试可以直接打它,但不是公共接口。

### 9.4 生命周期逐钩子职责表

| 钩子 | 职责 | 纪律来源 |
|---|---|---|
| `awake()` | 解析 `RoleCatalog` 只读快照进缓存;`getComponent(TeamComponent/DisplayComponent)` 缓存引用(可能为 null,可选依赖自查);**不改任何玩家状态** | 角色 `awake`:"只解析跨组件依赖并缓存引用。幂等;不得改动任何玩家可见状态" |
| `start()` | **空操作**。角色不在 start 预发——授权时机完全由 `policy.applyOnDeployOnly` 决定(v2 语义保留:炸弹模式"部署时才应用"的口径不变) | 角色 `start`:"开始生效:初始化数据、发放装备";我们的"发放"= 授权应用,时机归 policy |
| `update()` | `state.sample()`:每 `sampleIntervalTicks` 对全体持角成员采一帧,与 `lastSeen` 差分,**值真的变了才发** `RoleStateChanged`。成本核算沿用 §8.4(20 人 × 3 次/5 tick ≈ 12 次/tick,可忽略) | v2 的采样调度在桥接层(`RoleEventSource.sample(ctx)` 由谁调悬空);v3 移入组件,节拍随实例生灭 |
| `onEvent(ev)` | ① `ParticipantKilled` → `loadout.onDeath`(按 `policy.clearOnDeath` 释放占用+清角);② `RoleKill` → `rewards.evaluate`(命中映射则 `addEnergy/applyBuff/...`) | 角色 `PlayerKilledEvent` 的 `addPlayerKilledListener(owner=组件)` 模式:死亡善后挂在组件上 |
| `onHandoff(out)` | 可选:写"上局角色使用摘要"(谁玩了什么)进交接袋,大厅战报可显示 | 组件级交接钩子(§2.4) |
| `stop()` | **全员 `RoleFacade#clearRole`(幂等)→ 清占用表/采样快照/换角计数**。★v3.1:这是角色清场的**唯一闸门**——角色只有本组件一个写者(★23),stop 必然清光;引擎不再做框架级兜底(v3 的 §3.2-B3 已删,引擎不碰桥接) | 角色 `stop`:"与 start 严格对称。返回后框架自动回收本组件登记的资源" |

### 9.5 与桥接层的分工(★v3.1:事件合成也移入本组件)

| 关注点 | 桥接层(L1,§8) | `RoleComponent`(L3,本章) |
|---|---|---|
| `RoleAPI` 14 方法 + 阵营操作面 | ✅ 唯一 import 点,无状态翻译 | 经它,不直连 |
| **角色事件词汇**(RoleKillEvent/RoleStateChangedEvent) | ❌ ★v3.1 不住桥接(事件是消费面的词汇;桥接若定义,模式无法 import) | ✅ 本包定义并发布(`RoleEventSynth` 合成,§8.4) |
| 击杀归属合成(`onVanillaDeath`,LOWEST 监听器路由进来) | 提供原语(`lastDamagerUuid`/`roleIdOf`) | ✅ 合成 `RoleKillEvent` 并发布实例总线;计分留给模式规则,死亡善后/奖励在这里 |
| 能量/SanTE/buff 类型化读写 | ✅ `RoleStateAccess`(OptionalInt 语义) | **消费**:读口转发 + 采样差分调度 |
| **采样差分的"调度"** | ❌ v3 移出(桥接不应有实例节拍) | ✅ `update()` 驱动,快照住组件 |
| 选角授权/占用表/换角限额 | ❌ | ✅ `loadout` facet(解释 `RolePolicy`) |
| 敌对判定调用口径 | 提供非对称原语 `areHostile(a,b)` | ✅ 唯一封装点:其他组件一律经 `RoleComponent#areHostile`,桥接原语不外露给模式 |
| 能力声明("role" 标签) | ✅ `RoleFacade` 懒解析 + 注册/注销 `"role"` 标签(常量住本层,引擎零字面量) | `Spec` 声明所需能力 → `MatchModeMeta.requiredCapabilities = {"role"}`;开局期校验拒绝(§3.2-A2) |
| 玩家离开实例 | — | ✅ 成员 left 事件 → `loadout.release(uuid)`(v2 `onParticipantLeave` 语义) |

> **给实现者的一句话**:桥接层是"怎么和角色系统说话",`RoleComponent` 是"这一局怎么管角色"。前者无状态、进程级单例;后者有状态、每实例一份。任何"模式里 import `RoleFacade`"的代码都是越界——那等于绕过防腐层的消费者纪律,ArchUnit 规则 `onlyRoleComponentTouchesBridge` 冻结(§16.2-★23)。
