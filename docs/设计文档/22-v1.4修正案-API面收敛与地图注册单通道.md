# 22 · v1.4 修正案:API 面收敛与地图注册单通道

> HydroKarbs MiniGame Framework · v1.4 修正案(历史存档;现行修正案见 [23-v1.5修正案-REUSE_DIRTY副本随会话解散销毁.md](23-v1.5修正案-REUSE_DIRTY副本随会话解散销毁.md))
> 变更指示(非设计章节):本修正案执行**两项收缩性收敛**——①「API 面收敛」:两参 `createSession(String, String)` 重载删除,`SessionRecipe` 重载成为公共 API 建会话的唯一形态,API_VERSION 3 → 4(冻结面 16 方法 → **15 方法**);②「地图注册单通道」:「配置文件声明地图」特性退场——文件式装载(`maps/*.yml` 启动扫描)整链删除,`MapRegistry` 只剩显式注册/摘除通道,目录顺序 = 注册序。判据与 21 同源:**同一能力只保留一份口径**(One-Version Rule 精神落面)——建会话不再有"两参 = 空 recipe"的第二形态,地图不再有"文件半边 + 注册半边"的双簿记与双先到者语义。决策记录见 [docs/adr/0010-api-surface-consolidation.md](docs/adr/0010-api-surface-consolidation.md)(Supersedes [docs/adr/0008](docs/adr/0008-map-registration.md) 的文件式通道部分)。
> 验收追加 **★56~★57**(编号体系沿用 §16.2,只增不改不重排;框架/玩法两线同一套):两参建会话不复存在、配置装载零地图条目(§5)。
> 基线:v1.3。本修正案为**破坏性收敛但零触碰引擎内部机制**:会话/切换/两级挂载/三通道/世界零改动;地图注册通道的**守卫语义(20-D3/D4)一寸不动**——注册期校验(模板目录 `maps/templates/<mapId>/` 存在性、id 查重响亮抛、tags)与「有会话正用 → 摘除被拒」原样有效。既有架构断言族(★1~★9、★13~★55)零放宽;唯一允许的断言更新 = ★19/★44 冻结快照随 v4 面**合法重录**(15 行清单,以本修正案 §3 契约骨架为准)——冻结测试即架构,重录须有修正案背书,本次即背书(§7.2 版本协商纪律:破坏性变更必升 API_VERSION)。

## 0. 一页摘要

**变更(收缩,四条决策)**:

①**D1 两参 `createSession(String, String)` 删除**:公共 API 建会话仅剩 `createSession(SessionRecipe)`(★v1.1-D14 通道二)——`SessionRecipe` 是两参形态的**严格超集**(`SessionRecipe.of(modeId, mapId)` = 空池 + 零单次贡献,与两参重载语义逐字段等价,07 §7.1 原注「等价于空 recipe」),双形态唯一的区别是调用样板,消除它 = 消除"同一能力两份口径"。迁移口径:**两参调用一律改写为 `SessionRecipe.of(modeId, mapId)`**。

②**D2 API_VERSION 3 → 4**:删除冻结面既有方法是**定义上的破坏性变更**,必升版本(07 §7.2 版本协商纪律);冻结面计数口径 = 16 → **15 方法**(查询 3 + 控制 1 + 成员 2 + 订阅 1 + 能力 2 + 建会话 1 + 地图 2 + 目录 3;★19 反射冻结清单随 7.1 施工文档同步重录)。消费方 `onEnable` 首行 `api == null || api.API_VERSION < REQUIRED` → SEVERE + `setEnabled(false)` 拒载的既有纪律(14.36)即本次收敛的消费方保护面。

③**D3 文件式地图通道退场**:「配置文件声明地图」特性删除——`ConfigRepository` 的 `maps/*.yml` 启动扫描装载、`YamlCodec.readMap`、`MapDefinition.from`(静态解析构造,含其校验)全部退场;声明所有权自此完全由 20-D1 的「交成品不交工厂」承载。判据:**注册通道(v1.2)已承载文件通道的全部场景**(跨 jar 分发的玩法图:宿主代码构造 + 注册;模板解包口径不变),而双通道并存持续产生两类复杂度——同一命名空间两条「先到者」规则(撞名交互:文件图跳过 + WARN)、reload 语义分叉(`/sm reload maps` 只碰文件半边、注册式不经 reload 的分级注)。迁移口径:**原 `maps/*.yml` 声明改由宿主/玩法插件代码构造 `MapDefinition` 后 `registerMap`**(模板仍先解包到 `maps/templates/<mapId>/`,14.39 的 onEnable 顺序「解包 → 构造 → 注册」不变;服主侧的声明文件如其存在,交由宿主插件自理其解析,框架不再代劳)。

④**D4 `MapRegistry` 单通道化**:文件半边机制随 D3 整体拆除——`replace`(文件式整表替换入口)、「文件式半边」簿记(快照的来源半边)、无参构造一并删除;目录 = 纯注册序(先注册者在前),`api.maps()` 顺序即注册序,自动挑图取序首可预期(§15.2 口径不变,只换序来源)。`ConfigRepository.maps()` 持有口径不变(经构造注入模板根,装配传入;map 包仍是纯模型包不 import bridge)。

**不动**:引擎内部机制(会话/切换/两级挂载/三通道/世界)零改动;`SessionService#switchMode/dissolve` 受控命令、`SessionService.create(SessionSpec)` 内部唯一创建路径不动;`WorldPort` 世界生命周期与.切换阶段 A3/A6 零改动;`SessionRecipe` record 形状零改动(字段、合并序、装配期响亮失败语义全部原样);`config.yml`/`modes/*.yml` 配置装载零改动(★v1.1-D5 后的会话节律三键原样);`components/stats` 采集不动;★1~★55 断言零放宽(仅 ★19/★44 快照重录,见头部注)。

## 1. 决策 D1~D4

### D1:两参 `createSession` 删除(建会话单形态)

**决策**:`MiniGameApi` 删除 `createSession(String initialModeId, String initialMapId)` 重载;`createSession(SessionRecipe recipe)` 成为公共 API 建会话唯一形态(代码侧已落地:`MiniGameApiImpl` 仅余 recipe 委托,两参调用点随施工改写)。

**理由**:①**严格超集**——两参形态可表示的每一个调用,`SessionRecipe.of(modeId, mapId)` 都等价表示(空 `mapPool`/零 `extraComponents`;07 §7.1 原注「等价于空 recipe」即此义):两形态之间不存在表达力差异,只存在「是不是多一条解释性悬挂注」的差异。②**One-Version Rule 落面(07 §7.2)**——冻结面的「只增不改」默认维持存量,但当两形态并存的本质是同一能力两份口径时,收敛优于并存:双形态让每次讲建会话都要讲两遍(权限面表、示例、javadoc、冻结清单各两行),迁移后口径回到单行。③**双轨维护成本已现**——v1.1 引入 recipe 后,两参重载以「保留,等价于空 recipe」的形式悬挂三版(07 §7.1 / CONTEXT「SessionRecipe」词条 / ApiSurfaceTest 快照各带一注),悬挂注就是债务形态。④不做 hypothetical seam 的同一判据反向成立(A9/A13 同源):真实消费者某一形态用即可,不必替它养另一形态。

**迁移口径**:两参调用 `createSession(modeId, mapId)` → `SessionRecipe.of(modeId, mapId)`(便捷工厂即为此设,一眼对齐);带额外会话组件的调用(本就直接用 recipe)零改动。

### D2:API_VERSION 3 → 4(版本协商)

**决策**:`MiniGameApi.API_VERSION = 4`(v1.0 = 1;v1.1 = 2;v1.2 = 3;v1.3 维持 3;**v1.4 = 4**)。

**理由**:删除冻结面既有方法 = 定义上的破坏性变更,07 §7.2 版本协商纪律明文"破坏性变更必须升 API_VERSION"。该纪律同时许可"提供**至多一个次要版本**的双轨过渡期"——本次**取下限 0 个**:直接删除,不开弃用过渡窗口(备选与权衡见 ADR-0010:过渡期收益仅在存在无法随窗口升级的存量消费者时成立,当前消费面 = SHDF 宿主与测试/示例插件,随本次施工窗口一并迁移,git 实况可查;One-Version Rule 不允许长期双轨,与其短暂双轨不如一次付清)。**消费方保护面不变**:14.36 的 `onEnable` 首行版本检查 + 拒载不崩服,在 v4 下照常工作(旧消费方拒载并给出明确日志,而非 NoSuchMethodError 崩在玩家路径)。

### D3:文件式地图通道退场(注册单通道)

**决策**:「配置文件声明地图」特性删除,移除清单:

| 移除项 | 说明 |
|---|---|
| `ConfigRepository` 的 `maps/*.yml` 启动扫描装载 | `loadAll()` 只解析 `config.yml` + `modes/*.yml`;配置装载**不再产生任何地图条目**(★57 命题) |
| `YamlCodec.readMap(Path)` | 地图 YAML 编解码点随之消失;`YamlCodec` 回到 modes 单域 |
| `MapDefinition.from(Map, String)` | 静态解析构造与其内含校验删除;**结构合法性由调用方在构造期自理**(record 构造器的非空约束仍在),响亮抛纪律保留在注册口(模板目录/查重,`MapRegistry`) |
| `maps/*.yml` 声明文件口径 | 通用图模板随框架 jar、玩法图随玩法 jar 的**模板(s)分发约定不变**;变的只是"声明从文件读"→"声明由代码构造" |

**理由**:①**注册通道已承载全部场景**(★v1.2 后的实况):跨 jar 分发的玩法图 = 宿主 onEnable 解包模板 + 代码构造声明 + `registerMap`;动态活动图 = `unregisterMap` + `registerMap`;期初通用图 = 框架装配注册(或宿主代注册)——没有一种地图投放场景必须经配置文件。②**双通道的持续复杂度**:同一命名空间两条「先到者」规则(20-D3 原文要同时讲"与文件式撞名"与"注册式撞注册式"两种拒绝语义;文件 reload 对注册条目"跳过 + WARN"的交互注);reload 分叉(`maps` 级 reload 只碰文件半边,注册式整段"不经 reload"口径注挂在 13/15/14 三处)——每处都是无限期维护的解释义务。③**单通道后撞名语义只剩一条**:先注册者保留,重复点名先到者与其提供方——20-D3 的响亮抛纪律原样有效,只是不再有"文件来源"分支。④与本修正案 D1 同构:同一能力(地图进目录)只保留一份口径。

**迁移口径**:原 `maps/*.yml` 声明(SHDF 宿主侧或服主手工维护的)改由**宿主/玩法插件代码构造 `MapDefinition` 后 registerMap**——宿主如需保留"配置驱动的地图清单",由宿主插件自行解析自己的声明文件再逐张注册(解析是宿主的家务,框架不代劳;§15.2 的配置分工注随此同步);模板解包(`saveResource` → `maps/templates/<mapId>/`)与 14.39 顺序纪律不变;口径示例(§3 逐文档指示 13 号行)。

### D4:`MapRegistry` 单通道化(目录顺序 = 注册序)

**决策**:`MapRegistry` 收敛为纯注册通道——公开面仅余:`register(Object provider, MapDefinition map)` / `unregister(Object provider, String mapId)` / `registeredIdsOf(Object provider)` / `byId` / `byTag` / `all`(查询面零改动);构造仅 `MapRegistry(Path templatesRoot)`(无参构造删除——文件通道的第 0 步"启动扫描"随 loadMaps 一起退场)。快照结构从「文件式半边 + 注册式半边」双簿记收敛为单一注册条目表;**volatile 原子替换语义不变**(写操作换新不可变快照,读方永见完整目录)。

**理由**:①双半边簿记只为文件通道服务(D3):目录快照展示序(`order`)的拼接规则(文件装载序 + 注册序尾接)、`describeSource` 的"文件/插件"双分支、`replace` 的整表替换口——单通道后全部退化为一条注册序、一个来源。②**目录顺序 = 注册序**自此无歧义:`api.maps()` 顺序即注册序,自动挑图取序首(§15.2 口径)从"文件序 + 注册序"的拼接规则收敛为单一规则,可预期性不减反增。③守卫语义零变动:**注册期校验**(20-D3:id 查重点名先到者、tags、模板目录存在性)与「正用摘除被拒」(20-D4:该图为任一存活会话当前实例所用 → 摘除被拒,detail 点名会话;幂等 no-op;提供方 disable 兜底摘除)均为守卫不变量原样重申——D3/D4 只摘除文件半边,不触碰任何守卫语义。

## 3. 契约骨架(MiniGameApi v4 面,15 方法)

> **以下为现行 `src/main/java/com/hydrokarbs/api/MiniGameApi.java` 的实际签名转写(不得凭记忆)**——方法名、参数与返回类型逐字对应该文件(仅省略 javadoc 正文;注解要点为该文件头部注与各方法注的摘要)。★19(`MiniGameApiSurfaceTest`)15 行清单与 ★44(`ApiSurfaceTest`)白名单快照以此为基线重录。

```java
package com.hydrokarbs.api;

/** 本框架的对外公共面。经 Bukkit ServicesManager 暴露(07 §7.1/§7.2)。
 *  ★v1.4 收敛:API_VERSION = 4,冻结面 16 → 15 方法;建会话仅剩 recipe 形态(D1);地图注册通道维持。 */
public interface MiniGameApi {

    /** API 面版本常量(D7;只增不减):v1.0=1;v1.1=2;v1.2=3;v1.3 维持 3;v1.4 = 4(D2)。 */
    int API_VERSION = 4;

    // ── 查询(不可变快照;主线程调用;现取不缓存,14.31 纪律) ───────────────
    Optional<SessionInfo> sessionOf(UUID player);
    Optional<SessionInfo> session(String sessionId);
    List<SessionInfo> sessions();

    // ── 控制(与 /sm 命令同权,§7.1) ─────────────────────────────────────
    /** 切换某会话的模式(§3.2 受控暴露;失败语义 = 引擎三级回退管线透传)。 */
    CompletableFuture<SwitchResult> switchMode(String sessionId, MatchModeSelection target,
                                               Handoff payload);
    /** 创建会话(★v1.1-D14 通道二;合并序 = provider 贡献(注册序)→ recipe.extraComponents;
     *  装配闸:组件 id 查重 / 缺必需依赖 → 响亮抛,不留半装配态;随 dissolve 全灭,★52)。
     *  ★v1.4:本方法是公共 API 建会话的唯一形态(D1;两参重载已删除)。主线程调用。 */
    SessionInfo createSession(SessionRecipe recipe);

    // ── 成员操作(★v1.1-D2;★42;主线程调用) ─────────────────────────────
    JoinResult joinSession(String sessionId, UUID player);
    void leaveSession(UUID player, LeaveReason reason);

    // ── 会话事件订阅(★v1.1-D3;★43;句柄 close() 注销,14.38) ───────────────
    EventSubscription subscribeSessionEvents(Consumer<SessionEventView> handler);

    // ── 能力标签(★v1.1-D4;主线程调用) ──────────────────────────────────
    void registerCapability(org.bukkit.plugin.Plugin provider, String tag);
    Set<String> capabilities();

    // ── 地图注册(★v1.2;★54;守卫语义 20-D3/D4 不变;主线程调用) ─────────────
    MapInfo registerMap(org.bukkit.plugin.Plugin provider, MapDefinition map);
    void unregisterMap(org.bukkit.plugin.Plugin provider, String mapId);

    // ── 目录(顺序 = 注册序,不排序不过滤——14.21「大厅特判」反弹规避) ────────
    List<MatchModeInfo> modes();
    List<MapInfo> maps();
    Optional<MatchModeInfo> mode(String modeId);
}
```

配套类型(零改动,重申):`SessionRecipe`(record:initialModeId/initialMapId/mapPool/extraComponents)+ 便捷工厂 `SessionRecipe.of(modeId, mapId)`;`SessionInfo`/`MatchModeInfo`/`MapInfo`/`SessionEventView` 快照族原样。`MapRegistry` 侧:D4 后公开面 = `register(provider, map)` / `unregister(provider, mapId)` / `registeredIdsOf(provider)` / `byId` / `byTag` / `all`;构造 `MapRegistry(Path templatesRoot)`。
