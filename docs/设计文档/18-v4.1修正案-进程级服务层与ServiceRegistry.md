## 1. 一页摘要

一句话:**v4.1 新增"进程级服务层"——服务(Service)是与组件并列的另一类对象**:不挂进会话/实例、不进组件表、彼此经 `ServiceRegistry` 统一装配(两阶段:`install` 声明 → `seal` 校验+拓扑序创建+启动),经**订阅会话事件、只读快照、SessionService 受控命令**三条通道与会话对话;**组件体系与服务互不可见**,svc 成员数不变。

| 类别 | 内容 |
|---|---|
| 新增类型(4) | `ServiceRegistry`(两阶段装配容器)、`ServiceSpec<S>`(声明式描述符:id/type/factory/requires/requiresOptional/capabilities)、`ServiceEnv`(工厂取物口:dep/depOpt/plugin/cfg)、`ServiceLifecycle`(start/stop,默认空实现) |
| 新增端口类型(1) | `ConfigView`(惰性只读配置面,`ServiceEnv#cfg()` 返回,L1 `ConfigRepository` 实现) |
| 新增异常(1) | `ServiceDependencyException`(装配期失败,点名服务与缺失/成环的依赖) |
| 新增包(2) | `engine/service/`(机制,受 `EnginePurityTest` 管辖)、`service/`(内容性参照实现,与 `mode/` 平级) |
| 参照实现(2) | `GlobalLedger`(上报式:会话结转汇总)、`GlobalBoard`(拉取式:只读看板)——规格示例,证明两条服务形态可离线单测 |
| 保持不变(硬边界主体) | **组件挂载仍仅两级**(A10 不破:服务不是第三级*组件*)、引擎内容盲、`MatchMode` 聚合根零行为、`MatchModeInstanceServices` 三成员 / `SessionServices` 两成员封闭、switchMode 两阶段/三级回退、`Handoff` 机制、`WorldPort` 机制、**`MiniGameApi` 冻结面**(服务不进公共面) |
| 命名修正(D11) | `Instance` 家族 11 类型 + 2 测试名 → `MatchModeInstance` 前缀(对照表见 D11);包名(`engine/instance/`)与方法名不改 |

## 2. 决策(D1–D12,逐条写入 ADR-0005 并落到各文档)

### D1 定位:服务不是第三级组件挂载级(A10 不破)
- A10 原文保留:**组件**挂载仅两级(实例级/会话级),禁止第三级组件、禁止兼任。
- 新增第三类对象:**进程级服务(Service)**——进程生命周期(`onEnable` 装配 → `onDisable` 关停),不随任何 Session/Instance 生灭。服务与组件的三条硬边界:①服务不进组件描述符表,`svc().components()` 查不到它;②服务没有五钩子派发,不占 `tickAll` 的任何一步(它自行经 `ServiceLifecycle#start` 订阅事件驱动);③组件与模式**不得 import** 服务类型,服务**不得 import** `mode/**` 与 `component/**`(D6)。
- 归属判据(决断一 v4.1 修订版,两问扩为**三问**,写入 02 §2.8):
  | 判定 | 归属 | 例 |
  |---|---|---|
  | 不需要跨模式存活 | 实例级组件 | 阶段/计分/队伍/结束判定 |
  | 跨模式存活,且是机制/状态权威/可靠性底线 | `SessionService` 内核 | 名册、连接追踪、切换算法、世界引用计数 |
  | 跨模式存活,且是策略/裁决/聚合/展示,**状态可按会话隔离** | 会话级组件 | 空场解散(已实现);断线宽限等(候选) |
  | **状态必须跨会话聚合,或本就是进程级机制/外部世界翻译** | **进程级服务(★本版新增)** | 全服账本、全局看板、配对队列、经济适配 |

### D2 ServiceRegistry:两阶段装配契约
```java
public final class ServiceRegistry implements AutoCloseable {
    public <S> void install(ServiceSpec<S> spec);   // 阶段一:仅声明。重复 id / 重复类型 → IllegalStateException(点名先到者);seal/shutdown 后 install 抛
    public void seal();                             // 阶段二:依赖校验 → 拓扑排序 → 按序 factory(ServiceEnv) 创建 → start → 注册能力标签
    public <S> Optional<S> get(Class<S> type);      // seal 之前调用抛;未注册 → empty
    public <S> S require(Class<S> type);            // 缺席 → 人话异常
    @Override public void shutdown();               // 逆序 safeStop(异常记日志不中断)→ 幂等 → 摘除能力标签
}
```
- **seal 语义**:①缺必需依赖 → `ServiceDependencyException` 点名双方;②依赖环 → 点名环上服务;③拓扑序创建,**声明序为同层稳定次序**;④任一工厂/start 抛 → **回滚已启动服务(逆序 stop)再抛**,不留半启动态(镜像 switchMode"绝不停在中间态")。
- **shutdown 语义**:逆序、逐个 try/catch 不中断、幂等(连调 3 次 stop 恰一次);此后 `install` 抛。
- 消费面只有 `install/seal/get/require/shutdown` 五方法——**上帝注册表**是陷阱(14.32):事件转发、权限查询等一律不做。

### D3 ServiceSpec:与组件 Specification 的两处刻意差异
- 字段:`id / type / factory / required / optional / capabilities`;Builder 构建,构建期校验 id 非空。
- **无 `freeze()`**(与组件 Spec 的差异及理由,须写入 ADR-0005):组件 Spec 需要冻结是因常量 Spec 跨模式共享(`BOMB_POLICY`);服务 Spec 由 **L0 现场构建、只被一个注册表消费**,无共享串改问题——不加仪式(YAGNI)。
- **工厂收 `ServiceEnv` 而非 svc**:服务不持服务集 record,依赖在创建期经 `env.dep(Class)` 注入(拓扑序保证就绪);`depOpt` 表达可选依赖(缺席 empty,不抛);`plugin()`/`cfg()` 提供平台原语(`cfg()` 返回惰性 `ConfigView`,/reload 后自动读新值)。

### D4 单类型单服务 + ServiceLifecycle
- 一个服务 = 一个主类型;需要两个接口面就做一个门面接口,不做 multi-provide。
- `ServiceLifecycle { default void start(); default void stop(); }`:纯无状态服务(Facade 类)不必实现;实现者须保证 **stop 与 start 严格对称**。

### D5 服务 ↔ 会话:三条通道,无第四条
| 通道 | 方向 | 授权 |
|---|---|---|
| **订阅 `SessionEventBus`**(`SessionCreated / MemberJoined/Left / ModeSwitched / SessionDissolved / SessionComponentQuarantined`) | 会话 → 服务 | 感知生灭的官方通道(§3.1 事件行既有定位"给跨切面逻辑用");订阅句柄在服务 `stop` 中注销 |
| **只读快照**(`MiniGameApi.sessions()` 不可变 record;引擎内代码可经 `SessionService` 遍历 + `MatchModeInstanceAccess`) | 会话 → 服务 | 只读;**不得持有活实例/活组件引用跨切换**(镜像 ★29 的"现取不缓存"纪律) |
| **受控命令**(`SessionService#switchMode / dissolve / createSession`) | 服务 → 会话 | 服务属**外部调用方(切换来源②)**,与 `/sm` 命令同权;`force` 是显式选择,走 review 条款;无其他影响力端口 |

### D6 服务与组件互不可见
- 组件/模式不得 import `engine/service/**` 与 `service/**`;服务不得 import `mode/**` 与 `component/**`——双向冻结(ArchUnit,★40)。
- `MatchModeInstanceServices`(3 成员)与 `SessionServices`(2 成员)**不加成员**——服务不经 svc 注入组件(★25 口径不变)。组件要消费基础设施,走既有先例:**L1 适配器 + 包装组件**(RoleComponent 之于 RoleFacade 的同款),不是加 svc 成员。

### D7 包位置、线程、可测性
- `engine/service/`:装配**机制**,受 `EnginePurityTest` 禁词管辖(禁词表不变);`service/`:内容性**参照实现**,纪律 = 不 import `mode/**`/`component/**`、只经 D5 三通道触达会话、只消费 L1 适配器与引擎公开面。
- 线程:全部方法主线程(`onEnable`/`onDisable` 天然满足);注册表内部普通集合,不加锁,单线程约定写类头。
- `ServiceRegistry` 核心**零 Bukkit import**——全部验收离线可测(毫秒级,无需活服)。

### D8 常驻模块选型四案 + 注册受众五案(裁决记录,写入 13)
- **常驻模块选型**(按侵入度从低到高,先问再落):①拉取式(只读快照+事件,零侵入)→ ②伴随插件(框架零改动,消费 `MiniGameApi`)→ ③防腐包装式(L1 适配器+Port+包装组件)→ ④上报式(会话级组件本地权威 + 进程级服务汇总)。
- **注册受众**:A 显式装配(L0 基线,服务少时最优)/ B ServiceRegistry(内部服务群 ≥3 时)/ C ServicesManager(跨插件,既有机制)/ D `ServiceHandle<S>`(可选能力懒句柄,泛化 RoleFacade 懒解析 + `CapabilityRegistry`)/ E 版本化 SPI(第三方提供基础设施——**本版不做**,登记未决 §12-Q8)。
- 第一版落地:**A + B**(L0 显式装配进 B 注册表);C/D 沿用既有先例口径;E 不做。

### D9 公共 API 冻结面不变
`MiniGameApi` 方法集不动;服务、`ServiceRegistry`、服务查询一律**不进公共面**(第三方消费/提供服务列为未决 §12-Q9;将来开放走"只增不改")。`SessionService` 公开方法签名不变。

### D10 候选清单复核判据(与 §6.4 会话级组件候选的关系)
原"跨局累计/会话级看板"等候选,现在有两个可能落点(会话级组件 vs 服务)。**裁决一问:状态是否按会话隔离?** 隔离 → 会话级组件;跨会话聚合 → 服务(必要时两者组合:会话组件本地权威 + 服务汇总,即选型④)。本版不改变任何候选的既定归属,仅补判据。

### D11 命名修正:Instance 家族统一加 `MatchModeInstance` 前缀
- 动因:①与 `Session*` 家族并列时,`Instance*` 读不出宿主(最典型:`InstanceAccess` 其实是**会话侧**拿到的实例只读面);②"Instance" 在 Java 语境有泛化歧义(bean instance / JVM instance);③与 v3.1"裸 Mode → MatchMode"同一先例、同款理由。
- 规则:**类型名中的 `Instance` → `MatchModeInstance`**。三处刻意不改:包名(`engine/instance/`,v3.1 先例:包名不改)、方法名(`currentInstance()` / `tickCurrentInstance()` / `instanceEnded(...)`——上下文无歧义)、昵称 `svc`。
- **刻意不用缩写**(`MatchModePort` / `MatchModeEventBus` / `MatchModeStarted` 之类):会被误读为"模式模板的端口"或"进程级总线"——模板不可变、没有端口,启停的是实例不是模板;全称消除歧义。

### D12 L0 装配编排:单一静态装配类 + 单一编排函数
- **形状**:`SHDFMatchAssembly`——静态无状态类,`static Context assemble(JavaPlugin)` 一函承载 onEnable 全部装配序列(线性,自上而下可读完);`static void shutdown(Context)` 镜像 onDisable。主类退化为两行委托(`onEnable = assemble(this) 存字段;onDisable = shutdown(ctx)`)。`Context` 是不可变 record(装配产物聚合),由**插件实例字段**持有。
- **纪律一:静态类可有静态函数,不许有静态可变状态**——装配产物只经返回值交付(插件重载安全;镜像 ★27 对进程级静态的警惕)。
- **纪律二:`assemble` 保持线性装配语句**——除 topology/config 分支外无业务逻辑;超过一屏时抽**私有分段 helper**(仍只含语句),**不复活多个公共装配类**(对本规模的过度拆分)。
- **命名**:不得叫 `Bootstrapper`(12 §12.1 已有 Paper `PluginBootstrap` 占位类);定名 `SHDFMatchAssembly`。
- 理由:装配事实"一页纸"成为字面事实;主类纯净;无静态泄漏;单一接线点从"单一类"收紧为"单一函数"。

## 3. 契约骨架(写入 12-代码骨架.md;执行者照此落盘)

```java
// engine/service/ServiceSpec.java —— 声明式描述符(★D3:无 freeze;工厂收 ServiceEnv)
public final class ServiceSpec<S> {
    public static <S> Builder<S> of(String id, Class<S> type, Function<ServiceEnv, S> factory);
    public static final class Builder<S> {
        public Builder<S> requires(Class<?> type);          // 缺 → seal 抛,点名双方
        public Builder<S> requiresOptional(Class<?> type);  // 缺 → 不报错,运行期 depOpt 自查
        public Builder<S> capabilities(String... tags);     // seal 成功注册,shutdown 摘除(§8.8 口径)
        public ServiceSpec<S> build();
    }
    String id(); Class<S> type(); Function<ServiceEnv, S> factory();
    List<Class<?>> required(); Set<String> capabilities();
}

// engine/service/ServiceRegistry.java —— 两阶段装配容器(★D2;核心零 Bukkit import)
public final class ServiceRegistry implements AutoCloseable {
    public ServiceRegistry(CapabilityRegistry capabilities);
    public <S> void install(ServiceSpec<S> spec);   // 查重 id/类型(响亮);seal 后拒
    public void seal();                              // 校验→拓扑序→create→start→注册标签;失败回滚
    public <S> Optional<S> get(Class<S> type);       // seal 前抛
    public <S> S require(Class<S> type);
    public Set<String> ids();
    @Override public void shutdown();                // 逆序 safeStop;幂等;摘标签
}

// engine/service/ServiceEnv.java —— 工厂取物口(零内容词汇)
public interface ServiceEnv {
    <T> T dep(Class<T> type);                 // 拓扑序保证就绪;取不到 = 声明与取用不符,响亮抛
    <T> Optional<T> depOpt(Class<T> type);    // 可选依赖:缺席 empty 不抛
    org.bukkit.plugin.Plugin plugin();        // 平台原语:日志/调度/数据目录
    ConfigView cfg();                         // 惰性只读配置面(/reload 自动读新值)
}

// engine/service/ServiceLifecycle.java —— 可选生命周期(默认空;stop 与 start 严格对称)
public interface ServiceLifecycle { default void start() {}  default void stop() {} }

// engine/port/ConfigView.java —— 惰性只读配置面(L1 ConfigRepository 实现)
public interface ConfigView { <T> T get(String path, T fallback); }
```

**L0 装配接线(★D12:单一静态装配类,主类退化为委托;写入 12 §12.1):**
```java
// SHDFMatchAssembly.java —— 静态无状态;assemble 一函承载全部装配序列(线性,只含装配语句)
public final class SHDFMatchAssembly {
    public record Context(SessionService sessions, ServiceRegistry services,
                          EngineTicker ticker, MiniGameApi api) {}
    public static Context assemble(JavaPlugin plugin) {
        var cfg  = ConfigRepository.load(plugin);                       // ① L1 适配器
        var cap  = new CapabilityRegistry();
        var sess = new SessionServiceImpl(cfg, cap);                    // ② 内核机制(先于服务,供工厂闭包捕获)
        var reg  = new ServiceRegistry(cap);
        reg.install(ServiceSpec.of("economy", EconomyFacade.class,      // ③ 服务声明,顺序随意
                env -> new EconomyFacade(env.cfg(), plugin)).capabilities("economy"));
        reg.install(ServiceSpec.of("ledger", GlobalLedger.class,
                env -> new GlobalLedger(env.dep(EconomyFacade.class), sess)));
        reg.install(ServiceSpec.of("board", GlobalBoard.class,
                env -> new GlobalBoard(env.dep(GlobalLedger.class))));
        reg.seal();                                                     //    失败 → SEVERE + setEnabled(false)
        var sessions = SessionAssembler.topology(sess, cfg);            // ④ rotation / arena
        ModeAssembler.discover();                                       // ⑤ 模式双发现
        var ticker = new EngineTicker(plugin, sess); ticker.start();    // ⑥ 监听器 / 命令 / 节拍
        var api = new MiniGameApiImpl(sess, reg);                       // ⑦
        plugin.getServer().getServicesManager()
              .register(MiniGameApi.class, api, plugin, ServicePriority.Normal);
        return new Context(sess, reg, ticker, api);
    }
    public static void shutdown(Context ctx) { /* ticker 取消 → dissolve 全部会话 → services.shutdown() → api 注销 */ }
}
// SHDFMatchPlugin —— 主类退化为委托(onEnable = 存 assemble(this) 返回的 Context;onDisable = shutdown(ctx))
```
> **D12 纪律**:①静态类可有静态函数,不许有静态可变状态;②`assemble` 只含线性装配语句,超一屏抽私有分段 helper,不复活多个公共装配类。

## 5. 规则与纪律(写入 02 §2.8 与 14-陷阱清单)

1. **决断一 v4.1 修订版**:两问扩为三问(见 D1 表);争议先走三问,不留白。
2. **新增决断五(宿主先于接缝)**:"要加一个常驻能力"时,先决定宿主(组件级/L1/进程级服务/伴随插件,§13 选型四案),再决定接缝(是否需要 Port/组件读口/事件/API)——**Port 不是宿主**;给 `InstanceServices`/`SessionServices` 加成员永远是错误答案(★25)。
3. 服务不得缓存活实例/活组件引用(只读快照语义,镜像 ★29"现取不缓存");服务间依赖只能经 `ServiceSpec#requires` 声明、由注册表注入,禁止服务互 new。
4. 注册表消费面五方法封顶;扩需求 = 新独立机制,不是往注册表塞方法(14.32)。
