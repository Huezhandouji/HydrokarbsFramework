## 0. 一页摘要

**变更(闭环补全,三条决策)**:

①**D1 复用窗口 = 会话生命周期**:REUSE_DIRTY 副本目录的复用语义只发生在同会话内(副本目录名含会话短码,天然不跨会话)——复用的理由随会话死亡失效,目录从缓存变残留。会话解散 = **复用窗口关闭** = 名下全部世界副本销毁,无论策略;端口新增第三法 `discardSession(SessionId)` 作为窗口关闭的唯一动作,三类覆盖(存活条目 / 切换离开保留的目录 / 迟到 in-flight 的已死短码判据)。

②**D2 切换路径语义不变**:B5 换图的释放对 REUSE_DIRTY 仍**保留目录**(同会话复载语义原样);`TEMPLATE_RESTORE` 行为原样(归零即删);删除动作**仍收敛于 `deleteCopyDir` 唯一入口** + 路径形态断言(绝不递归删除任意路径);卸载/删除失败的 best-effort(保留目录 + WARN/SEVERE)原样。

③**D3 公共面零改动**:`API_VERSION` 维持 4;`WorldPort` 是 engine 内部口——**不在** `MiniGameApi` 冻结面(★44 白名单「永不导出」清单原样),三法(含新增 `discardSession`)只被会话内核调用(铁律 9:世界只有 `WorldPort` 一个口)。

**不动**:模式与组件无感(只消费 `ctx.map().world()` 只读读口,§3.7 规则表「谁调用」行原样);`WorldHandle`/`ResetStrategy` 类型契约零改动(枚举**不增第三值**——「会话已死」是端口内部的删除判据,不是策略);`acquire`/`release` 签名与语义零改动;注册通道的守卫语义(20-D3/D4)与「注册交付的只是声明」边界(20-D7)零触碰;★1~★57 断言零放宽(★58 为新增命题,§5);长运服的崩溃残留兜底(进程级孤儿)不在本次范围(§6-Q1 登记)。

## 1. 决策 D1~D3

### D1:复用窗口 = 会话生命周期(解散 = 窗口关闭,名下全部副本销毁)

**决策**:`WorldPort` 新增第三法 **`discardSession(SessionId)`**(会话解散时调用,幂等);其语义 = 关闭该会话的复用窗口,名下全部世界副本销毁,三类全覆盖——

| 类 | 副 本 面 | 覆 盖 机 制 |
|---|---|---|
| ① 存活条目 | 计数表中该会话正在用的条目(句柄已发放、世界已加载) | 从计数表**摘条目** → 逐句柄**卸载不存档 + 删目录**(策略无关——会话已死,复用收益失效;TEMPLATE_RESTORE 本就删目录,结论一致) |
| ② 曾发放已保留 | 曾切换离开(B5 归零保留)而在磁盘上的 REUSE_DIRTY 目录(无句柄、无条目、无引用) | 端口新增**「会话曾发放 mapId 集」**簿记(`acquire` 发布点记录 → `discardSession` 排空消费),按精确名 `mapId + "-" + 短码` 删除;被 ① 覆盖的 mapId 不重复派删 |
| ③ 迟到 in-flight | 解散后才完成的复制流水(超时竞争窗口之外的 post-解散完成) | `discardSession` 先把该会话短码记入**「已死短码集」**;其后任何归零处置(含迟到句柄经既有 onWorldReady 守卫释放,14.19 路径)发现短码已死,**无论策略一律删目录**——不产生无人持有的新副本 |

**理由**:①**保留的理由有寿命,而系统里没有人记得替它收尸**——REUSE_DIRTY 归零保留的唯一理由是「同会话复载」(03 §3.7 规则表「引用计数」行);理由的兑现者只有一个(该会话的下一次 `acquire`),会话解散后兑现者不复存在,目录立即失去全部价值,却无人回收:既有六步释放流水只在归零点分派,死会话名下的保留目录没有第二次处置机会(TEMPLATE_RESTORE 归零即删,无此问题)。②**残留是线性累积**——每一条会话生命周期(rotation 单会话连打、宿主频繁建/散会话)至多留「用过的图数」张孤儿目录;长运服的副本根单调增长,磁盘面无人回收。③**三类覆盖缺一类即不成立**——存活条目只删 ① 的话,切换离开保留的目录(②)恰好是既有口径「释放后保留」的输出;只删 ①② 的话,复制中途解散的迟到流水(③)会在窗口关闭后重新产出一个新副本(四步卸载点已过,复用窗口已关)。①②③ 是同一命题(「窗口关闭即回收」)的三个观测面,不是三条特性。④**回收点唯一且自然**:解散是面向「名下」的既有动作点(§3.7 释放时机行「dissolve 的 finally 兜底释放」接缝),在该点把「释放句柄」升级为「销毁名下全部副本」= 零新接缝、不引入任何清扫调度器;完整决策记录见 [ADR-0011](docs/adr/0011-reuse-dirty-copy-dispose-on-dissolve.md)(启动清扫、后缀匹配两条备选的否决理由)。

**边界**:「名下」以端口侧追踪为据(①计数表 + ②发放名册 + ③已死短码),不以宿主的会话注册表为据——端口不反向访问自家工作面之外的会话层状态(分层纪律:`bridge/**` 不得 `import` `engine/session/**` 以外更上层状态)。

### D2:切换路径语义不变(B5 保留;TEMPLATE_RESTORE 原样;删除唯一入口)

**决策**:不影响既有切换路径的任何一步:B5(换图)释放对 REUSE_DIRTY 归零仍**保留**目录(同会话回来 `acquire` 直接复载,脏标记黑盒判据不变);`TEMPLATE_RESTORE` 归零删目录不变(现存行为,成为本命题参照);归零/销毁的**目录删除只有一个入口** `deleteCopyDir`(删前路径形态断言:副本根下、文件名恰为 `<mapId>-<短码>`、无路径分隔符——不过断言即抛,绝不递归删除任意路径);卸载失败 SEVERE + 保留目录、删除失败 WARN + 残留兜底的 best-effort 纪律**原样**(失败路径不阻塞调用,future 在处置动作落定后才完成,完成语义与 `release` 同源)。

**理由**:本判据的边界归拢后做出注释(§3.7 与 `WorldPortImpl` 类注):「复用窗口」内的保留行为是**复用语义**本体,一步都不动;窗口关闭只在**会话死亡**这一时点发生——二者是从属关系并列——不存在「同一释放点两种行为」的分叉:`release` 行为本身不因解散而改变;改变的是它内部删除判据多了一个短路条件(短码已死 → 尽管策略说保留,也删)。「保留」与「已死删」两个条件全部收敛在端口处置函数的一个判据点(`TEMPLATE_RESTORE ∨ 短码已死 → 删`),不新增分支面。机制的观测者(测试)可黑盒验证:窗口内(活会话)复载不重拷、窗口外(死会话)归零即删。

### D3:公共面零改动(API_VERSION 维持 4;WorldPort 为 engine 内部口)

**决策**:`MiniGameApi` 冻结面 15 方法、`API_VERSION = 4`(22-D2)**零改动**;新增口 `discardSession` 落在内部口 `WorldPort`,**不为外部消费者打开任何入口**——它 **不在** `MiniGameApi` 上,无关公共面白名单(★44)与冻结清单(★19)是否重录(答案:重录弯路都不走,零重录);`SessionService#dissolve` 是其**唯一调用点**(§3.7 规则表「谁调用」行口径不变,多了第三法仍只有会话内核能调动端口)。消费方对「副本无限残留」的感知面 = **零**——他们从来没有见过副本目录的语义,也不应当见。

**理由**:①`WorldPort` 自 v2 建立起即「`SessionService`/`EngineTicker`/`WorldPort`/`ServiceRegistry` 族/`bridge/**` 永不导出」(19-D6 白名单;★44 正断言)——把生命周期闭环塞进公共面会破坏白名单纪律,且无真实消费者诉求(没有任何宿主需要亲手销毁世界副本——他们连句柄都拿不到);②铁律 9「世界只有 `WorldPort` 一个口」:`discardSession` 仍是该唯一口的一部分,不是第四个口;③One-Version Rule 反向成立:**没有对外可观测行为,就没有公共面承诺可冻结**——为内部语义申请公共面实名只会白白占用一版 API_VERSION 的破坏性窗口(22-D2 那样的裁决资源不为不存在的消费者动用)。

## 3. 契约骨架(`WorldPort` 三法)

> **以下为现行 `src/main/java/com/hydrokarbs/engine/port/WorldPort.java` 的实际签名转写(2026-10-27,不得凭记忆)**——方法名、参数与返回类型逐字对应该文件(仅摘 javadoc 要点;方法体与实现细节见 `bridge/world/WorldPortImpl`,其三方簿记「发放名册/已死短码集」为**端口内部实现件**,不进契约骨架——外部可见的只有三法语义)。§12 包树与 2.4 施工文档若引用世界端口契约,以本骨架为准。

```java
package com.hydrokarbs.engine.port;

/** 世界端口:世界的实例化/引用计数/释放(03-会话与模式切换 §3.7)。
 *  ★ 只有会话内核调用(获取在切换准备阶段、释放在切换完成/解散)——
 *  模式与组件无感,只消费世界句柄上的只读数据。同一 (map, session)
 *  重复获取幂等返回同句柄;引用计数归零按句柄的 ResetStrategy 处置副本。
 *  释放幂等,重复无害。会话解散经 discardSession 关闭复用窗口。 */
public interface WorldPort {

    /** 为地图获取就绪世界。同一 map 在不同会话得到独立副本。
     *  模板复制 = 文件 IO(虚拟线程);加载世界 = 主线程。 */
    CompletableFuture<WorldHandle> acquire(MapDefinition map, SessionId forSession);

    /** 引用计数归零 → 按句柄的 ResetStrategy 处置副本。幂等。 */
    CompletableFuture<Void> release(WorldHandle handle);

    /** 销毁该会话名下的全部世界副本(会话解散时调用,覆盖三类):
     *  计数表中该会话的存活条目(移除并逐句柄卸载不存档 + 删目录)、
     *  曾切换离开而保留在磁盘的目录、迟到的 in-flight 获取(其后的归零处置
     *  发现会话已死一律删)。
     *  复用窗口 = 会话生命周期:解散即关闭窗口——无论 ResetStrategy
     *  一律删除副本目录(会话已死,复用收益失效)。幂等:重复调用无害。
     *  处置动作全部完成后 future 才完成(与 release 完成语义同源)。 */
    CompletableFuture<Void> discardSession(SessionId session);
}
```

配套类型(零改动,重申):`WorldHandle` `record`(world/instanceName/map/reset,`requireNonNull` 全字段)与 `ResetStrategy` 二值枚举(`REUSE_DIRTY`/`TEMPLATE_RESTORE`)原样——**枚举不增第三值**:「会话已死」不进策略值域,是两端(`disposeHandle` 归零端与 `discardSession` 销毁端)共用的端口内部删除判据(已死短码集);端口侧因此各自只有一个删除归宿(D2 单分支)。实签依据:`engine/port/ResetStrategy.java`、`engine/port/WorldHandle.java` 现行(2026-10-27,git 实况)。
