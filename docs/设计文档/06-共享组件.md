### 6.2 `DisplayComponent` 的数据驱动设计(替代强耦合表现层)

> **★v1.3 迁出注(21-D2/R2)**:表现层整体出框架——本节全部设计(`DisplayModel`/`DisplayLine`/`Countdown`/`Progress` 中立模型、数据驱动论证、构建函数示例)已**原文完整迁 `Shdf具体玩法设计案/10-表现层组件.md`**(标注「自框架 06 §6.2 v1.3 迁入」);框架基线移除 `component/display/**`、`render/**` 与 config `display:` 块(P3 组件计数 L3 实数 21→20,施工子阶段 4.3 撤销)。以下原文保留为**历史存档**(教训与「数据驱动」结论仍被 §1.3 对照表引用),新代码勿在框架侧引用。

强耦合表现层的教训(旧插件的历史宿主,SHDF):Renderer 把玩法语义写死在渲染代码里,换个模式整套报废。新做法:组件只认一个中立模型。

```java
package com.hydrokarbs.component.display;

/** 表现层的中立数据模型。模式把语义翻译成行 + 进度 + 倒计时。 */
public record DisplayModel(
        Component title,
        List<DisplayLine> bossBarLines,      // 顶部 BossBar 多行
        List<DisplayLine> sidebarLines,      // 侧边栏
        Optional<Countdown> countdown,       // 经验条/标题倒计时
        Optional<Progress> globalProgress    // 全局进度(目标进度 / 分数 / 血条)
) {
    public record DisplayLine(Component text, int weight, LineStyle style) {}
    public enum LineStyle { NORMAL, HIGHLIGHT, DIM, DANGER }
    public record Countdown(int remainingTicks, int totalTicks, Component label) {}
    public record Progress(double current, double target, Component label) {}
}
```

模式的构建函数示例(一个 30 行量级的函数,证明零特权;倒计时从 `PhaseComponent` 经 `getComponent` 取,不是引擎口子。大厅/四模式各自的 `display` 挂法原文(bombDisplay/bossDisplay 等)已迁 `Shdf具体玩法设计案/05-四模式矩阵.md` §5.6,原文完整):

```java
// 中性示例(框架侧):一个模式的表现层构建函数——30 行量级,证明接入零特权
// (具体玩法的 display 挂法已迁 Shdf具体玩法设计案/05-四模式矩阵.md §5.6,原文完整)
DisplayModel exampleDisplay(MatchModeInstanceView ctx) {
    var last = ctx.handoff().get(StatsComponent.LAST_SUMMARY);   // ★v3.1:交接键由 StatsComponent 持有
    return new DisplayModel(
        Component.text("示例模式 · " + ctx.session().members().size() + " 人在线"),
        List.of(new DisplayLine(scoreLine(ctx), 1, NORMAL)),        // 记分行:模式把语义翻译成行
        last.map(s -> List.of(new DisplayLine(summaryLine(s), 1, HIGHLIGHT))).orElse(List.of()),
        ctx.component(PhaseComponent.class).countdown(),            // 倒计时从 PhaseComponent 经 getComponent 取
        ctx.component(ObjectiveComponent.class).globalProgress());  // 全局进度(目标进度/分数/血条皆可)
}
```

**收益**:下一个模式只需要写一个 30 行的 `display(ctx)` 函数,表现层零改动。

### 6.3 `InteractionComponent`(消灭旧插件最大的重复面)

旧插件在每个阶段各维护一份 `itemId → 行为` 的 switch。新做法:注册表 + 声明。

```java
public final class InteractionComponent extends MatchModeComponent {

    public sealed interface Trigger permits Instant, Channel, Toggle {
        record Instant(int cooldownTicks) implements Trigger {}
        /** 长按读条:按住 N tick 后触发,中途移动/受伤/松手打断。 */
        record Channel(int channelTicks, EnumSet<Interrupt> interrupts) implements Trigger {}
        record Toggle(int cooldownTicks, boolean initialOn) implements Trigger {}
    }
    public enum Interrupt { MOVE, DAMAGE, RELEASE, ITEM_SWITCH }

    public record InteractionPoint(
            String id,                       // "lever_a" / "button_b" / "range_button"
            RegionId region,                 // 来自 MapDefinition.interactPoints
            ItemMatcher matcher,             // 手持什么物品能触发(或空手/任意)
            Trigger trigger,
            Predicate<MatchModeInstanceView> allowed, // 允许条件(如"仅限当前目标区域内的参与者")
            Consumer<InteractionEvent> action
    ) {}

    public void register(InteractionPoint point);
    public void unregister(String id);
    /** 由 listener/InteractionListener 从 PlayerInteractEvent 转译而来,统一分发。 */
    public void dispatch(Player player, InteractionEvent event);
}
```

★ **无长按读条时的正确事件源**(v1 结论原样保留):`PlayerInteractEvent` 只能给你"点了一下"。实现"按住 3 秒的长按交互"要在 `dispatch` 落点起一个通道结算(在 `EngineTicker` 的 1-tick 节拍里推进进度),并在 `PlayerMoveEvent` / `EntityDamageEvent` 上监听打断(`ignoreCancelled = true`),**同时**在 `PlayerInteractEvent` 的 `RIGHT_CLICK_AIR` 分支检测松手。这是旧插件 `BombInteractionController` 已验证过的形态,直接搬(**SHDF 历史宿主,详见 Shdf具体玩法设计案/**)。

### 6.4 会话级组件清单(第一波)
