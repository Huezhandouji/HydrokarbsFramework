## 背景

v1.1 把框架拆为独立插件后,地图的**打包归属**清楚了(玩法图随玩法 jar、各自 `maps/` 根),但**运行期发现**只剩文件落位约定:框架的 `MapRegistry` 启动扫描自己的数据目录,玩法 jar 里的 `maps/*.yml` 与世界模板如何进入目录、如何与模式发现(`MatchModeProvider` 双发现)对称,没有机制承载。同时,赛程器/伴随插件"动态开一张活动图"的诉求(与 `SessionRecipe` 单次定制会话同构)也无入口。

## 决策

1. **显式注册 API**:`MiniGameApi#registerMap(Plugin, MapDefinition)` / `unregisterMap(Plugin, String)`(API_VERSION 2→3,只增不改)。与能力标签注册(D4 of 19)同款形状:显式调用、携带提供方插件、结构化错误当场可感。
2. **地图交成品,不交工厂**:`MapDefinition` 是纯静态值(无行为、无依赖图、无框架注入配置、无 reload 重建)——模式侧"必须交工厂"的三大理由在此均不成立,直接注册建好的实例是安全的。不提供 `MapProvider` 工厂形态。
3. **双通道汇入单点**:文件装载(`maps/*.yml` 启动扫描)与显式注册汇入 `MapRegistry` 同一私有 `register()`,同一命名空间查重——注册语义只有一份。
4. **模板落盘约定不变**:解析路径仍为框架数据目录 `maps/templates/<mapId>/`;形态 B 下宿主 onEnable 先解包(`saveResource`)再注册,注册期校验目录存在。19-D1 的"随玩法 jar 分发"描述打包归属,注册+解包是其发现机制,两者不冲突。
5. **卸载归属与守卫**:`unregisterMap` 显式 + `PluginDisableEvent` 兜底(D8 同款);该图为任一存活会话所用或存在未释放句柄 → 摘除被拒(镜像 `/sm reload maps` 纪律);副本处置走 `WorldPort` 既有引用计数,不因摘除声明强删。
6. **reload 口径**:注册式地图不经 `/sm reload maps`;宿主"reload" = unregister + register。
7. **WorldPort 边界重申**:注册只交声明;世界实例化/引用计数/释放/ResetStrategy 全留框架——按 D7 两问,世界句柄属可靠性底线,不可下放。

## 替代方案(已否)

- **只靠文件落位(维持 v1.1 现状)**:跨 jar 发现无机制承载,动态开图无入口;否。
- **`MapProvider` 工厂 SPI(与模式对称)**:为不存在的配置注入/reload 诉求造缝(hypothetical seam);否——纯静态值直接交成品。
- **注册时携带世界模板句柄/回调**:把世界生命周期的一部分漏给插件,击穿 WorldPort 边界;否——模板落盘走磁盘约定,注册只认目录存在。

## 后果

- 正:形态 B 地图发现有了与模式对称的机制;活动图/临时图成为一等公民;注册错误当场可感。
- 负:宿主多一步"解包落盘"时序义务(14.39);API 面再增两方法(冻结面扩张,`MiniGameApiSurfaceTest`/`ApiSurfaceTest` 快照随 7.5 更新)。
- 未决移交:20 §6(Q1 模板路径字段 / Q2 工厂形态 / Q3 MapInfo 来源标注)。
