# ADR-0011:REUSE_DIRTY 副本随会话解散销毁(v1.5)

- 状态:已接受(2026-10-27)
- 关联:[23-v1.5修正案-REUSE_DIRTY副本随会话解散销毁.md](../../23-v1.5修正案-REUSE_DIRTY副本随会话解散销毁.md)(变更指示全文);补充而非取代既有决策——[ADR-0008](0008-map-registration.md) 的「WorldPort 边界不变」(注册交付的只是声明)继续成立,本文动的是 `WorldPort` 自身的生命周期语义(注册方不为销毁负责)
- 验收:★58(§16.2 追加;归属框架线,首建于 2.4,持续验证 = `WorldRefCountTest` ⑧ 组)

## 背景

v2 建立世界端口以来的处置语义:`acquire` 按 `(map, session)` 复制模板为独立副本(目录名 = `mapId + "-" + 会话短码`),`release` 归零按 `ResetStrategy` 处置——`REUSE_DIRTY` **保留副本目录**(同会话复载,零复制成本),`TEMPLATE_RESTORE` 删目录。保留的复用理由只有一个:**同会话再次获取**(03 §3.7 规则表「引用计数」行)。

该理由有一个未被建模的寿命边界:**复用理由的兑现者(该会话下一次 `acquire`)随会话解散而消失**。会话死亡后,死会话名下保留的 REUSE_DIRTY 目录不再是缓存,而是残留——释放流水只在归零点分派(⑥ 删/留),归零之后的目录没有第二次处置机会;`TEMPLATE_RESTORE` 归零即删、无此问题。于是每一条会话生命周期(单会话轮换连打、宿主频繁建/散会话)至多残留「用过的图数」张孤儿目录,长运服副本根**线性累积**,磁盘面无人回收。既有的兜底全部错过它:超时回滚不涉及已保留目录(测试 ⑤);`deleteCopyDir` 的形态断言保安全但不发起删除(测试 ⑦);`prepareCopyDir` 只清理**同短码同图**的同名残留,异短码(即前任会话)目录互不触碰——这正是副本按会话隔离的正确行为,反过来说明没人会替死会话收尸。

## 决策

**复用窗口 = 会话生命周期:`WorldPort` 新增第三法 `discardSession(SessionId)`**,在会话解散的既有 finally 接缝(03 §3.7 释放时机行;`SessionServiceImpl#dissolveNow`)调用一次,名下全部副本销毁,三类覆盖:

1. **计数表该会话的存活条目**:摘条目 → 逐句柄卸载不存档 + 删目录,**策略无关**(存活条目与既有 `release` 归零共用同一处置函数,只是删除判据多了「短码已死」一个条件:`TEMPLATE_RESTORE ∨ 短码已死 → 删`)。
2. **曾切换离开而保留在磁盘的目录**:端口新增「会话曾发放 mapId 集」簿记(`acquire` 发布点记录,`discardSession` 排空消费),按精确名 `mapId + "-" + 短码` 删除;存活条目已覆盖的 mapId 不重复派删。
3. **迟到 in-flight**(复制中途解散):解散先把短码记入「已死短码集」;迟到流水照常完成(既有 onWorldReady 守卫,14.19 路径)、句柄释放,其后归零处置发现短码已死 → 无论策略删目录,不产生无人持有的新副本。

幂等:重复调用短码重记、条目已空、名册已空,零副作用;从未获取过的会话销毁无害。失败路径与 `release` 同源 best-effort(卸载失败 SEVERE + 保留目录、删除失败 WARN + 残留兜底)。

## 替代方案(已否)

- **启动清扫(onEnable/onLoad 扫描副本根,清掉不属于活会话的目录)**:**否**。①只能清「上一个进程生命周期」的残留,运行期死会话残留仍要到下次重启才收——覆盖不到本次正在修的累积机制;②「哪个目录属于活会话」需要反查会话注册表:要么把端口接到 `engine/session/**` 状态上(分层反向依赖),要么靠名字推断——而短码簿记只在端口内存里、重启即空,扫到无档案目录时连「房东是否还在」都判不出,误判即误删在用副本;③清扫点(启动期)与累积点(运行期)错位,疗法不对症。硬残留(崩溃残留)若确需治理,登记 23 §6-Q1(运维脚本/人工清理为先),不做假想接缝。
- **目录名后缀匹配(扫副本根,凡能匹配 `-<短码>` / 已死短码后缀的目录即删)**:**否,会误删他 session 的目录**。会话短码取值域含 `-`(保位替换纪律:`SessionId.shortCode()` 把不安全字符逐个替换为 `-`,`[a-z0-9_-]` 原样保留),mapId 同样可含 `-`;则目录名 `ctf-town-arena-xxxx` 无法唯一反推 `(mapId, 短码)`——灾难情形:会话 A 的 `("a", "b-x")` 与会话 B 的 `("a-b", "x")` 同名同形,按后缀/切分猜测必删其二。精确性要求迫使追踪成为名册(决策 2 的 mapId 集),而不是在删除时猜。
- **不增第三枚举(靠 `ResetStrategy` 加第三个值「会话已死删」表述销毁)**:**否**。策略回答「打完怎么还原」(值域 = 两个已冻结的处置行为),窗口回答「还打不打」——会话死亡不是地图作者的策略选择,塞进枚举会把生命周期判据伪装成声明口径,还把「策略 = 句柄字段」(随句柄发放锁定)与「判据 = 处置时点」(随解散翻转)两类时序搅在一起;端口内部判据(「已死短码集」)保持删除判据单一。
- **维持现状(不做任何运行期清理,靠重启自然回收)**:**否**。「重启收残留」对长驻进程形同虚设:残留随每次解散持续增长,重启间隔越长磁盘面越大;且真正的修复动作并不贵——回收点(既有 dissolve finally 接缝)与簿记底座(计数表键本来就是 `(map, session)`)都是现成的,新增只有一册一集(发放名册、已死短码集)。

## 权衡

- **得**:三类覆盖收口——死会话名下不再有任何留存目录;副本根占盘回到「活会话名单 × 用过的图数」的规模,与 `WorldRefCountTest`(★17)对内存面的守恒(`refCounts`/`inFlight` 必清)同一推理:生命周期终结处,资源清零。机制面成本可控:`discardSession` 幂等无锁竞争面(解散单时点、处置动作完成才完成 future),簿记全部收敛在端口内部。
- **失**:端口认领两份簿记(发放名册 + 已死短码集,各一个数据结构);归零处置的删除判据由单条件变双条件(策略 ∨ 短码已死)——多一个分支,但分支同时是维持切换语义不变的代价(策略判据原样,只在已死时短路)。崩溃硬残留(上一进程生命周期)不解决,登记 23 §6-Q1。
- **判据同源**:与 ★17「世界零泄漏」(100 次切换零残留)同一命题向生命周期维度伸延:内存面(句柄/条目/表)自 v2 起由测试冻结,磁盘面(副本目录)自 v1.5 起由同一测试类 ⑧ 组冻结;二者裂缝只在 REUSE_DIRTY × 会话死亡这一组合,本裁决闭合它。
- **不动面**:复用语义(同会话复载零复制)、`TEMPLATE_RESTORE` 行为、`deleteCopyDir` 唯一入口与路径形态断言、卸载/删除失败 best-effort 纪律、公共面(`MiniGameApi` v4 / `API_VERSION=4`,★19/★44 零重录)——全部原样(23-D2/D3)。

## 后果

- 正:解散后任何策略的副本目录消失(★58);副本根不再随会话代际线性增长;WorldPort 生命周期语义闭环(实例化 → 引用 → 归零处置 → 解散处置),接口三法各有明确的时点契约。
- 负:接口三法中第三法为端口新增契约,发布名册/死短码集两份簿记进入实现面(计数表/发放名册/已死短码集);进程硬崩溃残留仍待 23 §6-Q1 裁决(登记,不清零)。
- 验收:★58(命题文本见 23 §5;落 §16.2 由「编辑·正文与术语」执行)。
- 未决移交:23 §6(Q1 硬残留兜底 / Q2 死短码集淘汰)。
