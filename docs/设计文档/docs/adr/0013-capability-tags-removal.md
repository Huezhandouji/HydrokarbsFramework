# ADR-0013:能力标签机制退场,外部能力改会话组件桥接(v1.7)

- 状态:已接受(2026-10-28)
- 关联:[25-v1.7修正案-能力标签机制退场与会话组件桥接.md](../../25-v1.7修正案-能力标签机制退场与会话组件桥接.md)(变更指示全文);判据与 [ADR-0010](0010-api-surface-consolidation.md)/[ADR-0012](0012-explicit-api-registration.md)(「同一能力只留一份口径」)同源;机制前身裁决链:ADR-0002/v3.1(`enum Capability{ROLE}` 内容词汇字符串化——本裁决把字符串层也撤了)、ADR-0004(会话级组件层——桥接的承载机制)、24 号(显式注册四法——桥接的「进」口);**Supersedes(部分)** [ADR-0007](0007-standalone-framework-plugin-split.md)——其决策(D4:能力标签提供方注册 `registerCapability`/`capabilities()`)随本裁决退场,该决策不再有存续的机制面
- 验收:★60(§16.2 追加;★32 就地废止注、★21 就地注;★19/★44 冻结快照随 v6 面合法重录——修正案 25 §3/§5 为背书)

## 背景

至 v1.6,框架内并存**两套**「外部能力供给/消费」的表达:

1. **字符串能力标签(★v1.1-D4,进程级横切)**:提供方经 `registerCapability(Plugin, tag)` 注册标签;消费方在 `MatchModeMeta.requiredCapabilities` 声明标签,框架在**每次切换的阶段 A2** 重查(可用集 = 进程级标签 ∪ 本会话会话组件标签);会话组件与进程级服务还有各自的 `capabilities("tag")` 声明(装配/ seal 期注册、dissolve/shutdown 摘除)。防撞机制 = **词汇纪律**(文档约定:词汇由提供方注册,引擎零字面量)——机制本身不设防:`"role"` 与 `"Role"` 两串在编译期与装配期都合法,撞名/拼写错误要到**运行期切换 A2** 才炸(玩家面前的对局被 `REJECTED_BY_TARGET_MODE` 拒绝,detail 列一串没人认得的标签);跨域同标签(两个无关联提供方主张同一串)更是只有词汇纪律可依。
2. **组件类型化依赖图(v4/v4.1,装配期)**:供给 = 组件 `Specification#providedType()`(泛型推导),消费 = `requires`/`requiresOptional` 类型化声明,失败 = 装配期响亮(会话创建失败/seal 抛点名)+ 运行期 D9 quarantine——编译器与类型图守卫,零词汇纪律义务。

两套表达描述的是**同一关系**(谁供给能力、谁消费能力),却有两份簿记、两套失败语义(A2 拒切换 vs 装配响亮)、三处摘除时点(能力块随 disable / 服务随 shutdown / 会话组件随 dissolve)。字符串层是叠在类型图之上的**平行弱机制**,且是其中唯一不设防的一份。

## 决策

**能力标签机制全链退场 + 外部能力 = 会话组件桥接**(全文见 25 号 §1 D1~D4):

1. 退场清单:`registerCapability`/`capabilities()` 两法(api 层 `capabilityClaims` 随删)、`CapabilityRegistry` 机制件、切换 A2 校验步、`MatchModeMeta.requiredCapabilities` 首分量、`MatchModeInfo` 快照分量、`SessionComponent.Specification#capabilities` 与 `ServiceSpec#capabilities` 声明(服务 seal/shutdown 两端注册随注消失)、`ProviderUnloadListener` 能力块(兜底四族 → 三族)。
2. 外部能力 = **会话组件桥接**:提供方(或宿主自持防腐层)把外部能力包成 `SessionComponent` 桥接组件(外部类型 import 只住该组件类内部),经 `registerSessionComponents`/`SessionRecipe` 贡献;消费方组件 `requires`/`requiresOptional` 类型化声明——装配期响亮、运行期 quarantine。桥接所需的全部机制(贡献通道、装配闸、隔离)在框架内既有,**零新增机制**。
3. 校验时机位移:**每切换重查(进程级新鲜度)→ 创建时绑定 + 运行期降级/quarantine**——provider 摘除只影响后续会话,存量会话由桥接组件自身降级承接(D14 既有口径)。
4. `API_VERSION` 5 → 6(删冻结面公共方法 = 破坏性;零过渡窗口,22-D2/24-D4 同款)。

## 替代方案(已否)

- **强类型枚举(把标签改回 `enum`,编译期防拼写错误)**:**否,且历史已废止一次**——v3.1 正是把 `enum Capability{ROLE}` 请出引擎(ADR-0002 体检:引擎里出现 `ROLE` 字面量 = 引擎认识角色插件,内容词汇进引擎触 §4 铁律 1 红线)。枚举是**封闭集**:新外部能力 = 改框架源码加枚举值,跨插件扩展路径直接不存在——与「框架不认识内容」的立项哲学正面冲突;为保住封闭集就得在引擎里开注册口,又回到字符串。字符串化的原裁决已证死路,反向重走无意义。
- **框架定义类型化端口(框架为每类外部能力声明 `RolePort` 式接口,消费方依赖端口类型)**:**否,内容词汇进 engine 触红线**——端口的语义词汇(角色/经济/权限)本身就是内容;v3.1 已删过 `RolePort`/`DisplayPort`(§0.5.3);框架能定义的只有机制端口(WorldPort/JoinAdmission/SessionView),而「角色能力」不是机制。折中形态「框架定义 `CapabilityPort<T>` 泛型接口」只是给字符串握手换了件类型外衣:注册仍按名字索引、`T` 的绑定仍要运行期解析,不严谨性原样。
- **双轨保留(字符串标签与桥接并存,新代码走桥接)**:**否,One-Version Rule 直接否决**(与 ADR-0010 否决「薄便利方法」、ADR-0012 否决「双轨共存」同构)——并存意味着双簿记/双失败语义/三处摘除时点的解释义务无限期悬挂;「新代码走桥接」无法机械守卫(冻结测试管签名,管不住谁还在 `registerCapability`——虽然该方法若保留就在冻结面)。要么删,要么别改;本裁决选删。

## 权衡

- **得**:①**失败面整体前移**——拼写错误/漏装/缺依赖从运行期切换(A2,玩家面前)前移到会话创建装配期(响亮、点名缺失类型);跨组件握手由编译器与类型图守卫,词汇纪律义务清零。②**口径单行**——「外部能力供给/消费」只剩类型图一份表达;双簿记、A2 重查、三处摘除时点中的字符串半边全部退役,引擎对能力零认识且零机制(红线更干净)。③**机制件归零**——`CapabilityRegistry` 全部消费方在退场清单内(21-D1 零消费者判据),无残留悬挂。
- **失**:①**纯跨插件零编译契约场景失去一等公民形态**——原字符串标签允许提供方与消费方编译期互不认识、运行期共享字符串握手;类型化要求消费方能引用桥接组件类型(编译耦合,关进消费方防腐层组件)。该场景在框架基线无真实出现路径,登记 25 §6-Q1,出现再立项。②**失去每切换重查的进程级新鲜度**——provider 摘除不再即时影响存量会话的切换(改为只影响后续会话);存量会话的外部依赖活性语义从「框架代查」移交「组件自治」(自身降级 + D9 quarantine 兜底)。缓解:该新鲜度从来只保护「标签簿记一致性」,不保护业务正确性——标签在册而外部插件功能残缺时 A2 照样放行;组件自治反而把降级责任放到真正掌握语义的一侧。
- **判据同源**:与 21-D1(零消费者机制件删除)、22-D1/24-D2(同一能力两份口径,收敛优于并存)同一推理形状;桥接「由提供方或宿主自持、编译耦合关进组件内部」是 ★23 桥接单点纪律的泛化。

## 后果

- 正:★60 冻结(类型化桥接 = 外部能力唯一形态 + 标签机制零残留);MiniGameApi 编译面 19 → 17;`ProviderUnloadListener` 兜底三族;阶段 A 失败路径收窄为 A1/A3~A6;冻结快照 FROZEN 17 行/BASELINE 重录(API_VERSION=6)。
- 负:`API_VERSION` 6 窗口内未迁移的消费方拒载或编译失败(两公共法与 `MatchModeMeta` 位置实参);纯零编译契约场景失去(未决 25 §6-Q1);存量会话在 provider 摘除后不再有框架侧的标签级防线(由组件降级与 quarantine 承接)。
- 验收:★60(命题文本见 25 §5;落 §16.2 由「编辑·正文与术语」执行);★32/★21 就地注同表。
- 未决移交:25 §6(纯跨插件零编译契约场景 / 战绩悬置承接 / Shdf 侧桥接接线随玩法线施工计划)。
