# ADR-0015:切换与解散的世界清场经会话内核注入函数(v1.9)

- 状态:已接受(2026-10-28)
- 关联:[27-v1.9修正案-切换与解散的世界清场.md](../../27-v1.9修正案-切换与解散的世界清场.md)(变更指示全文);判据与 [ADR-0011](0011-reuse-dirty-copy-dispose-on-dissolve.md)(「复用窗口 = 会话生命周期」——清场把其销毁接缝的卸载失败面压到零)同源;**不修改** [ADR-0014](0014-map-declaration-path-direct.md) 的任何结论(`WorldPort`/`MapDefinition` 零触碰)
- 验收:★65(§16.2 追加;★17/★58 命题零放宽,★19/★44 冻结快照零重录)

## 背景

至 v1.8,切换/解散的世界收尾只有「引用计数释放 + 销毁」(`release`/`discardSession`),不处理**世界内还站着的人**:`Bukkit.unloadWorld` 对仍有玩家的世界返回 false → `disposeHandle` 走「SEVERE + 保留目录」防线 → 临时副本文件滞留。触发源恰是**名册外滞留者**(清场口径以会话名册为界,名册超集的物理面无人负责)——23 号销毁闭环(D1~D3)被这条伴生面击穿。留了两条路:把清场塞进 `WorldPort`,或在会话内核接缝上以平台函数注入收敛。

## 决策

**世界清场 = 会话内核机制,平台语义经 `SessionServiceImpl.Builder` 两个 L0 函数注入口收敛**(全文见 27 号 §1 D1~D4):

1. **归属内核、不经 `WorldPort`**:清场是切换/解散算法的一部分(与引用计数释放同族),落点 = `executeB` 与 `dissolveNow` 既有主线程路径;`WorldPort` 接口零改动,不新增世界触点(只消费句柄已持有的 `World` 引用)。
2. **切换双分支**:判据 = **`org.bukkit.World` 引用相等(`==`)**——引用相等只可能来自端口表命中同句柄(同图重开)→ **B3.5 清场先行于 B4 组件摆放**(殿后会把 `startAll` 刚摆好的位次拽回出生点);REUSE_DIRTY 同世界归零后再获取经 `prepareCopyDir` 复载产生**新的** `World` 对象(引用必不等)→ **B5 finally 殿后清场**(守卫内、完成事件之后、`release` 之前)。含空值分支(首切 `current == null` 跳过)与两失败窗口登记。
3. **解散「先名册后世界」**:名册传送(`hubRelocator`)在先,清场口在 `dissolveNow` finally、摘句柄后、`discardSession` 前——两级覆盖互为兜底、每人至多一次;目标口径与 `hubRelocator` 共用新抽 `hubSpawn()` 单一来源。
4. **best-effort**:清场失败 WARN 不阻塞,release/`discardSession` 照发;23-D2「卸载失败 SEVERE + 保留目录」防线原样为最后防线。

## 替代方案(已否)

- **`WorldPort` 内清场(acquire 时清旧 / release 时清)**:**否,玩家语义塞进世界端口**——世界端口的契约是实例化/引用计数/释放/销毁(§3.7),玩家传送是切换/解散算法的收尾动作;且 `release` 时清会**静默改写 23-D2 防线语义**(释放接缝从「计数动作」膨胀为「传送 + 计数」,同图重开的重复清场无处安放);端口也不持有「目标世界」概念(B5 需要把人从旧世界送进新世界)。
- **清场统一前置 B4 之前(不分同图/异图)**:**否,回退路径把人带进孤儿副本**——B1~B4 失败时句柄未换入(rollback 不触句柄),前置清场已把人送进 `plan.world`;随后回退切换放弃该副本 → 人站在孤儿世界里。殿后(异图)/先行(同图)双分支各自避开该窗口(27 号 §1-D2 表)。
- **事件监听兜底(监听 ModeSwitchCompleted 后清场)**:**否,隐式时序不可测**——订阅时序依赖注册顺序与总线实现,离线不可断言「清场先于 release」;违 14.6(不做隐式时序)与「切换语义只有一份」(清场成了第二份)。

## 权衡

- **得**:①「世界内有玩家 → unloadWorld false → SEVERE + 保留目录」路径触发概率压到零,23 号销毁闭环(★58)如期兑现,临时副本文件如期清除;②遗留人员口径以物理世界为界(名册超集),名册外滞留者(既有主因)被覆盖;③传送只落主线程既有路径,单 tick 原子不破,零新增异步;④函数注入模式与 `hubRelocator`/`safeStateCleaner` 同款,L0 落点唯一、离线可测(记录型假件 + 时序录)。
- **失**:①**同图重开「原地起步 → 出生点起步」是冻结语义变更**——依赖跨局位置保留的组件须自读 Handoff 坐标自行传送(27 号 §6-Q2 登记为组件层义务);②名册成员同 tick 两次传送(同世界复用:清场 + 组件摆位),耗时随名单线性(出生点区块 Paper 保持加载,风险低,runServer 观察项);③被清场传走的名册外滞留者不带通用安全态清理(`safeStateCleaner` 只吃名册,既有口径原样,27 号 §6-N2 登记)。
- **判据同源**:与 23-D1(窗口关闭即回收)、22-D3(同一能力一份口径)同一推理形状——清场把「销毁接缝」的前置条件(世界已空)补齐,是 23 号闭环的伴生收口,不是新命题域。

## 后果

- 正:★65 冻结(切换双分支时序 + 解散先名册后世界 + 失败不阻塞 + null 句柄无害);`WorldPort`/公共面/冻结快照零改动;引擎 `org.bukkit.World` import 有既有先例(`WorldHandle`/`EngineTicker`),★1 分层禁令不触。
- 负:同图重开位置语义变更(组件迁移义务);同 tick 双传送的耗时面(runServer 观察);断线宽限期重连落位与安全态清理两镜像面为非目标(27 号 §6-N1/N2)。
- 验收:★65(命题文本见 27 号 §5;落 §16.2 随窗口执行)。
- 未决移交:27 号 §6(N1~N4 登记、Q1~Q2 观察项/组件层义务,均不立项)。
