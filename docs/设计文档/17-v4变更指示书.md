# 17 · v4 变更指示书——会话级组件层

> **文档性质:变更指示**（不是设计章节）。执行者按本指示修改 `设计案/` 全部文档、根目录 `CONTEXT.md`、`docs/adr/` 与 `施工计划/`；本文件本身不并入设计章节编号序列（README 索引中列为"变更指示"）。

> 驱动需求（本次变更的全部理由，逐条可验收）:
> ① **模式要接入会话级能力**——模式/实例组件能读取并使用会话级组件提供的能力，可硬依赖声明；

## 1. 一页摘要

一句话:**v4 把组件从"单一挂载级"扩为两级挂载**——实例级（现有 `MatchModeComponent`，随 `close()` 全灭）与会话级（新增 `SessionComponent`，**每会话一份、跨模式切换存活**）；会话的*策略与行为*可从内核下放为会话级组件；实例组件 ↔ 会话组件按接口**互相只读查询**，对对方产生干预只能走端口。

| 类别 | 内容 |
|---|---|
| 新增类型（5） | `SessionComponent`（基类 + Specification）、`SessionServices`（svc）、`SessionPort`（会话自面）、`InstanceAccess`（会话侧只读实例访问面）、`SessionView`（实例侧只读会话视图） |
| 修订类型（4） | `InstancePort`（+`session()`）、`SessionSpec`（+会话组件表）、`CapabilityRegistry`（+会话组件注册的标签）、`SessionService`（装配/派发/回收接线；**公开方法签名不变**） |
| 新增端口方法（2） | `requestSwitch(target, payload)`、`requestDissolve(reason)`——会话级出局口，镜像实例级的 `switchTo()`/`end()` |
| 新增容器（1） | `SessionComponentRegistry`（装配期依赖校验 + 声明序派发 + 登记资源回收 + 故障隔离；会话版 `ComponentRegistry`） |
| 第一波迁移（1） | `EmptyArenaComponent`（空场解散策略从 `SessionPolicy` 下放；**rotation 不挂 = 永不解散**，镜像 JoinControl"不挂=默认"） |
| 保持不变（硬边界主体） | 引擎内容盲（`EnginePurityTest` 禁词表不动）、`MatchMode` 聚合根零行为、`InstanceServices` 三成员封闭、switchMode 两阶段/三级回退、`Handoff` 作为**实例间**唯一通道、`WorldPort` 机制、名册/状态机/切换执行仍在内核 |

**"单例"语义的精确化（对原始设想的一处修正，必须连同理由写入 ADR-0004）**:会话级组件在**会话生命周期内**是单例——同一 Session 内 `Specification#create` 至多调用一次，此后一切查询（实例组件、会话组件互查、会话内核）恒返回同一实例；**跨会话不共享**。原设想"进程级单例"在 arena 拓扑（N 个会话并发跑同一模板）下会串台，故修正为**每会话一份**。共享的只能是不可变声明（Spec/Snapshot/SPEC 常量），有状态实例永不跨会话共享。

## 2. 决策（D1–D11，逐条写入 ADR-0004 并落到各文档）

### D1 两级挂载
组件有两种挂载级，仅两种:
- **实例级 `MatchModeComponent`**（原样）:生命周期随 `MatchModeInstance`，`close()` 全灭；由模式聚合根的组件描述符表声明。
- **会话级 `SessionComponent`**（新增）:生命周期随 `Session`（create → dissolve），跨模式切换存活；由**会话装配**声明（见 D4）。
禁止第三级；禁止同一组件类兼任两级（同一行为若要跨级，拆成两个组件、经 D5 只读查询协作）。

### D2 会话级生命周期与钩子
钩子与实例级同名对齐，语义按会话重定义:
| 钩子 | 时机 | 语义 |
|---|---|---|
| `awake()` | 会话装配期，`create` 之后 | 只解析**会话级**依赖并缓存引用；幂等；无可见副作用 |
| `start()` | 会话创建完成、首个实例装配之前 | 生效:订阅会话说/实例事件、登记显示、初始化会话级数据 |
| `update()` | 每 tick，**与"当前是否有实例"无关** | 会话策略推进（空场计时等）。禁止阻塞、禁止 IO |
| `onEvent(SessionEvent)` | 会话事件中央总线广播 | 与订阅二选一皆可；订阅随 `stop` 自动回收 |
| `stop()` | dissolve（或隔离）时 | 与 `start` 严格对称；返回后框架自动回收本组件登记的资源（订阅/延时任务/显示） |

派发规则与实例级一致:**按声明序**广播，`stop` **逆序**；`stop` 由框架**无条件**调用（无单例豁免条款——这正是"组件"与"内核机制"的分界，见 D7）。

### D3 装配与"每会话一份"
- 装配点唯一:`SessionService.create(sessionSpec)` 内，先 `verifyDependencies()`（缺会话级必需依赖 → 抛，会话创建失败，L0 SEVERE）再按声明序 `create(id, svc)`；`svc` 构造期注入，四条件照抄实例级（注入先于一切钩子 / final 只注一次 / 未注入即抛 / 创建点唯一）。
- `SessionComponentRegistry.bind(id, snapshot)` 幂等:同会话重复绑定同 id 抛 `IllegalStateException`；id 跨类型去重（同一命名空间）。
- 每会话一份的机械保证:注册表挂在 `Session` 上，**不是进程级静态**。`SessionComponentSingletonTest` 冻结（同 Spec 装配两个会话 → 两个不同实例；同会话查询恒同一实例）。

### D4 装配来源（第一版）
- `SessionSpec` 新增 `List<SessionComponent.Specification<?>> sessionComponents`（有序表 = 装配序 = 派发序），由 **L0 装配期按配置构建**（例:rotation 不挂空场组件；arena 挂 `new EmptyArenaComponent.Spec(Duration.ofSeconds(cfg))`）。
- **模式不得注册/增删会话级组件**（第一版;模式接入会话能力走 D6/D5 的"读 + 声明"）。第三方会话组件 SPI 列为未决（§11-Q2）。
- 会话组件表**不参与模式切换**——切换的 A/B 两阶段与装配代码零改动（`SessionComponentSurvivesSwitchTest` 冻结:100 次切换后会话组件实例恒等、`update` 计数连续）。

### D5 跨级查询:互相只读，写只走端口
| 方向 | 通道 | 授权 |
|---|---|---|
| 实例组件 → 会话组件 | `svc().self().session()`（`InstancePort` 新增方法）→ `SessionView#component(Class<T extends SessionComponent>)` | **只读**；不得订阅会话事件（第一版，未决 §11-Q7） |
| 会话组件 → 实例组件 | `svc().self().currentInstance()` → `Optional<InstanceAccess>`；`InstanceAccess#component(Class<T extends MatchModeComponent>)` | **只读**；无实例或 `ENDING/SWITCHING` 间隙 → `empty`；**不得缓存实例组件引用越过切换**（现取不缓存） |
| 会话组件 → 实例干预 | 只有 `requestSwitch()` / `requestDissolve()` + 事件 | 等价于实例级 `end()/switchTo()` 的口径 |
| 实例组件 → 会话干预 | 只有原有 `end()` / `switchTo()`；会话级干预**不提供**（模式无权解散会话，第一版） | — |
- 查询类型 token 一律是**接口**（L3 组件类/引擎端口）；引擎侧签名是泛型（`<T extends …Component>`），引擎不认识任何具体组件类——`EnginePurityTest` 不受影响。
- "只读"是**架构纪律 + review 条款**（无法机械强制调用方不碰写方法）；写入 `14-陷阱清单` 与 code review checklist。

### D6 能力标签扩展（模式接入会话能力的硬依赖声明）
- `SessionComponent.Specification#capabilities(String...)`:会话组件在装配时注册能力标签（随 dissolve 摘除;词汇由提供方定义，引擎零字面量——沿用 v3.1 字符串标签口径）。
- `MatchModeMeta.requiredCapabilities` 语义扩展为"进程级标签 ∪ **本会话**会话组件标签"；切换阶段 A2 校验，缺任一 → `REJECTED_BY_TARGET_MODE`，detail 列缺失标签（机制不变，只扩可用集来源）。
- 软硬两挡:软接入 = 实例组件直接 `session().component(X.class)` 判空；硬依赖 = `requiredCapabilities` 声明标签，装配期挡住。

### D7 内核 vs 组件:职责判据表（写入 02 §2.8，作决断一 v4 修订版）
| 判定 | 归属 | 例 |
|---|---|---|
| 不需要跨模式存活 | 实例级组件 | 阶段/计分/队伍/结束判定 |
| 需要跨模式存活，且是**机制/状态权威/切换或交付算法的一部分/可靠性底线** | **SessionService 内核**（不组件化） | 名册数据结构与登记、成员连接态记录、会话状态机、switchMode 两阶段与三级回退、WorldPort 调用时点与引用计数、会话事件总线、dissolve 执行（传送/释放/摘除）、min-dwell 防护 |
| 需要跨模式存活，且是**策略/裁决/聚合/展示** | **会话级组件** | 空场解散策略（第一波）、断线宽限策略（候选）、跨局累计/系列赛（候选）、会话级看板（候选）、会话侧容量裁决（候选） |
- 争议仲裁原则:拿不准时问两问——"它坏了会话会失守底线（名册错/世界漏/切换不原子）吗?"（是 → 内核）；"服务器主想要另一种做法吗?"（是 → 组件）。
- 内核向组件只提供端口与事件;组件向内核只经端口请求（D5 表）。

### D8 会话级出局口（端口落点）
`SessionPort` 提供两个行动口，镜像实例级:
```java
void requestSwitch(MatchModeSelection target, Handoff payload); // 与 switchMode 同一实现,受 min-dwell/重入约束
void requestDissolve(DissolveReason reason);                    // 幂等;仅会话级组件与内核可调(内核本就有)
```
`requestDissolve` 是本版**新增的唯一"组件影响力的面"**——空场策略组件的动作落点；不新增其他影响力端口。

### D9 故障隔离（会话级 quarantine）
- 会话组件在 `update/onEvent` 抛异常 → 记日志（会话 id / 组件 id / 原因）→ 对该组件 `safeStop` + 打标 quarantined（此后跳过其派发）→ 发 `SessionComponentQuarantined`（新增会话事件）→ **会话不解散**，其余组件照常。
- 与实例级 quarantine 的差异及理由:**实例级**隔离 → `end()` → 回退模式（模式坏了有兜底）;**会话级**没有回退目标，解散代价过大——停用单个策略组件是可接受的降级（如空场策略停用 = 行为退回"永不解散"并留日志）。
- 装配期 `awake/start` 抛 → 会话创建失败（响亮，L0 SEVERE；arena 则该竞技场不启动）。

### D10 Handoff 边界修订
- 实例状态仍随 `close()` 全灭；**实例间**跨模式数据仍只走 `Handoff`（不变）。
- 新增合法通道:**跨切换存活的会话级状态可以住在会话级组件里**（这正是本版的目的），随 `dissolve` 全灭。
- README/16.2 硬边界句改为:"实例状态随 `close()` 全灭;跨模式数据只走 `Handoff` 或寄居会话级组件;会话组件状态随 `dissolve` 全灭"。

### D11 第一波迁移:空场策略下放
- `component/session/EmptyArenaComponent`:Spec 构造数据 `after`（空场持续时长）;`start` 订阅 `MemberJoined/MemberLeft`，`update` 维护空场起点，到点 `svc().self().requestDissolve(DissolveReason.EMPTY)`；有成员回归即重置计时。
- 装配:L0 按 `session.topology` —— rotation **不挂**（常驻永不解散）、arena 挂（时长读 `session.dissolve-after-empty-seconds`，键保留，消费者变更为 L0）。
- `SessionPolicy` 中的空场判定/`idleTimers` 空场部分**删除**；连接追踪与宽限 sweep 留在内核（第二波候选，未决 §11-Q1）。
- "不挂 = 默认"原则延续:不挂任何空场组件 = 永不解散（大厅零配置哲学一致）。

## 3. 契约骨架（写入 12-代码骨架.md；执行者照此落盘）

```java
// engine/component/SessionComponent.java —— 会话级组件基类(照抄 MatchModeComponent 纪律)
public abstract class SessionComponent {
    private final String id;
    private final SessionServices svc;                 // 构造期注入,四条件同实例级
    protected SessionComponent(String id, SessionServices services) { /* 校验同 MatchModeComponent */ }
    public final String id();
    protected final SessionServices svc();

    public void awake() {}      // 只解析会话级依赖;幂等;无可见副作用
    public void start() {}      // 订阅/登记/初始化;玩家可见副作用最早在这里
    public void update() {}     // 每 tick,与实例有无无关;禁止阻塞
    public void onEvent(SessionEvent event) {}
    public void stop() {}       // 与 start 严格对称;返回后框架回收登记资源

    public abstract static class Specification<T extends SessionComponent> {
        protected Specification(String descriptorLabel);
        public final Specification<T> requires(Class<? extends SessionComponent> type);
        public final Specification<T> requiresOptional(Class<? extends SessionComponent> type);
        public final Specification<T> capabilities(String... tags);           // ★D6
        public Class<? extends SessionComponent> providedType();              // 默认由泛型实参推导
        public final Snapshot freeze();
        public abstract T create(String id, SessionServices svc);             // 唯一创建点(装配期)
        public record Snapshot(String descriptorLabel, Factory<?> factory,
                Class<? extends SessionComponent> providedType,
                List<Class<? extends SessionComponent>> requiredTypes,
                List<Class<? extends SessionComponent>> optionalTypes,
                Set<String> capabilities) {}
    }
    @FunctionalInterface
    public interface Factory<T extends SessionComponent> { T create(String id, SessionServices svc); }
}

// engine/port/SessionServices.java —— svc 服务集:成员封闭(2)
public record SessionServices(SessionPort self, SessionComponentLookupPort components) {}

// engine/port/SessionPort.java —— 会话自面(端口落点)
public interface SessionPort {
    SessionId id();
    List<SessionMember> members();                     // 只读快照
    long tick();
    AttributeBag attrs();                              // 命名空间 = 组件 id
    SessionEventPort events();                         // 订阅随 stop 回收
    Optional<InstanceAccess> currentInstance();        // ★D5:只读实例访问面
    void requestSwitch(MatchModeSelection target, Handoff payload);   // ★D8
    void requestDissolve(DissolveReason reason);                      // ★D8
    void later(int delayTicks, Runnable task);
}

// engine/port/InstanceAccess.java —— 会话侧只读实例面(★D5;无写口)
public interface InstanceAccess {
    InstanceId id();  String modeId();  long tick();
    List<Participant> participants();
    MatchModeInfoPort modeInfo();
    AttributeBag attrs();                              // 只读约定:仅 get
    <T extends MatchModeComponent> T component(Class<T> type);          // 声明序第一个;无 → null
    <T extends MatchModeComponent> List<T> components(Class<T> type);
}

// engine/port/SessionView.java —— 实例侧只读会话视图(★D5;挂在 InstancePort 上)
public interface SessionView {
    SessionId id();
    List<SessionMember> members();
    AttributeBag attrs();                              // 只读
    <T extends SessionComponent> T component(Class<T> type);            // ★模式接入会话能力
    <T extends SessionComponent> List<T> components(Class<T> type);
}

// engine/port/InstancePort.java —— 唯一修订:新增一行
SessionView session();                                 // 我所属会话的只读视图
```

**装配/派发接线（`SessionServiceImpl` + `EngineTicker`,写入 12 与 11）:**
```
create(spec):
  建 Session 骨架 → SessionComponentRegistry.bind(逐 Spec freeze 快照,id 去重)
  → 按声明序 create(id, sessionServices) → awakeAll() → startAll()
  → 发 SessionCreated → 走首次 switchMode(初始模式)
  （会话组件先于首个实例就绪——首实例的组件才能查到它们）

tickAll(每 tick,每会话;★顺序是规格的一部分):
  ① 会话事务:runPendingSwitch()            （机制,不变）
  ② 当前实例 tick:instance.tick()          （若有实例;派发组件 update,不变）
  ③ 会话组件派发:tickSessionComponents()   （★每 tick 必调,与实例有无无关;逐组件 try/catch → D9 隔离）
  ④ 内核 sweep:断线宽限等                   （机制,不变）

dissolve:
  DISSOLVING → （若有实例）close()
  → 会话组件逆序 stop + reclaimRegisteredResources()      ★新增
  → 成员传送主城 → 释放世界句柄 → 从注册表摘除 → 发 SessionDissolved
```

## 4. 与既有决策的关系（写入 ADR-0004 的"背景/后果"，并修订 ADR-0001）

| 既有决策 | v4 处理 |
|---|---|
| ADR-0001 决策 4"组件只挂实例;不引入会话级组件（避免组件模型翻倍）" | **被取代**。理由变化:当年会话行为只有四件（名册/连接/空场/世界句柄）；v4 有三个新驱动（模式接入会话能力、会话行为可插拔、系统级读实例数据），且会话级行为必须能读取实例数据、按会话装配——内建 + 数据配置已表达不下 |

| ADR-0001 备选方案 B"会话级 + 实例级两层组件"（当年否决） | 当年否决理由"复杂度 vs 收益"在 v4 被重新核算后接受;**以 D7 判据表 + D9 隔离 + 冻结测试**作为复杂度的对冲，写入 ADR 后果段 |
| ADR-0001 决策 1/2（大厅是普通模式、switchMode 一等公民） | 不动 |
| ADR-0002（聚合根零行为 + 引擎纯度） | 不动;引擎仍定义组件契约（现在是**三个契约**:`MatchModeComponent`、`MatchMode`、`SessionComponent`），仍不 import `component/**` |
| ADR-0003（JoinPolicy 下放为组件） | 不动;并被引用为"行为下放"先例（v4 是同一条路走到了会话层） |

## 5. 规则与纪律（写入 02 §2.8 决断与 14-陷阱清单）

1. **决断一 v4 修订版**（替换原文）:组件两级挂载;机制在内核、策略在组件;判据表见 D7;"如果一段行为需要跨模式存活"不再是唯一判据，增加第二问（机制还是策略）。
2. **决断三扩展（状态唯一）**:会话容器（`Session`）不持有会话组件的状态;会话组件是会话级状态的唯一主人并提供强类型读口;实例组件不得写入会话组件，会话组件不得写入实例组件（只读 + 端口，D5）。
3. **新增决断四（跨级只读）**:跨级查询是只读授权;跨级干预只能走端口（`end/switchTo` ↔ `requestSwitch/requestDissolve`）;跨级引用不得跨切换缓存。
4. 命名空间纪律不变:会话 attrs 的命名空间 = 组件 id（`"session"` 保留给内核）。
5. 会话组件不得接触角色桥接（`bridge/role`）;角色接入仍只有 `RoleComponent` 一个落点。
