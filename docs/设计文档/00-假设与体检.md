9. **★A9(v3 新增)**:第三方扩展经由 `MatchModeProvider`(`{ id(); Mode build(); }`)注册——聚合根是 final 类不是接口,Builder 即 SPI(§2.2、§7.2)。第三方组件不开放(与 v2 口径一致),但第三方**可以**给已注册模式补充组件吗?**不可以**——聚合根 `build()` 后不可变,改模式 = 注册一个新 id。这是刻意的:模式即产品,不提供运行期"装饰"入口,杜绝加载顺序地狱。
10. **★A10(v4 新增,本版核心)**:**两级组件挂载**——实例级 `MatchModeComponent`(生命周期随 `MatchModeInstance`,随 `close()` 全灭)与**会话级 `SessionComponent`**(生命周期随 `Session`:create → dissolve,**每会话一份**、跨模式切换存活、随 `dissolve` 全灭;装配来源是 L0 按配置构建的会话组件表,§0.5.5)。**仅两级**:禁止第三级,禁止同一组件类兼任两级(同一行为若要跨级,拆成两个组件、经 A11 只读协作)。
11. **★A11(v4 新增)**:**跨级查询只读、写走端口**——实例组件 ↔ 会话组件的互通面只有只读视图(`SessionView` / `MatchModeInstanceAccess`),对对方产生干预只能走端口(`end()`/`switchTo()` ↔ `requestSwitch()`/`requestDissolve()`);**跨级引用不得跨切换缓存**(会话组件现取实例组件,不缓存越过切换)。"只读"是架构纪律 + review 条款,无法机械强制(落地为陷阱 §14.27/§14.29)。
12. **★A12(v4.1 新增)**:**进程级服务层**——服务(Service)是**进程生命周期**的非组件对象(`onEnable` 装配 → `onDisable` 关停,不随任何 Session/Instance 生灭),经 `ServiceRegistry` **两阶段装配**(`install` 声明 → `seal` 校验+拓扑序创建+启动),经**三通道**(订阅会话事件 / 只读快照 / `SessionService` 受控命令)触达会话,与组件**互不可见**(组件与模式不得 import 服务,服务不得 import `mode/**` 与 `component/**`);组件挂载仍仅两级——服务不是第三级组件,A10 不破。完整变更见同目录 `18-v4.1修正案-进程级服务层与ServiceRegistry`,映射见 §0.5.6。
13. **★A13(v1.1 新增)**:**存在真实的跨 jar 消费者诉求才触发 G2(物理拆分)**——Assumption-driven,不做 hypothetical seam(与 A9"第三方组件不开放"同一判据):形态 A(单 jar 彩排)是默认交付,形态 B(双 jar)仅在**首个真实跨 jar 消费者**(伴随插件或第二宿主)立项后执行(19-D11)。**可推翻它的动作**:伴随插件/第二宿主立项(G2 提前);或长期无跨 jar 诉求(G2 永不触发,形态 A 即终态)。
