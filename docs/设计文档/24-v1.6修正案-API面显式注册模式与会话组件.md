# 24 · v1.6 修正案:API 面显式注册模式与会话组件

> HydroKarbs MiniGame Framework · v1.6 修正案(历史存档;现行修正案见 [25-v1.7修正案-能力标签机制退场与会话组件桥接.md](25-v1.7修正案-能力标签机制退场与会话组件桥接.md);历史存档 17~23 见各文件)
> 变更指示(非设计章节):本修正案执行**注册通道的显式化收敛**——**模式与会话组件改经 `MiniGameApi` 显式注册**,跨插件 ServicesManager 提供方通道退场:①**显式注册四法**——`registerMode(Plugin, MatchModeProvider)` / `unregisterMode(Plugin, modeId)` / `registerSessionComponents(Plugin, specs)` / `unregisterSessionComponents(Plugin)` 进冻结面(15 → **19 法**,API_VERSION 4 → 5),注册期「启动期响亮 / 运行期事件通道不上抛」双口径合一为响亮(显式调用方可捕获,原「事件回调抛异常中断整轮派发」的顾虑随通道消失);②**SPI 提供方通道退场**——`SessionComponentProvider` 接口删除、`ProviderServiceListener` 整体删除,`MatchModeProvider` 降格为 `registerMode` 的载荷类型(`MatchModeRegistry#discover()` 的 ServiceLoader 本 jar 半边保留);注册时序反转:第三方**必须 `depend` 框架**、`load(MiniGameApi)` 后在 onEnable 显式登记,原「先启补收录」场景(框架晚启后补扫既有注册服务)随之退役;③**disable 兜底四族**——`ProviderUnloadListener` 对能力标签/显式模式/注册式地图/会话组件贡献四族按提供方摘除(模式族新增),摘除回退编排自原事件监听器迁入 api 层,失败语义与守卫不变量**一寸不动**。判据与 22-D1/D3 同源:**同一能力只保留一份口径**(One-Version Rule 落面)——注册不再有「ServicesManager 被动半边 + api 显式半边」的双簿记与双失败语义。决策记录见 [docs/adr/0012-explicit-api-registration.md](docs/adr/0012-explicit-api-registration.md)。
> 验收追加 **★59**(编号体系沿用 §16.2,只增不改不重排;框架/玩法两线同一套):显式注册面——四法语义(响亮闸 / 只摘自己的 / 摘除回退 / 幂等)+ SPI 半边清零(api 编译面收窄;ServicesManager 上不再有 MatchModeProvider/SessionComponentProvider 注册)+ disable 兜底四族(§5)。
> 基线:v1.5。本修正案为**破坏性收敛但零触碰引擎内部机制**:删除公共接口 `SessionComponentProvider` 是定义上的破坏性变更,必升 `API_VERSION`(4 → 5,§1-D4);会话 / 切换 / 两级挂载 / 三通道 / 世界 / 服务层零改动;摘除回退编排与 disable 兜底(14.38)为**语义原样迁移**——只换承载点(事件监听器 → api 层),不改任何失败语义与守卫语义。既有架构断言族(★1~★58)零放宽;唯一允许的断言更新 = ★19/★44 冻结快照随 v5 面**合法重录**(FROZEN 19 行、BASELINE 增删行,以本修正案 §3 契约骨架为唯一基线)——冻结测试即架构,重录须有修正案背书,本次即背书。

## 0. 一页摘要

**变更(显式化收敛,四条决策)**:

①**D1 显式注册四法(注册面收编进 api)**:冻结面新增四法(§3 实签)。`registerMode` **注册工厂,不是注册成品**(§13.4)——注册闸(build → verifyDependencies → id 查重)**全响亮**:坏声明 / 依赖失败 / 重复 id 原样抛给调用方,onEnable 注册失败 = 拒载信号;成功返回 `MatchModeInfo` 快照并进 `modes()` 目录。`registerSessionComponents` 同响亮:干跑合并校验(组件 id 查重 / 必需依赖)失败上抛,失败不留半收录态;同一提供方重注册 = 幂等重收录(旧条目先摘再干跑)。归属簿记 `modeClaims`(api 层伴生,镜像 `capabilityClaims` 先例)+ **「只摘自己的」守卫**:`unregisterMode` 越权(含本 jar 出厂模式)响亮拒、id 不存在幂等 no-op。

②**D2 SPI 提供方通道退场 + 依赖反转**:`SessionComponentProvider` / `ProviderServiceListener` 删除;`MatchModeProvider` 降格为 `registerMode` 载荷(接口本体、engine/mode 包位与 07 §7.2 白名单资格零改动);`MatchModeRegistry#discover()` 只剩 ServiceLoader 本 jar 半边(清单现存无工厂——框架不设出厂模式,21-D3)。注册时序自「框架被动监听事件」反转为「消费方主动登记」:`depend: [Hydrokarbs]` 硬依赖 + `onEnable` 首行 `load(MiniGameApi.class)` + 版本检查(14.36)+ 依次显式登记;原「先启补收录」兼容场景随依赖反转自然退役——depend 保证框架先启,时序倒挂不复存在。

③**D3 disable 兜底四族与摘除回退语义原样迁移**:`ProviderUnloadListener`(PluginDisableEvent)四职责块——①能力标签(D8 原样:多提供方主张同标签,摘后补回仍被主张者);②显式模式(**新增族**):逐 id 走与显式 `unregisterMode` 同一回退编排;③注册式地图(20-D4 原样:正用拒绝 = 保留并 WARN);④会话组件贡献(D14 原样:后续会话不再合并,已装配会话不受影响)。摘除回退编排(`runRemovalFallback`)自原 `ProviderServiceListener` 迁入 `MiniGameApiImpl`——**编排逻辑一份不写两处**(显式摘除与兜底摘除同一函数):`session.fallback-mode` 已配置且已注册 → force 切换回退(豁免 min-dwell);fallback 空 / 未注册 → `FALLBACK_DISSOLVE` 解散;回退被拒(`SWITCH_IN_PROGRESS`)WARN 放弃不自旋;切换间隙(无实例)会话不匹配、不重复编排。

④**D4 API_VERSION 4 → 5(破坏性)+ 迁移口径**:删公共接口 = 破坏性变更必升版本;双轨过渡**取 0**(22-D2 同款:One-Version 不允许长期双轨,消费面随本窗口一并迁移,git 实况可查)。消费方保护面不变:14.36 首行版本拒载。迁移口径:**第三方从「注册服务」改为「load 后调四法」**——`depend: [Hydrokarbs]` → onEnable 首行 `load(MiniGameApi.class)` + `API_VERSION < 5` 拒载检查 → 原 `register(MatchModeProvider.class, …)` 改 `api.registerMode(this, factory)`、原 `register(SessionComponentProvider.class, …)` 改 `api.registerSessionComponents(this, specs)`;onDisable 显式反注册(防御性;兜底仍在)。

**不动**:引擎内部机制(会话 / 切换 / 两级挂载 / 三通道 / 世界 / 服务层)零改动——摘除回退走 §3.2 既有二级回退链与 `FALLBACK_DISSOLVE` 码表语义原样;`SessionRecipe` record 形状、合并序(已收录贡献(注册序)→ recipe.extraComponents)与装配期响亮失败语义全部原样;能力标签(D4/D8)与地图注册(20-D2~D5)的既有语义、守卫与 reload 口径零触碰;`config.yml` 装载零改动(`session.fallback-mode` / `min-dwell-ticks` / `disconnect-grace-seconds` 三节律键原样——fallback-mode 自此成为摘除回退编排的配置源,§14.21 惰性读口);`MatchModeProvider` 接口本体与 A9 三限制原样;07 §7.3「第三方查询会话组件实例维持不开放」不动(19-§7-Q5);★1~★58 断言零放宽(仅 ★19/★44 快照重录,见头部注)。

## 1. 决策 D1~D4

### D1:显式注册四法(注册面收编进 api;响亮收录闸)

**决策**:`MiniGameApi` 冻结面新增四法(实签转写见 §3):

| 法 | 语义要点 |
|---|---|
| `MatchModeInfo registerMode(Plugin provider, MatchModeProvider factory)` | 注册工厂不注册成品(§13.4);注册闸 **build(配置) → verifyDependencies → id 查重**全响亮抛(委托 `MatchModeRegistry#registerProvider`,失败不留半注册态);成功返回快照并进 `modes()` 目录,可被 `switchMode` 选中;注册点打版本协商行(D7/14.36:记录 `requiredApiVersion()`——原事件通道收录打点随通道迁入本方法) |
| `void unregisterMode(Plugin provider, String modeId)` | 只准摘自己注册的 id(越权含本 jar 出厂模式 → `IllegalStateException` 响亮拒;id 不存在 → 幂等 no-op);摘除 = 注册表纯目录摘除(`MatchModeRegistry#unregister`)+ 摘除回退编排(§3.2 二级,见 D3) |
| `void registerSessionComponents(Plugin provider, List<SessionComponent.Specification<?>> specs)` | D14 通道一的显式面(07 §7.3「受限开放」):干跑合并校验(scratch 注册表复用真实装配算法——bind 查重 + verifyDependencies,**装配算法只有一份**)失败响亮上抛;失败不留半收录态;同一提供方重注册 = 幂等重收录(旧条目先摘再干跑);通过后所有后续 `createSession` 合并其贡献(注册序);**模式仍无权贡献、无运行期增删**(v4-D4 不变) |
| `void unregisterSessionComponents(Plugin provider)` | 摘除本提供方全部贡献(幂等——未注册 no-op);后续会话不再合并,已装配会话不受影响(无运行期拆卸,随 dissolve 自然消亡,D14) |

**理由**:①**注册期双口径合一为响亮**——分歧根源是「事件回调抛异常会中断整轮派发」,故原运行期事件通道设计为 SEVERE 拒收录、不上抛;显式调用方可捕获,该顾虑随通道消失,坏注册物在 onEnable 就地失败 = 拒载信号(与能力/地图自 7.5 起的实况口径同构)。②**模式收 provider 不收成品——cfg 生命周期理由**:聚合根由框架以自己的配置源 `build(cfg)` 产出(`modes/<id>.yml` 的读取 / 缺省 / 生命周期归框架,§10.2/§15.2 铁律 1;工厂不持成品状态),交成品则模式声明从此脱离框架配置面;`MapDefinition` 纯静态值无配置注入,交成品安全(20-D1)——两类注册物的差异是**配置生命周期归属**,不是孰优孰劣,故模式注册保持工厂形态并原样沿用 §13.4 依赖白名单与 A9 三限制。③**归属簿记与「只摘自己的」守卫**:api 层伴生 `modeClaims`(提供方身份键 → 其注册的模式 id 集;身份键语义按实例,7.2 要点 4 同款)——`unregisterMode` 只能摘本提供方主张的 id,越权即响亮拒;守卫点在 api 层(注册表 `unregister` 保持纯目录口径,不认识提供方,离线可测)。④与 22-D1 同构:注册作为一项能力,其口径应该单行——四法即「模式注册」「会话组件贡献」两项能力各自的「进」「出」两口,语义在 §3 一处讲完。

### D2:SPI 提供方通道退场 + 依赖反转(先启补收录退役)

**退场清单**:

| 退场项 | 说明 |
|---|---|
| `api/SessionComponentProvider` 接口 | 删除(D14 通道一的 SPI 形态;贡献能力改经 `registerSessionComponents` 显式面——边界不变式原样,只换承载点) |
| `listener/ProviderServiceListener` | 整体删除(`ServiceRegisterEvent` / `ServiceUnregisterEvent` 收录 / 摘除半边的唯一承载;其摘除回退编排迁入 api 层,D3) |
| `MatchModeRegistry#discover()` 的 ServicesManager 半边 | 退场——双发现收敛为 ServiceLoader 本 jar 半边(引擎零 Bukkit 静态调用的离线可测性不受损,反而更纯);「运行期 registerProvider 不上抛」的旧口径随之失效 |
| 「先启补收录」场景 | 退役(框架晚启后补扫 ServicesManager 既有注册物的兼容路径不再存在,也不再需要——见依赖反转) |

**`MatchModeProvider` 转载荷**:接口本体(`id()` / `build(cfg)` / `requiredApiVersion()` 默认方法)、engine/mode 包位、07 §7.2 白名单资格**零改动**;变化只在注册路径——从「第三方 register 到 ServicesManager、框架事件收录并 build」降格为「`registerMode` 的载荷类型」(A9 三限制与第三方依赖白名单语义跟着接口走,一份不写两处)。

**理由(One-Version,22-D1/D3 同源)**:注册同一能力此前有两份口径——ServicesManager 被动半边(双失败语义、事件时序、先启补收录)与显式半边(能力/地图已先行落此)。通道并存让每次讲注册都要讲两遍:收录打点、失败语义(响亮 vs SEVERE 拒收录)、摘除路径(事件 vs 显式)、先启补收录的特殊时序注——每处都是无限期维护的解释义务;而显式半边已承载全部场景(第三方模式 / 贡献全部可经 api 面,examples/TheirPlugin 实测),SPI 半边不再提供显式半边所没有的能力——按 22-D1 判据「同一能力两份口径,收敛优于并存」,删除优于悬挂。

**依赖反转**:注册时序自「框架被动监听」反转为「消费方主动登记」。第三方插件 `plugin.yml: depend: [Hydrokarbs]`(形态 B 纪律,19 号已定,自此从纪律变**前提**——softdepend 不再足够,api 缺席即 `load` 返回 null = 拒载,14.36);`onEnable` 首行 `getServer().getServicesManager().load(MiniGameApi.class)` → 版本检查 → 依次显式登记(`registerMode` / `registerSessionComponents` / 解包 → `registerMap` / `subscribeSessionEvents`)。原 SPI 通道不要求 depend(softdepend 即可,框架会扫描 ServicesManager),v1.6 起 depend 是硬前提;「先启补收录」场景(框架因加载序晚启、第三方先启已注册服务)随依赖反转自然退役——depend 保证框架先于第三方启动,时序倒挂不复存在,补收录的特殊时序注(07/12/13 三处)随之消解。

### D3:disable 兜底四族与摘除回退语义原样迁移

**决策**:`ProviderUnloadListener`(`PluginDisableEvent`,`EventPriority.NORMAL`)是四族注册物**唯一**的框架侧兜底监听(原事件半边退役后无第二监听器),四职责块:

| 族 | 落点 | 语义 |
|---|---|---|
| ① 能力标签 | `unregisterCapabilitiesOf`(D8,7.5 决策 5 原样) | 逐标签摘除,多提供方主张同一标签时补回仍被主张者(「可用 ⟺ 至少一个提供方主张」不变式) |
| ② 显式模式 | `unregisterModesOf`(**新增族**) | 逐 id 走与显式 `unregisterMode` 同一回退编排——会话回退不因插件下线而缺位(§13.4) |
| ③ 注册式地图 | `unregisterMapsOf`(20-D4 原样) | 逐张走 `unregisterMap` 同一守卫:正用拒绝 = 保留并 WARN(摘除被拒是特性),不因插件下线强拆存活对局 |
| ④ 会话组件贡献 | `unregisterSessionComponentsOf`(D14 原样) | 后续会话不再合并;已装配会话不受影响(无运行期拆卸,随 dissolve 自然消亡) |

摘除回退编排(`runRemovalFallback`)自原 `ProviderServiceListener`(7.2 施工起承载于该监听器)迁入 `MiniGameApiImpl`,**语义原样、只换承载点**:对每个当前模式 id ∈ 被摘集的存活会话——`session.fallback-mode`(经 `fallbackModeId` 读口惰性取,不写死任何 id,§14.21)已配置且已注册 → 发起 force 切换回退(豁免 min-dwell,§3.5;`MatchModeSelection(fallback, empty, force=true)`);fallback 空或未注册 → 直接解散(`DissolveReason.FALLBACK_DISSOLVE`,§3.2 二级;21-R3 空值语义同款);回退被拒(`SWITCH_IN_PROGRESS`)WARN 放弃不自旋(§14.17),执行由节拍器下一 tick 驱动;切换间隙无实例(空)的会话不匹配、不重复编排。**编排逻辑一份不写两处**——显式 `unregisterMode` 与兜底 `unregisterModesOf` 调同一函数。

**理由**:①兜底职责自 19-D8 建立起就是「提供方插件 disable 时框架代行摘除」——承载点是 `PluginDisableEvent`,从来不是 `ServiceUnregisterEvent`(7.5 施工决策 5 即已落 PluginDisableEvent;原设计注的 ServiceUnregisterEvent 半边只服务 SPI 注册物,随通道退场自然消亡)——四族化是同一判据的自然延伸,不是新机制。②编排迁入 api 层镜像既有职责分离先例(`MatchModeRegistry#unregister` 纯目录、编排归调用方;贡献收录表同理)——engine 保持零 Bukkit 依赖,编排可离线测试(`ThirdPartyModeRegistrationTest` ④ 组即端到端用例);③消费方显式反注册(onDisable)仍是纪律,兜底是防线不是替代(14.38 原文不动)。

### D4:API_VERSION 4 → 5(破坏性:删公共接口)+ 迁移口径

**决策**:`MiniGameApi.API_VERSION = 5`(v1.0 = 1;v1.1 = 2;v1.2 = 3;v1.3 维持 3;v1.4 = 4;**v1.6 = 5**)。删除公共接口 `SessionComponentProvider` 是**定义上的破坏性变更**,07 §7.2 版本协商纪律明文「破坏性变更必须升 API_VERSION」。双轨过渡**取 0**:不开弃用过渡窗(备选与权衡见 ADR-0012;理由与 22-D2 逐字同构——过渡期收益仅在存在无法随窗口升级的存量消费者时成立,当前消费面 = SHDF 宿主与测试/示例插件,随本次施工窗口一并迁移,git 实况可查;One-Version Rule 不允许长期双轨,与其短暂双轨不如一次付清)。**消费方保护面不变**:14.36 的 onEnable 首行版本检查 + 拒载不崩服,在 v5 下照常工作(旧消费方拒载并给出明确日志;SPI 形态的存量代码则直接编译不通过——编译期即暴露,比运行期拒载更早)。

**迁移口径(第三方:从注册服务 → load 后调四法)**:

1. `plugin.yml` 写 `depend: [Hydrokarbs]`(softdepend 不再足够);
2. `onEnable` 首行:`api = getServer().getServicesManager().load(MiniGameApi.class)`;`api == null || api.API_VERSION < 5` → SEVERE + `setEnabled(false)`(14.36);
3. 原 `getServicesManager().register(MatchModeProvider.class, factory, this, ServicePriority.Normal)` → `api.registerMode(this, factory)`(响亮抛 = 拒载信号);
4. 原 `getServicesManager().register(SessionComponentProvider.class, provider, …)` → `api.registerSessionComponents(this, specs)`;
5. `onDisable` 显式反注册(`unregisterMode` / `unregisterSessionComponents`——防御性纪律;框架 PluginDisableEvent 兜底四族仍在,见 D3)。

## 3. 契约骨架(MiniGameApi v5 面,19 方法)

> **以下为现行 `src/main/java/com/hydrokarbs/api/MiniGameApi.java` 的实际签名转写(2026-10-27,不得凭记忆)**——方法名、参数与返回类型逐字对应该文件(仅省略 javadoc 正文;注解要点为该文件头部注与各方法注的摘要)。★19(`MiniGameApiSurfaceTest`)19 行 FROZEN 清单与 ★44(`ApiSurfaceTest`)BASELINE 快照以此为基线重录(已随施工窗口完成:BASELINE 增 MiniGameApi 四行、SessionComponentProvider 两行出册,`MatchModeProvider` 三行保留)。

```java
package com.hydrokarbs.api;

/** 本框架的对外公共面。经 Bukkit ServicesManager 暴露(07 §7.1/§7.2)。
 *  ★v1.6 显式注册收敛(24 号):API_VERSION = 5,冻结面 15 → 19 方法 = 查询 3 +
 *  控制 1 + 建会话 1 + 成员 2 + 订阅 1 + 能力 2 + 地图 2 + 模式显式注册 2 +
 *  会话组件显式注册 2 + 目录 3;ServicesManager 提供方通道退场
 *  (SessionComponentProvider SPI 删除为破坏性变更,未设双轨窗口)。
 *  引擎契约类型(SwitchResult/MatchModeSelection/Handoff)直接 import 自
 *  engine.session,不复制;apiDependsOnlyOnEngine 放行(§16.2)。 */
public interface MiniGameApi {

    /** API 面版本常量(★v1.1-D7 版本协商;只增不减):v1.0 = 1;v1.1 = 2;
     *  v1.2 = 3;v1.3 维持 3;v1.4 = 4(两参 createSession 重载删除);
     *  v1.6 = 5(显式注册收敛:模式/会话组件经 registerMode/registerSessionComponents
     *  注册,ServicesManager 提供方通道与 SessionComponentProvider SPI 删除)。
     *  消费方 onEnable 首行检查 api == null || api.API_VERSION < REQUIRED
     *  → SEVERE + setEnabled(false)(拒载不崩服,14.36);框架 onEnable 日志输出版本。 */
    int API_VERSION = 5;

    // ── 查询(不可变快照;现取不缓存,14.31 同款纪律;主线程调用) ──────────────
    Optional<SessionInfo> sessionOf(UUID player);
    Optional<SessionInfo> session(String sessionId);
    List<SessionInfo> sessions();

    // ── 控制(与 /sm 命令同权,§7.1) ────────────────────────────────────────
    /** 切换某会话的模式(§3.2 受控暴露):id 不在注册表 → Rejected(MODE_NOT_FOUND);
     *  其余拒绝经引擎三级回退管线透传;空白 id / null target → future 异常完成;
     *  future 永不悬挂。任意线程发起,Impl 内部回主线程,future 在主线程完成。 */
    CompletableFuture<SwitchResult> switchMode(String sessionId, MatchModeSelection target,
                                               Handoff payload);
    /** 创建会话(★v1.1-D14 通道二):合并序 = 已收录贡献(注册序)→ recipe.extraComponents
     *  (装配点唯一不变;模式仍无权贡献);装配闸响亮抛,不留半装配态;随 dissolve 全灭(★52)。
     *  公共 API 建会话唯一形态(★v1.4)。主线程调用。 */
    SessionInfo createSession(SessionRecipe recipe);

    // ── 成员操作(★v1.1-D2;★42;主线程调用) ─────────────────────────────────
    /** 引擎既有裁决原样透传(不存在 / 解散中 / 入场拒绝 → Rejected;已在册 → 幂等重入)。 */
    JoinResult joinSession(String sessionId, UUID player);
    /** 不在任何会话 = no-op(幂等);QUIT = 断线宽限在册 / KICK = 立即移除。 */
    void leaveSession(UUID player, LeaveReason reason);

    // ── 会话事件订阅(★v1.1-D3;★43) ────────────────────────────────────────
    /** 返回句柄,close() 注销(句柄只在插件实例字段中持有,onDisable 显式 close,14.38);
     *  订阅者异常被隔离;单会话内事件有序,跨插件订阅者间不承诺送达顺序。 */
    EventSubscription subscribeSessionEvents(Consumer<SessionEventView> handler);

    // ── 能力标签(★v1.1-D4;主线程调用) ─────────────────────────────────────
    /** 幂等;标签空白响亮抛;提供方插件 disable → 框架 PluginDisableEvent 兜底摘除(14.38)。 */
    void registerCapability(org.bukkit.plugin.Plugin provider, String tag);
    Set<String> capabilities();

    // ── 地图注册(★v1.2;★54;守卫语义 20-D3/D4 不变;主线程调用) ───────────────
    /** 交成品不交工厂(20-D1);注册期校验响亮抛(重复 id 点名先到者/tags/模板目录存在性)。 */
    MapInfo registerMap(org.bukkit.plugin.Plugin provider, MapDefinition map);
    /** 正用摘除被拒(detail 点名会话,20-D4);幂等:已不在目录 = no-op;disable 兜底摘除。 */
    void unregisterMap(org.bukkit.plugin.Plugin provider, String mapId);

    // ── 模式显式注册(★v1.6;24 号:ServicesManager 提供方通道退场) ─────────────
    /** 注册工厂,不是注册成品(§13.4;cfg 生命周期归框架,§10.2);注册闸全响亮
     *  (坏声明/重复 id 原样抛,onEnable 失败 = 拒载信号);A9 三限制原样。主线程调用。 */
    MatchModeInfo registerMode(org.bukkit.plugin.Plugin provider, MatchModeProvider factory);
    /** 只准摘自己注册的 id(越权含出厂模式 → 响亮拒;不存在 → 幂等 no-op);摘除后
     *  执行摘除回退编排:fallback-mode 已配置且已注册 → force 切换(豁免 min-dwell);
     *  否则 FALLBACK_DISSOLVE 解散;回退被拒 WARN 放弃不自旋(§14.17)。主线程调用。 */
    void unregisterMode(org.bukkit.plugin.Plugin provider, String modeId);

    // ── 会话组件显式注册(★v1.6;D14 通道一的显式面) ─────────────────────────
    /** 宿主级会话策略贡献;模式仍无权贡献(v4-D4)、无运行期增删;干跑合并校验
     *  失败响亮上抛(注册闸只有一份);同一提供方重注册 = 幂等重收录。主线程调用。 */
    void registerSessionComponents(org.bukkit.plugin.Plugin provider,
                                   List<SessionComponent.Specification<?>> specs);
    /** 幂等;后续会话不再合并,已装配会话不受影响(随 dissolve 自然消亡,D14)。主线程调用。 */
    void unregisterSessionComponents(org.bukkit.plugin.Plugin provider);

    // ── 目录(顺序 = 注册序,不排序不过滤——14.21「大厅特判」反弹规避) ─────────
    List<MatchModeInfo> modes();
    List<MapInfo> maps();
    Optional<MatchModeInfo> mode(String modeId);
}
```

配套类型(零改动,重申):`MatchModeProvider`(engine/mode;接口本体零改动,**降格为 `registerMode` 载荷**——07 §7.2 白名单资格与 A9 三限制不变);`SessionComponent.Specification`(引擎既有描述符);`SessionRecipe`(record:initialModeId/initialMapId/mapPool/extraComponents + 便捷工厂 `SessionRecipe.of`);快照族 `SessionInfo`/`MatchModeInfo`/`MapInfo`/`SessionEventView` 与 `EventSubscription` 原样。**退场类型**:`SessionComponentProvider`(公共接口,删除——存量实现编译不通过,迁移见 §1-D4)、`ProviderServiceListener`(内部监听器,删除)。`MiniGameApiImpl` 的 L0 装配面(`unregisterCapabilitiesOf`/`unregisterModesOf`/`unregisterMapsOf`/`unregisterSessionComponentsOf`)不在冻结面,仅供兜底监听调用(§1-D3)。
