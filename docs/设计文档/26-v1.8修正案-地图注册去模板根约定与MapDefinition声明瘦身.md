## 1. 决策 D1~D4

### D1:模板寄居约定退场(注册方直交声明路径;框架不再派生模板根)

**决策**:世界目录的落点完全由注册方声明;框架对路径只做「存在且为目录」的唯一校验:

| 维度 | v1.7 及之前(模板寄居) | v1.8 起(声明按路径直交) |
|---|---|---|
| 落盘位置 | 框架数据目录 `maps/templates/<mapId>/`(20-D2 约定:注册方必须按框架文件系统布局摆) | **注册方自选任意落点**(构造期规范化为绝对路径入库,构造后不再重解析) |
| id 服务 | id 字段即目录名(约定驱动:`templates/<id>` 以 id 反查路径) | id **派生** = 声明目录名(路径先行, id 随之) |
| 注册校验(20-D3 延续,响亮抛) | id 查重/tags/模板目录存在性(`maps/templates/<id>/` 缺失拒绝) | **声明路径存在且为目录**(`Files.isDirectory`,缺失/非目录同一闸,消息带完整绝对路径)+ 同路径查重(id 派生同源,§1-D3 问一) |
| 框架侧路径知识 | `MapRegistry(Path templatesRoot)`(v1.4 收敛后的构造口)+ 对 `templates/<id>` 的目录拼装 | **零模板根**——`MapRegistry` 公开构造唯一 = 无参(反射守卫);`HydrokarbsAssembly` 无任何模板根派生 |
| acquire 缺模板 | 缺模板目录 → A6 失败路径(§3.7 规则表「模板」行) | 缺声明目录 → 同一失败路径(future 异常完成,不降级)——复制源恒为声明路径 |

**理由**:①**耦合不对称**——`maps/templates/` 是框架数据目录的布局决定,机制收益为零(校验只用得上「目录在不在」,用不上「在框架目录下」);注册方解包世界目录到**自己的数据目录**即地缘自洽,不必越到框架目录摆位。②20 §6-Q1 登记「是否需要显式模板路径字段——出现多模板同图/外部模板源诉求再加」的真实诉求路径在 v1.4(文件通道退场)后必然到来:每个注册方有自己的落点,框架再无单一约定根可反查——直交是 Q1 的存量解,不是新机制。③响亮纪律收敛:14.39 时序纪律(注册前落盘)在两口径下同构,本裁决把它改写为「路径已就位」的一般化表述,校验点在注册口不变(零新增机制)。

### D2:`MapDefinition` 声明瘦身((worldDirectoryPath, metaAttributes) 两分量)+ AttributeBag 三口径

**决策**:声明收缩为 record `(Path worldDirectoryPath, AttributeBag metaAttributes)`,原 **id/displayName/tags/bounds/spawns/regions/interactPoints/metadata/resetStrategy** 八分量全删(id 退场为 `#id()` 派生,见 D3);`map/` 包内仅服务于旧结构件的 **Bounds/RegionSet/NamedRegion/SpawnPoint/InteractPoint** 四类机制件整体删除。配套 `AttributeBag` 三口径(定案语义):

| 口径 | 决策 | 机制落点(现行实签) |
|---|---|---|
| ① 声明级专用写口(不放开组件 set 断言) | 声明词料出生走 `MetaAttributes` 门面(`set`,约定键 + 值递归不可变拷贝)或 `AttributeBag#declaration(Map)` 整表构造;**`AttributeBag#set` 的「仅组件」栈断言与命名空间断言原样、不放开**——map 包不为声明词料开任何组件写口或关闭断言的口子 | `AttributeBag#declaration` 出生即无组件授权表(`AttributeBag.java:122`);泄漏到组件手里也写不进(set 断言 `AttributeBag.java:58-72` 拦下),天然只读;`namespaceCheckEnabled` 开关对组件路径执法原样 |
| ② 注册期冻结与注册方脱钩 | `MetaAttributes#frozen()` 落袋后门面再改不影响落袋产物;`MapDefinition` 构造期 `AttributeBag#copyOf` 再收一道**双保险**——注册后注册方手里的门面/bag 再改不影响已注册声明 | `MapDefinition.java:38`(`copyOf`)+ `MapRegistryTest` 脱钩断言族(`registeredDeclarationIsDecoupledFromRegistrarFacadeAndBag`) |
| ③ 声明级生命周期 | 声明 bag 不参与实例 attrs/参赛者 attrs 的 `close()` 销毁链(§2.7「加严①」口径无涉);随 `MapRegistry` 目录条目存亡——`unregisterMap` 摘除后无从复得;volatile 快照替换不改持旧引用方的值(record 不可变) | `MapRegistry` 快照语义原样;无历史簿记(摘除即存亡终点) |

**理由**:①「声明字段持续膨胀、消费面只有三样」的直接裁剪——框架对地图的全部消费 = `acquire(map)`(世界从路径来)+ 约定键读口(tags/resetStrategy)+ id 簿记;出生点/区域/交互点是**模板数据本身**(副本里自带,玩法组件按需直读世界),框架历年零消费面(删除自证:map/ 包现行文件 = MapDefinition/MapRegistry/MetaAttributes 三件)。②门面 `MetaAttributes` 统一持有约定键词汇——写入方与读方同源,散串不出现(与 Handoff 键随主人同款纪律);随声明瘦身的不是能力而是**表单形状**。③三口径是「组件断言不为一类调用方放宽」的守恒裁决:声明级走新出生口独立收口,组件断言面零改动(`AttributeBag#set` 行为一字不变,`ComponentResolution`/命名空间断言族零触碰)。

### D3:三问裁决(三问 = id 从哪来 / ResetStrategy 放哪 / tags 放哪 + MapInfo 视图怎么办)

**问一(id 从哪来)→ 路径派生**:地图 id = 声明目录名(`MapDefinition#id()`);**查询/副本命名/钉图键三同一源**——目录查重(同一路径规范化后再注册必撞、同名异父目录同样撞,`IllegalStateException` 点名先到者及其提供方、先到者保留)、世界副本命名(`instanceName = map.id() + "-" + 会话短码`,`deleteCopyDir` 路径形态断言同基准)、`SessionRecipe#initialMapId` 钉图与 `MapInfo#id` 快照键全走同一字符串。**替代(显式 id 字段保留)否决**:双真源(显式 id + 目录名)存在漂移面——目录改名而 id 不动,则查重键与复制源的对应关系凭空出现第二种解释;单真源 = 派生,20 §6-Q1 的「显式模板路径字段」诉求被本裁决的整路径直交一并吸收。
**问二(ResetStrategy 放哪)→ 约定键 `map.reset-strategy`**:强类型分量删除,枚举类型与两枚值(REUSE_DIRTY/TEMPLATE_RESTORE)原样、**缺省 REUSE_DIRTY 语义不变**(未声明 = REUSE_DIRTY——23 号的复用窗口 = 会话生命周期闭环、A6/释放/归零处置语义全部原样);`WorldHandle#reset` 值来源改端口按约定键解出(`MetaAttributes#resetStrategy` 读口,单一缺省点)。**替代(全删策略词汇)否决**:静默改语义——TEMPLATE_RESTORE 的破坏性玩法处置是既有冻结语义(★58),「缺省不变」是红线。
**问三(tags 放哪 + MapInfo 视图怎么办)→ 约定键 `map.tags` + 视图收缩**:标签走约定键(`MetaAttributes#TAGS`,缺省空集 = 不被按标签选中,A3 过滤逻辑与 20-D3 口径不变);`MapInfo` 收缩为 `(id, tags, resetStrategy)`——tags 直接来自约定键、resetStrategy 以 `name()` 进快照(**枚举不进冻结面**,§0.5.3 末行同款理由);`displayName`/`world` 分量删除——框架零消费面(展示属宿主自持数据、声明文件系统路径不进冻结面快照,instanceName 语义归句柄)。
