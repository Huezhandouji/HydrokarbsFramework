## 0. 一页摘要

**变更**:①框架独立为插件 `HydroKarbs`(engine/api/bridge 通用件/component 通用件/service 参照件/map/data/listener 通用件/command/render/util),玩法成为消费插件(SHDF:`mode/*`、`bridge/role`、私有组件、玩法命令/监听,`depend: [HydroKarbs]`);②`MiniGameApi` 面扩充(成员操作 join/leave、会话事件订阅、能力标签注册、**会话组件贡献 SPI(D14)**——补齐跨 jar 编排/感知/会话定制的全部缺口);③API 编译面白名单冻结与版本协商;④加载/卸载顺序与第三方组件信任边界;⑤双形态交付(单 jar 彩排 → 双 jar 物理拆分,两道闸门)。

**不动**:引擎内部机制(会话/切换/世界/持久化/三通道/svc 冻结/两级挂载)零改动;`ServiceRegistry` 与服务三通道原文保留——**服务不经 `MiniGameApi`**(见 D2 注、陷阱 14.37)。

**交付顺序**:两道闸门。**G1(API 面扩充,单 jar 可承载)**——先补 API 面并在单 jar 内按跨 jar 纪律"彩排";**G2(物理拆分)**——G1 全绿且出现首个真实跨 jar 消费者(伴随插件或第二宿主)后执行工程拆分。理由:过早物理拆分会把 API 面的每个瑕疵固化成二进制契约(Hyrum 定律);先在单 jar 内把边界守成铁的,拆分只是换打包方式。

## 1. 术语与产物形态

| 术语 | 定义(指示同步入 CONTEXT.md) |
|---|---|
| **框架插件(Framework Plugin)** | 独立插件 `HydroKarbs`:L2 引擎 + api/ + L1 通用桥(config/world/persistence)+ L3 通用组件 + L5 数据 + 通用 listener/command/render。一个 Bukkit 插件,一个主类 `HydroKarbsPlugin`(机制上仍恰有一个主类,§12.1 不变) |
| **玩法插件(Gameplay Plugin / 宿主插件)** | 消费框架的插件(如 SHDF):`MatchModeProvider` 模式工厂、私有组件、宿主桥接(如 `bridge/role`)、玩法命令与监听。`plugin.yml: depend: [HydroKarbs]` |
| **伴随插件(Companion Plugin)** | §13.9 案②的既有形态,本修正案起拥有完整执行权(经扩充后的 `MiniGameApi`) |
| **API 编译面(API Surface)** | 玩法/伴随插件 compileOnly 依赖框架 jar 时**允许 import 的白名单包集**(D6);由 `ApiSurfaceTest` 冻结,与 `MiniGameApiSurfaceTest`(★19 方法集冻结)互补 |
| **API_VERSION** | 框架 API 面的版本常量(D7);v1.0 = 1,v1.1 = 2 |
| **双形态交付** | 形态 A(单 jar,现状:框架+宿主同 jar)+ 形态 B(双 jar);同一套源码与验收,产物不同(D11) |

产物边界(形态 B):

```
HydroKarbs/            框架插件 jar(框架线产物)
  engine/ api/ bridge/{config,world,persistence}/ component/(除 role)/
  service/(GlobalLedger/GlobalBoard 参照件) map/ data/
  listener/(SessionIngest/Stats/Interaction/Protection) command/ render/ util/
  resources/{plugin.yml, config.yml, maps/templates/(通用), sql/, META-INF/services/…MatchModeProvider}

ShdfHost/              玩法插件 jar(玩法线产物,SHDF)
  mode/{lobby,bomb,tdm,boss}/  component/role/  bridge/role/
  listener/RoleSignalListener  command/(玩法命令,如 /join)

```

注:`MatchModeProvider` 的 ServiceLoader 发现(①)只覆盖同 jar;跨 jar 注册走双发现的②(ServicesManager + `ServiceRegisterEvent`)——既有机制,零改动。

包根(D13):框架插件 = `com.hydrokarbs.*`(主类 `com.hydrokarbs.HydroKarbsPlugin`);玩法插件 = **独立顶级包 `com.shdf.*`**(主类 `com.shdf.ShdfPlugin`)——宿主是独立插件、自有品牌,不嵌框架命名空间;禁 shade 断言因此更简单:任何消费方 jar 内不得出现 `com.hydrokarbs.` 前缀类。

## 2. 决策 D1~D14

### D1:拆分形态与产物边界

框架拆为独立插件,玩法为消费插件,**切缝即既有分层线**:engine 不 import mode/component 的 ArchUnit 断言原样有效,拆分不新增任何引擎→玩法的依赖。`bridge/role`、`component/role`、`mode/*` 迁往玩法工程(它们本就是 SHDF 扩展线占位);`maps/templates/` 按"模板随地图包分发"原则:通用图随框架 jar,玩法图随玩法 jar(各自 `maps/` 根)。配置分工不变(§15.2):框架 `config.yml` 管拓扑与会话节律;`modes/*.yml`、玩法 `maps/*.yml` 归玩法插件资源。

### D2:API 面扩充一——成员操作(补齐路由编排的"执行手")

`MiniGameApi` 新增(只增不改):

```java
// ── 成员操作(D2;★42)──────────────────────────────
/** 将玩家加入会话(= SessionService#join 的受控暴露,§3.2;含 JoinAdmission 裁决)。主线程调用。 */
JoinResult joinSession(String sessionId, UUID player);
/** 将玩家移出其当前会话;不在任何会话 = no-op(幂等)。主线程调用。 */
void leaveSession(UUID player, LeaveReason reason);
```

- 调用方:命令/监听/伴随插件/玩法插件(外部调用方阵营);**服务不得经此通道**——三通道原文保留(见 14.37);
- `JoinResult`/`LeaveReason` 纳入 API 编译面白名单(D6);
- 权限/审计口径未决(Q3);`force` 语义不适用于 join(与 switchMode 的 force 条款不同域)。

### D3:API 面扩充二——会话事件订阅(§7.1/2.1 预留的兑现)

```java
// ── 会话事件订阅(D3;★43)─────────────────────────
/** 订阅会话事件(七事件族,§3.1)。返回句柄,close() 注销;订阅者异常被隔离(镜像总线既有隔离)。 */
EventSubscription subscribeSessionEvents(Consumer<SessionEventView> handler);

public interface EventSubscription extends AutoCloseable { @Override void close(); }
```

- `SessionEventView`:**不可变 record 快照**(type/sessionId/tick/载荷字段),七事件各一 record——不泄漏活会话/活组件引用(镜像 ★29 现取不缓存纪律);
- 消费者:伴随插件(全局看板)、玩法插件的路由编排器(听 `SessionDissolved`/`MemberLeft`);
- 顺序承诺:单会话内事件有序;跨插件订阅者间不承诺送达顺序;
- 实例事件(`MatchModeInstanceEvent`)第一版**不**经此面暴露(玩法侧组件经自身实例总线已有全量;跨插件订阅实例事件登记 Q6 关联项,不裁)。

### D4:API 面扩充三——能力标签提供方注册(★32 跨 jar 侧)

```java
// ── 能力标签(D4)───────────────────────────────────
/** 注册能力标签(提供方 = 本插件,如角色/经济适配)。幂等;提供方插件 disable 时自动摘除。 */
void registerCapability(org.bukkit.plugin.Plugin provider, String tag);
Set<String> capabilities();
```

既有 `CapabilityRegistry` 机制零改动(注册者三类:L1/第三方插件/服务);本面把"第三方插件"注册路径正式化并接通 `ServiceUnregisterEvent` 摘除(§8 先例 14.7 的懒解析与动态刷新纪律沿用)。

### D5:会话级组件 SPI——由 D14 受限开放(修订原"第一版不开放")

~~第一版不开放~~ → **本修正案内裁决开放(D14)**:插件(宿主/伴随)可经两条通道贡献会话组件;模式仍无权(v4-D4 不变);无运行期增删。07 §7.3 的另一未决——"第三方**查询**会话组件实例"——维持不开放。

### D6:API 编译面白名单(不搬家,定白名单)

**不移动引擎类型到 api/ 包**(避免 engine→api 的依赖倒挂);改为**白名单冻结**:玩法/伴随插件允许 import 的包集 = 

```
api/**                                     (MiniGameApi、view/*、EventSubscription、SessionEventView 族)
engine.mode/**                             (MatchMode MatchModeMeta MatchModeProvider ComponentEntry)
engine.component/{MatchModeComponent, SessionComponent}(两基类 + Specification + Factory;不含 Registry)
engine.session/{Handoff, EndResult, TransitionIntent, MatchModeSelection,
                SwitchResult, JoinResult, LeaveReason, SessionId, DissolveReason}
engine.port/{MatchModeInstanceServices, MatchModeInstancePort, SessionServices, SessionPort,
             MatchModeInstanceAccess, SessionView, JoinAdmission, AttributeBag(实为 engine 根)}
engine.event/**                            (MatchModeInstanceEvent 根 + SessionEvent 族)
component/** 各包的公开数据件与事件类型     (如 PhaseSpec、EndCondition、MatchOutcome、DisplayModel、
                                             TeamId…;白名单逐包清单落 7.5 施工文档)
map/{MapDefinition, RegionSet, NamedRegion, SpawnPoint, InteractPoint}(读面)
```

**机械守卫**:`ApiSurfaceTest` 双断言——①`MiniGameApi` 全部方法签名(含参数/返回/泛型)只引用白名单类型;②白名单内类型的公开签名**只增不改**(反射快照,同 `MiniGameApiSurfaceTest` 纪律)。玩法插件侧自建 ArchUnit 模板随 7.5 施工文档提供(框架无法跨 jar 强制,review 条款兜底)。

**永不导出**(白名单反面,断言显式列出):`SessionService(Impl)`、`EngineTicker`、`WorldPort`、`PersistencePort`、`ServiceRegistry` 族、`ComponentRegistry` 族、`bridge/**`、`data/**`、各 Impl。**跨 jar 场景下进程内全权访问特权仅保留给形态 A 的宿主 L0 装配/监听/命令**(彩排纪律:形态 A 下宿主代码也应只用白名单 + L0 装配点,不用内部面)。

### D7:版本协商与二进制兼容

```java
public interface MiniGameApi {
    int API_VERSION = 2;   // v1.0 = 1;v1.1 = 2。只增不减。
}
```

- 玩法/伴随插件 `onEnable` 首行检查:`api.API_VERSION < REQUIRED_API_VERSION` → SEVERE + `setEnabled(false)`(拒载不崩服);
- 框架 `onEnable` 日志输出 API_VERSION;对注册的每个 Provider 记录其声明的要求版本(`MatchModeProvider` 增 `default int requiredApiVersion() { return 1; }`,只增默认方法,不破既有实现);
- 兼容纪律:白名单内公开签名只增不改;破坏性变更必须升 API_VERSION 并提供**至多一个次要版本**的双轨过渡期(One-Version Rule:不允许长期双轨);
- 玩法插件**禁 shade 框架类**(compileOnly + 运行期 depend;见 14.35)。

### D8:加载/卸载顺序与热插拔

| 场景 | 机制 |
|---|---|
| 加载顺序 | 玩法插件 `depend: [HydroKarbs]`;框架先 enable(装配引擎/服务),玩法后 enable(注册模式);**会话拓扑装配延迟至全部插件 enable 完成后(首 tick / `ServerLoadEvent`)执行**,使 `initialModeId` 可解析玩法注册的模式(形态 B 新增时序约束;形态 A 同批装配无此问题) |
| 玩法插件 disable(Bukkit 保证依赖者先停) | 框架监听 `PluginDisableEvent`:①`MatchModeRegistry` 摘除该插件注册的全部模式;②正跑已摘模式的会话 → `switchMode(fallback)`(三级回退既有机制);无可用回退目标 → `dissolve`;③摘除其注册的能力标签(D4);④残留句柄断言(★47) |
| 框架 disable(最后) | `EngineTicker.close()` 既有路径:取消任务 → dissolve 全部会话 → `services.shutdown()` → api 注销(§12.2 D12 接线不变) |
| PlugMan/运行期重载 | 走同一摘除路径(`ServiceUnregisterEvent` 同 §8.4 动态刷新先例);旧 Provider 的静态句柄必须随 disable 注销(14.38) |

### D9:第三方组件信任边界(防线三层)

跨 jar 后第三方私有组件(经模式夹带)进入框架 tick 循环,防线:

1. **装配期拒坏声明**(既有):`verifyDependencies`/`checkMap`/注册期 build 校验;
2. **运行期隔离**(既有,扩展适用):实例组件异常 → quarantine → `end()` → 回退(会话不解散);会话组件异常 → 隔离不解散——跨 jar 场景断言不变(★48 扩展复验);
3. **预算观测(新增)**:`EngineTicker` 对组件 `update` 计时,单组件单 tick 超阈值(默认 5ms,`config.yml: performance.component-budget-ms`)记 WARNING(会话 id/组件 id/提供方插件);**硬熔断不做**(未决 Q4)。

### D10:三通道与 API 面的正交声明

服务三通道(D5 of v4.1)与 API 面扩充**互不打通**:服务是引擎内部居民,不消费 `MiniGameApi`;`joinSession/leaveSession` 扩大的是**外部调用方**阵营(命令/监听/伴随插件/玩法插件)的执行权。`CONTEXT.md` 三通道条目原文保留,追加一句注:"通道③受控命令清单不变;跨 jar 外部调用方经 `MiniGameApi` 的成员操作不构成第四通道(调用方阵营不同,见 19-D2/D10)"。

### D13:包根更名——框架 `com.hydrokarbs.*`,宿主自立 `com.shdf.*`

- **时机**:搭 v1.1(API_VERSION 1→2)的破坏性窗口一次付清——包名变更是编译期破坏,不搭窗口就要单独发一版;

- **不受影响**:Handoff 键(组件 id 命名空间)、数据库 schema、配置文件路径与键、能力标签词汇——均为字符串域,与包名无关;
- **灰度**:无——v1.0 尚未发布第三方编译期消费者,无兼容负担;若届时已有,按 D7 双轨至多一个次要版本。

### D14:会话组件贡献 SPI(修订 D5)——插件可"拼"会话,模式仍不可

**开放对象与两条通道**(贡献只发生在**会话创建时**,无运行期增删——装配点唯一不变):

| 通道 | 形态 | 适用 |
|---|---|---|
| 一·全局默认 | `SessionComponentProvider` 经 ServicesManager 注册;框架 `ServiceRegisterEvent` 收录时**干跑合并校验**(查重/依赖),坏 provider 拒收录(SEVERE 点名)、会话照常;收录后**所有后续会话装配**(含拓扑启动装配)合并其贡献 | 宿主级会话策略(自定义重连/宽限/准入记账) |
| 二·单次 | `createSession(SessionRecipe)` 重载:recipe 携带 `extraComponents`;合并后统一 `verifyDependencies`,查重/缺依赖 → `createSession` 响亮失败(装配期失败代价低,与既有会话创建语义一致) | 特殊竞技场按需定制 |

**合并序**(声明序 = 装配序 = 派发序,stop 逆序):L0 拓扑表 → 各 provider(注册序)→ recipe.extra。时序保障:D8"拓扑装配延迟至全部插件 enable 后"天然保证 provider 先注册、会话后装配。

**防线**(原 D5 否决理由的配套消解):①注册期干跑校验(坏贡献进不了默认面);②装配期 `verifyDependencies`(既有);③运行期单组件 quarantine(既有 ★30——会话不解散);④D9-③ 预算告警**明示扩至会话组件**;⑤卸载:provider 插件 disable → 贡献自后续装配摘除(D8 同款路径),已装配会话不受影响(无运行期拆卸,随 dissolve 自然消亡)。

**仍关闭**:模式无权贡献(v4-D4 不变);运行期增删组件;API 查询会话组件实例(07 §7.3 查询面未决维持)。

**白名单**:`SessionComponent.Specification` 已在 D6 白名单;`api/SessionRecipe`、`api/SessionComponentProvider` 随 api/** 自动入白名单;`engine.session.SessionSpec` 保持内部(recipe→spec 由框架转换,外部不见)。

## 3. 契约骨架(MiniGameApi v2 增量)

```java
package com.hydrokarbs.api;

/** v1.1:API 面扩充(只增不改;§7.1 既有方法原样保留,此处只列增量)。 */
public interface MiniGameApi {

    int API_VERSION = 2;

    // ── D2 成员操作 ──
    JoinResult joinSession(String sessionId, UUID player);
    void leaveSession(UUID player, LeaveReason reason);

    // ── D3 会话事件订阅 ──
    EventSubscription subscribeSessionEvents(Consumer<SessionEventView> handler);

    // ── D4 能力标签 ──
    void registerCapability(Plugin provider, String tag);
    Set<String> capabilities();
}

// api/view/SessionEventView —— 不可变快照族(七事件各一 record;字段口径 = §3.1 七事件载荷:
// from/to、reason、时间戳;不含活引用)
public sealed interface SessionEventView {
    record Created(SessionId session, long tick) implements SessionEventView {}
    record MemberJoined(SessionId session, UUID player, long tick) implements SessionEventView {}
    record MemberLeft(SessionId session, UUID player, String reason, long tick) implements SessionEventView {}
```
