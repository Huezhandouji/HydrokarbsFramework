## 0. 一页摘要

**变更(能力标签全链退场,四条决策)**:

①**D1 标签机制全链退场(字符串契约不严谨)**:`MiniGameApi#registerCapability`/`#capabilities` 两法删除(随删 api 层 `capabilityClaims` 簿记与 `MiniGameApiImpl` 兜底口 `unregisterCapabilitiesOf`);`engine/session/CapabilityRegistry` 机制件整体删除;切换 A2 校验步删除(阶段 A 失败路径覆盖自此为 A1/A3/A4/A5/A6,`REJECTED_BY_TARGET_MODE` 拒绝码与三码枚举原样,语义面收窄);`MatchModeMeta.requiredCapabilities` 首分量删除(模式工厂 Builder 声明语言变更:构造实参少一枚);`MatchModeInfo.requiredCapabilities` 快照分量删除(公共快照形状变更);`SessionComponent.Specification#capabilities` 与其 `Snapshot` 分量删除(★v4-D6 的字符串供给面落点退场);`ServiceSpec.Builder#capabilities` 删除(18 号扩注的「服务 seal 期注册者」通道消失,seal 注册 / shutdown 摘除两端随注消失);`ProviderUnloadListener` 能力块删除(四职责块 → 三职责块:模式 / 地图 / 贡献)。

②**D2 外部能力 = 会话组件桥接(类型化,机制既有)**:提供方(或宿主自持防腐层)经 `registerSessionComponents`/`SessionRecipe` 贡献**类型化桥接组件**——外部能力进框架的唯一通道收敛到 D14 显式贡献面(24 号刚落);消费方组件以 `requires(Class)`/`requiresOptional(Class)` 类型化声明依赖——装配期缺必需依赖**响亮抛**(会话创建失败,不留半装配态,★35 同款闸)、可选依赖运行期自查;运行期故障由 D9 quarantine 承接(桥接组件异常 → 停用 + 事件 + 会话不解散)。编译耦合(桥接组件 import 外部插件类型)关进桥接组件类内部,只住提供方 jar(或宿主防腐层),框架与其他组件零 import(★23 单点纪律的泛化)。**纯跨插件零编译契约场景失去**(原字符串标签允许提供方与消费方编译期互不认识、运行期字符串握手)——真实性未在基线出现,登记未决 §6-Q1,不预置机制。

③**D3 校验时机位移(每切换重查 → 创建时绑定 + 运行期降级/quarantine)**:原 A2 的语义是「进程级新鲜度」——每次切换重查(进程级注册表 ∪ 本会话标签并集),provider 摘除即时影响后续所有切换。新形态下依赖绑定发生在**会话创建装配期**(装配闸响亮):provider 摘除只影响**后续会话**(贡献摘除 → 后续 `createSession` 不再合并,缺依赖的会话创建响亮失败),**存量会话由桥接组件自身降级承接**(D14 既有口径:无运行期拆卸,随 dissolve 自然消亡;外部插件下线后的活性语义从「框架代查」移交给「组件自治」,异常路径由 D9 quarantine 兜底)。模式「硬依赖外部能力」的表达随之位移:不再由 meta 声明标签、由框架切换时挡,而由**消费该能力的组件**在装配期挡——缺桥接组件 = 会话创建失败,而非切换被拒。

④**D4 API_VERSION 5 → 6(破坏性)+ 迁移口径**:删冻结面既有方法 = 破坏性变更必升版本(07 §7.2);双轨过渡**取 0**(22-D2/24-D4 同款,One-Version 不允许长期双轨)。迁移口径:原 `registerCapability(this, tag)` → 桥接组件经 `registerSessionComponents`/recipe 贡献;原 `capabilities()` 查询 → 消费方 `svc().components().get(桥接组件.class)` 类型化读口;原 `new MatchModeMeta(Set.of("role"), …)` → 少一枚位置实参、硬依赖改由组件 `requires` 表达;原 `.capabilities("tag")` 声明(组件/服务)→ `.requires(X.class)`/`.requiresOptional(X.class)`;版本检查 `API_VERSION < 6` 拒载(14.36)。

**不动**:引擎内部机制零新增——切换管线步序(A1/A3~A6)、三级回退、min-dwell、两级挂载、三通道、世界、服务层两阶段装配(`install`/`seal`/`get`/`require`/`shutdown` 五法封顶)零改动;`registerMode`/`unregisterMode`/`registerSessionComponents`/`unregisterSessionComponents` 四法与 `modeClaims` 簿记、摘除回退编排(24 号)零触碰;地图注册(20-D2~D4)零触碰;`SwitchResult` 三拒绝码枚举与 `REJECTED_BY_TARGET_MODE` 语义原样(注文案收窄);★1~★59 断言零放宽(处置与重录见 §5);20/22/23 号修正案结论全部继续有效。

## 1. 决策 D1~D4

### D1:能力标签机制全链退场(字符串契约不严谨)

**退场清单**:

| 退场项 | 落点 | 说明 |
|---|---|---|
| 能力标签两法 | `MiniGameApi#registerCapability(Plugin, String)` / `#capabilities()` | ★v1.1-D4 的公共面;随删 `MiniGameApiImpl` 的 `capabilityClaims` 簿记与 L0 兜底口 `unregisterCapabilitiesOf`(冻结面 19 → 17 法) |
| 进程级注册表 | `engine/session/CapabilityRegistry` | v3.1 字符串化的机制件,整体删除(测试 `CapabilityRegistryTest` 随删;离线装配件 `OfflineApi`/`OfflineAssembly` 不再装配该机制件) |
| 切换 A2 校验步 | `SessionServiceImpl#switchMode` | 「声明标签 ⊆ 进程级 ∪ 本会话标签」删除;`Session#sessionComponentCapabilities()`(A2 会话侧来源)随删;阶段 A 失败路径覆盖自此为 A1/A3/A4/A5/A6;`REJECTED_BY_TARGET_MODE` 拒绝码保留(人数窗/依赖校验/地图适配/世界副本准备仍走它),三码枚举零改动 |
| 模式元数据分量 | `MatchModeMeta.requiredCapabilities` | record 首分量删除——模式工厂 Builder 声明语言变更:`MatchModeMeta` 构造实参少一枚(位置分量,无兼容构造器);「硬依赖」表达改由组件 `requires` 承接(§1-D3) |
| 模式快照分量 | `MatchModeInfo.requiredCapabilities` | 公共快照形状变更(★44 BASELINE 重录范围) |
| 会话组件供给面声明 | `SessionComponent.Specification#capabilities(String...)` 与 `Snapshot#capabilities` | ★v4-D6「会话组件注册标签(随装配注册、随 dissolve 摘除)」的字符串供给落点退场——供给/消费关系改经 `providedType()`/`requires` 类型化表达(机制既有) |
| 服务端声明 | `ServiceSpec.Builder#capabilities(String...)` | 18 号扩注的「服务(seal 期)注册者」通道删除——seal 成功注册、shutdown 摘除两端随注消失;服务对外能力的供给/消费改经 `requires`/`requiresOptional` 类型化依赖(既有) |
| 兜底能力块 | `ProviderUnloadListener` | 四职责块 → **三职责块**(模式/地图/贡献);能力块随机制退场,`PluginDisableEvent` 监听与幂等语义原样 |

**理由**:①**字符串契约不严谨(裁决主判据)**——标签词汇的唯一防撞机制是「词汇纪律」(文档约定:词汇由提供方注册,引擎零字面量),机制本身不设防:`"role"` 与 `"Role"` 两串在编译期与装配期都合法,炸点在**运行期切换 A2**——玩家面前的对局切换被 `REJECTED_BY_TARGET_MODE` 拒绝,detail 列一串没人认得的标签;撞名(两个无关联提供方主张同一标签)更是在 A2 才可能暴露,而「可用 ⟺ 至少一个提供方主张」的不变式本就无法表达「是谁提供、语义是否同一」。②**与组件依赖图平行的弱机制(One-Version)**——同一「能力供给/消费」关系已由类型化机制完整承载(供给 = `providedType()` 泛型推导;消费 = `requires`/`requiresOptional`;失败 = 装配期响亮 + D9 quarantine,★28~★30/★35),字符串层是叠在其上的第二套口径:双簿记(标签集 + 类型图)、双失败语义(A2 拒切换 vs 装配响亮)、三处摘除时点(能力块随 disable / 服务随 shutdown / 会话组件随 dissolve)。同一能力两份口径,收敛优于并存(22-D1/24-D2 同源判据),删除优于悬挂。③**仓库边界自证**——引擎对「外部能力」零认识的红线(§4 铁律 1)在字符串化(v3.1)与类型化两个方向上都成立,退场后引擎对能力**零认识且零机制**,红线只会更干净;字符串域(Handoff 键/DB schema/配置键)的包根豁免句随标签机制退场收窄(AGENTS §5 同步)。④**判据同源**——与 21-D1(零消费者端口删除)、22-D1(同一能力收敛单口径)同一推理形状:CapabilityRegistry 的全部消费方(A2 校验 / 两法 / 两端声明)都在本次退场清单内,机制件无残留消费者。

### D2:外部能力 = 会话组件桥接(类型化;桥接由提供方或宿主自持)

**决策**:外部能力进框架的唯一形态是**会话组件桥接**:

1. **进**:提供方插件(或宿主自持防腐层)把自己的外部能力包成 `SessionComponent` 桥接组件(外部插件的类型 import 只出现在该组件类内部),经 `registerSessionComponents(Plugin, specs)`(全局默认贡献)或 `SessionRecipe.extraComponents`(单次贡献)进会话——通道与收录闸(干跑合并校验响亮)全部既有,零新增;`examples/TheirPlugin` 的 `TheirSessionComponent` 即桥接形态样例。
2. **声明**:消费方组件(实例级 `MatchModeComponent.Specification` 或会话级 `SessionComponent.Specification`)以 `requires(桥接组件.class)`(必需)或 `requiresOptional(桥接组件.class)`(可选)类型化声明——同一类型不得既必需又可选(既有纪律);**软依赖由 ★21 的类型化 `requiresOptional` 独自承载**(机制已在框架内,非新增)。
3. **失败**:装配期缺必需依赖 → 会话创建失败响亮抛(点名组件与缺失类型,`ComponentResolutionTest` 断言族既有);运行期桥接组件异常 → D9 quarantine(停用 + `SessionComponentQuarantined` 事件 + 会话不解散,★30 既有)。
4. **归属**:编译耦合(桥接组件 import 外部插件类型)关进桥接组件类内部——只住提供方 jar(或宿主自持防腐层),框架与其他组件零 import(★23「任何类不得 import 桥接类型,只见包装组件读口」单点纪律的泛化)。

**理由**:①类型化声明的失败面整体**前移**——拼写错误/漏装/缺依赖在会话创建(装配闸)就地响亮,不进运行期;跨组件握手由编译器与类型图守卫,零词汇纪律义务。②**桥接由提供方或宿主自持**是唯一现实的承载点:外部能力(角色系统/经济/权限)的词汇本来就住提供方 jar,框架定义任何中间形态都会把内容词汇拉进引擎(§4 铁律 1 红线)。③**代价(登记未决)**:纯跨插件零编译契约场景失去——原字符串标签允许提供方与消费方在编译期互不认识、运行期靠共享字符串握手;类型化要求消费方能引用桥接组件类型(编译期耦合),该耦合被关进消费方自己的防腐层组件。该场景在框架基线无真实出现路径(现消费面 = SHDF 宿主与 TheirPlugin 样例,均为可 depend 的形态 B 消费者),按 A9/A13 假想接缝判据不预置机制,登记 §6-Q1。

### D3:校验时机位移(每切换重查 → 创建时绑定 + 运行期降级/quarantine)

**决策**:模式对外部能力的依赖校验从「**每次切换重查(进程级新鲜度)**」位移为「**创建时绑定 + 运行期降级/quarantine**」:

| 维度 | v1.6 及之前(A2) | v1.7 起(桥接) |
|---|---|---|
| 校验点 | 每次 `switchMode` 阶段 A2 重查(`requiredCapabilities ⊆ 进程级 ∪ 本会话标签`) | 会话创建装配期一次绑定(装配闸响亮);切换同步段无字符串校验步 |
| provider 摘除的影响 | 即时:后续每次切换都可能因标签缺席被拒 | 只影响**后续会话**(贡献摘除 → 不再合并);**存量会话不受影响**——桥接组件已随会话创建,随 dissolve 自然消亡(D14 既有口径) |
| 外部插件下线后 | 注册表摘标签 → 下一次切换 A2 拒(进程级新鲜度) | 桥接组件**自身降级承接**(组件自治):无运行期拆卸,异常路径 D9 quarantine 兜底 |
| 失败形态 | 切换被拒(`REJECTED_BY_TARGET_MODE` + detail 列标签) | 会话创建失败(装配期响亮)或运行期组件隔离(quarantine) |

**理由**:①「进程级新鲜度」是字符串机制的自保语义,不是独立需求——它存在的前提是「声明与供给在两套簿记里,必须反复对表」;类型化绑定后声明与供给在同一次装配里对上,重查无对象。②存量会话的降级承接与既有结论一致:**provider 摘除只影响后续会话**是 D14 对贡献通道的既定口径(24-D3 第④族原样),桥接组件寄居其上,语义自然同构;硬性运行期拆卸(强拆存活对局)反而违背 20-D4「正用不强拆」同源精神。③模式侧「硬依赖」表达的位移是本裁决的净效果:缺外部能力从「切换被拒」变为「**带该依赖的组件装配不进去 → 会话创建失败**」——失败更早、更响亮、责任点更精确(点名缺哪个类型,而非列一串标签)。

### D4:API_VERSION 5 → 6(破坏性:删两公共法 + 删 MatchModeMeta 分量)+ 迁移口径

**决策**:`MiniGameApi.API_VERSION = 6`(v1.0 = 1;v1.1 = 2;v1.2 = 3;v1.3 维持 3;v1.4 = 4;v1.6 = 5;**v1.7 = 6**)。删除冻结面既有方法与公共快照分量是**定义上的破坏性变更**,07 §7.2 明文「破坏性变更必须升 API_VERSION」。双轨过渡**取 0**(22-D2/24-D4 同款:One-Version 不允许长期双轨;当前消费面 = SHDF 宿主与测试/示例插件,随本窗口一并迁移,git 实况可查)。消费方保护面不变:14.36 首行版本拒载;存量 `registerCapability` 调用直接编译不通过——编译期即暴露,比运行期拒载更早。

## 3. 契约骨架(MiniGameApi v6 面,17 方法)

> **以下为现行 `src/main/java/com/hydrokarbs/api/MiniGameApi.java` 的实际签名转写(2026-10-28,不得凭记忆)**——方法名、参数与返回类型逐字对应该文件(仅省略 javadoc 正文;注解要点为该文件头部注与各方法注的摘要)。★19(`MiniGameApiSurfaceTest`)17 行 FROZEN 清单与 ★44(`ApiSurfaceTest`)BASELINE 快照以此为基线重录(已随施工窗口完成:BASELINE 删能力标签两法 + `MatchModeInfo`/`MatchModeMeta` 能力分量 + `SessionComponent$Specification`/`Snapshot` 的 capabilities 共 6 行)。

```java
package com.hydrokarbs.api;

/** 本框架的对外公共面。经 Bukkit ServicesManager 暴露(07 §7.1/§7.2)。
 *  ★v1.7 能力标签机制退场(25 号):API_VERSION = 6,冻结面 19 → 17 方法 =
 *  查询 3 + 控制 1 + 建会话 1 + 成员 2 + 订阅 1 + 地图 2 + 模式显式注册 2 +
 *  会话组件显式注册 2 + 目录 3(能力 2 随标签机制删除);
 *  外部能力 = 会话组件桥接(registerSessionComponents/recipe 贡献,
 *  消费方 requires/requiresOptional 类型化声明)。引擎契约类型
 *  (SwitchResult/MatchModeSelection/Handoff)直接 import 自 engine.session,
 *  不复制;apiDependsOnlyOnEngine 放行(§16.2)。 */
public interface MiniGameApi {

    /** API 面版本常量(★v1.1-D7 版本协商;只增不减):v1.0 = 1;v1.1 = 2;
     *  v1.2 = 3;v1.3 维持 3;v1.4 = 4(两参 createSession 重载删除);
     *  v1.6 = 5(显式注册收敛);v1.7 = 6(能力标签机制退场——外部能力 =
     *  会话组件桥接,25 号修正案裁决)。
     *  消费方 onEnable 首行检查 api == null || api.API_VERSION < REQUIRED
     *  → SEVERE + setEnabled(false)(拒载不崩服,14.36);框架 onEnable 日志输出版本。 */
    int API_VERSION = 6;

    // ── 查询(不可变快照;现取不缓存,14.31 同款纪律;主线程调用) ──────────────
    Optional<SessionInfo> sessionOf(UUID player);
    Optional<SessionInfo> session(String sessionId);
    List<SessionInfo> sessions();

    // ── 控制(与 /sm 命令同权,§7.1) ────────────────────────────────────────
    /** 切换某会话的模式(§3.2 受控暴露):id 不在注册表 → Rejected(MODE_NOT_FOUND);
     *  其余拒绝经引擎三级回退管线透传(★v1.7 起无能力校验步);空白 id / null target
     *  → future 异常完成;future 永不悬挂。任意线程发起,Impl 内部回主线程。 */
    CompletableFuture<SwitchResult> switchMode(String sessionId, MatchModeSelection target,
                                               Handoff payload);
    /** 创建会话(★v1.1-D14 通道二):合并序 = 已收录贡献(注册序)→ recipe.extraComponents
     *  (装配点唯一不变;模式仍无权贡献);装配闸响亮抛,不留半装配态;随 dissolve 全灭(★52)。
     *  公共 API 建会话唯一形态(★v1.4)。主线程调用。 */
    SessionInfo createSession(SessionRecipe recipe);

    // ── 成员操作(★v1.1-D2;★42;主线程调用) ─────────────────────────────────
    /** 引擎既有裁决原样透传(不存在 / 解散中 / 入场拒绝 → Rejected;已在册 → 幂等重入)。 */
    JoinResult joinSession(String sessionId, UUID player);
    /** 不在任何会话 = no-op(幂等);QUIT = 断线宽限在册 / KICK = 立即移除。 */
    void leaveSession(UUID player, LeaveReason reason);

    // ── 会话事件订阅(★v1.1-D3;★43) ────────────────────────────────────────
    /** 返回句柄,close() 注销(句柄只在插件实例字段中持有,onDisable 显式 close,14.38);
     *  订阅者异常被隔离;单会话内事件有序,跨插件订阅者间不承诺送达顺序。 */
    EventSubscription subscribeSessionEvents(Consumer<SessionEventView> handler);

    // ── 地图注册(★v1.2;★54;守卫语义 20-D3/D4 不变;主线程调用) ───────────────
    /** 交成品不交工厂(20-D1);注册期校验响亮抛(重复 id 点名先到者/tags/模板目录存在性)。 */
    MapInfo registerMap(org.bukkit.plugin.Plugin provider, MapDefinition map);
    /** 正用摘除被拒(detail 点名会话,20-D4);幂等:已不在目录 = no-op;disable 兜底摘除。 */
    void unregisterMap(org.bukkit.plugin.Plugin provider, String mapId);

    // ── 模式显式注册(★v1.6;24 号:ServicesManager 提供方通道退场) ─────────────
    /** 注册工厂,不是注册成品(§13.4;cfg 生命周期归框架,§10.2);注册闸全响亮
     *  (坏声明/重复 id 原样抛,onEnable 失败 = 拒载信号);A9 三限制原样。主线程调用。 */
    MatchModeInfo registerMode(org.bukkit.plugin.Plugin provider, MatchModeProvider factory);
    /** 只准摘自己注册的 id(越权含出厂模式 → 响亮拒;不存在 → 幂等 no-op);摘除后
     *  执行摘除回退编排:fallback-mode 已配置且已注册 → force 切换(豁免 min-dwell);
     *  否则 FALLBACK_DISSOLVE 解散;回退被拒 WARN 放弃不自旋(§14.17)。主线程调用。 */
    void unregisterMode(org.bukkit.plugin.Plugin provider, String modeId);

    // ── 会话组件显式注册(★v1.6;D14 通道一的显式面) ─────────────────────────
    /** 宿主级会话策略贡献——★v1.7 起亦为外部能力桥接组件的唯一「进」口(25 号);
     *  模式仍无权贡献(v4-D4)、无运行期增删;干跑合并校验失败响亮上抛(注册闸只有一份);
     *  同一提供方重注册 = 幂等重收录。主线程调用。 */
    void registerSessionComponents(org.bukkit.plugin.Plugin provider,
                                   List<SessionComponent.Specification<?>> specs);
    /** 幂等;后续会话不再合并,已装配会话不受影响(随 dissolve 自然消亡,D14)。主线程调用。 */
    void unregisterSessionComponents(org.bukkit.plugin.Plugin provider);

    // ── 目录(顺序 = 注册序,不排序不过滤——14.21「大厅特判」反弹规避) ─────────
    List<MatchModeInfo> modes();
    List<MapInfo> maps();
    Optional<MatchModeInfo> mode(String modeId);
}
```
