## v1.12 版本定位(JoinDecision 二值化与 SPECTATE 退场)

> **变更指示 [30-v1.12修正案](30-v1.12修正案-JoinDecision二值化与SPECTATE退场.md)(历史存档,现行见 31 号),决策记录 [docs/adr/0018](docs/adr/0018-binary-join-verdict.md)。**

**引擎的入场裁决结果收缩为二值:`JoinDecision.Kind` = `ADMIT`/`REJECT`,`SPECTATE` 全库退场**(A 项收缩;代码与测试已随 v1.12 施工窗口完成,git 实况为准)。**判据**:①引擎对 `Kind` 的全部分支只有两处 `== REJECT`(`MatchModeInstance#startAll`、`SessionServiceImpl#join`),非 `REJECT` 一律登记名册并进参赛者表;②「参赛位/观战位」的差别引擎从不区分——`SPECTATE` 是一个引擎不消费的安置语义;③「观战」是玩法/表现概念,不该占引擎结构词汇位(14.12 同病)。**新口径**:引擎结构词汇 = 「收不收」(`ADMIT` 成为参赛者 / `REJECT` 不收);观战安置非引擎词汇,归组件层(组件在 `ADMIT` 之后用自己的词汇自理)。**边界不变**:引擎行为零变化(两处 `== REJECT` 与无实现者默认 `ADMIT` 原样,`join` 返回 `Joined`/`Rejected` 不变);`JoinAdmission`/`JoinResult`/两触发点/`JoinControlComponent` 挂载口径原样;`MiniGameApi` 17 方法签名与 `API_VERSION = 7` 零改动;★19 FROZEN 17 行不动、★44 BASELINE 删 `JoinDecision$Kind#SPECTATE` 一行后合法重录(背书 = ADR-0018);不新增 ★ 编号,计数维持 65 条;17~29 号正文与既有 ADR(0001~0017)按存档保留。

## v1.11 版本定位(属性袋纯容器回归与声明词料三件退场)

**属性袋以纯不可变容器形态回归,`MapDefinition` 第三分量定为 `AttributeBag`,不透明词料与两层标签中间件退场**(A 项收缩;代码已随 v1.11 施工窗口完成,git 实况为准;决策记录 [docs/adr/0017](docs/adr/0017-attribute-bag-pure-container.md),变更指示 [29-v1.11修正案](29-v1.11修正案-属性袋纯容器回归与声明词料三件退场.md))。**判据**:①28 号的「不透明对象 + 按引用存储、视为冻结」把冻结责任完全交给注册方,框架无结构保证;②单方法标签约定与标签门面唯一职责只是从一个不透明对象里取一个 `Set<String>`,其余声明词料只能塞进注册方自定义类型;③纯容器可把「声明级单写方 + 构造即冻结」落进类型结构,而无需恢复旧属性袋的命名空间断言/授权表/`close()` 链。**新形状**:`AttributeBag` 纯不可变容器(`Key<T>(name,type)` 二元组、`Builder` 唯一写侧、`Map.copyOf` 收口、`get/getOrDefault/has` 三读口、`empty()` 共享空实例);`MapDefinition(Path worldDirectoryPath, ResetStrategy resetStrategy, AttributeBag metadata)`(非空,无词料传 `empty()`;构造即冻结);标签 = `MapDefinition.TAGS` 约定键 + `tags()` 唯一读口(缺省空集)。**退场**:`Object metadata` 不透明词料、原标签提取接口、原标签门面三件删除,`map/` 包只剩 `MapDefinition` + `MapRegistry`。**命名消歧**:旧属性袋(命名空间 + 断言 + 授权表 + `attrs()`)仍废止,现役同名容器是**不同机制**;机械分界 = `Key` 二元组、无 `namespace`/授权表成员、不参与实例 `close()`(CONTEXT 历史词条已加注)。**边界不变**:`MiniGameApi` 17 方法签名与 `API_VERSION = 7` 零改动;★19 FROZEN 17 行不动、★44 BASELINE 随 `AttributeBag` 回归与第三分量类型变更合法重录(背书 = ADR-0017);★26 维持废止(命名空间断言检验不复活)、★63 就地注再校准(②注册期冻结由容器结构恢复),不新增 ★ 编号,计数维持 65 条;切换管线/`WorldPort` 三法/复用窗口(★58)/`deleteCopyDir`/`MapInfo` 三分量/24 号四法/25 号桥接/27 号清场接缝/28 号的路径直交与 id 派生零触碰。

## v4.1 版本定位(相对 v4.0 的一处扩建:进程级服务层)

**进程级服务层:服务(Service)是与组件并列的另一类对象类别**——不挂进会话/实例(进程生命周期,`onEnable` 装配 → `onDisable` 关停)、不进组件表,经 `ServiceRegistry` 两阶段装配(`install` 声明 → `seal` 依赖校验 + 拓扑序创建 + 启动),经**订阅会话事件、只读快照、`SessionService` 受控命令**三条通道触达会话,与组件**互不可见**(双向禁止 import)。完整变更见 18(变更指示,非设计章节),决策记录见 ADR-0006(docs/adr/0006-process-service-registry.md;修正案原文编号 0005,因 docs/adr/0005 已被《架构冻结测试门禁》占用,顺延为 0006)。

## v4.0 版本定位(相对 v3.2 的一处扩建:会话级组件层)

**组件从"单一挂载级"扩为两级挂载**:实例级 `MatchModeComponent`(原样,随实例 `close()` 全灭)+ **会话级 `SessionComponent`**(新增,随会话 `create` → `dissolve`,**每会话一份**、跨模式切换存活);两级互相只读查询,对对方的干预只走端口。驱动来自三处:①模式要接入会话级能力(`SessionView` 只读查询 + 能力标签硬依赖声明);②会话行为要可插拔(空场解散策略自 `SessionPolicy` 下放为 `component/session/EmptyArenaComponent`,rotation 不挂 = 永不解散);③系统级要读实例运行数据(`MatchModeInstanceAccess` 只读查询当前实例)。**"单例"语义的修正**:会话级组件在会话生命周期内单例(同一会话内 `Specification#create` 至多一次,此后一切查询恒返回同一实例),**跨会话不共享**——原设想"进程级单例"在 arena 拓扑(N 个会话并发跑同一模板)下会串台,故修正为"每会话一份";共享的只能是不可变声明。完整映射见 00 §0.5.5,决策记录见 docs/adr/0004,变更指示见 17(非设计章节)。

## v3.0 版本定位(相对 v2 的三个推到底)

1. **模式聚合根零行为**:`MatchMode` 只有 id/名称/描述/图标/标签/MatchModeMeta + 一张有序组件描述符表;v2 的 `plan()`/`rolePolicy()`/`transition()`/`validateMap()` 全部拆除。形状逐字段对照角色系统 `core/Role`(已验证的参照物,非猜想)。

## 硬边界(速记,详见 16.2)

- `engine/**` 不 import `mode/**`、`component/**`、`bridge/**`;源码不含任何 mode id 字面量(含 `lobby`),不含 `Phase`/`Rule`/`EndCondition`/`Role`/`Team`/`Score` 等内容词汇;引擎不写任何 Handoff 键
