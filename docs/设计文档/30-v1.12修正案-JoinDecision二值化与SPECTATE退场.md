> 变更指示(非设计章节):本修正案把 [ADR-0018](docs/adr/0018-binary-join-verdict.md) 的裁决追认为正式修正案——**`JoinDecision.Kind` 收缩为 `ADMIT`/`REJECT` 二值**,`SPECTATE` 常量全库退场;引擎行为**零变化**(全库仅两处 `== REJECT` 分支:`MatchModeInstance#startAll` 与 `SessionServiceImpl#join`,均原样;无实现者默认 `ADMIT` 原样;`join` 返回 `Joined`/`Rejected` 不变;`SessionRosterTransferTest` 触发点②用例已在 v1.12 施工窗口内改写)。**判据**(ADR-0018「背景」):①引擎对 `Kind` 的全部分支只有 `== REJECT` 两处,非 `REJECT` 一律登记名册并进参赛者表;②「参赛位/观战位」的差别引擎从不区分——三值里的 `SPECTATE` 从出生起就是一个引擎不消费的安置语义;③「观战」是玩法/表现概念,不该占用引擎结构词汇位。**不新增 ★ 编号**;★1~★65 原样有效;★19 零改动,★44 BASELINE 合法重录(删 `JoinDecision$Kind#SPECTATE` 一行)。
> 基线:v1.11。本修正案为**引擎端口枚举常量侧的收缩、方法面零变化**:`MiniGameApi` 17 方法签名一字不动,`API_VERSION` 维持 **7**;`ApiSurfaceTest` BASELINE 删 `JoinDecision$Kind#SPECTATE` 一行后合法重录(背书 = 30 号/ADR-0018),★19(`MiniGameApiSurfaceTest`)FROZEN 17 行不动。
> 版本口径:本修正案只升设计案版本(v1.11 → **v1.12**),不升 `API_VERSION`(同一 v7 窗口内的又一次公共面收缩,版本轴不区分;风险沿用 28 §6-Q1 / 29 §6-Q1 先例,本件 §6-Q1 再次登记)。

## 1. 决策 D1~D4

### D1:`Kind` 收缩为 ADMIT/REJECT 二值

**决策**:`public enum Kind { ADMIT, REJECT }`(`JoinDecision.java:18-23`);常量注释按现行实签:「许可入场,安置为参赛位」/「拒绝入场(会话不收,名册不登记)」。引擎行为逐点核对如下(**全部零变化**):

| 消费点 | 现行行为(以现行实签为准) |
|---|---|
| `MatchModeInstance#startAll`(`MatchModeInstance.java:132-146`) | 无实现者 → `ADMIT`(`:138`);`== REJECT` → `continue`,名册保留、不进参赛者表(`:139-141`);其余 → `participants.put`(`:142`) |
| `SessionServiceImpl#join`(`SessionServiceImpl.java:610-638`) | 无实例/切换中 → 名册登记 + `Joined`(`:621-624`);无实现者 → `ADMIT`(`:630`);`== REJECT` → `Rejected`(`:631-633`);其余 → 登记名册 + `admitParticipant` + `Joined`(`:635-637`) |

**理由**:引擎对 `Kind` 的全部分支只有 `== REJECT`;`SPECTATE` 与 `ADMIT` 在引擎侧走同一条路径,差别从未被消费。保留三值等于让一个无消费者的安置语义占用结构词汇位,并持续暗示引擎认识它(14.12 同病:枚举把行为/策略写成名字)。

### D2:词汇处置——观战归组件层

**决策**:「观战」不再出现在引擎结构词汇位;消费点注释统一口径为「**ADMIT 成为参赛者;观战安置非引擎词汇,归组件层**」。现行实签已落此口径(逐处转写):`MatchModeInstance.java:128-131`(`:130` 原句)、`JoinAdmission.java:9-10`、`JoinResult.java:5-8`、`SessionServiceImpl.java:636`(「安置细节归组件层」)。组件要观战安置,在 `ADMIT` 之后用自己的词汇自理(如 `VisibilityComponent`/`TeamComponent` 的 SPECTATOR 队——组件侧词汇,不进引擎)。

**理由**:结构词汇只应表达引擎真实区分的东西——「收不收」。「怎么安置」是玩法/表现,引擎不消费;把观战留在 `Kind` 里会让下一位读者以为引擎有一个观战位(与 v3.2「入场路由是行为,下放组件」同一条推理)。

### D3:测试与冻结处置

**决策**:

| 件 | 处置 |
|---|---|
| ★19 `MiniGameApiSurfaceTest` | **零改动**(FROZEN 17 行不动;`JoinDecision.Kind` 不在其中) |
| ★44 `ApiSurfaceTest` BASELINE | **合法重录**:删 `JoinDecision$Kind#SPECTATE` 一行;现行基线含 `ADMIT`/`REJECT` 两常量行(`ApiSurfaceTest.java:691-692`)。背书 = 30 号/ADR-0018 |
| `SessionRosterTransferTest` 触发点② | **用例改写**:原观战位用例随枚举删除改写为第二例 `ADMIT`(`SessionRosterTransferTest.java:249-255`);修测试理由按 AGENTS §4-12 写明于测试 javadoc(`:226-228`);覆盖不缩水——`REJECT` 不收/名册不登记(`:256-259`)、`ADMIT` 进当前实例两例(`:249-255`)均保留 |
| 触发点① 用例 | 原样(现有 `ADMIT`/`REJECT` 两分支已足) |

**理由**:冻结测试的重录仅限「被删枚举常量退出白名单」,不得顺手放宽其它签名或删断言;测试改写保留原有覆盖面(两种裁决结果 × 名册/参赛者两面),只把已不存在的第三值换成第二例 `ADMIT`。

### D4:文档处置与边界

**决策**:活文档按 §4 清单修订;历史存档 17~29 号正文与既有 ADR(0001~0017)不回改;`01-分层架构.md:208` 与 `SessionIngestListener.java:81` 的「观战」保留(组件侧职责表述,非 `Kind` 语义)。「观战」概念本身仍现役——它是组件词汇,不是引擎词汇。

## 3. 契约骨架(以现行实签转写,不得凭记忆)

```java
// engine/port/JoinDecision.java(现行实签)
public record JoinDecision(Kind kind, String reason) {                 // :11
    public JoinDecision { Objects.requireNonNull(kind, "kind"); }       // :13-15

    /** 裁决二值:许可入场(成为参赛者)/ 拒绝入场(会话不收)。 */
    public enum Kind {                                                  // :18
        /** 许可入场,安置为参赛位。 */
        ADMIT,                                                          // :20
        /** 拒绝入场(会话不收,名册不登记)。 */
        REJECT                                                          // :22
    }
}

// engine/port/JoinAdmission.java(端口形状零改动)
public interface JoinAdmission {                                        // :18
    JoinDecision admit(UUID player, JoinContext ctx);                   // :27
}

// engine/session/JoinResult.java(结果形状零改动)
public sealed interface JoinResult {                                    // :10
    record Joined(SessionId session) implements JoinResult { }          // :13
    record Rejected(String reason, String detail) implements JoinResult { }   // :17
}

// 引擎消费(两处,均只认 == REJECT;无实现者默认 ADMIT)
// MatchModeInstance#startAll(MatchModeInstance.java:132-146)
JoinDecision decision = gate != null
        ? gate.admit(member.uuid(), ctx)
        : new JoinDecision(JoinDecision.Kind.ADMIT, null);              // :138
if (decision.kind() == JoinDecision.Kind.REJECT) {                      // :139
    continue;                                                           // 名册保留,不进参赛者表
}
participants.put(member.uuid(), new Participant(member.uuid()));        // :142

// SessionServiceImpl#join(SessionServiceImpl.java:610-638)
JoinDecision decision = gate != null
        ? gate.admit(player, new JoinContext(JoinContext.Trigger.MID_JOIN, session.id()))
        : new JoinDecision(JoinDecision.Kind.ADMIT, null);              // :630
if (decision.kind() == JoinDecision.Kind.REJECT) {                      // :631
    return new JoinResult.Rejected("rejected-by-mode", ...);            // :632-633
}
registerMember(session, player);                                        // :635
current.admitParticipant(player);                                       // :636 安置细节归组件层
return new JoinResult.Joined(session.id());                             // :637
```

**退场类型/成员**:`JoinDecision.Kind#SPECTATE`(单个枚举常量)。**本裁决不触碰**:`JoinAdmission` 端口形状、`JoinContext`、`JoinControlComponent` 实现、组件侧安置词汇、`MiniGameApi` 方法面。

## 6. 未决与风险(登记,不静默决定)
