## 目标

落盘设计案 v4 的**会话级组件层**(两级挂载的会话侧):组件从"单一挂载级"扩为两级——实例级 `MatchModeComponent`(随 `close()` 全灭,本子阶段不动)与**会话级 `SessionComponent`**(**每会话一份**、跨模式切换存活、随 `dissolve` 全灭);会话的*策略与行为*(第一波:空场解散)从内核下放为可插拔组件,加/换行为不改 `SessionService`。本子阶段结束时,新增的可验证物:

1. **契约件**:`engine/component/SessionComponent`(基类 + `Specification`/`Factory`/`Snapshot`,纪律照抄实例级)与 `engine/port/` 五类型——`SessionServices`(2 成员封闭)/`SessionPort`(会话自面,含 `requestSwitch`/`requestDissolve` 两个行动口)/`SessionComponentLookupPort`/`MatchModeInstanceAccess`(会话侧只读实例面)/`SessionView`(实例侧只读会话视图);`MatchModeInstancePort` **只加一行** `session()`(其余不动);
2. **容器**:`SessionComponentRegistry`——装配期依赖校验 + 声明序派发 + 逆序 `stop` + 登记资源回收 + 故障隔离;注册表**挂在 `Session` 上**(每会话一份的机械保证,**不是进程级静态**);
3. **装配与回收接线**:`SessionService.create` 内装配(先于首个实例就绪)、`dissolve` 逆序 `stop` + 回收;`EngineTicker.tickAll` 四步(③ 会话组件派发,**每 tick 必调、与实例有无无关**);`SessionService` **公开方法签名不变**;
4. **第一波迁移**:`component/session/EmptyArenaComponent`(空场解散策略;rotation **不挂** = 永不解散;arena 挂,时长读 `session.dissolve-after-empty-seconds`,**键保留、消费者变更为 L0**——**★v1.3-D5:该键随启动建会话特性删除,时长改由宿主组装 `SessionSpec.sessionComponents` 时自供**,21-D5);`SessionPolicy` 的空场判定与 `idleTimers` 空场部分**删除**(2.1 回改;连接追踪与宽限 sweep 仍内核);
5. **数据与能力**:`SessionSpec` 扩展 `List<SessionComponent.Specification<?>> sessionComponents`(有序表 = 装配序 = 派发序;**L0 按配置构建,模式无权注册/增删**);`SessionEvent` 族新增 `SessionComponentQuarantined`;`CapabilityRegistry` 扩展(会话组件标签进 A2 可用集,随 dissolve 摘除);
6. **验收**:§16.2 的 ★27~★33 全部落绿(★32 的桥接部分除外,见「测试与验收」),外加 1.4 架构测试族的 v4 修订。

有序步骤:

1. **SessionComponent**(§12.2 v4 骨架逐行):`abstract class`,字段仅 `id` + `SessionServices svc`;构造校验同 `MatchModeComponent`(id 非空非空白、services 非空);`id()` final、`svc()` 未注入即抛;五个钩子空实现 `awake`/`start`/`update`/`onEvent(SessionEvent)`/`stop`;嵌套 `abstract static class Specification<T extends SessionComponent>`——`descriptorLabel`(只进异常文案)、`requires`/`requiresOptional`(接口/抽象类 token;同一类型不得既必需又可选)、`capabilities(String...)`(★D6,词汇由提供方定义、引擎零字面量)、`providedType()`(默认由泛型实参推导)、`freeze()`(子类自检 → 不可变 `Snapshot`,此后 Spec 拒改)、`abstract T create(String id, SessionServices svc)`(唯一创建点);`Snapshot` 六字段(descriptorLabel/factory/providedType/requiredTypes/optionalTypes/capabilities);`@FunctionalInterface Factory`。**基类不认识子类**:要协作就经 `svc().components()` 取强类型读口。
2. **端口组之一**:`SessionServices`(record,2 成员封闭——**不为领域增设成员**,照抄实例级三成员纪律的口径);`SessionComponentLookupPort`(`<T extends SessionComponent> T get(Class<T>)` / `<T extends SessionComponent> List<T> getAll(Class<T>)` / `Optional<SessionComponent> byId(String)`;按类型取"声明序第一个")。
3. **SessionPort**(会话自面,§12.2 逐字):`id()` / `members()`(**只读快照**) / `tick()`(会话已存活 tick 数,与 `MatchModeInstancePort#tick()` 同构;空场计时与 min-dwell 的同一量纲来源) / `attrs()`(命名空间 = 组件 id,`"session"` 保留给内核,§2.7) / `events()`(订阅随 `stop` 回收) / `currentInstance()`(**无实例或 `ENDING/SWITCHING` 间隙 → `empty`**) / `requestSwitch(MatchModeSelection, Handoff)`(**与 `switchMode` 同一实现**,受 min-dwell 与重入约束,§3.5) / `requestDissolve(DissolveReason)`(**幂等**;仅会话级组件与内核可调) / `later(int delayTicks, Runnable task)`(句柄登记到组件,`stop` 自动取消)。`events()` 引用的 `SessionEventPort`(形状对齐 `MatchModeInstanceEventPort`:publish/subscribe、订阅句柄、随 `stop` 自动回收)在 §12.2 骨架中出现但 §12.1 未单列,随本步一并落(建议 `engine/port/`;已登记待裁决,见「要点」末条)。
4. **端口组之二**:`MatchModeInstanceAccess`(会话侧只读实例面,无写口)——`id()`/`modeId()`/`tick()`/`participants()`/`modeInfo()`/`attrs()`(**只读约定:仅 get**)/`<T extends MatchModeComponent> T component(Class<T>)`(声明序第一个;无 → null)/`<T extends MatchModeComponent> List<T> components(Class<T>)`;`SessionView`(实例侧只读会话视图)——`id()`/`members()`/`attrs()`(只读)/`<T extends SessionComponent> T component(Class<T>)`/`components(Class<T>)`;**`SessionView` 无 `events()`**(第一版实例组件不得订阅会话事件,未决 §11-Q7)。两接口 javadoc 写明:**只读是架构纪律 + review 条款**(无法机械强制);**不得缓存实例组件引用越过切换**(现取不缓存,D5)。`MatchModeInstancePort` 只加 `SessionView session()` 一行。
5. **SessionComponentRegistry**(容器,职责逐项):`bind(id, snapshot)` 幂等——同会话重复绑定同 id 抛 `IllegalStateException`,**id 跨类型去重(同一命名空间)**;装配期依赖校验(算法逐行照 §2.6 六行换成会话级类型:自己不算自己的提供者、环不检查、缺必需依赖抛 `ComponentDependencyException`);`createAll(svc)` 按**声明序** `create(id, svc)`;**声明序** `awakeAll`/`startAll`;`tickAll()` 逐组件广播 `update()`;`stopAll()` **逆序** `stop`;`reclaimRegisteredResources()`(订阅/延时任务/显示,幂等)与实例级同法(§1.3 步 4);**故障隔离**(见步骤 9)。注册表**不持有组件状态,只持描述符与实例引用**;每会话一份。
6. **SessionSpec 扩展 + 2.1 回改**:`SessionSpec` 追加 `sessionComponents` 字段(有序;构造做防御性拷贝、暴露不可变视图);`SessionPolicy` 的空场判定与 `Session.idleTimers()` 的空场部分**删除**(D11)——空场时长改由 L0 读配置喂组件(步骤 12;**★v1.3-D5:改由宿主组装 spec 时喂组件**——L0 读配置口径废止,21-D5);`SessionPolicyTest` 的空场断言移入 `EmptyArenaComponentTest`(★31),宽限断言不动。
7. **Session 挂注册表**:`Session` 增加 `SessionComponentRegistry` 字段(构造期随 `SessionSpec` 建立)、包级 `tickSessionComponents()`(委托 `registry.tickAll()`,隔离语义在内)、`sessionComponentCapabilities()` 读口(供 A2 并集);`Session` 本身**不持有会话组件的状态**(§2.8-决断三扩展)。
8. **SessionServiceImpl 装配接线**(**公开方法签名不变**):`create(spec)` 内——建 `Session` 骨架 → `registry.bind`(逐 Spec `freeze()` 快照,id 去重) → `verifyDependencies()`(缺会话级必需依赖 → 抛,**会话创建失败**,L0 SEVERE;arena 则该竞技场不启动) → 按声明序 `create(id, sessionServices)`(**构造期注入 svc,四条件同实例级**) → `awakeAll()` → `startAll()` → 发 `SessionCreated` → 走首次 `switchMode`(初始模式)。**会话组件先于首个实例就绪**——首实例的组件才查得到它们。
9. **dissolve 回收接线 + 故障隔离**:`dissolve`——`DISSOLVING` →(若有实例)`close()` → 会话组件**逆序 `stop` + `registry.reclaimRegisteredResources()`** → 成员传送主城 → 释放世界句柄 → 从注册表摘除 → 发 `SessionDissolved`(**`stop` 由框架无条件调用,无单例豁免条款**——这正是"组件"与"内核机制"的分界)。隔离(会话级 quarantine,D9):`update`/`onEvent` 抛异常 → 记日志(会话 id/组件 id/原因)→ 对该组件 `safeStop` + 打标 quarantined(此后跳过其派发)→ 发 `SessionComponentQuarantined` → **会话不解散**,其余组件照常;与实例级的差异写入 javadoc(实例级隔离 → `end()` 有兜底;会话级没有回退目标,停用单个策略组件是可接受的降级)。
10. **EngineTicker.tickAll 四步**(顺序是规格的一部分):① `runPendingSwitch()`(机制,不变)→ ② 当前实例 `tick()`(若有实例;派发实例组件 `update`,不变)→ ③ **`tickSessionComponents()`(每 tick 必调,与实例有无无关;逐组件 try/catch → D9 隔离)** → ④ 内核 sweep(断线宽限等,机制不变)。切换间隙:② 跳过、③ 照常(§11.4)。
11. **EmptyArenaComponent**(`component/session/`,§6.4):Spec 构造数据 `after`(空场持续时长);`start` 订阅 `MemberJoined`/`MemberLeft`;`update` 维护空场起点(无成员 → 起算;有成员回归 → **重置计时**);到点 `svc().self().requestDissolve(DissolveReason.EMPTY)`(**幂等,恰一次**);`stop` 与 `start` 严格对称(订阅随框架回收,不手写 cancel)。**计时的量纲**:update 每 tick 推进、`after` 折算 tick(与 §3.5 min-dwell 的 ticks 量纲、`later(int delayTicks)` 同源),离线测试以推进 tick 的假时钟驱动、不吃真实时间(量纲设计案未钉死,落地时二选一并在 javadoc 注明,见「要点」末条)。
12. **L0 装配接线**(`HydroKarbsPlugin.onEnable`,§6.4):按 `session.topology` 构建 `SessionSpec.sessionComponents`——**rotation 不挂**(空表,常驻永不解散)、**arena 挂**(`List.of(new EmptyArenaComponent.Spec(Duration.ofSeconds(seconds)))`,`seconds` 读 `session.dissolve-after-empty-seconds`);**键保留、消费者变更为 L0**(§15.2);引擎零感知(拓扑差别只在装配期,没有一个 `if (topology == ARENA)` 超出装配函数,§3.6 口径);L0 装配点唯一,模式侧零代码。(**★v1.3-D5:整段口径废止**——`session.topology`/`session.dissolve-after-empty-seconds` 键与 L0 建会话/装配分支删除,框架 onEnable 零会话;**会话组件表由宿主组装** `SessionSpec.sessionComponents`(要空场策略就挂 `EmptyArenaComponent.Spec` 并自供 `after`,不挂 = 永不解散),「装配点唯一、模式侧零代码、引擎零感知」纪律不变,装配主体自框架 L0 移宿主,21-D5)
13. **CapabilityRegistry 扩展 + A2 并集**(★32 会话侧,D6):会话组件在装配时把 `Snapshot.capabilities` 登记入**本会话标签集**(随会话存活、随 dissolve 消灭);切换阶段 A2 校验改为 `mode.meta().requiredCapabilities() ⊆ CapabilityRegistry.available() ∪ 本会话会话组件标签`;缺任一 → `REJECTED_BY_TARGET_MODE`,**detail 列缺失标签**(机制不变,只扩可用集来源);引擎零字面量(标签词汇由提供方定义)。推荐取"本会话标签集并集"而非进程级 `register/unregister`(`"role"` 标签的进程级注册路径归 3.3——宿主扩展线,迁 Shdf 侧;理由与备选见「要点」末条)。

## 关键实现要点

- **每会话一份的机械保证**:注册表挂在 `Session` 上,**不是进程级静态**;同一 Spec 可跨会话复用(共享的只能是不可变声明 Spec/`Snapshot`/`SPEC` 常量),有状态实例永不跨会话共享——`SessionComponentSingletonTest` 冻结(★27)。
- **声明序纪律**:装配序 = 声明序 = 派发序;`stop` **逆序**;`update`/`onEvent` 按声明序广播。不用"我把两件事写在同一 `update()` 里的先后"表达顺序,顺序靠表本身(14.30)。
- **两种失败语义不可混淆**(对照表):

  | 时机 | 行为 | 后果 |
  |---|---|---|
  | 装配期 `awake`/`start` 抛 | 会话创建失败(响亮,L0 SEVERE) | arena 则该竞技场不启动;不静默降级 |
  | 运行期 `update`/`onEvent` 抛 | 该组件 `safeStop` + quarantined(跳过其派发)+ 发 `SessionComponentQuarantined` | **会话不解散**、其余组件照常(D9) |

- **切换零参与**:会话组件表**不参与模式切换**——切换的 A/B 两阶段与装配代码零改动;切换前后会话组件实例恒等、`update` 计数连续(`SessionComponentSurvivesSwitchTest` 冻结:100 次切换,★33)。
- **"不挂 = 默认"**:rotation 不挂任何空场组件 = **永不解散**(镜像 `JoinControlComponent` 的"不挂 = 默认全接纳");隔离停用空场组件时行为同样退回"永不解散"并留日志(§6.4)——大厅零配置哲学一致。
- **与实例级的同构/差异一览**(评审对照用):

  | 维度 | 同构 | 差异 |
  |---|---|---|
  | 契约 | 同名五钩子、注入四条件、`Specification`/`freeze`/`Snapshot`/`Factory` | 挂载级与装配来源:随会话、由 `SessionSpec` 表(模式无权) |
  | 派发 | 声明序广播、`stop` 逆序、登记资源回收 | `update` 与"当前是否有实例"无关(切换间隙照常 tick) |
  | 端口面 | svc 服务集成员封闭 | 无 `map()`/`cfg()`/`handoff()`(那是实例面);多 `currentInstance()` 与两个行动口 |
  | 失败 | 隔离打标 + 可观测 | **不解散**(实例级隔离 → `end()` 有兜底;会话级没有回退目标) |

- **常见实现偏差对照**:

  | 错误做法 | 为什么错 | 正确做法 |
  |---|---|---|
  | 注册表做成进程级静态单例 | arena 下 N 个会话串台(★27) | 注册表挂在 `Session` 上,每会话一份 |
  | 会话组件字段里缓存 `MatchModeInstanceAccess`/实例组件引用 | 切换后悬空;吞掉"无实例"合法状态(14.27) | 现取不缓存;要留存就记**会话级**状态 |
  | 把名册/世界/切换搬进会话组件 | 可靠性底线失守,隔离停用即永久降级(14.28) | 机制留内核;组件只接策略/裁决/聚合/展示(D7 两问) |
  | 装配期异常按"隔离"处理 | 会话未就绪,坏组件带着起跑 | 装配期抛 → 会话创建失败(响亮) |
  | 模式 Builder 里注册/增删会话组件 | 违反 D4(装配来源唯一 = L0) | 只有 L0 构建 `sessionComponents` |
  | 切换时重装会话组件表 | ★33 破功,会话状态随切换丢失 | 表不参与切换,A/B 与装配代码零改动 |

- **待裁决登记**(设计案未钉死处,本文件按最小自洽实现落,提请统筹):①`SessionEventPort` 的位置与形状(§12.2 骨架引用、§12.1/§0.5.5 未单列);②会话能力标签的登记路径(本会话标签集并集 vs 进程级 `CapabilityRegistry.register/unregister`——arena 并发下后者需保证多会话同标签不互踩);③空场计时的量纲(`after` 为 `Duration`,按 tick 折算落地);④**D2 的"订阅实例事件"无接口落点**(会话侧订阅面仅 `SessionPort.events()`/会话事件;删该半句或补订阅面待上游裁决;登记见 ADR-0004 D2 落盘注与 03 §3.8);⑤**D3 的 `bind`"幂等"与"重复同 id 抛"语义相抵**(实现口径待上游澄清——候选:"同 id 同快照幂等去重、异快照抛",或"重复即抛"并删"幂等"字样;实例级对照见 1.3 步骤 4;登记见 ADR-0004 D3 落盘注)。

## 陷阱与纪律

- §14.27 会话级组件缓存实例组件引用——`currentInstance()` **现取不缓存**;`empty` 覆盖"无实例"与 `ENDING/SWITCHING` 间隙两种合法情况,不得回落到旧值。
- §14.28 把机制职责塞进会话组件——名册/连接态/状态机/切换/WorldPort/事件总线/dissolve/min-dwell 一律留内核;归属争议先过 D7 两问,不留白。
- §14.29 跨级裸写——跨级**只读**(`SessionView#component` / `MatchModeInstanceAccess#component`),干预**只走端口**(`end()`/`switchTo()` ↔ `requestSwitch()`/`requestDissolve()`);事件是通知,不是写通道。
- §14.30 会话组件膨胀成上帝对象——`update` 每 tick 无豁免,按 D7 拆组件;组件间关系用 `requires` 显式声明。
- 引擎内容盲(施工计划 §1 强约束):`engine/**` 零 mode id 字面量;新增类型与钩子名一律非内容词(`EnginePurityTest`/`EngineHasNoModeStringsTest` 持续生效)。
- 模式无权增删会话级组件(D4,第一版):模式接入会话能力只有"读 + 声明"两条路(§13.7 软接入 / 硬依赖);把会话组件当"模式兼容层"即触发 14.28。
- 会话组件不得接触宿主扩展层(如 `bridge/role`):宿主扩展线整体非框架组成,角色接入的唯一落点在宿主侧组件、不经会话组件中转(变更指示 §5-5;`LayeringTest` 守门);角色系统接入的实现见 Shdf具体玩法设计案/08、09。
- 命名空间纪律:会话 attrs 的命名空间 = **组件 id**,`"session"` 保留给内核(§2.7-③);跨级往他人命名空间写与 14.26 同级违规。
- `stop` **无条件调用、无单例豁免**——"我只有一个实例所以不用停"是错误心智;与 `start` 严格对称,登记资源由框架回收。
