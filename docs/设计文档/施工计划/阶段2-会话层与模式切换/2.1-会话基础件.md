# 2.1 会话基础件

> 对应设计案:`03-会话与模式切换.md` §3.1(Session 状态机与职责表)、§3.6(部署拓扑)、`02-核心概念.md` §2.8-决断一(v4 修订版:机制在内核、策略可下放组件;本子阶段按 v3.2 口径施工,空场部分的改造见 2.6)、§2.7(AttributeBag);路线图:`16-路线图与验收.md` §16.1-P1;前置:阶段1(P0 容器与事件、1.1 Threads、1.3 `MatchModeInstance#close`、1.4 架构测试族)

## 目标

本子阶段结束时,`engine/session/**` 拥有一组**可离线单测**的会话数据件与状态机骨架,新增的可验证物:

1. Session 可被直接构造并持有状态机(RUNNING/ENDING/SWITCHING/DISSOLVING),非法迁移被守卫拒绝——尚无切换(`SessionService` 在 2.3);
2. 名册支持原地位移与断线宽限:成员进/出/断线/重连的登记语义固定,★16「名册零搬运」的名册侧断言在本子阶段建立(2.3 扩全链路);
3. 空场策略可计时(rotation 常驻不解散 / arena 空场 300s 触发回调),断线宽限可扫描(默认 60s);
4. 七类会话事件可发布/订阅(内部总线,非 Bukkit Event)。

有序步骤:

1. **SessionId**:`record SessionId(String value)`;`shortCode()` 返回小写、仅 `[a-z0-9_-]` 的安全文件名形式(2.4 副本目录名 = mapId+短码,§3.7 接口注释「目录名 = mapId + "-" + sessionId 短码」)。null/空白构造即抛(响亮失败)。取值约定:rotation 建议常量值 `main`(L0 装配传入,不在引擎写死任何语义);arena 用 `config.yml` 的 `arenas[].id`(§15.2,如 a1/a2)(**★v1.3-D5:两键已删——取值约定归宿主**:`SessionId` 由宿主构造 `SessionSpec` 时自定,框架不消费任何清单键,21-D5)。
2. **SessionSpec**:`record SessionSpec(SessionId id, String initialModeId, List<String> mapPool)`。§3.1:「spec 含初始模式(通常 lobby)与地图策略」;`mapPool` 对应 §15.2 `arenas[].map-pool`。纯数据;`initialModeId` 是字符串,Session 自身不解析它(解析是 2.3 对 `MatchModeRegistry` 的查询)。(**★v1.3-D5:`initialModeId` 字段保留——每会话首切换目标改由宿主填;`mapPool` 对应的 arenas 键已删,清单由宿主自定;「通常 lobby」为历史口径,框架不设出厂模式,21-D3/D5**)
3. **SessionMember**:`record SessionMember(UUID uuid, ConnectionStatus connection, long joinedAtMillis)`,内嵌 `enum ConnectionStatus { ONLINE, DISCONNECTED }`。**字段刻意只有这三个**——无 team/role/state,那些是实例概念(§3.1 职责表;§14.18 的编译期隔离靠这里的克制)。javadoc 写自问句:「这个数据应该活过切换吗?该活 → 会话;不该 → 实例」(§14.18)。
4. **SessionRoster**:内部 `final LinkedHashMap<UUID, SessionMember> members`(加入序=声明序,遍历稳定)。方法契约:
   - `join(UUID)`:在册即幂等返回;新成员 `joinedAtMillis=now`、`ONLINE`;
   - `remove(UUID)`:真正移除(宽限期满或显式离开时由 2.3 调);
   - `markDisconnected(UUID, long atMillis)`:置 `DISCONNECTED`,**不移除**——宽限期内成员仍在册(§3.1「宽限期内 member 保留、重连即恢复」;★16 要求宽限期成员在切换前后恒等);
   - `markReconnected(UUID)`:置 `ONLINE`;
   - `all()` 不可变视图 / `size()` / `contains(UUID)` / `onlineCount()`;
   - `disconnectedBefore(long nowMillis, long graceMillis)`:返回宽限已过的 uuid 列表(供 sweep);
   - `toParticipants()`:按当前成员集生成 `Participant` 视图列表——**每局新造 Participant,成员 uuid 集来自本名册**(§12.2 `startAll` 的位移点)。
5. **ConnectionTracker**:构造注入宽限毫秒(默认 60_000,§15.2);`onDisconnect(UUID, long nowMillis)` 记账、`onReconnect(UUID)` 销账、`sweep(long nowMillis)` 返回宽限已过者。**不自起任务**:由 `Session.idleTimers()` 每 tick 调 sweep(§14.6 禁每会话起周期任务)。与 Roster 的分工:tracker 只管"断线多久了",名册增删的执行权在 Session(2.3)。
6. **SessionPolicy**:`record SessionPolicy(Topology topology, int dissolveAfterEmptySeconds, int minDwellTicks, int disconnectGraceSeconds)`,内嵌 `enum Topology { ROTATION, ARENA }`。语义:ROTATION 常驻不解散(§3.6「永不空场解散」→ 空场计时器不启动);ARENA 空场默认 300s 自动 dissolve;`minDwellTicks` 默认 100(§3.5 防护①,2.3 消费);宽限秒与 ConnectionTracker 同源。纯数据;从 `config.yml` 构造发生在 2.3 的 L0 装配。(**★v1.3-D5:`topology`/`dissolveAfterEmptySeconds` 字段随 `session.topology`/`session.dissolve-after-empty-seconds` 键删除失去填充来源**——SessionPolicy 收敛为内核节律载体(minDwellTicks/disconnectGraceSeconds;fallback-mode 仍构造注入);空场时长由宿主组装 `SessionSpec.sessionComponents` 时直接喂 `EmptyArenaComponent.Spec.after`,不再经 SessionPolicy;字段瘦身登记 21 §5 回填义务-7,本子阶段文档不改冻结结构,21-D5)
7. **SessionState**:`enum { RUNNING, ENDING, SWITCHING, DISSOLVING }`(§3.1)。独立文件便于测试断言。合法迁移矩阵(2.3 落地写点,本步冻结枚举与守卫):

| 迁移 | 触发 | 出处 |
|---|---|---|
| RUNNING→ENDING | 组件经 `end()` 端口请求(置位,不立即切) | §3.1 状态机图 |
| RUNNING→SWITCHING | 外部 `switchMode` 阶段 A 就绪后挂起 | §3.1、§3.2 |
| SWITCHING→RUNNING | B 段 attach 成功(新模式);失败走三级回退 | §3.2 |
| RUNNING→DISSOLVING | 空场超时(arena)/管理命令/onDisable | §3.1 |

8. **DissolveReason**:`enum { EMPTY_TIMEOUT, ADMIN, SHUTDOWN, FALLBACK_DISSOLVE }`。`SHUTDOWN` 有出处(§12.2 `EngineTicker.close`);其余对应 §3.1 的三个触发源与 §3.2 二级回退;命名是建议集(设计案未枚举全,已登记待裁决)。
9. **LeaveReason**:`enum { QUIT, KICK }`(§15.1 `SessionIngestListener` 处理 quit/kick;命名是建议集)。
10. **SessionEvent**(engine/event/,与 §12.1 event/ 行的 `SessionEvent` 同包):非 Bukkit Event 的接口 + 七个 record(§3.1 事件行):

## 关键实现要点

- **原地位移是对象恒等,不是数据拷贝**:★16 的名册侧断言落点是「切换前后 `roster` 同一实例、成员集合恒等(含 DISCONNECTED 成员)」。实现纪律:内部 map 为 final;任何"切换时重建名册"的写法直接测试红。位移的另一半在实例侧:`startAll()` 调 `roster().toParticipants()` 生成新局视图(§12.2)——名册不动,参与者重建。
- **两层成员彻底分居**(§14.18):`SessionMember` 活过切换,`Participant` 随 `close()` 全灭(§2.8-决断三)。「带出去的数据走 Handoff,不许从旧实例捞」(§16.4-三律③)是 2.3 的纪律,但字段隔离在本步就已钉死。
- **状态机先行、动作后接**:本步冻结枚举+守卫,2.3 只填迁移写点——避免状态迁移散落在多个调用方(§3.1「ENDING 与 SWITCHING 是显式的中间态」;「切换永远不发生在事件派发栈内」)。
- **计时全部 piggyback 全局 ticker**:宽限扫描与空场计时是 `idleTimers()` 内的毫秒比较(§3.1「清场由 ticker 在下一 tick 驱动」同款纪律;§14.6)。
- **MemberLeft 的事件语义**(设计案未细化,按七事件+★16 推导的最小自洽实现,已登记待裁决):quit/kick 即发 `MemberLeft` 并把成员标记 DISCONNECTED 保留在册;宽限期满由 sweep 移除,不再单独发事件;宽限期内重连发 `MemberReconnected`。
- **时间源单点注入**:`idleTimers(long nowMillis)` 以参数收时间(生产传 `System.currentTimeMillis()`,测试传手动时钟)——空场/宽限的到期判定离线可测,不依赖真实睡眠。
- **只读视图纪律**:`roster.all()` 返回不可变快照或只读包装,外部(含 2.3 的切换单元)不得绕过名册方法改成员;写点唯一,收敛在步骤 4 的四个变更方法。
- **七事件与实例事件的边界**:`SessionEvent` 描述会话层事实(成员/模式/生死),`MatchModeInstanceEvent`(阶段1)描述实例层事实(参赛者/生命周期)——两族不互转、不共用类型;要跨层就同时订两条总线(2.5 的 VoteComponent 只订实例侧 `PhaseChanged`,即此边界的使用例)。
- **状态守卫的实现形态**:写点内部用断言式(`requireNotIn(...)` 违规抛 `IllegalStateException`,响亮);对外查询用 `state()` + 布尔判定(返回值表达,不抛)——两套口分开,避免调用方误吞断言异常。
- **枚举命名纪律**:`SessionState`/`DissolveReason`/`LeaveReason`/`ConnectionStatus`/`Topology` 全部是封闭枚举,语义锚定 §3.1/§3.6;新增枚举值须过设计评审——它们会进事件载荷与日志,是事实上的对外词汇。

**常见实现偏差对照**:

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 给 SessionMember 加 teamId/roleId 字段 | 两层成员混淆(§14.18) | team/role 只在 Participant |
| 宽限期内直接 remove 成员 | 断线即除名,重连恢复无从谈起(§3.1) | `markDisconnected` + sweep 到期移除 |
| 每会话起 `runTaskTimer` 计时 | 任务爆炸+重载翻倍(§14.6) | 全局 ticker 的 `idleTimers()` |
| 名册在切换时重建集合 | ★16 名册零搬运破功 | 原地位移,集合对象恒定 |

**给 2.3/2.4 的接线契约**(本子阶段留口、后续子阶段填):

1. `idleTimers()` 的空场超时回调:构造注入 `Consumer<DissolveReason>` 形态,2.3 接 `dissolve(EMPTY_TIMEOUT)`;**★v4:该回调随 D11 自 2.6 起删除(空场计时下放 `EmptyArenaComponent`);`idleTimers` 仅剩宽限 sweep 等内核节律**;
2. 状态迁移写点:Session 对外只暴露"查询 + 守卫",迁移写点收敛为包级方法,2.3 的 `SessionServiceImpl` 是唯一调用者;
3. 世界句柄:字段位已注释预留,2.4 落 `Optional<WorldHandle>` 字段与 `worldHandle()` 读口;
4. 会话 tick 计数:2.3 编排补齐时在 Session 增加每 tick 递增的计数器(min-dwell 的驻留基准,§3.5)。

## 陷阱与纪律

- §14.18 把 SessionMember 当 Participant 用(或反之)——本步主纪律;review 时对照两张字段表,发现向 SessionMember 加 team/role/state 即打回。
- §14.6 每实例起一个周期任务——宽限/空场计时禁止 `runTaskTimer`,一律走全局 ticker 的 `idleTimers()`。
- §14.7 跨局残留——「实例状态随 close 全灭」是 2.3 的事,但名册**不**随 close 走;测试把这条边界钉死(实例换血、名册恒定)。
- 引擎内容盲(施工计划 §3.6):`engine/session/**` 不得出现任何 mode id 字面量(含 `lobby`);`SessionSpec.initialModeId` 是纯字符串,默认值由 L0 从 `config.yml` 读(`session.initial-mode`,§15.2)(**★v1.3-D5:该键已删——`initialModeId` 由宿主填入 spec,框架零默认值;本句前半「L0 从 config.yml 读」为 v1.3 前历史口径**,21-D3/D5)。
