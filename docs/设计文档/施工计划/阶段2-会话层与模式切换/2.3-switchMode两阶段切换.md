# 2.3 switchMode 两阶段切换

> 对应设计案:`03-会话与模式切换.md` §3.2(两阶段算法与三级回退)、§3.3(Handoff)、§3.4(EndResult/TransitionIntent)、§3.5(四类防护)、§3.6(拓扑只在 L0);`16-路线图与验收.md` §16.2-★14/★15/★16/★18 首建、★6/★7 切换路径复测;路线图:§16.1-P1;前置:2.1(会话基础件)、2.2(注册表/配置)、阶段1(容器 close 语义、EngineTicker、1.1 Threads);弱依赖 2.4(面向 `WorldPort` 接口编程,实现体 2.4 到位,测试注入假实现)

## 目标

本子阶段结束时,`SessionService#switchMode` 成为**引擎里唯一的切换路径**,新增的可验证物:

1. 阶段 A(A1~A6)准备可异步、对旧实例零副作用——任何准备失败旧实例继续 tick;
2. 阶段 B(B1~B5)由 ticker 驱动、主线程单 tick 原子;三级回退绝不停在中间态;
3. 拒绝码收缩为 3 个(§0.5.3),四类防护(§3.5)全部生效;
4. 外部入口可用:Brigadier `/sm switch`、`SessionIngestListener` 路由 join/quit/kick;
5. 离线单测:★14/★15/★16/★18 首建,★6 close 幂等与 ★7 清场逆序在切换路径复测。

## 关键实现要点

- **挂起-驱动是本子阶段的骨架决策**:A 完成后不在当前调用栈里做 B,而是挂起计划、由 ticker 下一 tick 执行——同时满足「切换永远不发生在事件派发栈内」(§3.1)、「切换只由 EngineTicker 驱动」(§16.4-三律①)、「EngineTicker=切换的唯一驱动点」(§12.2)与防护②(§3.5)。`CompletableFuture` 的完成点在 ticker 的 B 段,绝不在异步线程(§14.1)。
- **挂起计划对象**(A 完成与 B 执行之间的唯一交接物,字段封闭):sessionId、mode(`MatchMode`)、map(`MapDefinition`)、cfg(`MatchModeConfig`)、world(`WorldHandle`)、payload(`Handoff`)、目标选区(`MatchModeSelection`)、发起时会话 tick——B 段从计划执行,**不再回查注册表**(A 阶段的裁决在挂起时刻已冻结;唯一例外是防护③的人数重校验,§3.5)。
- **A 段的执行线程决策**:A1~A5 是内存只读检查,主线程同步完成(§3.2「准备阶段可异步」说的是允许、不是必须;同步最简单且无并发可见性问题);异步的只有 A6。
- **A 阶段对旧实例零副作用**:A1~A5 全是注册表/元数据/名册的只读检查(★14① 的底气);唯一可能耗时的是 A6(§3.2 注),它失败也只是"这次切不成"。
- **拒绝码纪律**:新增拒绝场景先问"调用方要据此做什么决定?"——答不出就进 `detail`(§0.5.3 收缩论证);`detail` 是人读清单,只进日志与提示,不是可编程契约。
- **fallback 是配置项**:实现里 fallback id 与任意模式 id 同构地走 `registry.require`;`LobbyIsJustAModeTest`(2.5)断言大厅与其他模式切换路径逐字相同。
- **merge 方向固定**:B3 中 external 覆盖 outgoing(§3.3)——方向写反 = 管理员强切被旧实例自报数据劫持。
- **min-dwell 的计时基准**:Session 维护会话级 tick 计数(`tickAll` 每 tick 递增;2.3 编排补齐时加入 Session,见 2.1 接线契约第 4 条);B5 写 `lastSwitchTick`;比对用计数差 < `policy.minDwellTicks`。不用真实时间——与 §3.5 的"ticks"量纲一致,且离线测试时钟可推进。
- **`/sm switch` 规格**:Brigadier `literal("switch")` + 必选 `mode`(suggestion 取 `registry.all()` 的 id)+ 可选 `map` + 可选 `force`;权限建议 `shdfmatch.command.switch`;拒绝时以文本回显 `detail`(人读清单,§0.5.3),成功回显 from→to;命令体只做参数装配后委托 `SessionService`,零业务分支(L0 判据,§1.2)。
- **`Succeeded.cause` 的语义**:携带触发本次切换的 `EndResult`(§3.2 记录签名)——外部 force 切换时为 `nowhere()`,自动切换时为结束请求原样透传;调用方据此区分"主动切"与"打完自动切"。
- **dissolve 与 switchMode 的互斥**:DISSOLVING 期间一切 `switchMode`/`join` → 拒绝(状态守卫);`dissolve` 对 SWITCHING 中的会话 = 先作废挂起计划(future 以 Rejected 完成)再走解散——绝不让解散与切换并行推进。

**常见实现偏差对照**:

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| A 就绪后在回调栈里直接执行 B | 切换进入事件派发栈(§3.1、§14.17) | 挂起计划 + ticker 下一 tick |
| 回退时 new 一个大厅特判 | 大厅特权(§14.21) | 递归 `switchMode(fallback 配置 id)` |
| B 失败后留下半装配实例 | 成员无实例/双实例并存 | 先 closeAll 再回退,绝不驻留中间态 |
| 自造第 4 个拒绝码 | 码表是冻结契约(§0.5.3) | 并入 `REJECTED_BY_TARGET_MODE` + detail |
| future 在异步线程完成 | 完成回调的消费者误判线程(§14.1) | 完成点收敛在 ticker 的 B 段 |
- **`force` 的两个豁免点**:A4 人数下限(§3.2-A4)与 min-dwell(§3.5)——其余检查(能力/地图/依赖)不因 force 跳过。

| 入口 | 产出者 | force | 示例 |
|---|---|---|---|
| ① 外部调用 | 管理命令 `/sm switch`、第三方(7.1 `MiniGameApi`) | 可带 | 强切任意已注册模式 |

## 陷阱与纪律

- §14.16 切换风暴——min-dwell 100 tick:自动切换(EndGate 显式意图/缺省数据,即 §3.4 编号的①③)一律受限,仅外部 force 豁免;拒绝时 WARN 注明剩余 tick。
