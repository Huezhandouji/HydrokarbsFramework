# 2.4 WorldPort 世界生命周期

> 对应设计案:`03-会话与模式切换.md` §3.7(WorldPort 接口/规则表/ResetStrategy)、§3.5 防护④(准备超时 30s);`12-代码骨架.md` §12.1(`engine/port/WorldPort`、`bridge/world/WorldPortImpl`);`16-路线图与验收.md` §16.2-★17;路线图:§16.1-P1(bridge/world 最小实现);前置:2.2(模板目录约定与默认资源)、2.3(A6 调用点与释放接缝)、阶段1(1.1 Threads)

## 目标

本子阶段结束时,世界的实例化/引用计数/释放有一个**只有 SessionService 调用**的端口实现,新增的可验证物:

1. 同图并发各得独立副本:副本目录名 = mapId+会话短码,互不干扰(§3.7);
2. 同 (map,session) 重复 acquire 幂等返回同句柄;并发 acquire 合并到同一次复制;计数归零才处置(§3.7 规则表);
3. 释放按 `ResetStrategy` 处置副本(REUSE_DIRTY 保留目录 / TEMPLATE_RESTORE 删除目录);
4. 准备超时 30s(§3.5 防护④):超时/缺模板 → acquire 异常完成,旧实例无感知;
5. ★17 `WorldRefCountTest`(100 次切换零泄漏)首建并**永久生效**——任何后续阶段不得为通过功能放宽其断言(施工计划 §3.4);
6. 副本目录的创建/清空/删除全部限定在本实现管理的路径形态内(安全边界,见「关键实现要点」)。

## 施工步骤

路径相对 `src/main/java/com/shdf/match/`。

**新增文件清单**:`WorldPort`/`WorldHandle`/`ResetStrategy`(engine/port/,若阶段1未建)、`WorldLoader`/`BukkitWorldLoader`/`WorldPortImpl`(bridge/world/)、`WorldRefCountTest`(test/…/session/)。

**路径与目录约定**:

| 项 | 值 | 出处 |
|---|---|---|
| 模板根 | `<dataDir>/maps/templates/`(数据目录默认 = `plugins/HydroKarbs/`) | §15.2 文件分工 |
| 模板目录 | `<模板根>/<mapId>/`(世界目录母本) | §3.7 规则表「模板」行 |
| 副本根 | 服务器根(Bukkit 世界容器目录) | 加载即被 Bukkit 识别 |
| 副本目录名 | `<mapId>-<sessionId.shortCode()>` | §3.7 接口注释「目录名 = mapId + "-" + sessionId 短码」 |
| 短码来源 | 2.1 `SessionId.shortCode()`(文件名安全化) | 2.1 步骤 1 |
| 副本目录名即世界名 | `instanceName` = 副本目录名,`WorldCreator.name(instanceName)` | 步骤 4/5(Bukkit 以目录名识别世界) |
| 残留防御 | 副本目录已存在 → 复制前先清空 | 上次异常残留的兜底 |

有序步骤:

1. **WorldPort**(engine/port/;§3.7 接口逐字):
   - `CompletableFuture<WorldHandle> acquire(MapDefinition map, SessionId forSession)`;
   - `CompletableFuture<Void> release(WorldHandle handle)`——引用计数归零 → 按句柄的 ResetStrategy 处置副本;幂等,重复 release 无害。
   - javadoc 写明规则表行 1:**只有 SessionService 调用**(acquire 在切换阶段 A6,dissolve 时 release);模式与组件只消费 `svc().map()` 的地图数据,不知道世界从哪来(§3.7)。
2. **WorldHandle**:`record WorldHandle(World world, String instanceName, MapDefinition map, ResetStrategy reset)`(§3.7)。§12.1 未单列此类型,就近置于 `engine/port/`(与 WorldPort 同包),已登记待裁决。
3. **ResetStrategy**:`enum { REUSE_DIRTY, TEMPLATE_RESTORE }`(§3.7):REUSE_DIRTY 打完不重建(靠 CleanupComponent 把方块/实体还原,快,适合回合制连续开局);TEMPLATE_RESTORE 切走时删除副本、下次 acquire 从模板重新复制(慢但绝对干净,适合破坏性玩法)。来源:`MapDefinition` 的 `reset-strategy` 字段(§15.2 地图 yml);v1 的 `world-unload-on-close` 配置项不迁移、删除(§3.7 规则表末行)。
4. **WorldLoader**(bridge/world/)——主线程世界装卸的**抽象缝**:
   - `World createWorld(String instanceName, Path copiedDir)` / `boolean unloadWorld(World world, boolean save)` / `List<String> loadedWorldNames()`;
   - `BukkitWorldLoader` 实现:`WorldCreator.name(instanceName).createWorld()`;`Bukkit.unloadWorld(world, save)`;`Bukkit.getWorlds()`。
   - 理由:线程契约(必须主线程,§3.7)与可测性(★17 离线跑)集中一处——code review 只看这一个文件。
5. **WorldPortImpl**(bridge/world/)——引用计数表与两条流水:
   - **引用计数表**:`ConcurrentHashMap<CountKey, RefEntry>`;`CountKey = (mapId, sessionId)`;`RefEntry { AtomicInteger count; WorldHandle handle }`。同 key 重复 acquire:+1 并幂等返回同句柄(规则表行 2);切换到同图同策略时句柄复用——回合制连打同图零复制成本。
   - **并发合并**:同 key 两请求同时 miss 时,先到者放入 in-flight future(`putIfAbsent`),后到者直接等待同一 future——同图并发只复制一次。
   - **acquire 流水**(七步):①主线程入口查表(miss 才走后续);②挂 in-flight;③虚拟线程复制模板目录→副本目录(先清残留);④`Threads` 回主线程;⑤`worldLoader.createWorld(...)`;⑥包装 `WorldHandle` 入表 +1、清 in-flight;⑦完成 future。整体 `orTimeout(30, SECONDS)`(防护④,§3.5);超时/失败 → future 异常完成 + 清 in-flight,调用方(A6)转 `REJECTED_BY_TARGET_MODE`,旧实例未动;缺模板目录 → 同一失败路径(§3.7 模板行)。
   - **release 流水**(六步):①未知句柄或计数已零 → 直接完成(幂等,规则表「重复 release 无害」);②计数 -1;③大于零 → 完成;④归零 → `Threads` 回主线程 `unloadWorld(world, false)`;⑤按 `reset` 分派:`REUSE_DIRTY` 保留副本目录(同会话下次 acquire 直接复载该目录、跳过复制;目录名含会话短码,天然不会跨会话混用),`TEMPLATE_RESTORE` 删除副本目录(删目录是文件 IO,丢回虚拟线程);⑥卸载失败 → SEVERE 日志 + 保留目录,不阻塞调用方。
   - 复制源恒为模板目录;REUSE_DIRTY 的"复用"只发生在**同会话**(句柄级/目录级),不引入跨会话脏副本。
6. **接线 2.3 三处接缝**:A6 改注入真 `WorldPortImpl`;B5 成功后 `release(旧句柄)`(**try/finally**,§14.19;同图复用时句柄未换、无释放);`dissolve` 的 finally 里 `release(当前句柄)` 兜底(规则表「释放时机」行:换图切换完成之后释放旧句柄;dissolve 的 finally 兜底)。
7. **L0 装配**:`onEnable` 构造 `WorldPortImpl`(模板根 = `dataDir/maps/templates`,§15.2 文件分工)注入 `SessionServiceImpl`;**onEnable 不做任何模板预复制**(§14.2)。
8. **模板物料规程**(2.5 实测要用,本子阶段先定):`maps/templates/lobby_main/`、`maps/templates/lobby_mini/` 两个世界母本目录——runServer 首次生成的默认世界改名入位即可;模板内容本阶段不要求(能加载、有出生点即可)。

**与 §3.7 规则表的逐行对照**:

| 规则表行 | 本实现落点 |
|---|---|
| 谁调用:只有 SessionService | `WorldPort` javadoc + 调用点仅 `SessionServiceImpl` 两处(A6/release);review 可 grep 验证 |
| 引用计数:同 (map,session) 幂等同句柄;同图同策略复用 | `CountKey`/`RefEntry` + 并发合并 |
| 释放时机:换图完成后释放旧句柄;dissolve finally 兜底;泄漏由 WorldRefCountTest 冻结 | 2.3 三接缝 + 本步骤 6;★17 |
| 模板:`maps/templates/<mapId>/`;策略由 MapDefinition 声明 | 步骤 3/5;`reset-strategy` 字段(§15.2) |

**两条流水的线程时序(文本)**:

```
acquire:  主线程(查表) ──miss──▶ 虚拟线程(复制模板 → 副本目录)
                                        │ 复制完成
                                        ▼
              主线程 ◀── Threads 回程 ──
                │ createWorld + 入表 +1 + 清 in-flight
                ▼
              future 完成(WorldHandle)          [整体 orTimeout 30s]

release:  主线程(计数 -1) ──归零──▶ 主线程(unloadWorld)
                                        │ 卸载完成
                                        ▼
              虚拟线程 ◀── 分派 ── TEMPLATE_RESTORE 删目录 / REUSE_DIRTY 保留
                                        ▼
              future 完成
```

**常见实现偏差对照**(code review 清单):

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 在虚拟线程里 `createWorld` | 随机 `Asynchronous world` 异常(§14.1) | 只在 `WorldLoader`(主线程)内 |
| release 直接删目录不卸载世界 | Bukkit 仍持引用,下次加载撞名 | 先 `unloadWorld` 再删目录 |
| 换图切换前释放旧句柄 | 旧实例仍在 tick,世界被抽走 | B5 成功后(新世界已就绪)再释放(§3.7 释放时机行) |
| REUSE_DIRTY 的目录给别的会话复载 | 跨会话脏副本共享(§3.7 副本独立性) | 目录名含会话短码,复用只限同会话 |
| 在主线程同步删大目录 | 阻塞主线程一 tick 以上 | 删目录丢回虚拟线程(§3.7 线程注释) |
| 用真实时间做 30s 超时 | 测试不可控、离开主线程 | future `orTimeout`(§3.5 防护④) |

## 关键实现要点

- **两段线程纪律**(§3.7 接口注释 + §16.4-三律②):复制/删目录 = 虚拟线程;`createWorld`/`unloadWorld` = 主线程;回程一律经 `Threads`(§14.1),future 完成点定在主线程回程之后。
- **幂等是三层,不靠"记得调用"**:①acquire 幂等(同 key 同句柄+计数);②release 幂等(重复无害);③释放点收敛(只有 A6 后的换图释放与 dissolve 兜底,均在 `SessionServiceImpl` 内)——★17 的全部信心来自这三层。
- **超时即失败,不降级**:30s 到点 future 异常完成 → A6 转 `REJECTED_BY_TARGET_MODE`(detail 注明世界准备失败/超时,§3.5);绝不出现"切一半等世界"。
- **`WorldHandle.world` 只活在主线程消费点**:虚拟线程段只碰 `Path`;§14.1 的规矩——方法名里有 `world` 的调用必须在 `Threads.runOnMain` 块里。
- **in-flight 必须在失败路径也清理**:超时/复制失败后从表里摘除 in-flight 条目,否则该 (map,session) 的后续 acquire 会永远等到一个已失败的 future。
- **两个执行器均构造注入**:主线程执行器(生产=`Threads` 回程,测试=同线程直跑的"模拟器")与 IO 执行器(生产=虚拟线程,测试=直跑)——线程契约因此离线可断言。
- **与 2.5 的衔接点**:①lobby_main 是 REUSE_DIRTY、lobby_mini 是 TEMPLATE_RESTORE,100 次往返让两种策略都被覆盖;②闭环中同会话重复 acquire 同图( lobby→minilobby→lobby)时,句柄换图必释放、回图重新 acquire——不依赖缓存侥幸。
- **状态不变式**(★17 之外的自检,测试以断言复检):①表中每个 handle 的 count ≥ 1;②同一 instanceName 至多一条;③in-flight 完成/失败后必清;④release 归零的条目必被移除。
- **副本清空的安全边界**:清空残留目录仅限"本实现创建的副本目录"(路径必须匹配 `<mapId>-<短码>` 形态且位于副本根,删除前断言路径形态)——绝不递归删除任意路径。
- **`release` 的返回语义**:归零处置完成(卸载+目录处置)后 future 才完成;未归零立即完成——调用方(dissolve 的 finally)无需区分两种情况。

## 陷阱与纪律

- §14.19 世界句柄泄漏——本子阶段靶心:释放点 try/finally、release 幂等、★17 冻结 100 次循环;**不在 WorldPort 之外新增第二个 release 调用点**。
- §14.1 异步回调里碰 Bukkit API——CompletableFuture 链每一环自查所属线程;`createWorld`/`unloadWorld` 只出现在 `WorldLoader` 实现内。
- §14.2 onEnable 阻塞 IO——模板复制只发生在运行期 A6;onEnable 零复制。
- §14.6 任务管理——本子阶段不新增任何周期任务;超时用 future 的 `orTimeout`,不是 `runTaskLater` 轮询。
- 调用面单点(§14.13 同款纪律)——grep 验证 `acquire(`/`release(` 只出现在 `SessionServiceImpl` 与 `WorldPortImpl` 自身,列为 review 清单项。
