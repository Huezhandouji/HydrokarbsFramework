## 目标

模式从"阶段1 里能 build 的聚合根"变成"**起服即被发现、注册、可查询**的目录"。新增的可验证物:

1. 本 jar 模式经 `META-INF/services` 一行注册、第三方经 `ServicesManager` 注册,`MatchModeRegistry.require()/all()/forMap()` 可用——2.3 的 A1/A3 与 2.5 的工厂注册都站在这上面(2.5 已迁玩法线:`../../Shdf具体玩法设计案/施工计划/2.5-大厅模式与最小闭环.md`);
2. `maps/*.yml` 与 `modes/*.yml` 解析为不可变 record,容错三铁律生效(§15.2);
3. 默认资源首次启动释放、二次启动不覆盖;
4. 坏模板(依赖校验失败)被注册闸拦截并 SEVERE,不进注册表(§2.6)。

有序步骤:

1. **MatchModeProvider**:`String id(); MatchMode build(MatchModeConfig cfg);`(CONTEXT 术语表、§7.2)。javadoc 写明 A9 两条约束:聚合根是 final 类不是接口;build 后不可追加组件,改模式=注册一个新 id(§0.2-A9)。
2. **MatchModeConfig**:模式参数只读视图接口——`getInt(String key, int def)` / `getString(String key, String def)` / `getStringList(String key, List<String> def)` / `keys(String section)` 最小口(具体取值示例属玩法线,见 Shdf具体玩法设计案/04-大厅模式.md §4.2/§4.5)。**缺键返回默认、非法值降级并 WARN 是接口契约的一部分**(§15.2 铁律 1/2)。§12.1 未列此类型,按消费方就近置于 `engine/mode/`(聚合根与 SPI 签名直接消费),已登记待裁决。
3. **MatchModeConfigLoader**:读 `plugins/HydroKarbs/modes/<id>.yml` 产出 `MatchModeConfig` 实现(`YamlMatchModeConfig`,内部类或同包)。文件缺失 → 空 config + WARN(容错可用,铁律 1);解析异常 → `ConfigException` 带文件名(§15.2 骨架)。
4. **map/ 五 record**(§12.1 map/ 包;引擎与桥接共享、零 Bukkit 依赖):

   - `NamedRegion(String id, RegionType type, …, List<String> tags)`:cuboid(min/max)/cylinder(center/radius/height)/sphere(center/radius) 三形(§15.2 crossfire.yml 出现过三种);附纯几何 `contains(double[] xyz)`;
   - `RegionSet`:不可变集合,按 id 查、按 tag 过滤;
   - `InteractPoint(String id, double[] pos, double radius, String tag, String anchor)`(§15.2 interact-points 格式);
   - `MapDefinition` 字段表:

     | 字段 | 类型 | 来源键(§15.2) |
     |---|---|---|
     | id / displayName / world | String | `id` / `display-name` / `world` |
     | tags | Set<String> | `tags`(模式按 tag 匹配,§12.2) |
     | bounds | Bounds(min/max) | `bounds.min` / `bounds.max` |
     | spawns | Map<String,List<SpawnPoint>> | `spawns.<组名>`(键=出生点组名,如 lobby/attacker) |
     | regions | RegionSet | `regions.*`(cuboid/cylinder/sphere,§15.2 三形) |
     | interactPoints | List<InteractPoint> | `interact-points.*` |
     | metadata | Map<String,Object> | `metadata.*`(min-players/authors 等,透传不解释) |
     | resetStrategy | ResetStrategy | `reset-strategy`(§3.7) |

   - 静态 `from(Map root, String fileName)` 内含校验:缺 `id`/`world`/`tags` 即 `ConfigException`(响亮;§15.2 铁律 3 的"局部失败")。
5. **MapRegistry**:`byId`/`byTag(String)`/`all()`;整体引用 `volatile` 原子替换(§15.2 热重载纪律:「虚拟线程解析 → 主线程原子替换 MapRegistry 引用」);持有旧快照者不受替换影响。

   **装载与注册时序的不变式**:
   1. `saveDefaults()` 先行——已存在的用户配置永不被覆盖;
   2. `loadAll` 局部失败跳过+SEVERE,装载结果要么全量要么缺件可查(日志点名文件);
   3. `discover()` 双发现:ServiceLoader 先(本 jar)、ServicesManager 后(跨插件);每个 provider 走 `build → verifyDependencies → putIfAbsent`;
   4. 收尾不变式:注册表中每个 `MatchMode` 都已通过依赖校验(§2.6 注册闸);重复 id 在入表前已响亮失败。

## 关键实现要点

- **两类失败语义不要弄反**:重复 id 是装配期错误→响亮抛 `IllegalStateException`;单模式依赖校验失败→跳过+SEVERE 继续装其余(§12.2 的两种写法;§15.2 铁律 3 的分寸)。整仓 0 个模式可注册属合法状态(阶段2 早期),不打 ERROR。
- **注册期 build 一次、进程级复用**:聚合根 build 后不可变,注册表持有同一实例,切换期不再重建(§2.3「模式模板因此可以是进程级单例」);`MatchModeConfig` 随注册缓存,`/sm reload modes` 之前 no-op。
- **tag 匹配是唯一的模式↔地图耦合面**:`MatchMode.mapTags × MapDefinition.tags` 交集(§12.2 `forMap`;Shdf具体玩法设计案/04-大厅模式.md §4.3 注「同一条 tag 匹配规则」);地图 yml 不写规则、模式 yml 不写坐标(§15.2 两个文件的分工)。
- **解析层零 Bukkit 依赖**:`map/` 五 record 与 `YamlCodec` 不 import Bukkit——离线可测(★9 的同款思路);`World`/`Location` 换算推迟到消费点(2.4/2.5)。
- **默认 `config.yml` 是后续所有阶段的取默认值基准**:含 v3.1 注释(`role-sample-interval` 已删、`display-refresh-interval` 移入 `display:` 块,§15.2 注)。
- **热重载分级预留**(§15.2 `/sm reload` 三级:config/modes/maps):本阶段只落 `loadAll`(启动期一次性);分级 reload 命令属后续阶段,但 `MapRegistry` 的引用原子替换本阶段就位——reload 的实现只是再次 `loadAll`+换引用。
- **注册期不强制"有图"**:`forMap` 空交集是合法状态(地图可后补);地图适配的强制点在切换 A3 的 `checkMap`(2.3),不在注册表。
- **`MatchModeConfig` 缓存与 reload 的关系**:注册期 build 只发生一次(§2.3 进程级单例);`/sm reload modes` 的语义是"新会话生效、进行中实例不受影响"(§15.2)——命令入口留待后续,本阶段保证 ConfigRepository 可整体重建。
- **SPI 文件是"新增模式"的唯一登记处**:新增一个模式的全部非模式代码动作 = 一行工厂 FQCN + 一份 modes yml(§13.1-#7/#5);2.5(玩法线,Shdf 侧)的两行注册即是对这条路径的第一次走通验证。

**常见实现偏差对照**:

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 缺键裸取 `getInt("x")` | 0/空语义埋雷(§15.2 铁律 1) | 全部带默认值 |
| 单地图失败中断全部装载 | 一个坏文件瘫痪全服(铁律 3) | 跳过该文件 + SEVERE,其余照常 |
| 重复 id 静默覆盖 | 先到者被无声替换 | `putIfAbsent` + 抛(§12.2) |
| 在注册表/装载层特判某模式 | 引擎认识内容(§14.21 同源) | 只认 id/tag/依赖校验结果 |
| 解析层 import Bukkit | 离线不可测、层越界 | record 纯数据,Bukkit 换算留给消费点 |

## 陷阱与纪律

- §14.13 让模式在 engine 里注册自己——本步是反向保障:注册表在 `engine/mode/`,但**发现是声明式的**(SPI 资源行+ServicesManager),引擎零模式知识;今后任何"在 engine 里 new 某工厂"都是越界,机械验证=新增模式的 PR diff 中不出现 `engine/` 路径(§14.13)。
- §14.2 onEnable 阻塞 IO——yml 解析量小可同步;**世界模板复制绝不在此阶段出现**(2.4 运行期行为)。
- §14.12 if-else 反弹——`MatchModeConfig` 是"数据进、数据出",装载层不出现按 mode id 的 switch 分支。
- 引擎内容盲:注册表不认识任何具体模式;`forMap` 只算 tag 交集;`MatchModeProvider` 的 javadoc 不举任何具体模式名。
