## 关键实现要点

1. **快照纪律**:SessionView 在转换点一次性取值,集合 `List.copyOf`;绝不把 `Session`/`SessionRoster`/`MatchModeInstance`/组件实例放进 record(§7.2 表"值对象"行:"SessionView 是快照,不含活实例引用")。理由:实例每 tick 在变(§10.5),泄漏活引用 = 跨线程读非线程安全结构。
2. **薄委托**:Impl 除"查表 → 转换 → 返回"外不得有业务分支;api 挂 L0(§1.1 分层图),逻辑写进 Impl = 引擎外长出第二个引擎(§1.2 禁止依赖表反推)。
3. **依赖面**:api 包只准依赖 engine 契约 + JDK + Bukkit/Adventure;禁 import `mode/**`、`component/**`、`data/**` 实现(★v1.3:`data/**` 已出框架基线,历史口径)、`bridge/**`(`apiDependsOnlyOnEngine`,§16.2;`LayeringTest` 持续守)。
4. **线程契约(javadoc 冻结,依据 §10.5 逐行 + §3.2 javadoc)**:

   | 方法 | 线程 | 依据 |
   |---|---|---|
   | sessionOf/session/sessions/modes/maps/mode/createSession | 主线程调用(同步返回快照) | 会话/注册表结构非线程安全(§10.5 第 4 行) |
   | switchMode | 任意线程发起;Impl 内部 `Threads.runOnMain`(§3.2"主线程发起");future 在主线程完成 | §14.1 回调线程纪律 |
   | stats/top | 任意线程;IO 在虚拟线程(§10.3.1) | §10.5 第 12 行 |

5. **战绩副本转换的线程安全**:`thenApply` 回调跑在完成线程(虚拟线程)——转换只碰不可变 record 字段复制,不碰 Bukkit(§14.1);这与"查询方法须主线程"不矛盾:future 消费方自担时序,javadoc 提示回调里做玩家操作要回主线程。
6. **`MapInfo` 与 `com.shdf.match.map`**:`MapDefinition` 是引擎契约旁路模型(§3.7 `WorldPort` 签名用它)但包名不匹配 `..engine..` 模式——转换集中 Impl 一处;ArchUnit 按字面报红则放行 `com.shdf.match.map..` 须单独 PR 说明(施工计划 §3 纪律 4)。同列待裁决。
7. **"只增不改"的运营细则**(写进 SurfaceTest 类注释,给未来维护者):
   1. 新增方法 = 追加清单 + PR 单独说明动机与消费者(谁在调它);
   2. 改签名 = 视同删 + 增,需新消费场景论证;已有调用方(TheirPlugin 示例)同步改;
   3. 删除方法原则上不允许——先标 `@Deprecated`(javadoc 指明替代),一个发布周期后再议;
   4. 返回的 record 加字段 = 对消费者无损(构造方兼容),仍需在清单外补 record 分量断言(可选,不强求)。
8. **onDisable 注销**:显式 `unregister(MiniGameApi.class, impl)`(幂等);即使容器在插件停用时会清理注册,显式注销保证 reload 期间第三方 `load(...)` 不拿到悬挂实现——与消费侧懒解析的时序纪律对齐(§14.22 同类问题:晚注册/早注销都要有路径;该纪律的 SHDF 宿主侧实现见 Shdf具体玩法设计案/08-角色桥接.md §8.8)。

## 陷阱与纪律

- **§14.1 异步回调线程**:Impl 不留任何 `.thenAccept(v -> player.sendMessage(...))` 式代码;`CompletableFuture` 回调运行在完成它的线程(§14.1 触发场景原文)。
- **§14.18 两层成员不分**:SessionView.members 只有 uuid——把 team/role 塞进会话视图就是把 SessionMember 当 Participant 用(§14.18 后果行)。
- **§14.21 大厅特判反弹**:`modes()` 不因 lobby 出厂自带而置顶/过滤/排序;目录顺序 = 注册序(§14.21 规避行精神:引擎/API 按表查,不认识具体 id)。
- **§14.13 注册不经引擎**:Impl 不设任何"注册模式"成员——注册面是 7.2 的 `MatchModeProvider`/`ServicesManager`,查询面与注册面分离(§7.2 表"第三方注册模式"行)。
