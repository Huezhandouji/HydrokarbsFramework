1. **环境准备(一次性)**:runServer 服务器目录放好 `TheirPlugin` jar(宿主扩展插件不在框架基线,如需一并实测随 Shdf 玩法线,见 Shdf具体玩法设计案/);MySQL 起本地 8.x 实例并建库(`hydrocarbs`,§15.2);`config.yml` 按 §15.2 填默认值,`password-env`(`HYDROCARBS_DB_PASSWORD`)指向的环境变量在启动脚本里设;2 个及以上测试客户端就绪(S2 需 10 个无头客户端或协作真人)。
2. **自动批(一条命令)**:`.\gradlew.bat test`——覆盖下表全部 `[自动]` 项;记录 BUILD SUCCESSFUL 与测试计数。单条复跑用过滤器,例如:`.\gradlew.bat test --tests "com.shdf.match.architecture.LayeringTest"`、`.\gradlew.bat test --tests "com.shdf.match.api.MiniGameApiSurfaceTest"`。禁止为通过而改断言(施工计划 §3 纪律 4)。
3. **手动批**:下表 `[手动]` 5 条(5/8/10/11/12),逐条在《验收执行记录表》填:执行时间、执行人、命令/操作、结果、通过与否。记录表行模板:

   ```
   | 验收# | 执行时间 | 执行人 | 方式(命令/操作) | 结果 | 通过 |
   |---|---|---|---|---|---|
   ```

4. **压测 5 场景**(见下节):每场景一份记录(设置/步骤/观测/判据/结果),在**独立 runServer 配置目录**跑(S4/S5 污染配置与世界,压完丢弃)。
5. **发布 checklist** 逐项勾选(见下)。
6. **发布动作**:tag `release/<v>`;验收记录与压测记录归档入 `docs/release/`(7.3 迁移报告与回滚预案随 Shdf 玩法线归档,见 Shdf具体玩法设计案/施工计划/7.3-旧插件迁移替换.md);回滚预案确认仍有效。

### 验收失败处置流程(红项怎么办)

1. 定位验收条目 → 按施工计划 README §4 映射表找到**首建子阶段**(玩法线首建条目回 Shdf 侧对应子阶段);
2. 回该子阶段修复(改实现,不改断言);修测试本身须单独 PR 说明理由(施工计划 §3 纪律 4);
3. 复跑该条 + 全量自动批(防修 A 破 B);
4. 记录表追加一行"复验"记录,保留失败原记录(不覆盖)。
