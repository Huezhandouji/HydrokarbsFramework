# 4.2 目标区域与交互族

> HydroKarbs MiniGame Framework · v1.0(自 SHDFMatch 设计案 v4.1 剥离玩法重构;玩法实现见 Shdf具体玩法设计案/)

> 对应设计案:§6.1(#7 Objective / #8 Region / #9 Interaction / #17 RegionGuard)、§6.3(InteractionComponent 与长按读条事件源)、§15.1(事件优先级表)、§12.1(objective/region/interact/listener 包)、§4.3(地图 regions/interact-points 声明);路线图:P3(§16.1);前置:阶段1(基类/事件总线/EngineTicker 节拍)、阶段2 的 2.4(`map/` 包:MapDefinition/NamedRegion/InteractPoint,含 cuboid/cylinder/sphere 三形状与 bounds)、阶段2 的 2.5(IdleActivitiesComponent 回接点)。**本子阶段在推荐执行序中最先动工**——`Objective` 接口是 4.1 `ScoreObjective` 的供给方,`ProtectionListener` 是 4.4 投票 GUI 的保护面。

## 目标

本子阶段结束时,新增四组可离线测试的能力:

- 挂 `ObjectiveComponent.Spec` 即获得目标注册表、进度聚合(`globalProgress()`)与完成事件(§6.1-#7;§6.2 的显示构建函数要读它);
- 全模式默认可挂 `RegionComponent.Spec`:具名区域(cuboid/cylinder/sphere)点/实体归属查询与进出事件(§6.1-#8;数据全部来自地图声明,组件零内容词汇);
- 挂 `RegionGuardComponent.Spec` 即获得出界惩罚/传送回、违规物品防护、区域保护(§6.1-#17);
- 挂 `InteractionComponent.Spec` + `listener/InteractionListener` 即获得交互点注册表:瞬发/长按读条/开关三态与统一分发(§6.1-#9、§6.3),长按读条的事件源形态照搬 §6.3 的已验证结论,不自创。

各玩法模式对本族组件(#7 Objective / #8 Region / #9 Interaction / #17 RegionGuard)的采用矩阵与目标语义落位属玩法实现,本文不复述;原文完整见 Shdf具体玩法设计案/05-四模式矩阵.md(§5.3 复用切分表与 §6.1 组件矩阵各模式挂法列)。

## 施工步骤

1. **`component/objective/Progress.java` —— `record Progress(double current, double target, String label)`**
   - §5.2 用法原样:`new Progress(0, 1, "已安放")`。
   - 注意与 `DisplayModel.Progress`(`Component` 标签版,§6.2;★v1.3:DisplayModel 已迁 Shdf 侧 10-表现层组件.md)是**两个类型**——显示层构建函数负责适配,不合并、不互相 import 语义。

2. **`component/objective/Objective.java` —— 接口**
   - 最小面:`id()`、`progress(): Progress`(§5.2 `BombObjective` 的实现形状)。
   - 完成判定 = `current >= target`,放在 ObjectiveComponent 统一判(接口不设 `isComplete()`,避免每个实现自判漂移)。

3. **`component/objective/ObjectiveComponent.java` —— 注册表与进度聚合**
   - `Spec()` 无参(§12.1:`new ObjectiveComponent.Spec()`)。
   - 状态:`LinkedHashMap<String, Objective> registry`(注册序即聚合序)+ 已完成去重集。
   - `register(Objective)` / `unregister(String id)`;重复注册响亮抛(装配期错误早炸)。
   - `update()` 逐目标取 `progress()`:值变化 → 发布 `ObjectiveProgressed`;首次达到完成 → 发布 `ObjectiveCompleted`(去重,不重发)(§6.1-#7"完成事件")。
   - `globalProgress()`:聚合读口,§6.2 bombDisplay 直接调用——聚合算法委托步骤 4。
   - 两类事件住本包(事件词汇跟发布者走,§12.2)。

4. **`component/objective/ProgressTracker.java` —— 聚合器(内部协作者,非组件)**
   - 多目标加权汇总:输入各 Objective 的 `Progress`,输出聚合 `Progress`;权重是构造数据,缺省等权。
   - 纯函数,离线可测;ObjectiveComponent 在 `awake()` 构造它(awake 只建协作者,§9.4 职责口径)。

5. **`component/region/RegionComponent.java` —— 具名区域查询与进出事件**
   - `Spec()`(§12.1 region 包;§12.1 工厂示例 `new RegionComponent.Spec()`)。
   - **区域数据不复制**:`awake()` 从 `svc().self().map().regions`(RegionSet)取只读引用(§4.3 声明驱动;地图真值在 MapDefinition,状态唯一)。
   - 查询读口:`contains(String regionId, Location)`、`regionAt(Location): Optional`、`regionsWithTag(String tag)`、`regionOf(Entity)`(Boss/掉落物场景按需查询,不轮询非玩家实体)。
   - 几何判定沿用 `NamedRegion` 既有实现(阶段2),本组件不重写 cuboid/cylinder/sphere 几何;区域引用类型用 `map/` 包既有类型(§6.3 记作 `RegionId` 的那一位),不为交互另造平行类型。
   - **进出检测**:`update()` 对全体 Participant 逐区域比对"上一帧归属集合"(本组件唯一运行态),变化 → 发布 `RegionEntered(uuid, regionId)` / `RegionLeft(uuid, regionId)`(住本包,§12.2)。
   - 成本口径:O(参与者×区域) 纯内存比较,符合 §15.3 流水线①"微秒级"预算。

6. **`component/region/RegionGuardComponent.java` —— 出界惩罚/违规物品/区域保护**
   - `Spec()`(§12.1;lobby 工厂即有 `new RegionGuardComponent.Spec()`,其 `checkMap` 声明 bounds 需求,§4.2)。
   - **出界**:`update()` 低频抽查(每 N tick,N 为 Spec 数据)全体参与者对 `map().bounds` 的包含性;出界 → 传送回最近合法点(合法位置缓存住本组件)+ 提示(§6.1-#17"出界惩罚/传送回")。
   - **区域保护**:保护语义由区域 tags 声明(标签字符串是配置数据,组件内不出现具体标签词);本组件提供 `isProtected(Location): boolean` 读口,取消动作发生在 ProtectionListener(步骤 8)。
   - **违规物品**:禁持清单(Material 集,Spec 构造数据)命中 → 没收/警示;判定读口形态 `violation(Material): Optional<Penalty>`,执行落点在 ProtectionListener(§15.1 优先级表行)。

7. **`component/interact/ItemMatcher.java` —— 手持匹配(纯函数)**
   - §6.3 `InteractionPoint.matcher` 字段的类型。
   - 工厂方法:`any()` / `bareHand()` / `of(Material...)`;`matches(ItemStack inHand): boolean`。
   - 离线可测:对 ItemStack 判定不碰世界。

8. **`component/interact/InteractionComponent.java` —— 交互注册表(§6.3 形状照抄)**
   - `Spec()`(§12.1:`new InteractionComponent.Spec()`)。
   - **类型逐字落地 §6.3**:
     - `sealed interface Trigger permits Instant, Channel, Toggle`;
     - `record Instant(int cooldownTicks)` / `record Channel(int channelTicks, EnumSet<Interrupt> interrupts)` / `record Toggle(int cooldownTicks, boolean initialOn)`;
     - `enum Interrupt { MOVE, DAMAGE, RELEASE, ITEM_SWITCH }`;
     - `record InteractionPoint(String id, RegionId region, ItemMatcher matcher, Trigger trigger, Predicate<MatchModeInstanceView> allowed, Consumer<InteractionEvent> action)`。
   - **状态**:注册表 + 冷却表 + **活跃读条通道表(uuid → 进度/起始 tick/目标点)**(本组件唯一运行态真值)。
   - **入口**:`register/unregister/dispatch(player, event)`(§6.3 原样);`dispatch` 是 Bukkit 监听器的唯一落点:校验 allowed → 匹配 matcher → 按 Trigger 分派。
   - **长按读条(§6.3 ★结论,原样照搬)**:`Channel` 在 dispatch 落点起通道;进度在 **EngineTicker 的 1-tick 节拍**(`update()`)里推进;打断在 `PlayerMoveEvent`/`EntityDamageEvent` 上监听(`ignoreCancelled = true`);**松手检测在 `PlayerInteractEvent` 的 `RIGHT_CLICK_AIR` 分支**(RELEASE)。出处:§6.3 注明这是旧插件 `BombInteractionController` 已验证的形态。
   - 读条进度渲染:直接 ActionBar 或经 DisplayComponent 由模式(★v1.3:display 迁 Shdf 侧 10,宿主工程内接线)选择;组件提供 `channelProgress(uuid): OptionalDouble` 读口。
   - `Toggle` 维护每点开关态;`Instant` 维护冷却表;交互触发/打断发布实例总线事件(类型住本包)。

9. **`src/main/java/com/shdf/match/listener/InteractionListener.java` —— Bukkit 事件入口(只路由)**
   - `PlayerInteractEvent`:**NORMAL + ignoreCancelled=true**(§15.1:"只处理真正生效的交互,被取消的不该起读条");LEFT/RIGHT 分支转 `dispatch`;`RIGHT_CLICK_AIR` 分支先查活跃通道做 RELEASE 打断(§6.3)。
   - `PlayerMoveEvent`:**MONITOR、只读观察**(§15.1:"打断读条用的只读观察;高频事件,内部必须先做廉价判断再做事")——第一步查"该 uuid 是否有活跃通道"(O(1)),无则立即返回;有再算移动语义,命中 MOVE 打断。
   - `EntityDamageEvent`:打断 DAMAGE,`ignoreCancelled=true`(被取消的伤害不算受伤打断;§15.1 规范清单 + §6.3)。
   - **路由纪律**:监听器只做"会话→实例→组件"定位后转发,不合成、不判玩法(§12.1 listener 注释;§15.1"回调只做路由→发内部事件→返回");全部在 onEnable 注册一次,不在切换期反复 registerEvents(§15.1)。
   - **`listener/ProtectionListener.java`**(与步骤 6/4.4 共用):`InventoryClickEvent` + **`InventoryDragEvent` 双订阅**(§15.1 ★"只处理 Click 会漏掉拖拽");方块破坏/放置/交互的 HIGH + ignoreCancelled 取消;路由到 RegionGuardComponent 读口与 GUI 保护登记表(4.4 投票 GUI 复用)。

10. **回接线(确认项)**:核对阶段2 的 IdleActivitiesComponent——若其自带点按监听(2.5 当时的最小实现),把靶场/跑酷入口改注册为 `InteractionPoint`(`Trigger.Instant`),删除其私有监听分支;若 2.5 已留 InteractionComponent 接缝则只补测试。**不改引擎、不改地图格式**(§4.3 的 regions/interact-points 声明原样)。

## 关键实现要点

- **事件词汇跟发布者走**:RegionEntered/RegionLeft 住 `component/region`,ObjectiveProgressed/ObjectiveCompleted 住 `component/objective`,交互事件住 `component/interact`——全部直接 `implements MatchModeInstanceEvent`(§12.2);引擎零新增、事件族不进 engine 包。
- **区域几何不重写**:三形状判定已在 `map/NamedRegion`(阶段2);RegionComponent 只做归属缓存与事件化。自写几何 = 复制漂移源。
- **读条打断的三处一致性**:MOVE(监听器)、DAMAGE(监听器)、RELEASE(INTERACT 落点)都必须先查通道表再动作——通道表查询是 O(1),这是高频路径唯一允许的开销(§15.1)。
- **组件内容盲**:本族是全模式通用的组件行(§6.1-#8;各模式的挂法落位属玩法实现,见 Shdf具体玩法设计案/05-四模式矩阵.md §5.3),标签、目标名、区域 id 全部来自地图/配置数据;源码不出现任何具体玩法的区域名/标签/目标字样(内容盲回归,★4/★24)。
- **allowed 拿到的是 MatchModeInstanceView**:与 EndCondition 同一视图面(§3.4),模式侧谓词可读全部组件读口——组件本身不认识"进攻方"。

## 陷阱与纪律

- **§14.6 周期任务**:读条推进/出界抽查一律 `update()` 节拍;禁止组件自起 `runTaskTimer`。
- **§14.26 裸写**:RegionGuard 不直接改 Display/Score;惩罚动作经读口或发布事件由规则消费。
- **§14.12 if-else 反弹**:区域标签/保护语义是数据;组件不写 `if (tag.equals("bomb-site"))`。
- **§14.7 跨局残留**:上一帧归属集、通道表、冷却表、开关态随 stop 清空。
- **§14.26/§2.7 命名空间**:本族若有 attrs 键,namespace 各自为**组件 id**,且与 Builder 声明 id 一致(§12.1 工厂:`"regions"`/`"interact"`/`"guard"`)。
- **§15.1 事件规范**:被取消的交互已被 ignoreCancelled 过滤;监听器不重复判取消态;`PlayerMoveEvent` 是只读观察,不 `setCancelled`。
