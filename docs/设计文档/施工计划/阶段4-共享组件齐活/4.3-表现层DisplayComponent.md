## 目标

本子阶段结束时:

- 任意模式在 Builder 加一行 `addComponent("display", new DisplayComponent.Spec(XxxDisplays::xxxDisplay))` 即获得 BossBar/侧边栏/标题/倒计时/ActionBar 全套渲染(§6.1-#12)——**新模式的表现层只是一个 30 行构建函数**(§6.2"数据驱动"结论);
- 组件只认中立模型 `DisplayModel`,渲染器只认 `DisplayModel`——两者互相零认识,模式语义进不了渲染器(§6.2;§0.1 历史体检"表现层写死玩法语义"行的反证,原文枚举见 §0.1 与 Shdf 05 §5.6 迁入注);
- `display:` 配置块(refresh-interval=10、三开关、标题三段时长,§15.2)生效;
- §6.2 的中性示例构建函数(`exampleDisplay`)随本组件交付并离线可测——"数据驱动"结论的框架侧证据与各玩法函数的回归模板;各模式构建函数与既有工厂的回接(含战报行、投票行等用法)归玩法线,见 `Shdf具体玩法设计案/施工计划/` 2.5、5.1、6.1、6.3。

各模式 ×Display 的挂载矩阵落位见 `Shdf具体玩法设计案/05-四模式矩阵.md`(§5.3 责任切分表与矩阵"表现层"行)。

## 施工步骤

1. **`component/display/DisplayModel.java` —— 中立模型(§6.2 逐字段照抄)**
   - `record DisplayModel(Component title, List<DisplayLine> bossBarLines, List<DisplayLine> sidebarLines, Optional<Countdown> countdown, Optional<Progress> globalProgress)`。
   - 内嵌:`DisplayLine(Component text, int weight, LineStyle style)`、`enum LineStyle { NORMAL, HIGHLIGHT, DIM, DANGER }`、`Countdown(int remainingTicks, int totalTicks, Component label)`、`Progress(double current, double target, Component label)`。
   - 纯数据 + Adventure `Component`:零 Bukkit 类型、零行为、零模式词汇。

2. **`component/display/DisplayComponent.java` —— 数据驱动渲染组件**
   - **Spec**:`Spec(Function<MatchModeInstanceView, DisplayModel> builder)`(§12.1;Builder 骨架与 `display` 挂行的模式侧原文随玩法线迁 `Shdf具体玩法设计案/04` §4.2、05 §5.8;§6.2 中性示例为最小用例);另提供 `Spec(builder, DisplayOptions)` 二参构造(步骤 3)。freeze 语义照 §2.4(构建函数引用不可变)。
   - **状态**:上一帧 `DisplayModel` 缓存(diff 基准)+ 参与者显示登记表——本组件唯一运行态。
   - **`update()`**:每 `refreshIntervalTicks` 调一次构建函数(缺省 10,§15.2 `display.refresh-interval`),与上一帧 diff——行文本/进度/倒计时未变不发包;变化 → 交渲染器(步骤 4~7)。
   - **失败隔离**:构建函数抛异常不炸实例——记 WARN、保持上一帧(显示抖动不应触发 quarantine;容器级隔离是 §12.1 tick 的兜底,不是日常路径)。
   - **参与者进出**:订阅 `ParticipantJoined/Left`(§12.2 Structural)登记/注销各渲染器受众;`stop()` 全员清除(BossBar 隐藏、侧边栏还原、Title 清空)并清缓存——幂等。
   - 读条等即时语义不经本组件刷新节拍(10 tick 太粗):读条进度走 ActionBar 即时口(4.2 步骤 8 的选择);本组件的 ActionBar 渲染留给低频行。

3. **`component/display/DisplayOptions.java` —— 配置数据(§15.2 `display:` 块的 record 化)**
   - 字段与缺省值全部出自 §15.2 示例:`refreshIntervalTicks=10`、`useBossbar/useSidebar/useActionBar=true`、`titleFadeIn/Stay/Out = 5/30/10`。
   - 单参 Spec 用全缺省;二参 Spec 由模式工厂显式覆盖。
   - `config.yml display:` 块的接线(L0 从 ConfigRepository 组装 → 组件)受"组件访问引擎全局端口通道"待裁决影响(阶段 README §5-3)——本阶段以内建缺省 + Spec 二参覆盖交付,不阻塞,裁决后一行接线。

4. **`src/main/java/com/shdf/match/render/BossBarRenderer.java`**(§12.1 render 包)
   - 每参与者一条 Adventure `BossBar`;`Player` 继承 `Audience`,`showBossBar/hideBossBar` 可用(papermc-plugin-dev 技能 references/05:59)。
   - `DisplayLine.weight` 决定多行排序与取舍(顶部行位有限,weight 降序截断)。
   - diff:name/progress/color 未变不更新;`use-bossbar=false` 整体旁路。

5. **`render/SidebarRenderer.java`**
   - 侧边栏经记分板 Objective 渲染,行序 = `DisplayLine` 列表序。
   - 行数上限、entry 长度约束、行文本 entry+team 前后缀拼装的实现细节,动工时以 papermc-plugin-dev 技能 references/05 实查为准(**查不到就别说**,该技能 §8 纪律)。
   - `use-sidebar=false` 旁路;stop 还原参与者原记分板。

6. **`render/TitleRenderer.java` + `render/CountdownRenderer.java`**
   - Title:`showTitle(Title.title(...))`,三段时长取 DisplayOptions(§15.2)。
   - Countdown:`DisplayModel.countdown` 渲染为经验条(level/exp)+ 标题标签(§6.2:"经验条/标题倒计时");`remainingTicks` 每 tick 折算;归零发一次结束标题后静默。
   - 两渲染器可合并文件,但类名照 §12.1 各自存在。

7. **`render/ActionBarRenderer.java`**
   - `sendActionBar`(Audience 面,references/05:59)。
   - §12.1 render 包清单未列此文件——**新增不违设计**(§6.1-#12 明列 ActionBar),PR 描述注明依据。

8. **各模式构建函数 `mode/*/XxxDisplays.java` —— 玩法线交付(指向)**
   - 构建函数是"模式语义 → `DisplayModel`"的翻译层,属 L4 玩法实现,随各模式工厂在玩法线施工:§6.2 三例函数原文完整迁 `Shdf具体玩法设计案/05-四模式矩阵.md` §5.6;各工厂内的函数规格、字段映射与 `display` 挂行见 `Shdf具体玩法设计案/施工计划/` 的 2.5、5.1、6.1、6.3。

9. **构建函数的框架侧契约(无论函数由哪条线交付,组件侧保证不变)**

   - 内容盲边界:内容词只允许出现在 `mode/*/XxxDisplays`(L4;§1.2 的 L3/L4 判据对照),组件与渲染器侧见步骤 11 与「陷阱与纪律」。

## 关键实现要点

- **diff 是性能关键**:refresh=10 tick × 每参与者多通道渲染,不 diff 就是发包放大;diff 基准 = 上一帧模型整体相等(记录值类型直接 equals)。
- **受众管理单点**:参与者登记表由 DisplayComponent 持有并推给各渲染器;渲染器不自查在线态(会话/连接真值在 Session 侧,§14.18)。
- **构建函数的失败分级**:单帧异常保上一帧 + WARN;连续失败(如 5 帧)升日志级别——避免刷屏(与 §15.2 配置容错同风格)。
- **中立模型的价值锚点**:§6.2 中性示例就是回归用例——给假 `MatchModeInstanceView`,断言产出模型逐字段等于示例形状;各玩法模式的构建函数照抄此测试模板(函数原文与断言落点见 `Shdf具体玩法设计案/05` §5.6 与施工计划 2.5/5.1/6.1/6.3)。

## 陷阱与纪律

- **§14.10 玩家可控字符串进 MiniMessage**:战报行含玩家名(重灾区)、GUI/标题文案——一律 `Placeholder.unparsed` 或 `NON_INTERACTABLE`;只有服主配置文案允许解析标签。
- **§14.25 svc 膨胀**:显示的便利口**不得**进 MatchModeInstanceServices(§1.1 "DisplayPort 已删"的同款结论——消费面是 DisplayComponent 本身);要显示就 `getComponent(DisplayComponent.class)`。
- **§14.6 周期任务**:刷新由组件 `update()` + refresh 间隔实现,不自起任务。
- **§14.7 跨局残留**:stop 必须隐藏 BossBar/还原记分板/清 Title——旧插件"下一局带着上一局状态"事故的表现层切片。
- **§14.26 裸写**:Display 只读他组件读口,不写任何人的命名空间;`DisplayModel` 的组装函数全部在 L4。
- **内容盲边界**:`component/display` 与 `render/**` 禁模式字样(★4/★24);内容词只允许出现在 `mode/*/XxxDisplays`(L4)。
