## 目标

本子阶段结束时,`engine/mode`、`engine/component`、`engine/port` 三包内存在**全部可编译的契约类型**:

- `MatchMode`:final 聚合根 + Builder + 有序描述符表,零行为,仅 `verifyDependencies`/`createInstance` 两方法(§2.3);
- `MatchModeComponent` 基类 + `Specification` + `Factory`:svc 构造期注入四条件(§2.4);
- `MatchModeInstanceServices`(三成员封闭)/`MatchModeInstancePort`/`ComponentLookupPort`/`MatchModeInfoPort`(§2.5);
- `AttributeBag`:命名空间 = 组件 id(§2.7);
- `engine/port` 其余端口:`ConfigPort`/`PlatformPort`/`WorldPort`(★v1.3:原 `PersistencePort` 已删——连接口一起删,零消费者,21-D1);
- 引擎契约签名所需的纯数据件:`Handoff`/`EndResult`/`TransitionIntent`/`MatchModeSelection`(§3.3/§3.4;★v3.2:原清单中的 `JoinPolicy` 已删除——入场裁决下放为组件,见阶段2 的 `JoinAdmission` 端口)。

它们是 1.3 容器、1.4 冻结测试、阶段 2/3/4 一切代码的唯一基座。**零行为契约,零运行逻辑**——本子阶段不写任何 tick/派发。

## 关键实现要点

1. **零行为是本子阶段的全部**:
   聚合根上"每删一个方法,架构纯度就升一格"(§2.8-决断二);
   写每个类型前自问"这在 `core/Role.java` 里有对应物吗"——有,照抄;没有,先怀疑自己越界。
2. **ComponentEntry 不持有 Spec**(§2.2):
   `addComponent` 时 freeze 快照、只留五元组——"防串改"是结构保证,不靠共享者自觉。
3. **依赖校验不需要实例**(§2.6):
   检查只看描述符声明的类型,所以能在"还没有实例"时做——这正是它能在注册期(阶段 2 的 `MatchModeRegistry`)与 createInstance 前两处设闸的原因。
4. **端口只定义、不实现**(§2.5):
   `MatchModeInstancePort` 的实现体(含 `end` 的置位语义)是 1.3 容器的事;
   本阶段签名若写偏,1.3/1.5 全线返工——逐字对照 §2.5。
5. **EngineServices/MatchModeConfig/MapDefinition 是最小形状**:
   字段只由"被谁引用"驱动,扩充只增不改;不要在本阶段"预支"阶段 2/4 的字段设计。

## 陷阱与纪律

- **§14.23 聚合根长出行为**:
  本子阶段是高危点——契约刚立,最容易被"顺手"。
  任何"差一个小逻辑"的正确动作:给某组件的 Spec 加构造数据,或新造一个组件;不是加到 MatchMode 上。
- **§14.25 svc 服务集成员膨胀**:
  三成员封闭;想要领域能力就 `getComponent(XxxComponent.class)`——组件协作走组件,不走服务集。
- **§14.26 绕过状态主人裸写**:
  AttributeBag 加严②就是本条的结构化执法;键常量包私有的可见性纪律从阶段 4 第一个组件开始执行,机制本阶段立好。
- **§14.20 Handoff 键冲突/类型漂移**:
  `get` 类型不符返回 empty 不抛;框架不写任何键、不保留命名空间(框架保留键机制已删除)。
- **§14.18 SessionMember ≠ Participant**:
  本阶段两者都只立数据形状,字段集刻意不同(uuid/连接态/时间 vs 实例视图);
  阶段 2 写代码时自问:"这个数据应该活过切换吗?"该活 → 会话;不该 → 实例。
