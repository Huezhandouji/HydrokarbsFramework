## 目标

本子阶段结束时,进程级服务层以可离线测试的形态落地(修正案 §1/§3/§8):

- **契约件**:`engine/service/` 五类型——`ServiceRegistry`(两阶段装配容器)/`ServiceSpec`(声明式描述符)/`ServiceEnv`(工厂取物口)/`ServiceLifecycle`(可选生命周期)/`ServiceDependencyException`(装配期异常,点名服务与缺失/成环的依赖),加 `engine/port/ConfigView`(惰性只读配置面);
- **参照服务**:`service/GlobalLedger`(上报式:会话结转汇总)与 `service/GlobalBoard`(拉取式:只读看板)——规格示例,证明两条服务形态可离线单测;
- **能力标签接线**:seal 成功注册、shutdown 摘除(§8.8 口径:注册者扩为"服务(seal 期)",机制与字符串标签口径不变);
- **测试**:★34~★39 六个新测试类 + ★40 `LayeringTest` 增补,全部离线(毫秒级、无需活服,D7)。

**硬边界(本子阶段不得触碰)**:组件挂载仍仅两级(A10 不破——服务不是第三级*组件*,D1);组件与模式不得 import 服务、服务不得 import `mode/**`/`component/**`(D6 双向冻结,★40);`MatchModeInstanceServices` 三成员/`SessionServices` 两成员**不加成员**(D6,★25 口径不变);`MiniGameApi` 冻结面不变(D9,服务不进公共面);`EnginePurityTest` 禁词表不变(`engine/service/` 无内容词)。

## 施工步骤

路径相对 `src/main/java/com/shdf/match/`(测试相对 `src/test/java/com/shdf/match/`)。

1. **契约**(`engine/service/` + `engine/port/ConfigView`,修正案 §3 骨架逐字):

   - `ServiceSpec<S>`:`static <S> of(String id, Class<S> type, Function<ServiceEnv, S> factory)` + Builder(`requires`/`requiresOptional`/`capabilities(String...)`/`build`);构建期校验 id 非空;访问器 `id()`/`type()`/`factory()`/`required()`/`capabilities()`。`requires` 缺 → seal 抛点名双方;`requiresOptional` 缺 → 不报错,运行期 `depOpt` 自查;`capabilities` seal 成功注册、shutdown 摘除。
   - `ServiceEnv`(接口):`<T> T dep(Class<T>)`(拓扑序保证就绪;取不到 = 声明与取用不符,响亮抛)/`<T> Optional<T> depOpt(Class<T>)`(缺席 empty 不抛)/`Plugin plugin()`(日志/调度/数据目录)/`ConfigView cfg()`(惰性只读,/reload 自动读新值)。
   - `ServiceLifecycle`:`default void start()`/`default void stop()`——纯无状态服务不必实现;实现者保证 **stop 与 start 严格对称**(D4)。
   - `ConfigView`:`<T> T get(String path, T fallback)`;L1 `ConfigRepository` 实现之(L1 本体按所有权边界归后续阶段,本子阶段测试以 Map 背后假实现,镜像 1.2 `MatchModeConfig` 的做法)。
   - `ServiceDependencyException`:`RuntimeException` 子类,装配期失败专用,消息点名服务与缺失/成环的依赖。

2. **注册表**(查重/校验/拓扑/回滚,修正案 §2-D2 + §3):

   - `ServiceRegistry(CapabilityRegistry capabilities)` 构造注入;**核心零 Bukkit import**(D7);注册表内部普通集合、不加锁,单线程约定写类头(全部方法主线程,`onEnable`/`onDisable` 天然满足)。
   - `install(spec)`:阶段一仅声明——重复 id/重复类型 → `IllegalStateException` **点名先到者**;seal/shutdown 后 install 抛(★34)。
   - `seal()`:阶段二——①缺必需依赖 → `ServiceDependencyException` 点名双方;②依赖环 → 点名环上服务;③拓扑序创建,**声明序为同层稳定次序**;④任一工厂/start 抛 → **回滚已启动服务(逆序 stop)再抛**,不留半启动态(镜像 switchMode"绝不停在中间态")(★35/★36/★37)。
   - `get(type)`:seal 之前调用抛;未注册 → empty。`require(type)`:缺席 → 人话异常。`ids()`:已注册 id 只读视图(§3)。
   - `shutdown()`:逆序 safeStop(逐个 try/catch,异常记日志不中断)→ 幂等(连调 3 次 stop 恰一次)→ 摘除能力标签;此后 `install` 抛(★38)。
   - **消费面五方法封顶**(`install/seal/get/require/shutdown`;`ids` 为只读查询):事件转发、权限查询等一律不做——上帝注册表是陷阱(14.32);扩需求 = 新独立机制,不是往注册表塞方法。

3. **能力标签接线**:seal 成功后按 `ServiceSpec.capabilities` 注册进 `CapabilityRegistry`,shutdown 摘除(修正案 §4:§8.8 语义扩注——注册者 = L1/第三方插件/**服务(seal 期)**;机制、字符串标签口径、A2 校验均不变);引擎零字面量,词汇由提供方定义;`requiredCapabilities` 消费面与 A2 并集不动(`CapabilitySoftDependTest` 的服务侧扩展归 3.3,修正案 §7 修订行)。

4. **参照服务**(`service/` 顶层包,与 `mode/` 平级;修正案 §3 骨架):

   - `GlobalLedger`(上报式):`implements ServiceLifecycle`;`onSessionDissolved(SessionDissolved)` 取终局账本并入总账;`sweep()` 对存活会话做只读快照拉取、刷新实时视图。
   - `GlobalBoard`(拉取式):零状态;`start` 订阅 `SessionCreated`/`SessionDissolved`/`ModeSwitchCompleted`(修正案 §3 骨架注的"ModeSwitched",按 §3.1 事件清单落到本库事件名)维护"现存会话"视图;数据一律来自 `sessions()` 只读快照,**永不持有活引用**(D5 通道②)。
   - 共同纪律:服务是 `SessionEventBus` 的正式订阅者(§3.1 该行预言的"跨切面逻辑"的第一类正式居民),订阅句柄在 `stop` 中注销(D5 通道①);只读快照,**不得持有活实例/活组件引用跨切换**(镜像 ★29"现取不缓存");受控命令走 `SessionService#switchMode/dissolve/createSession`(服务属切换来源②,与 `/sm` 命令同权;`force` 是显式选择走 review 条款,D5 通道③);服务间依赖只能经 `ServiceSpec#requires` 声明、由注册表注入,**禁止互 new**(14.34)。

5. **测试**(★34~★40;全部离线、零 Bukkit 静态):

   - 六个新测试类(落 `test/.../service/`,§12.1 测试树):`ServiceRegistryDupTest`/`ServiceRegistryDepTest`/`ServiceRegistryOrderTest`/`ServiceRegistryRollbackTest`/`ServiceRegistryShutdownTest`/`ServiceEnvTest`(断言要点逐条照修正案 §7,见「测试与验收」表);
   - `LayeringTest` 增补 ★40 两款(1.4"v4.1 增补注"预留的判定在本子阶段落地);`EnginePurityTest` 禁词表确认不变(engine/service 无内容词,执行时确认);`MatchModeInstanceServicesMembersTest`/`SessionServicesMembersTest` 保持 3/2 成员;

## 关键实现要点

- **两阶段装配的心智模型**:`install` 只声明、`seal` 才校验+创建+启动——失败回滚保证"绝不停在中间态";拓扑序注入使工厂经 `env.dep(...)` 拿到的依赖必然就绪;声明序是同层稳定次序,顺序可测(★36)。
- **L0 接线样例**(`HydroKarbsAssembly`,修正案 §3/D12;类名按 v2 改名,修正案存档原文为旧名):单一静态装配类 + `assemble(JavaPlugin)` 单一编排函数,线性装配语句(cfg → cap → sess → reg → install×N → seal → …;服务声明顺序随意,拓扑序由 seal 保证);**静态类可有静态函数,不许有静态可变状态**;`shutdown(Context)` 镜像 onDisable(ticker 取消 → dissolve 全部会话 → services.shutdown → api 注销);主类退化为两行委托。样例引用的 `SessionServiceImpl` 等类型归阶段 2——按「前置与依赖」交付次序注以最小落点支撑"样例编译通过"(DoD),正式接线随阶段 2 落地。
- **单类型单服务**(D4):一个服务 = 一个主类型;需要两个接口面就做一个门面接口,不做 multi-provide。
- **离线可测**(D7):核心零 Bukkit import → 毫秒级单测;`cfg()` 惰性语义以"换底层读新值"断言(★39)。
- **服务层不新增清场路径**(修正案 §4):服务自己管自己的 stop 对称性(★38);服务无五钩子派发、不占 `tickAll` 任何一步,经自身订阅与事件驱动(D1 边界②)。
- **待裁决登记**(修正案 §12 未决问题原样带入,无静默决定):①`CapabilityRegistry` 交付次序与本子阶段最小落点的边界(见「前置与依赖」;提请统筹);②**未决 Q8**:第三方提供基础设施的版本化 SPI(E 案)本版不做,仲裁去向 = `13-扩展步骤.md` 选型节 + ADR-0006 未决项;③**未决 Q9**:服务查询/进程级快照不进 `MiniGameApi` 冻结面,仲裁去向 = `07-公共API.md` §7.4;④**未决 Q10**:服务装配配置化(services.yml)第一版不做、L0 硬编码,仲裁去向 = `15-PaperMC适配.md`;⑤**未决 Q11**:服务热替换/热重载第一版不支持(进程生命周期 = 插件生命周期),仲裁去向 = `15-PaperMC适配.md` 热重载分级。

## 陷阱与纪律

- **14.31 服务缓存活实例/活组件引用跨切换(悬空)**:只读快照、现取不缓存(镜像 ★29);`GlobalBoard` 的"现存会话"视图一律来自 `sessions()` 快照。
- **14.32 ServiceRegistry 长成上帝容器**:消费面五方法封顶(★34~★39 只测这五个);事件转发、权限查询一律不做;新需求一律新机制。
- **14.33 把服务当第三级组件挂载/组件 import 服务**:双向互不可见(D6,★40 ArchUnit 执法);服务不进组件描述符表(`svc().components()` 查不到)、无五钩子派发、不占 `tickAll` 任何一步(D1 三条硬边界)。
- **14.34 服务间互 new 绕过注册表**:依赖只经 `requires` 声明、`ServiceEnv` 注入;拓扑序与失败回滚都以此声明为准。
- **引擎内容盲**:`engine/service/` 受 `EnginePurityTest` 禁词管辖且禁词表不变(D7);`service/` 纪律 = 不 import `mode/**`/`component/**`、只经 D5 三通道触达会话、只消费 L1 适配器与引擎公开面。
- **stop 与 start 严格对称**(D4):`ServiceLifecycle` 实现者的硬义务;关停逆序、异常不中断、幂等由注册表统一保证(★38)。
