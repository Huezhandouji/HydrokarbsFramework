## 目标

本子阶段结束时,仓库里存在一个能 `gradlew build` 通过、能 `gradlew runServer` 起服并打出插件 enable 日志的**空装配** Paper 插件工程:

- 依赖坐标一次定版(§12 的 build 脚本块),后续阶段不再动构建;
- (★v1.3:本行废止——HikariCP/mysql 依赖与 shade 义务随持久化出框架,框架 jar 零 DB 依赖,21-D1/总览 §11;原文:)shadow 打包链路就绪(HikariCP/驱动进 fat-jar,§12 尾注);
- `util/Threads` 主线程单点回程口成立(§10.5;★8 的工具面);
- `plugin.yml` 按 §12 原样落盘(commands + POSTWORLD;框架基线无 softdepend,§12 同口径)。

不含任何引擎/模式代码——那是 1.2 起的事。

   - `runOnMain(Runnable)`:先判 `Bukkit.isPrimaryThread()`——已在主线程就就地执行,不调度(§10.5 第 2 条:主线程 `runTask` 会被延后一 tick)。
   - 内部执行器:本阶段用 `Executors.newVirtualThreadPerTaskExecutor()` 私有静态持有

## 关键实现要点

1. **依赖范围纪律**:
   - `paper-api` 一律 `compileOnly`——服务端运行期自己提供;
   - HikariCP/驱动一律 `implementation` + shadow——服务端不提供(§12 尾注)。
   - 写反任何一边:要么 fat-jar 膨胀,要么运行期 `NoClassDefFoundError`。
   - 宿主角色插件的 `compileOnly` 纪律属 SHDF 宿主扩展线(框架基线零宿主插件依赖,见 Shdf具体玩法设计案/)。
2. **`onEnable` 零阻塞**(§14.2):本阶段没有 DB/文件 IO,天然满足;
   但骨架期就立起"enable 里不做阻塞 IO"的评审习惯,阶段 5 落库时按 §14.2 三步规避(建池不建连/异步预热/DEGRADED 照常)。
3. **Threads 是唯一回程口**(§14.1 原文规矩):
   "凡是方法名里有 `player`/`world`/`entity`/`inventory` 的调用,必须在 `Threads.runOnMain` 块里"。
   `CompletableFuture#thenAccept` 的回调跑在**完成它的那个线程**上——所以 `supplyThenOnMain` 内部必须 `runTask` 显式回程,不能用 then 链"顺理成章"。
4. **Paper 接口名核实姿势**(papermc 技能 §2):
   - `javap -classpath <paper-api jar 全路径> io.papermc.paper.plugin.loader.PluginLoader`;
   - `javap -classpath <同上> io.papermc.paper.plugin.bootstrap.PluginBootstrap`;
   - 查 jar:`Get-ChildItem "$env:USERPROFILE\.gradle\caches\modules-2\files-2.1\io.papermc.paper" -Recurse -Filter "paper-api-*.jar"` 取非 sources/javadoc 的第一个。
   - 文档:`https://docs.papermc.io/llms.txt` 找页,URL 后加 `/index.md` 取原文。
5. **`POSTWORLD` 不要顺手改 `STARTUP`**(§12):地图坐标解析依赖世界已加载。
6. **run-paper 与 Copy 二选一**:3.0.2 的 `runServer` 自己决定哪个 jar 进测试服(有 shadowJar 用 shadowJar);
   不要另写 Copy 任务造成双份 jar 同名冲突。

## 陷阱与纪律

- **§14.1 异步回调里碰 Bukkit API**:
  本阶段唯一暴露点就是 Threads——用它,不要在调用点直接 `runTask`(回程口单点化正是 ★8 的检验面)。
- **§14.2 onEnable 阻塞 IO**:骨架期零 IO,保持住;watchdog 默认 60s 就杀。
- **§14.6 每处一个调度任务**:
  本阶段只有 Threads 的回程 `runTask`;周期任务一律等 1.3 的 `EngineTicker` 全局单任务,不要在这里预埋任何 `runTaskTimer`/`runTaskLater`。

## 测试与验收

- 本子阶段**无离线单测**:Threads 依赖 `Bukkit.getScheduler()` 静态态,不可离线测试。
  工程纪律(阶段 README §4):离线测试不碰 Bukkit 静态——所以它的验收是构建 + 起服实测,不是单测。
- 实测验收(命令与判据):
  - `gradlew build` 绿,fat-jar 生成且 `META-INF/services/` 完好;
  - `runServer` 冒烟:enable 日志可见,无加载错误,无命令注册冲突告警。
- ★8(主线程边界单点回程)在此**建立工具**;
  其检验方式原文就是"Threads 单点回程 + code review"(§16.2-★8)——评审只认 `Threads.runOnMain`/`supplyThenOnMain` 两处回程,调用点私开调度即打回。
