## 目标

本子阶段结束时,框架能**离线**驱动一次"容器生命周期":

- `MatchModeInstance` 按描述符表造组件(svc 构造期注入)、按声明序派发 `awake → start → update×N`;
- `requestEnd` 只置位不立即清场;`close` 幂等、逆序 stop、登记资源回收(★6/★7);
- `MatchModeInstanceEventBus` 主线程同步派发,订阅者异常隔离(§11.1/§11.3);
- `EngineTicker` 以全局单任务、初始 delay=1L 驱动会话两层——切换的唯一驱动点(§12.2)。

本阶段不写任何玩法解释:容器只做装配 / 派发 / 供端口 / 回收(§2.2-MatchModeInstance 行)。这里没有、将来也不能有阶段/规则/胜负词汇(§14.24)。

## 关键实现要点

1. **两相纪律是容器的心智模型**(角色系统 `RoleInstance` 同款纪律):
   构造器只装配(失败零玩家痕迹),`awakeAll`/`startAll` 显式二段;
   阶段 2 的 B 段先 **B2 `close` 旧实例**、**B4 再 `createInstance` → `awakeAll` → `startAll`** 唤醒新实例(§3.2-B 顺序:handoff→close→merge→create→awake→start)——
   回退判据靠的就是这个分段:`createInstance/awakeAll` 抛 = 旧状态已清、新实例未生效,直接回退;
   `startAll` 抛 = 部分组件已生效,先 `closeAll` 再回退(§3.2-B 注)。
2. **派发一律走快照**:
   `inDeclarationOrder()` 返回不可变快照,遍历期间组件再订阅/退订都不破坏本轮(写时复制口径)。
3. **资源回收的登记点只有三处**:总线订阅、`later` 句柄、显示句柄;
   全部挂"组件实例"索引,`close` 一把回收——组件 stop 返回后框架自动做,组件自己不注销(§2.4 stop javadoc)。
4. **事件 record 携带时间组件**(步骤 3 实现注记):
   发布点永远在容器/组件,时间取自 `MatchModeInstanceClock`,不要在事件里各自取系统时钟。
5. **离线可测的关键取舍**:
   `tickAll()` 与 Bukkit 接线分离(单测直调驱动序方法);`MatchModeInstancePort.later` 的调度口经 `EngineServices.platform()` 注入;
   **离线测试不碰任何 Bukkit 静态**(阶段 README §4)——`runAtFixedRate` 的接线由 runServer 冒烟覆盖。

## 陷阱与纪律

- **§14.6 每实例起一个周期任务**:
  全局唯一 `EngineTicker` 一个句柄;组件级"稍后执行"走 `later` 登记回收;delay 恒 1L。
  任务数随会话/实例线性增长、重载翻倍,都是本条防的事故。
- **§14.7 跨局残留**:
  close 是唯一清场入口 + ENDING 延迟一 tick 由 ticker 处置 + 逆序 stop——本阶段把三条全部结构化,不留"顺手清理"的口子。
- **§14.17 切换重入**:
  本阶段只保证机械前提——`requestEnd` 只置位、自动切换的驱动点只有 `EngineTicker.tickAll` 里的 `runPendingSwitch`;
  状态机防线(§3.5)归阶段 2,但"事件栈内不发切换"从今天就是纪律。
- **§14.24 引擎重新长出状态机**:
  `tick()` 里除了"派发 update"不允许出现任何第二类解释逻辑;
  禁词测试(1.4)守源码面,评审守语义面。
- **§14.18 两层成员**:
  名册位移发生在 `startAll`(会话成员 → 实例 Participant);容器不发明会话级字段。
