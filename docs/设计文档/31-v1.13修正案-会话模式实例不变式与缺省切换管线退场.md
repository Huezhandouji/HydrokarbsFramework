# 31 · v1.13 修正案:会话模式实例不变式与缺省切换管线退场

> HydroKarbs MiniGame Framework · v1.13 修正案(现行,非历史存档;历史存档 17~30 见各文件)
> 变更指示(非设计章节):本修正案把特性「**Session 在任何时刻必须有一个模式实例**」的设计裁决落盘为正式修正案(决策记录 [ADR-0019](docs/adr/0019-shipped-limbo-mode-and-fallback-single-channel.md))——两条主线:①**出厂兜底空模式** `EmptyMatchModeFactory`(id = `limbo`,零组件、空 mapTags 通配、meta `(false, 0, Integer.MAX_VALUE)`)经本 jar SPI 清单注册,`modes/limbo.yml` 注释-only 文件随默认资源发布,`session.fallback-mode` 默认 `"limbo"`——默认配置下回退必有其落点,「会话有成员而无实例」的中间态不再可能;②**缺省去向管线整体退场**——`MatchModeMeta.defaultTransition` 分量与嵌套枚举 `DefaultTransition`(FALLBACK/STAY/ROTATION)删除,无显式去向的结束一律回落 `session.fallback-mode`(回退单通道),`MatchModeInfo` 快照 9→8 分量,`API_VERSION` **7→8**(经用户裁决不设双轨过渡期,§1-D3)。回退链收敛单点 `fallbackSwitch`:空串/未注册/被拒/异常一律 **SEVERE**(原 WARN 跳级)+ 即时二级解散(`FALLBACK_DISSOLVE`);无显式去向的自动切换改为「空串先行即散 + 驻留预检回填重试 + 满后 force 切回退」三步(防回退环风暴,§1-D4)。
> 基线:v1.12。本修正案为**引擎回退链语义 + 模式声明形状 + 公共快照面**三侧变更:方法面零变化(17 法签名一字不动),破坏性在 `MatchModeMeta`/`MatchModeInfo` 分量侧(删公开快照分量 = 跨 jar 破坏,消费过 `defaultTransition` 的旧编译物需按 API_VERSION 8 重编译);★19 FROZEN 17 行不动、★44 BASELINE 随分量删除合法重录(背书 = 31 号/ADR-0019)。
> 版本口径:设计案版本 v1.12 → **v1.13**,`API_VERSION` 7 → **8**(破坏性变更升版,One-Version Rule 的双轨过渡经用户裁决豁免——特性文逐字要求直接删除,无过渡表述;同 ★v1.4/★v1.6/★v1.7 三次破坏性收敛先例,本次为**首次升版本常量**而非维持)。

### D2:空 mapTags × A3 地图解析 = 通配(单一谓词)

### D4:driveAutoSwitch 三步 + fallbackSwitch 单判据 + 驻留节流保留

**决策**(以现行实签为准,`SessionServiceImpl.java:545-628`):

**① `driveAutoSwitch` 无显式去向分支(`:618-627`)**——删 `defaultTransitionOf` 与 switch 表达式,改三步:

```
无显式去向(EndResult 无 intent):
  1) fallbackModeId 为空串 → 直呼 fallbackSwitch(其内 SEVERE + dissolveNow,
     即时解散不等驻留——消灭空串下每拍 A1 拒绝的无限空转)
  2) dwellRemaining(session) > 0(驻留不足)→ session.restoreEndNotices(notices)
     回填重试(瞬态节流,铁律 6)
  3) 驻留已满 → fallbackSwitch(session, result)(force 切回退,cause = 本条结束结果)
```

显式意图分支与既有 restore-retry 原样(`:607-617`)。**② `fallbackSwitch` 改签名 `(Session, EndResult cause)`**(`:557-581`;rollback/onQuarantine/create 传 `nowhere()`):空串 → **SEVERE**(原 WARN 跳级)+ `dissolveNow(FALLBACK_DISSOLVE)`;`beginSwitch(force=true)` 被拒/异常 → SEVERE(带 detail)+ `dissolveNow`;`DISSOLVING` 幂等护栏吸收重复;`cause` 仅承载来源语义,不改变判据。**③ 回退选择带 `force=true`**(豁免人数下限,服务不变式——自定义回退模式 min>0 时空名册回退不被拒),**驻留节流在驱动层保留**——「空串先行即散」消灭的是现行空串空转,驻留窗内的回填重试是有意保留的铁律 6 节流。**④ rollback/onQuarantine/create 三路不加驻留预检**(见 D7)。**⑤ `create()` 首切失败(`:176-197`)**:保留 WARN → 改调 `fallbackSwitch`;回退成功 = 会话泊在出厂空模式,「宿主晚注册模式后补切换」场景保留——但后补非 force 切换受最短驻空约束:泊回退走完整 B5 落位会记切换时刻,防护①对非 force 请求在默认 100 tick 内拒(`:338-349`;现行「WARN+保留」从未切换故立即成功)——宿主可传 force(`MatchModeSelection` 在 api 白名单)或等 100 tick;**此为相对现行的行为回退,§6-Q3 明文登记**。**回退触发单一所有权(复审 S1 增补,`:181-197`)**:create 挂接的首切回调只接管「同步段被拒/A6 失败」(完结时状态回 `RUNNING` 且无挂起计划);B 段失败(rollback 完结 future 时仍在 `SWITCHING`,其自身会调 `fallbackSwitch`)、隔离(`onQuarantine` 尾部自调)与解散(`DISSOLVING`)各有归属,回调让位——否则双重回退的第二发被重入守卫拒 → 误 SEVERE + 强制解散(fallback 明明有效,违需求 1「仅 fallback 无效才解散」)。

**理由**(评审③实证):若回退统一 force 且无驱动层节流,服主把 fallback 配成会无意图结束的真实模式(竞技打完即 end 是 §3.4 典型场景)时,结束→force 切回退→再结束→……每约两 tick 一轮,A6 世界获取与 B3.5 清场全在环内,无任何节流——「防风暴由 EmptyMode 零组件天然闭环」**仅对默认配置成立,不能作为机制保证**。修复 = 驻留预检回填重试(与既有防护①对自动切换的节流同构,`SwitchStormGuardTest` 既有用例形状保住);force 仍需保留以豁免人数下限(否则自定义回退模式 min>0 时空名册回退被拒→解散,惩罚无辜)。

### D7:rollback / onQuarantine 核对(零语义冲突)

**决策**:两路径已走 `fallbackSwitch`,仅随签名传 `EndResult.nowhere()`,**不加驻留预检**——`rollback`(`SessionServiceImpl.java:506-518`)顺序「拒 future → 回常态 → 清实例 → 回退」与不变式不冲突(同 tick 内要么切要么解散);`onQuarantine`(`:910-926`)SWITCHING→RUNNING 归一与「ENDING 可直达切换」口径原样,`dissolveNow` 的 DISSOLVING 幂等护栏吸收重复;`fallbackSwitch` 内部升级(空串/被拒 → SEVERE)自动被两路径继承。**理由**:故障自愈与首切(lastSwitchTick==NO_SWITCH_YET 本就不设限)立即执行;回退目标 B 段抛 → 二级解散终止,无循环死锁;回退链单点收敛是 §3.2 既有设计,新不变式只在 `fallbackSwitch` 内部加码,不在两个调用方复制判据。

### D8:MiniGameApiImpl 摘除回退编排(结构不动)

**决策**:结构不动——`runRemovalFallback`/`initiateFallback`/`isRegistered`(`MiniGameApiImpl.java:479-517`)在新默认下自洽:fallback=limbo 已注册 → 对被摘模式的会话 force 切到 limbo;`fallbackModeId` 惰性读口(构造参数与 `HydrokarbsAssembly.java:166` lambda)维持默认空串(D5);类 javadoc 已补新默认值与本件语义。**既有 gap 保留并登记**(§6-Q2):`initiateFallback` 被拒仅 WARN 不自旋(§14.17),此时会话保留被摘模式旧实例继续跑——摘除编排既有口径,不随本特性扩大,本件列观察项。**理由**:api 编排在回退目标可用时行为完全等价,重写只会复制引擎侧 `fallbackSwitch` 判据(浅模块反模式);被摘会话停在旧实例不违特性 1(「任何时刻有一个模式实例」——旧实例仍是实例)。

/** 驻余判据(单一落点):<= 0 = 驻留已满;NO_SWITCH_YET 首切不设限恒 0。
 *  beginSwitch 防护①(非豁免请求拒)与 driveAutoSwitch 回退预检(节流回填)共用。 */
private long dwellRemaining(Session session) {                             // :419
    if (session.lastSwitchTick() == Session.NO_SWITCH_YET) return 0L;
    return Math.max(0L, policy.minDwellTicks() - (session.ticks() - session.lastSwitchTick()));

/** 一级回退(单点收敛):无效回退(空串/未注册)→ SEVERE + 即时二级解散;

private void fallbackSwitch(Session session, EndResult cause) {           // :572
    if (session.state() == SessionState.DISSOLVING) return;
    if (fallbackModeId.isBlank()) {                                        // :578
        log.log(Level.SEVERE, "…回退模式未配置(无效回退): 直接二级解散兜底…");
        dissolveNow(session, DissolveReason.FALLBACK_DISSOLVE);
        return;
    }
    beginSwitch(session, new MatchModeSelection(fallbackModeId, Optional.empty(), true),
            Handoff.empty(), cause)
        .whenComplete((result, err) -> {
            if (err != null || result instanceof SwitchResult.Rejected rejected) {
                if (session.state() == SessionState.DISSOLVING) return;   // 解散作废不告警
                log.log(Level.SEVERE, "…回退切换被拒/异常,二级解散兜底…");
                dissolveNow(session, DissolveReason.FALLBACK_DISSOLVE);
            }
        });
}

// 自动切换无显式去向:三步(空串先行即散 + 驻留预检回填 + 满后 force 切回退)
if (fallbackModeId.isBlank()) { fallbackSwitch(session, result); return; }   // :636-637
if (dwellRemaining(session) > 0) {                                           // :640
    session.restoreEndNotices(notices);   // 驻留窗内回填重试(节流,防回退环风暴)
    return;
}
fallbackSwitch(session, result);           // 驻留已满:force 切回退(cause = 本条结束结果) :644

// create() 首切失败泊回退(:186-197;回退触发单一所有权,复审 S1——回调只接管
// 「同步段被拒/A6 失败」:完结时状态回 RUNNING 且无挂起计划;B 段失败归 rollback、
// 隔离归 onQuarantine、解散归 DISSOLVING,回调让位,防双重回退误解散)
beginSwitch(session, MatchModeSelection.of(spec.initialModeId()), Handoff.empty(), EndResult.nowhere())
        .whenComplete((result, err) -> {
            if (!(result instanceof SwitchResult.Rejected rejected)) {
                return;
            }
            if (session.state() != SessionState.RUNNING || session.pendingSwitch() != null) {
                return;             // 已由 rollback/onQuarantine/dissolveNow 接管(所有权判据)
            }
            log.log(Level.WARNING, "…初始模式…装配失败(为空或未注册;泊回退模式待后补切换)…");
            fallbackSwitch(session, EndResult.nowhere());
        });

## 6. 未决与风险(登记,不静默决定)

| # | 问题 | 倾向 |
|---|---|---|
| Q1 | **API_VERSION 8 窗口的编译期暴露面**:`MatchModeInfo#defaultTransition` 删除使消费方源码在编译期断、二进制在运行期 `NoSuchMethodError`;当前无真实第三方消费该分量(grep 零命中),风险为假想面。 | 接受:升版常量已锚定破坏(与 28/29/30 的「维持 7」先例不同,本次删的是公共快照分量);14.36 首行版本检查拦截旧编译物。 |
| Q2 | **摘除编排的既有 gap**:`initiateFallback` 被拒(典型 `SWITCH_IN_PROGRESS`)仅 WARN 不自旋,此时会话保留被摘模式旧实例继续跑——旧实例仍是合法实例,不违特性 1,但「被摘模式还在跑」与摘除语义有张力。 | 观察项:既有口径(§14.17/24 号),不随本特性扩大;出现真实故障再裁(候选解 = 被拒后排队下一拍重试,需防自旋上限)。 |
| Q3 | **首切失败泊回退的行为回退**:后补非 force 切换在最短驻留窗口(默认 100 tick)内被防护①拒——相对旧「WARN+保留从未切换、立即可切」是回退;宿主可传 force(`MatchModeSelection` 在 api 白名单)或等窗口。 | 接受并明文登记:泊回退走完整 B5 落位会记切换时刻,防护①对新实例一律生效是其既有语义;文档(03 §3.2 回退表/13)已写明两条出路。 |
| Q4 | **回退目标为玩法模式时的自持期望**:服主把 fallback 配成会无意图结束的真实模式时,依赖驻留节流防环(每窗口至多一轮)——每窗口一次「结束→切回退」的抖动仍可观测(默认 100 tick 一轮)。 | 接受:节流把无限风暴压为有限频率;config 注释已引导「回退模式不应依赖无意图结束自持」;进一步抑制(如回退专用冷却)待真实部署反馈。 |
| Q5 | **`limbo` 作为保留 id 的词汇占用**:宿主若想注册自己的 `limbo` 模式会撞注册闸(响亮抛,先到者保留)——id 现为框架保留词汇。 | 接受:与 Bukkit 保留键同构;注册闸点名先到者,宿主换 id 即可;CONTEXT 已注明「保留 id」。 |
