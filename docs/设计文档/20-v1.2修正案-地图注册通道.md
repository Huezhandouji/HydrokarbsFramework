# 20 · v1.2 修正案:地图注册通道

> HydroKarbs MiniGame Framework · v1.2 修正案(历史存档;现行修正案见 [21-v1.3修正案-框架基础设施瘦身与配置中立化.md](21-v1.3修正案-框架基础设施瘦身与配置中立化.md))
> 变更指示(非设计章节):本修正案定义**地图注册通道**——宿主/伴随插件经 `MiniGameApi` 显式向框架注册与摘除地图声明(`MapDefinition`),补齐 v1.1 形态 B(双 jar)下"玩法图随玩法 jar 分发、但框架无从发现"的缺口,并使临时/活动地图(赛程器动态开图)成为一等公民。决策记录见 [docs/adr/0008-map-registration.md](docs/adr/0008-map-registration.md)。
> 验收编号 **★54~★55**(编号体系沿用 §16.2,只增不改;框架/玩法两线同一套)。
> 基线:v1.1。本修正案**不改变任何既有不变式**(★1~★53 全部原样有效,ArchUnit 断言零放宽);`WorldPort` 世界生命周期(实例化/引用计数/释放/ResetStrategy)**一寸不动**——注册交付的只是声明,不是世界。

---

## 0. 一页摘要

**变更**:①`MiniGameApi` 增两方法(只增不改):`registerMap(Plugin, MapDefinition)` / `unregisterMap(Plugin, String)`;API_VERSION 2 → 3;②`MapRegistry` 增第二输入通道(显式注册),与既有文件装载(`maps/*.yml` 启动扫描)汇入**同一私有 `register()`**——注册语义只有一份;③注册期校验:id 查重(与文件式同一命名空间,重复点名先到者)、tags、**世界模板目录存在性**(缺失 = 响亮拒绝);④卸载:显式 `unregisterMap` + `PluginDisableEvent` 兜底摘除(D8 同款路径);**有会话正在使用该图 → 摘除被拒**(镜像 `/sm reload maps` 既有纪律);⑤注册式地图不经 `/sm reload maps` 触碰(声明在插件手里,宿主"reload" = unregister + register);⑥注册前宿主须将世界模板解包落盘(如 `saveResource`)——模板解析路径仍以框架数据目录 `maps/templates/<mapId>/` 约定为准。

**不动**:引擎内部机制零改动;`MapDefinition` 形状不变(纯静态值,本就在 D6 白名单读面);文件装载通道照旧;`WorldPort` 与切换阶段 A3/A6 的消费方式照旧。

**为什么地图可以直接交成品(与模式必须交工厂相对)**:`MapDefinition` 是纯静态值——无行为、无依赖图(`verifyDependencies` 不适用)、无框架注入的配置、无 reload 重建需求;"交工厂不交成品"的三大理由(配置注入/reload 重建/ServiceLoader 形状)在地图侧均不成立。直接注册建好的 `MapDefinition` 实例是安全的。

## 1. 决策 D1~D7

### D1:注册通道与注册单位
显式 API(经 `MiniGameApi`),注册单位 = 一个建好的 `MapDefinition`(纯静态值)。与模式(`MatchModeProvider` 工厂)、会话组件(`SessionComponentProvider` 返回 Spec)不同,地图**交成品合法**——理由见 §0 末段。不提供 `MapProvider` 工厂形态(无配置注入/reload 重建诉求,不做 hypothetical seam)。

### D2:模板落盘与解析
模板解析以框架数据目录 `maps/templates/<mapId>/` 约定为准(既有约定,不变)。形态 B 下宿主/伴随插件在 `onEnable` 中先将自带模板从玩法 jar 解包落盘(`saveResource` 或等价手段),再调 `registerMap`——**19-D1 的"玩法图随玩法 jar 分发"描述的是打包归属,注册 + 解包是它的运行期发现机制**,两者不冲突。注册期校验模板目录存在;缺失 = 响亮拒绝(带路径)。

### D3:注册期校验与错误语义
①id 查重:注册式与文件式共用 `MapRegistry` 同一命名空间,重复 id 响亮抛(点名先到者与其来源:文件/插件);②tags 校验(空 tags 合法,等于不被任何模式按标签选中);③模板目录存在性(D2)。成功返回 `MapInfo` 快照;失败响亮抛——与 `createSession` 的装配期失败口径一致(错误当场可感,不留半注册态)。

### D4:卸载
显式 `unregisterMap(provider, mapId)` + `PluginDisableEvent` 兜底按提供方插件摘除(D8 同款)。**摘除守卫**:该图为任一存活会话当前实例所用、或存在未释放的世界句柄 → 摘除被拒(detail 点名会话);守卫通过 → 从目录摘除,已实例化副本的处置走 `WorldPort` 既有引用计数与 `ResetStrategy` 路径(框架不因摘除声明而强删副本)。

### D5:reload 语义
`/sm reload maps` 只触碰文件式地图(既有纪律:有会话正用则拒绝)。注册式地图**不经 reload**——声明的所有权在插件;宿主要"reload"就 unregister + register,或整插件重载(走 D4)。

### D6:双通道汇入单点
`MapRegistry` 两条输入(启动文件扫描 / 显式注册)汇入**同一个私有 `register()`**;"注册语义只有一份"的机械保证(与 `MatchModeRegistry` 的双发现同款纪律)。`api.maps()` 目录对两种来源一视同仁,`MapInfo` 不区分来源(`MapDefinition` 无来源字段;诊断经注册表内部记录)。

### D7:与 WorldPort 的边界(重申)
注册只交付声明(id/tags/出生点/区域/交互点/静态字段)。世界的实例化、(map, session) 副本、引用计数、释放、还原策略**全部留在框架**(D7 两问:世界句柄泄漏会失守切换原子性底线 → 内核)。任何"注册时顺带管世界"的扩需求一律拒绝。

## 2. 契约骨架(MiniGameApi v3 增量)

```java
package com.hydrokarbs.api;

public interface MiniGameApi {
    int API_VERSION = 3;   // v1.0 = 1;v1.1 = 2;v1.2 = 3。只增不减。

    // ── 地图注册(v1.2;★54) ──────────────────────────────
    /** 注册地图(声明 = 纯静态 MapDefinition,直接交成品)。注册期校验:id 查重(与文件式同一
     *  命名空间,重复点名先到者)、tags、世界模板目录存在性(maps/templates/<mapId>/,
     *  缺失响亮抛)。成功返回 MapInfo 快照。主线程调用。 */
    MapInfo registerMap(org.bukkit.plugin.Plugin provider, MapDefinition map);
    /** 摘除注册式地图;文件式地图(id 来自 maps/*.yml)→ 拒绝。该图为任一存活会话当前
     *  实例所用、或存在未释放世界句柄 → 摘除被拒(detail 点名会话)。幂等:已不在目录 = no-op。 */
    void unregisterMap(org.bukkit.plugin.Plugin provider, String mapId);
}
```

`MiniGameApiImpl` 增量均为薄委托(`registerMap`/`unregisterMap → MapRegistry`)。
