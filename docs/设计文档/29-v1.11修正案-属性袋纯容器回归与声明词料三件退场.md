# 29 · v1.11 修正案:属性袋纯容器回归与声明词料三件退场

> HydroKarbs MiniGame Framework · v1.11 修正案(历史存档,非现行——现行修正案见 31 号;历史存档 17~28 见各文件;本头部行为 31 号窗口对齐注,正文按 v1.11 时点存档不改写)
> 变更指示(非设计章节):本修正案把 [ADR-0017](docs/adr/0017-attribute-bag-pure-container.md) 的裁决追认为正式修正案——**属性袋以纯容器形态回归**(`engine/AttributeBag`:`Key<T>(name, type)` 二元组、`Builder` 唯一写侧、`Map.copyOf` 收口、`get/getOrDefault/has` 三读口、`empty()` 共享空实例),`MapDefinition` 第三分量由 `Object metadata` 改为 `AttributeBag metadata`;`MapDefinition.TAGS` 约定键 + `tags()` 唯一标签读口;**`Object metadata` 不透明词料、`map/TagProvider` 约定接口、`map/MetaAttributes` 门面三件全删**。**判据**(ADR-0017「背景」1~3):①28 号的「不透明对象 + 按引用存储、视为冻结」把冻结责任完全交给注册方,框架侧无结构保证;②`TagProvider` 的唯一作用是从不透明对象里取一个 `Set<String>`,而其余声明词料只能塞进注册方自定义类型,框架既不解释也无处安放;③纯容器把「声明级单写方 + 构造即冻结」落进类型结构,同时**不恢复**旧属性袋的命名空间断言、组件授权表与实例 `close()` 链。**不新增 ★ 编号**;★26 维持就地废止(命名空间断言的检验对象不复活),★63 就地注再校准(②注册期冻结由容器结构真正恢复);★1~★65 其余命题零放宽。

## 0. 一页摘要

**变更(五条决策,D1~D5)**:

① **D1 `AttributeBag` 以纯容器形态回归**:`com.hydrokarbs.engine.AttributeBag` 重写为纯不可变容器——`Key<T>(String name, Class<T> type)` **二元组**(无命名空间分量)、`Builder#put` 是**唯一写侧**、`build()` 经 `Map.copyOf` 一次收口、读口只有 `get`/`getOrDefault`/`has`、`empty()` 返回共享空实例。零 Bukkit 依赖;不参与实例 `close()` 链;写只发生在声明装配期一次。

② **D2 `MapDefinition` 第三分量回归容器**:`record MapDefinition(Path worldDirectoryPath, ResetStrategy resetStrategy, AttributeBag metadata)`;新增约定键常量 `TAGS = AttributeBag.Key.of("tags", stringSetType())`(`MapDefinition.java:37-38`,受检擦除转换返回 `Set` 层类型);`tags()` 成为**全框架唯一标签读口**(`metadata.getOrDefault(TAGS, Set.of())`,`MapDefinition.java:79-81`);二参便利构造 `(Path, AttributeBag)` 缺省 `REUSE_DIRTY`;`metadata` **非空**——无词料传 `AttributeBag.empty()`,不接受 `null`。

③ **D3 三件退场**:`Object metadata`(不透明词料 + 按引用冻结契约)、`map/TagProvider`(单方法约定接口)、`map/MetaAttributes`(唯一剩余 `tags(Object)` 的门面)**全部删除**,`map/` 包只剩 `MapDefinition` + `MapRegistry`。冻结改由**容器不可变性结构**承担:构造后无公开写口,装配来源 `Map` 的后续改动不跟随;`null` 语义由 `empty()` 取代。

④ **D4 公共面与冻结测试处置**:`MiniGameApi` 17 方法签名与 `API_VERSION = 7` 零改动;★44 BASELINE 合法重录(增回 `AttributeBag` 及其 `Key`/`Builder`/三读口/`empty` 行,删 `TagProvider#tags()` 行,`MapDefinition` 第三分量类型改为 `AttributeBag`);★19 FROZEN 17 行不动;**★26 维持废止**(命名空间断言机制不复活,ArchUnit 检验对象不回来)、★63 就地注再校准(②注册期冻结由容器结构真正恢复);**不新增 ★ 编号**,计数维持 **65 条 = 框架 58 + SHDF 扩展线 3 + 联合 1(★32 废止)+ 宿主线 3**。

⑤ **D5 命名消歧**:旧属性袋(`AttributeBag` 历史形态:命名空间 + 名字 + 类型、命名空间断言、组件授权表、各端口 `attrs()`)仍在 CONTEXT「历史术语」废止名单,**废止不变**;现役 `AttributeBag` = 声明词料纯容器(29 号/ADR-0017),**同名不同物**——机械分界 = `Key` 是二元组、类上无命名空间/授权表、不参与实例 `close()`。CONTEXT 历史词条加注,现役术语表补 `AttributeBag(纯容器)` 与 `tags()` 两条。

**不动**:切换管线(阶段 A3 标签过滤逻辑原样,标签改读 `MapDefinition#tags()`)、`WorldPort` 三法/引用计数/复用窗口(★58)/`deleteCopyDir` 唯一删除口、`TEMPLATE_RESTORE` 行为、`MapInfo` 三分量 `(id, tags, resetStrategy)`、`SessionRecipe` record 形状、24 号显式注册四法、25 号桥接结论、27 号世界清场接缝、路径构造期规范化/缺目录名响亮抛/id = 声明目录名、注册期路径直验与查重。

## 1. 决策 D1~D5

### D1:`AttributeBag` 以纯容器形态回归

**决策**:`com.hydrokarbs.engine.AttributeBag`(`AttributeBag.java:26`)重写为纯不可变容器:

| 件 | 形态(以现行实签为准) |
|---|---|
| `Key<T>` | `record Key<T>(String name, Class<T> type)`(`AttributeBag.java:29`)——**二元组,无命名空间分量**;构造期非空校验;`Key.of(name, type)` 工厂 |
| 写侧 | `Builder#put(Key<T>, T)`(`AttributeBag.java:90`)**唯一公开写口**;覆盖式入表(同键后写胜);键与值均拒绝 `null` |
| 收口 | 私有构造 `this.values = Map.copyOf(values)`(`AttributeBag.java:47-49`);无任何公开写口 |
| 读口 | `get`(键缺席或值不是 `key.type()` 实例 → `Optional.empty()`,`AttributeBag.java:62-69`)、`getOrDefault`(同情形返回 fallback,`:72-74`)、`has`(只问键存在,`:77-80`) |
| 空实例 | `empty()` 返回共享不可变实例(`AttributeBag.java:42/52-54`);`Builder#build()` 空表亦返回它(`:98-100`) |

**理由**:28 号把第三分量定为不透明 `Object` 后,冻结只能靠契约;纯容器把「单写方 + 构造即冻结」变成类型结构,同时不恢复旧属性袋的任何运行期机制(无命名空间断言、无组件授权表、不参与实例 `close()`)。判据同 21-D1/25-D1:形态由真实消费面决定——框架消费标签,宿主可携带其余词料,但**只有一个容器、一个写侧**。

### D2:`MapDefinition` 第三分量与唯一标签读口

**决策**:`record MapDefinition(Path worldDirectoryPath, ResetStrategy resetStrategy, AttributeBag metadata)`(`MapDefinition.java:34`):

- **约定键常量**:`public static final AttributeBag.Key<Set<String>> TAGS = AttributeBag.Key.of("tags", stringSetType())`(`MapDefinition.java:37-38`)——键名 **`tags`**,无 `map.` 前缀(命名空间机制已不存在);`Set<String>` 的元素类型被擦除,读口只校验到 `Set` 层(`MapDefinition.java:52-59` 受检擦除转换,词料不承载元素类型承诺);
- **唯一标签读口**:`tags()` = `metadata.getOrDefault(TAGS, Set.of())`(`MapDefinition.java:79-81`)——缺键或值不是 `Set` 实例 → 空集;空集 = 不被任何模式按标签选中(20-D3 口径);`MapRegistry#byTag` 只经此口取标签(`MapRegistry.java:157-166`);
- **`metadata` 非空**:构造期 `Objects.requireNonNull(metadata, "metadata")`(`MapDefinition.java:43`);无词料传 `AttributeBag.empty()`,**不接受 `null`**;
- **二参便利构造** `(Path, AttributeBag)`:`resetStrategy` 缺省 `REUSE_DIRTY`(`MapDefinition.java:66-68`);
- **路径权威不变**:`toAbsolutePath().normalize()` 入库、缺目录名响亮抛、`id()` = 声明目录名(`MapDefinition.java:40-50/71-73`);
- **其余词料**:同一容器,宿主自定 `Key`(`Key.of("display-name", String.class)` 等)原样携带,框架只解释 `TAGS`。

**理由**:标签是框架**唯一**解释的声明词料,给它一个常量键 + 一个读口即可;把 `resetStrategy` 继续留在强类型字段(28-D2 的正确部分)避免唯一消费的枚举穿过 `Class<T>` 转换;其余词料不再需要一个「什么都能装」的不透明对象,而由类型化键自描述。

### D3:`Object metadata` / `TagProvider` / `MetaAttributes` 三件退场

**决策**:删除下列三件,零过渡窗口:

| 退场件 | 原职责(28 号时点) | 处置 |
|---|---|---|
| `MapDefinition` 第三分量 `Object metadata` | 不透明词料,按引用存储、视为冻结,允许 `null` | 改 `AttributeBag metadata`;非空;结构冻结 |
| `map/TagProvider`(`Set<String> tags()`) | `metadata` 实现本接口即声明标签集 | 整接口删除;标签改由 `MapDefinition.TAGS` 词料键声明 |
| `map/MetaAttributes`(`tags(Object)`) | 唯一标签读口,非实现/`null` → 空集 | 整类删除;唯一读口 = `MapDefinition#tags()` |

**冻结语义**:旧「按引用存储、视为冻结」契约退场,改为**容器不可变性结构保证**——`Builder#build()` 后容器无公开写口,装配来源 `Map` 的后续改动不跟随(`MapRegistryTest.registeredDeclarationIsFrozenAndHasNoMutationChannel`,`MapRegistryTest.java:127-147` 守护:同一声明实例、同一容器引用、来源 `Map` 改后读值不变)。`null` 语义由 `empty()` 取代:无词料是**空容器**,不是空引用。**残留契约**:容器结构冻结 ≠ 词料值的深度冻结——值本身应为不可变值(如 `Set.of(...)`),提交后不得再改其内容(§6-Q2;与 20-D1「交成品不交工厂」一致,框架不做通用深拷贝)。

**理由**:`MetaAttributes` 在 28 号之后只剩一个纯函数读口,`TagProvider` 只剩一个方法——两者都是被纯容器直接取代的中间层;保留即是一条无消费者的公共面(One-Version Rule:同一形状不留两套表达)。

### D4:公共面、版本与冻结测试处置

**决策**:`MiniGameApi` 17 方法签名一字不动;`API_VERSION` **维持 7**(方法面零变化,破坏性在声明形状侧);★44 BASELINE 合法重录(增回 `AttributeBag`/`Key`/`Builder`/`empty`/三读口行,删 `TagProvider#tags()` 行,`MapDefinition` 第三分量类型改为 `AttributeBag`),★19 FROZEN 17 行不动;★26 维持就地废止注(再校准),★63 就地注再校准(②注册期冻结由容器结构恢复);不新增 ★ 编号,计数维持 65。

**理由**:方法面未变,版本常量不因声明形状第三次再动(v1.8 已付 6→7);冻结测试的重录仅限「新类型/新成员进入白名单」与「被删类型/成员退出白名单」,不得顺手放宽其它签名。★26 的旧检验对象(带命名空间的 `Key`、`set` 断言、授权表)在纯容器里**不存在**,ArchUnit 腿无法也不应复活——「状态主人唯一」命题仍由 14.26 的字段封装 + 强类型读口纪律承接,不是放宽。

### D5:命名消歧与历史术语处置

**决策**:旧属性袋与现役容器**同名不同物**,文档按三层处置:

1. **历史术语词条保留**:CONTEXT「历史术语」表的 `AttributeBag`(命名空间 + 名字 + 类型的通用键值袋 + 各端口 `attrs()`/`attr()`)条目**不删、废止不变**,补注:「现役 `AttributeBag` = 声明词料纯容器(29 号/ADR-0017),与废止的旧机制同名不同物」;
2. **现役术语表补两条**:`AttributeBag(纯容器)`(声明词料的唯一容器:`Key<T>(name,type)` 二元组、`Builder` 唯一写侧、`Map.copyOf` 收口、`get/getOrDefault/has` 三读口、`empty()` 共享空实例;无命名空间/无授权表/不参与实例 `close()`)与 `tags()`(`MapDefinition` 的唯一标签读口:`TAGS` 约定键缺失或类型不符 → 空集);
3. **机械分界(供 review 用)**:`Key` 是二元组、类上没有 `namespace`/`bindComponent`/`setNamespaceCheckEnabled`、`MapDefinition#tags()` 存在——据此判定看到的是现役容器而非旧机制;旧机制的代码/文档口径一律不复活。

**理由**:同名是最容易误导后来者的一处——「属性袋已退场」与「`AttributeBag` 在代码里」必须同时成立,只有把「旧机制废止」与「同名新机制现役」分开写清楚,才不会诱发两种错误:把新容器当旧机制删除,或把旧命名空间断言顺手加回来。

## 3. 契约骨架(以现行实签转写,不得凭记忆)

```java
// engine/AttributeBag.java(纯不可变容器;零 Bukkit 依赖)
public final class AttributeBag {

    /** 词料键:名字 + 值类型(无命名空间分量)。 */
    public record Key<T>(String name, Class<T> type) {
        public Key { Objects.requireNonNull(name, "name"); Objects.requireNonNull(type, "type"); }
        public static <T> Key<T> of(String name, Class<T> type) { ... }
    }

    private static final AttributeBag EMPTY = new AttributeBag(Map.of());
    private final Map<Key<?>, Object> values;                 // Map.copyOf 收口,无公开写口

    public static AttributeBag empty() { ... }
    public <T> Optional<T> get(Key<T> key) { ... }            // 缺席/类型不符 → empty
    public <T> T getOrDefault(Key<T> key, T fallback) { ... }
    public boolean has(Key<?> key) { ... }                    // 只问键存在,不论值类型

    /** 唯一写侧:声明装配期逐项覆盖式入表,build() 一次冻结。 */
    public static final class Builder {
        public <T> Builder put(Key<T> key, T value) { ... }   // 键/值均拒 null
        public AttributeBag build() { ... }                   // 空表 → empty()
    }
}

// map/MapDefinition.java(第三分量 = 纯容器;record,构造即权威)
public record MapDefinition(Path worldDirectoryPath, ResetStrategy resetStrategy, AttributeBag metadata) {

    /** 标签词料键:名字 "tags",值类型 Set<String>。 */
    public static final AttributeBag.Key<Set<String>> TAGS =
            AttributeBag.Key.of("tags", stringSetType());

    public MapDefinition { /* 路径 normalize;缺目录名抛;resetStrategy/metadata 非空 */ }
    public MapDefinition(Path worldDirectoryPath, AttributeBag metadata) { /* 缺省 REUSE_DIRTY */ }
    public String id() { /* worldDirectoryPath.getFileName().toString() */ }

    /** 全框架唯一标签读口:TAGS 缺失或值不是 Set → 空集。 */
    public Set<String> tags() { /* metadata.getOrDefault(TAGS, Set.of()) */ }
}

// map/TagProvider.java      —— 整接口不存在
// map/MetaAttributes.java   —— 整类不存在
// map/ 包 = MapDefinition + MapRegistry(两件)
```

**退场类型/成员**:`map/TagProvider`(整接口)、`map/MetaAttributes`(整类)、`MapDefinition` 的 `Object metadata` 分量与「按引用存储、视为冻结」契约。**不在冻结面**:`MapRegistry` 的注册实现、`MiniGameApiImpl` 的快照转换点。

## 6. 未决与风险(登记,不静默决定)

| # | 问题 | 倾向 |
|---|---|---|
| Q1 | **同一 `API_VERSION=7` 窗口内第三次声明形状变更**(v1.8 两分量 → v1.10 三字段 `Object` → v1.11 第三分量 `AttributeBag`):版本轴不区分,消费方升级只在编译期暴露。 | 接受(28 §6-Q1 先例):方法面零变化不升版;出现真实消费方误用时再评估版本轴。 |
| Q2 | **容器结构冻结 ≠ 词料值深度冻结**:`Map.copyOf` 只冻结映射结构,值(如可变 `Set`)仍可与外部共享引用。 | 契约承担:词料值应按不可变值交付(如 `Set.of`),提交后不得再改;不引入通用深拷贝(ADR-0016 已否决「表面拷贝造假冻结」)。 |
| Q3 | **`TAGS` 元素类型擦除**:`Key<Set<String>>` 的运行期类型只校验到 `Set` 层,`Set<Integer>` 可被放入并按 `Set<String>` 读出(堆污染)。 | 接受(代码类注已声明「词料不承载元素类型承诺」);消费点 `MapInfo` 构造期 `Set.copyOf` 再收口;出现真实误用时再评估专用标签类型。 |
| Q4 | **同名不同物**:旧属性袋与新容器共用 FQCN,review 中可能误判「属性袋又回来了」或顺手恢复命名空间断言。 | 靠 CONTEXT 三层消歧 + 机械分界(`Key` 二元组/无 namespace 成员/不参与 `close()`)与 14.26 纪律;不预置机械断言(检验对象不存在)。 |
| Q5 | **二进制/源码不兼容**:`MapDefinition` 第三分量 `Object` → `AttributeBag`,构造器与方法描述符改变;`API_VERSION` 不变,运行期只在 `NoSuchMethodError` 暴露。 | 登记为同窗口内形状变更的已知代价;消费方须按 v1.11 重新编译。出现真实跨 jar 消费方后,再评估是否以版本轴锚定声明形状。 |
