### 11.3 解耦要点

| 解耦点 | 做法 | 收益 |
|---|---|---|
| 角色系统 ↔ 模式 | `RoleFacade` 是唯一 `import` 点;模式与其他组件只见 `RoleComponent` 读口(角色事件词汇也在 `component/role`)——**SHDF 扩展线,整行仅作扩展先例引用,接入件见 Shdf具体玩法设计案/08、09** | 角色系统升级只改 1 个文件 |
| 模式 ↔ 引擎 | 模式只是聚合根(纯数据 + 组件描述符表),无行为方法 | 引擎无 `if (mode == ...)`,也无"模式该做什么"的任何假设 |
| 模式 ↔ 模式 | 模式之间零 import;共享逻辑下沉 L3;**交接只经 `Handoff`** | 加下一个模式不碰现有模式 |
| 实例 ↔ 实例 | 实例状态随 close 全灭,带出去的数据必须显式交接 | 跨局残留结构性不可能 |
| 会话 ↔ 实例 | 组件经 `svc().self()` 拿本实例面;**内核**不读实例内部(★v4:会话级组件经 `MatchModeInstanceAccess` 只读查询实例,见下一行);实例结束只经 `end()` 端口上报 | 切换逻辑不依赖任何模式细节 |
| 实例组件 ↔ 会话组件(★v4) | **跨级只读、写走端口**:查询经 `SessionView#component` / `MatchModeInstanceAccess#component`(只读;现取不缓存,不越过切换);干预只有 `end()`/`switchTo()` ↔ `requestSwitch()`/`requestDissolve()` | 两级状态各有唯一主人;会话策略可插拔而不触碰实例组件 |
| 组件 ↔ 组件 | 组件之间**不持有引用**,只经 `svc().components().get(类型)` 查 | 可单独测试;装配期依赖校验保证 requires 在场(声明序派发,不承诺拓扑序) |
| 规则 ↔ 副作用 | `Rule` 是纯函数,由 RuleBookComponent 求值(规则簿本身是可选组件) | 规则可离线单测(无需活服) |
| 引擎 ↔ 数据库 | (★v1.3:v1.2 前引擎只见 `PersistencePort`;该端口已删、持久化迁宿主线——框架与 DB 零耦合,21-D1) | 可切成"无 DB"模式跑单测(v1.3 起框架**本来就没有** DB) |
| 引擎 ↔ 世界生命周期 | 引擎只见 `WorldPort`;只有 SessionService 调它(★v1.5:dissolve 侧接缝 = discardSession,销毁名下全部副本,23 号) | 模式无感世界从哪来 |
| 事件派发 ↔ 故障 | 订阅者异常被隔离 | 一个坏规则不会毁掉整局 |
| 本插件 ↔ 第三方 | 对外只暴露 `MiniGameApi`,`MatchModeProvider` 注册 = api 显式注册面(§7.2;★v1.6:第三方经 `registerMode`/`registerSessionComponents` 显式四法进出——原 ServicesManager 提供方半边退场,24 号) | 我们消费 RoleAPI(消费实例在 SHDF 扩展线,见 Shdf具体玩法设计案/)与被消费是同一套纪律 |
| 服务 ↔ 组件(★v4.1) | **服务三通道触达会话**:订阅会话事件 / 只读快照 / 受控命令(D5,无第四条;时序见 §11.5);**双向互不可见**:服务不进组件描述符表,组件/模式与服务互不 import(★40) | **组件不可见服务**:服务是进程生命周期的另一类对象(A10 不破),`svc` 成员数不变(★25) |

### 11.4 文本时序图:会话级组件生命周期(★v4:装配 → start → update×N → 逆序 stop)

```
 L0/EngineTicker   SessionService(内核)          会话组件(声明序 a…b)                    成员/实例
    │                 │                             │                                       │
─── 装配:create 内,先于首个实例(声明序 = 装配序 = 派发序)
    │ create(spec) ──▶│
    │ (L0 按 SessionSpec 装配;模式无权增删,第一版)
    │                 │ SessionComponentRegistry
    │                 │ bind(逐 Spec 快照,id 去重)
    │                 │ verifyDependencies ✔        │ 缺任一 → 抛;会话创建失败(L0 SEVERE)
    │                 │ create(id, svc)(声明序) ───▶│ 构造期注入 svc(四条件同实例级)
    │                 │ awakeAll() ────────────────▶│ awake ×N(声明序;幂等)

    │                 │ ② instance.tick()           │ 实例侧组件 update(声明序);无实例跳过
    │                 │ ③ tickSessionComponents() ─▶│ update ×N(声明序;与实例有无无关)
    │                 │ ④ 内核 sweep(断线宽限等)
─── 间隙与切换:实例 ENDING/SWITCHING → 下一 tick ① 内原子完成切换(§11.2)
    │                 │ (切换间隙无当前实例)
    │                 │ ② 实例侧组件不 tick;        │ ③ 会话组件照常 tick(tickAll ③ 步)
    │                 │                             │ 会话组件表不参与切换装配;
    │                 │                             │ 实例恒等、update 计数连续(★33)
─── dissolve:逆序 stop + 登记资源回收 + 会话终结
    │ dissolve() ────▶│ DISSOLVING
    │                 │ (若有实例)close()
    │                 │ stop ×N(逆序) ─────────────▶│ stop(与 start 严格对称)
    │                 │ reclaimRegisteredResources()│ 框架回收登记资源(订阅/延时任务/显示)
    │                 │ 成员传送回主城出生点 ───────┼──────────────────────────────────────▶│ 成员退场
    │                 │ 释放世界句柄 → 从注册表摘除 → 发 SessionDissolved
─── 故障隔离(会话级 quarantine;会话不解散,D9)
    │                 │ 逐组件 try/catch            │ update/onEvent 抛异常
    │                 │ safeStop + quarantined ────▶│ 打标(此后跳过其派发)
    │                 │ 记日志(会话 id / 组件 id / 原因)
    │                 │ 发会话事件 SessionComponentQuarantined(会话 id / 组件 id / 原因)
    │                 │                             │ 其余组件照常 tick;会话存活
```

> 读图要点:会话级组件随**会话**存活(`create` → `dissolve`),装配先于首个实例——首实例的组件才查得到它们;`stop` 逆序、由框架无条件调用(与 `start` 严格对称,返回后回收本组件登记的资源)。`update×N` 一段含**切换间隙**(实例 ENDING/SWITCHING 期间无当前实例,`tickAll` 第 ③ 步照常:实例侧组件不 tick,会话组件照常 tick);会话组件表不参与切换装配,切换前后其实例恒等(★33;派发节拍见 §3.8)。`update`/`onEvent` 抛异常 → 该组件被隔离(停用 + 发会话事件 `SessionComponentQuarantined`,字段:会话 id / 组件 id / 原因),**会话不解散**,其余组件照常(D9;会话事件族清单见 §3.1)。★v1.5 就地注(23 号,图体不改写):dissolve 段「释放世界句柄」一步升级为**解散销毁接缝**——该步 = `worlds.discardSession(会话 id)`,名下全部世界副本销毁(三类覆盖:存活条目/曾发放已保留目录/迟到 in-flight,★58;接缝仍在 dissolve 的 finally,见 03 §3.7「副本销毁」行与 §3.8)。★v1.9 就地注(27 号,图体不改写):dissolve 段「成员传送回主城出生点」与「释放世界句柄」两步之间存在**世界清场接缝**——finally 内、摘句柄后、`discardSession` 前,经 `hubWorldClearer` 注入函数把地图世界内遗留人员(`getPlayers()`,不以名册为界)传往主世界出生点(与 `hubRelocator` 同源 `hubSpawn()`;「先名册后世界」;best-effort WARN 不阻塞,见 03 §3.8 注与 27 号 §1-D3)。★v4 未决(变更指示 §11-Q7):**实例组件订阅会话事件**第一版不开放(`SessionView` 无 `events()`;登记去向:本节与 §7.3,待裁决)。

```
─── 运行:事件驱动,不占 tickAll 四步(§3.8);与会话只走三条通道(D5,无第四条)
    │                            │                            │◀── ① 订阅会话事件:生灭感知 ────│
    │                            │      ② 只读快照:sessions() 不可变 record,现取不缓存(★29)
    │                            │      ③ 受控命令:switchMode / dissolve / createSession
    │                            │        (服务属切换来源②,与 /sm 命令同权;force 是显式选择,走 review 条款)
─── 关停:onDisable,逆序 stop(与 start 严格对称;服务不新增任何清场路径)
    │ onDisable ────────────────▶ shutdown():逆序 safeStop ─▶│ stop:注销订阅句柄、停自身任务
    │                            │ (逐个 try/catch 不中断;幂等,连调 3 次恰一次)
    │                            │ 摘除能力标签(§8.8)
```

> 读图要点:服务随**进程**存活(`onEnable` 装配 → `onDisable` 关停),不随任何 Session/Instance 生灭——服务不是第三级*组件*挂载级,A10 原文保留(D1)。装配两阶段:`install` 只声明(重复 id / 类型响亮失败;`seal` / `shutdown` 后 install 抛),`seal` 才校验 + 拓扑序创建 + 启动;任一工厂/start 抛 → 回滚已启动服务(逆序 stop)再抛,不留半启动态(镜像 switchMode"绝不停在中间态")。服务没有五钩子派发、不占 `tickAll` 任何一步(§3.8),自行经订阅事件驱动;与会话只走三条通道(D5):①订阅会话事件(通道一全集为 `SessionCreated / MemberJoined/Left / ModeSwitchStarted/Completed / SessionDissolved / SessionComponentQuarantined`,图示取其主干;订阅句柄在 `stop` 中注销);②只读快照(`MiniGameApi.sessions()` 不可变 record;现取不缓存,不持活实例/活组件引用跨切换,镜像 ★29);③受控命令(与 `/sm` 同权;`force` 是显式选择,走 review 条款)。组件/模式与服务**双向互不可见**(★40):组件/模式不得 import `engine/service/**` 与 `service/**`,服务不得 import `mode/**` 与 `component/**`;`MatchModeInstanceServices`(3 成员)与 `SessionServices`(2 成员)不加成员(★25)。决策全文见 18-v4.1 修正案(D1~D12)与 ADR-0006(`docs/adr/0006-process-service-registry.md`;修正案原文编号 0005,因 `docs/adr/0005` 已被《架构冻结测试门禁》占用,顺延为 0006)。**★v1.7 就地注(25 号,图体不改写)**:上图装配段的「注册能力标签(§8.8 口径)」与关停段的「摘除能力标签(§8.8)」两行随能力标签机制全链退场为**历史口径**——`ServiceSpec.capabilities` 声明与 seal/shutdown 两端标签注册删除(25 号);seal/shutdown 的其余接线(校验/拓扑/启动/逆序 safeStop)零改动。
